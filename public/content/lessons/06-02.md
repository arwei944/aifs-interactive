# Spectrogram, MEL scale and audio functions

> Neural networks cannot handle the original waveforms very well. They consume the spectrum. They can make better use of mel spectra. In 2026, the survival of every ASR, TTS and audio classifier depends on this single preprocessing choice.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 6 · 01 (Audio Fundamentals)
**Time:** ~45 minutes

## This question

Take a 10-second 16 KHZ clip. There are a total of 160,000 buoy original waveforms with information, but they exist in a form that the model cannot easily extract. Two identical phonemes spoken 100 milliseconds apart have completely different original samples.

The spectral graph solves this problem. It folds up the temporal details (microsecond jitter) that human perception ignores and retains the structure involved in perception (with a high frequency and a time window of ~ 10-25 milliseconds).

The Mel spectrum has made further progress. Human perception of pitch is logarithmic: 100hz vs 200hz sounds the same as 1000hz vs 2000hz. The mel scale distorts the frequency axis to match. From 2010 to 2026, MEL scale spectra will be the most important feature in speech machine learning.

## This concept


*Short-time Fourier Transform (STFT) Cut the waveform into overlapping frames (typical: 25-millisecond window, 10-millisecond hop = 400 samples / 160 samples at 16 kHz). Multiply each frame by a window function (Hann is the default value; Hamming is slightly different). FFT per frame. Superimpose the amplitude spectrum into a shape matrix. This is your spectrum diagram.

*Logarithmic amplitude. The original magnitude range was 5 to 6 orders of magnitude. Use the right magnitude for each production pipeline instead of the original magnitude.

*"MEL scale. The frequency mapping is approximately linear below 1 kHz and approximately logarithmic above 1 kHz. An 80-mel box covering 0-8 kHz is the standard ASR input.

*MEL filterbank. A set of triangular filters with equal intervals on the mel scale. Each filter is the weighted sum of adjacent FFT boxes. Multiply the STFT amplitude by the filter bank matrix to obtain a mel spectrum within the matrix.

*Log-mel spectrum. Whisper input. Input from a long-tailed parrot. The input of SeamlessM4T. General 2026 Audio Front-End.

** MFCCs. Take the logarithmic spectrum graph, apply DCT (Type II), and retain the first 13 coefficients. Unassociate the features and further compress them. It was not until around 2015 that cnn /Transformers caught up on the original logs. It is still used for speaker recognition (x vector, ECAPA).

*"Resolve trade. A larger FFT = better frequency resolution, but worse time resolution. 25ms / 10ms is the default value of audio-ML; 50 milliseconds / 12.5 milliseconds music Transient detection of 5 milliseconds / 2 milliseconds (drumbeats, explosions).

## Build it

### Step 1: Construct the waveform

”“python
Def frame(signal, frame_len, hop)：
N = 1 + (len(signal) - frame_len) //跳
返回[signal[i * hop: i * hop + frame_len] for i in range(n)]
```

A 10-second 16 kHz clip with `frame_len=400, hop=160` yields 998 frames.

### Step 2: Hann window

```python
import math

def hann(N):
    return [0.5 * (1 - math.cos(2 * math.pi * n / (N - 1))) for n in range(N)]
```

Multiply by element before FFT. Eliminate spectral leakage caused by non-zero endpoint truncation.

### Step 3:STFT amplitude

”“python
Def stft_magnitude(signal, frame_len=400, hop=160)：
Win = hann（frame_len）
Frames = frame（signal, frame_len, hop）
[magnitudes(dft([w * s for w, s in zip(win, f)])) for f in frames]
```

Production uses `torch.stft` or `librosa.stft` (FFT-backed, vectorized). The loop here is pedagogical; it runs on short clips in `code/main.py`.

### Step 4: mel filterbank

```python
def hz_to_mel(f):
    return 2595.0 * math.log10(1.0 + f / 700.0)

def mel_to_hz(m):
    return 700.0 * (10 ** (m / 2595.0) - 1)

def mel_filterbank(n_mels, n_fft, sr, fmin=0, fmax=None):
    fmax = fmax or sr / 2
    mels = [hz_to_mel(fmin) + (hz_to_mel(fmax) - hz_to_mel(fmin)) * i / (n_mels + 1)
            for i in range(n_mels + 2)]
    hzs = [mel_to_hz(m) for m in mels]
    bins = [int(h * n_fft / sr) for h in hzs]
    fb = [[0.0] * (n_fft // 2 + 1) for _ in range(n_mels)]
    for m in range(n_mels):
        for k in range(bins[m], bins[m + 1]):
            fb[m][k] = (k - bins[m]) / max(1, bins[m + 1] - bins[m])
        for k in range(bins[m + 1], bins[m + 2]):
            fb[m][k] = (bins[m + 2] - k) / max(1, bins[m + 2] - bins[m + 1])
    return fb
```

80 moles cover 0-8 kilohertz multiplied

### Step 5: Logarithm

”“python
Def log_mel(mel_spec, eps=1e-10)：
[[math.log(max(v, eps)) for v in frame] for frame in mel_spec]
```

Common alternatives: `librosa.power_to_db` (reference-normalized dB), `10 * log10(power + eps)`. Whisper uses a more involved clip + normalize routine (see Whisper's `log_mel_spectrogram`).

### Step 6: MFCCs

```python
def dct_ii(x, n_coeffs):
    N = len(x)
    return [
        sum(x[n] * math.cos(math.pi * k * (2 * n + 1) / (2 * N)) for n in range(N))
        for k in range(n_coeffs)
    ]
```

Apply DCT to each logarithmic frame and retain the first 13 coefficients. This is the MFCC matrix. The first coefficient is usually removed (it encodes the total energy).

## Use it

Stack for 2026

| Task | Features |
|------|----------|
| ASR (Whisper, Parakeet, SeamlessM4T) | 80 log-mels, 10 ms hop, 25 ms window |
| TTS acoustic model (VITS, F5-TTS, Kokoro) | 80 mels, 5–12 ms hop for fine temporal control |
| Audio classification (AST, PANNs, BEATs) | 128 log-mels, 10 ms hop |
| Speaker embedding (ECAPA-TDNN, WavLM) | 80 log-mels or raw-waveform SSL |
| Music (MusicGen, Stable Audio 2) | EnCodec discrete tokens (not mels) |
| Keyword spotting | 40 MFCCs for tiny devices |

Rule of thumb: ** If you're not making music, start with 80 log-meels. Any deviation shall bear the burden of proof.

## These traps will still occur by 2026

- Mel counts do not match. Training 80 Mels, reasoning 128 Mels. Silent failure. Record the characteristic shapes at both ends.
- The upstream sampling rate does not match. The mel calculated at 22.05 kHz appears different from that at 16 kHz. Fix SR before characterization.
- "dB vs log. Whisper expects log-mel, not dB-mel. Automatic detection of some high-frequency pipelines; Your custom code won't.
- "Standardized drift. Normalization of each sentence during the training process and global normalization during the reasoning process. A production bug that doubles WER.
- The packing is leaking. Zero-fill ending the clip generates a flat spectrum in the trailing frame. Symmetrical floor MATS or replicas.

## Key terms

| Term | What people say | What it actually means |
|------|-----------------|-----------------------|
| Frame | A slice | 25 ms chunk of waveform fed to one FFT. |
| Hop | Stride | Samples between consecutive frames; 10 ms is ASR default. |
| Window | Hann/Hamming thing | Point-wise multiplier that tapers the frame edges to zero. |
| STFT | Spectrogram generator | Framed + windowed FFT; yields time × frequency matrix. |
| Mel | Warped frequency | Log-perception scale; `m = 2595·log10(1 + f/700)`. |
| Filterbank | The matrix | Triangular filters that project STFT onto mel bins. |
| Log-mel | Whisper's input | `log(mel_spec + eps)`; standardized in 2026. |
| MFCC | Old-school feature | DCT of log-mel; 13 coeffs, decorrelated. |
