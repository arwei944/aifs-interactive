# 内存块和睡眠时间计算（Letta）

> MemGPT于2024年更名为莱塔。2026年的进化增加了两个想法：模型可以直接编辑的离散功能内存块，以及在主代理空闲时异步整合内存的睡眠时间代理。这就是将内存扩展到一个会话之外的方法。

**Type:** Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 · 07 (MemGPT)
**Time:** ~75 minutes

## 学习目标

- 说出Letta使用的三个内存层（核心、召回、存档）和每个层的角色。
- 解释内存块模式：Human块、Persona块和用户定义块作为第一类类型对象。
- 描述睡眠时间计算是什么，为什么它位于关键路径之外，以及为什么它可以运行比主代理更强大的模型。
- 实现一个脚本化的双代理循环，其中主代理提供响应，睡眠时间代理在回合之间合并块。

## 这个问题

MemGPT（第07课）解决了虚拟内存控制流。出现了三个生产问题：

1. * *延迟。**每个内存操作都位于关键路径上。如果代理必须在用户等待时进行修剪、汇总或协调，那么尾部延迟就会爆发。
2. **内存损坏。**写入累积。相互矛盾的事实依然存在。检索淹没在陈旧的内容中。
3. * *结构损失。**扁平的归档存储不能表达“Human block is always in the prompt；角色块总是在提示符中；每个会话的任务块交换。”

Letta （letta.com）是2026年的版本。内存块使结构显式；睡眠时间计算将整合移出关键路径。

## 这个概念

### 三层

| Tier | Scope | Where it lives | Written by |
|------|-------|----------------|------------|
| Core | Always visible | Inside the main prompt | Agent tool call + sleep-time rewrites |
| Recall | Conversation history | Retrievable | Automatic turn logging |
| Archival | Arbitrary facts | Vector + KV + graph | Agent tool call + sleep-time ingest |

核心是MemGPT核心。召回是会话缓冲区，它的尾部被清除。档案是外部存储。拆分清理了MemGPT的两层重载。

### 内存块

块是核心层的一个类型化的、持久的、可编辑的部分。最初的MemGPT论文定义了两个：

- **人类块** -关于用户的事实（姓名，角色，偏好，目标）。
- 角色障碍——代理人的自我概念（身份、语气、约束）。

### 睡眠时间计算

2025年的莱塔增加：在后台运行第二个代理，离开关键路径。睡眠时间代理处理会话记录和代码库上下文

产生的属性：

- **无延迟成本。**主响应不等待内存操作。
- **允许更强的模型。**睡眠时间代理可能是一个更昂贵、更慢的模型，因为它没有延迟约束。
- **自然整合窗口。**在用户不等待的时候，删除、总结、取消矛盾的事实。

它的形状与人类的工作方式相符：你完成任务，睡在上面，长期记忆在一夜之间形成。

### 莱塔V1和原生推理

Letta V1 (响应API （OpenAI）和具有扩展思维的消息API （Anthropic）在一个单独的通道上发出推理，轮流传递（在生产中跨提供者加密）。控制循环仍然是ReAct。思维轨迹是结构性的，而不是速成的。

### 这种模式哪里出错了

- * *块膨胀。**无限在写完封顶之前，先连接一个块总结器。
- * *沉默的漂移。**睡眠时间代理重写了一个块，而主代理永远不会注意到。跟踪中的版本块和表面差异。
- * *毒整合。**睡眠时间代理处理攻击者可访问的内容到核心。第27课也适用于睡眠时间曲面。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Memory block | "Editable prompt section" | Typed, persistent, LLM-editable segment of core memory |
| Human block | "User memory" | Facts about the user, pinned in core |
| Persona block | "Agent identity" | Self-concept, tone, constraints, pinned in core |
| Sleep-time compute | "Async memory work" | Second agent doing consolidation off the critical path |
| Core / Recall / Archival | "Tiers" | Three-layer memory split: always-visible / conversation / external |
| Block limit | "Cap" | Character limit per block; forces summarization |
| Native reasoning | "Thinking channel" | Provider-level reasoning output, not prompt-level `Thought:` |
| Learned context | "Sleep output" | Facts the sleep-time agent writes into shared blocks |
