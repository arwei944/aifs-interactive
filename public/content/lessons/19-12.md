# 顶点12 -视频理解管道（场景，QA，搜索）

> 十二实验室生产马伦戈+飞马。VideoDB发布了用于视频的crud API。AI2的Molmo 2发布了开放的VLM检查点。双子座长上下文处理数小时的本地视频。TimeLens-100K在尺度上def 了时间接地。2026年的流水线已经确定：场景分割，每个场景的字幕+嵌入，文本对齐，多向量索引，以及一个带有（开始，结束）时间戳和帧预览的查询。测试的顶点是摄入100个小时，达到公共基准，并在计数和行动问题上测量幻觉。

## 问题

在2026年，长视频QA是最需要带宽的多模式问题。Gemini 2.5 Pro可以本地读取2小时的视频，但将100小时的视频提取到可查询的语料库中仍然需要场景级索引。生产形状结合了场景分割（TransNetV2或PySceneDetect），带有VLM的每个场景字幕（Gemini 2.5， qwen3 - v1 - max或Molmo 2），转录本对齐（带有单词时间戳的Whisper-v3-turbo），以及存储标题，帧嵌入和并排转录本的多向量索引。查询管道使用（开始、结束）时间戳和帧预览进行应答。

基准测试是公开的（ActivityNet-QA, NeXT-GQA），加上您自己的100条查询自def 集。计数和行动型问题的幻觉是已知难的失败类；顶点明确地测量了它。

## 概念

三个管道在摄取时并行运行。**场景分割**将视频切割成场景。VLM字幕生成每个场景的字幕和从关键帧嵌入的帧。**ASR对齐**产生字级时间戳。三个流由（scene_id, time range）连接。每个场景在一个多向量索引（Qdrant）中得到三种向量类型：标题嵌入、关键帧嵌入、文本嵌入。

在查询时，自然语言问题对所有三个向量触发；结果与RRF合并；一个临时接地适配器（timelens风格）改进了顶部场景中的（开始、结束）窗口。VLM合成器（Gemini 2.5 Pro或qwen3 - v1 - max）采用查询+顶级场景+裁剪帧和引用时间戳和帧预览的答案。

幻觉测量很重要。计数（“有多少人进入房间？”）动作型（“厨师在搅拌之前会倒酒吗？”）问题是出了名的不可靠。报告准确性与描述性问题分开。

## 体系结构

```
video file / URL
      |
      v
PySceneDetect / TransNetV2  (scene segmentation)
      |
      +--- per-scene keyframe --- VLM caption + frame embedding
      |                            (Gemini 2.5 Pro / Qwen3-VL-Max / Molmo 2)
      |
      +--- audio channel --- Whisper-v3-turbo ASR + word timestamps
      |
      v
multi-vector Qdrant: {caption_emb, keyframe_emb, transcript_emb}
      |
query:
  dense queries against all three -> RRF merge -> top-k scenes
      |
      v
TimeLens / VideoITG temporal grounding (refine start/end within scene)
      |
      v
VLM synth: query + top scenes + frame previews
      |
      v
answer + (start, end) timestamps + frame thumbs + citations
```

## 堆栈

- 场景分割：TransNetV2（最先进的2024-26）或PySceneDetect
- ASR：耳语-v3涡轮通过更快的耳语与文字时间戳
- VLM字幕+答录机：Gemini 2.5 Pro或Qwen3-VL-Max或Molmo 2
- 时间接地：timelens - 100k训练适配器或VideoITG
- 索引：多向量支持的Qdrant（标题/帧/文本）
- UI：带有HTML5视频播放器和场景缩略图的Next.js 15
- 评估：ActivityNet-QA， NeXT-GQA，自def 100个问题的手动标签集
- 幻觉基准：用手标记计数和动作类型子集

## 构建它

1. **摄取沃克。**接受YouTube url或本地MP4s。如果需要的话，降低到720p。坚持

2. **场景分割。**运行TransNetV2或PySceneDetect生成目标100小时：~6k-8k场景。

3. ** ASR通过。**运行Whisper-v3-turbo音频；导出字级时间戳；分割成每个场景的脚本片段。

4. ** VLM字幕。**每个场景，调用Gemini 2.5 Pro（或Qwen3-VL-Max）的关键帧和简短的标题模板。生成标题+框架嵌入。

5. ** Multi-vector指数。** Qdrant集合与三个命名向量。有效载荷：

6. **查询。**自然语言问题触发三个密集查询；采用秩倒融合合并；top-k = 5。

7. **时间接地。**在顶部场景上运行timelens样式的适配器，以细化场景中的（开始，结束）窗口。

8. ** VLM合成器。**拨打Gemini 2.5 Pro查询+前3名场景剪辑（图像或短片）+成绩单。要求

9. ** Eval。**运行ActivityNet-QA和NeXT-GQA。构建一个包含100条查询的自def 集。报告总体准确性+每个类的细分（计数，动作，描述性）。

## 练习

1. 把Gemini 2.5 Pro换成Qwen3-VL-Max。报告人类评级的50个场景样本的标题质量delta。

2. 减少每个场景帧嵌入到一个池向量，而不是多个向量。测量检索回归。

3. 构建“严格计数”模式：合成器使用时间戳提取每个计数实例，用户单击以进行验证。衡量用户验证是否减少了幻觉。

4. 基准摄取成本：在三种VLM选择中，每美元的视频小时数。选择最佳位置。

5. 添加speaker-diarized transcript：在音频上运行pyannote speaker dialarization并嵌入每个speaker的transcript。演示“Alice说了关于X的什么？”

## 关键术语

| Term | What people say | What it actually means |
|------|-----------------|------------------------|
| Scene segmentation | "Shot detection" | Cutting video into scenes at shot boundaries |
| Multi-vector index | "Caption + frame + transcript" | Qdrant collection with named vectors per representation |
| Temporal grounding | "When exactly did it happen" | Refining the (start, end) window for a query answer |
| Frame embedding | "Visual representation" | A vector embedding of a keyframe; used for scene-visual similarity |
| RRF fusion | "Reciprocal rank fusion" | Merge strategy across multiple ranked lists; a classic hybrid-retrieval trick |
| Counting hallucination | "Miscount" | Known failure mode of VLMs on "how many X" questions |
| ActivityNet-QA | "Video-QA benchmark" | Long-form video QA accuracy benchmark |
