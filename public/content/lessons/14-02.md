# ReWOO和计划-执行：解耦计划

> ReAct将思想和行动交织在一个流中。ReWOO将它们分开：预先制定一个大计划，然后执行。减少5倍的代币，在HotpotQA上增加4%的准确率，你可以将计划器提炼成7B模型。计划与执行概括了它；Plan-and-Act将其扩展到网页导航。

**Type:** Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 · 01 (Agent Loop)
**Time:** ~60 minutes

## 学习目标

- 解释为什么ReWOO的Planner / Worker / Solver拆分节省了令牌，并提高了ReAct交错循环的鲁棒性。
- 实现一个计划DAG、一个依赖顺序执行器和一个组成工作输出的求解器——所有这些都是标准库。
- 使用2026“五种工作流模式”框架（Anthropic），决定任务何时应该以计划-然后执行的方式运行，而不是交错的ReAct。
- 认识到何时需要plan -and- act的综合计划数据用于长期网络或移动任务。

## 这个问题

ReAct的思考-行动-观察交错循环简单而灵活，但每个工具调用都必须携带完整的先前上下文-包括之前的每个想法。令牌的使用随着深度呈二次增长。更糟糕的是：当一个工具在循环中失败时，模型必须从错误观察中重新导出整个计划。

ReWOO （Xu et al., arXiv:2305.18323, May 2023）注意到了这一点，并打了一个赌：提前计划整个事情，并行获取证据，最后撰写答案。一个LLM调用用于计划，N个工具调用用于证据（可以并行），一个LLM调用用于解决。交易的灵活性较低（计划是静态的），以获得更好的代币效率和更清晰的故障模式。

## 这个概念

### 三个角色

```
Planner:  user_question -> [plan_dag]
Workers:  [plan_dag]     -> [evidence]        (tool calls, possibly parallel)
Solver:   user_question, plan_dag, evidence -> final_answer
```

Planner生成DAG。每个节点命名一个工具、它的参数，以及它依赖于哪个早期节点(引用如工作器按拓扑顺序执行节点。求解器把所有的东西缝合在一起。

### 为什么代币减少了5倍

ReAct的提示长度随着步数线性增长。在第10步，提示包含思想1 +行动1 +观察1 +思想2 +行动2 +观察2，以此类推。每个中间步骤还冗余地包含原始提示。

ReWOO支付一个计划者提示（大），N个小工人提示（每个只是工具调用，没有链）和一个求解器提示。在HotpotQA上，纸张测量的代币减少了约5倍，而绝对准确率为+4。

### 为什么它更健壮

如果worker 3在ReAct中失败，则循环必须在流程中间排除错误。在ReWOO中，worker 3返回一个错误字符串；求解器将其置于原始计划的上下文中，并可以优雅地降级。故障定位是每个节点，而不是每个步骤。

### 规划师蒸馏

这篇论文的第二个结论是：因为规划器看不到观察结果，所以你可以根据规划器输出的175B教师对7B模型进行微调。小模型处理计划；在推理时不需要大模型。这是现在的标准——许多2026生产代理使用一个小的计划者和一个大的执行者，反之亦然。

### 计划与执行（LangChain, 2023）

LangChain团队在2023年8月的文章中将ReWOO概括为一个模式名称：计划-执行。预先规划程序发出一个步骤列表，执行程序运行每一步，可选的重新规划程序可以在观察结果后修改。这比ReWOO更接近ReAct（重新规划器将观察结果带回到规划中），但保留了令牌节省。

### 计划与行动（Erdogan等人，arXiv:2503.09572, ICML 2025）

计划-行动将模式扩展到长期的网络和移动代理。关键的贡献是综合计划数据：标记轨迹生成器在计划明确的地方产生训练数据。用于微调计划器模型，使其在webarena类任务中保持超过30-50个步骤，其中单个ReAct轨迹失去一致性。

### 什么时候选哪个

| Pattern | When |
|---------|------|
| ReAct | Short tasks, unknown environment, need reactive exception handling |
| ReWOO | Structured tasks with known tools, token-sensitive, parallelizable evidence |
| Plan-and-Execute | Like ReWOO but with replanning after partial execution |
| Plan-and-Act | Long-horizon (>30 steps), web/mobile/computer-use |
| Tree of Thoughts | Search is worth paying for (Lesson 04) |

Anthropic的2024年12月指南：从最简单的开始。如果任务是一个工具调用加一个摘要，则不要构建ReWOO。如果任务是一个40步的研究任务，不要单独做ReAct。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| ReWOO | "Reasoning without observations" | Plan, then fetch evidence in parallel, then solve — no observations in the planning prompt |
| Plan-and-Execute | "LangChain's plan-execute pattern" | ReWOO with an optional replanner node after execution |
| Plan-and-Act | "Scaled plan-execute" | Explicit planner/executor split with synthetic plan training data for long-horizon tasks |
| Evidence reference | "#E1, #E2, ..." | Plan-node placeholder substituted with prior worker output at dispatch time |
| Planner distillation | "Small planner, big executor" | Fine-tune a small model on planner traces from a large teacher |
| Token efficiency | "Fewer round trips" | 5x fewer tokens on HotpotQA vs ReAct in the paper |
| DAG executor | "Topological dispatcher" | Runs plan nodes in dependency order; parallel at each level |
