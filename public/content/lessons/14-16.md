# OpenAI代理SDK：切换，护栏，跟踪

> OpenAI Agents SDK是基于响应API构建的轻量级多代理框架。五个原语：代理、切换、护栏、会话、跟踪。移交是工具的名称护栏在输入或输出时跳闸。默认情况下，跟踪是开启的。

**Type:** Learn + Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 · 01 (Agent Loop), Phase 14 · 06 (Tool Use)
**Time:** ~75 minutes

## 这个问题

不能清晰地委托的代理最终会将所有内容塞进一个提示中。没有护栏的代理发送PII、违反策略的输出或永远循环。OpenAI的SDK编写了使多代理工作易于处理的三个基本要素。

## 这个概念

### 五个基本类型

1. **代理。** LLM +指令+工具+移交。
2. **切换。**委托给其他代理。在模型中表示为一个名为
3. **护栏。**验证输入（仅第一个代理），输出（仅最后一个代理）或工具调用（每个功能工具）。
4. **会话。**自动会话历史跨越回合。
5. **跟踪。**内置的LLM世代跨度，工具调用，移交，护栏。

### 作为工具的交接

模型看到调用它会向运行时发出信号：

1. 复制对话上下文(或通过
2. 使用其指令初始化目标代理。
3. 继续运行目标代理。

这是主管模式（第13课/第28课）的产品化。

### 护栏

三种口味:

- **输入护栏。**运行第一个代理的输入。在任何LLM调用之前拒绝不安全或超出范围的请求。
- **输出护栏。**运行最后一个代理的输出。捕捉PII泄漏、策略违反、格式错误的响应。
- **工具护栏。**运行每个功能工具。验证参数，检查权限，审计执行。

模式:

- ** **(默认)平行。护栏LLM与主LLM一起运行。较低的尾部延迟。如果触发，主LLM的工作将被丢弃（令牌浪费）。
- **阻塞** (护栏LLM首先运行。如果触发，则不会在主调用上浪费令牌。

绊网升高

### 跟踪

默认为开启。每个LLM生成、工具调用、移交和护栏都会发出一个跨度。`OPENAI_AGENTS_DISABLE_TRACING=1` opts out. `add_trace_processor(processor)` fans spans to your own backend alongside OpenAI's.

### 会话

`Runner.run(agent, input, session=session)` auto-loads and appends.

### 这种模式哪里出错了

- **切换漂移。**座席A将业务移交给座席B，座席B再将业务移交给座席A。
- **护栏绕过。**工具护栏只适用于功能工具；内置工具（文件读取器，web获取）需要单独的策略。
- ** Over-tracing。**敏感内容在跨度。与OTel GenAI内容捕获规则配对（第23课）-外部存储，按ID引用。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Agent | "LLM + instructions" | Agent type in the SDK; owns tools and handoffs |
| Handoff | "Transfer" | Tool the model calls to delegate to another agent |
| Guardrail | "Policy check" | Validation on input / output / tool invocation |
| Tripwire | "Guardrail trip" | Exception raised when guardrail rejects |
| Session | "History store" | Conversation memory persisted between runs |
| Tracing | "Spans" | Built-in observability over LLM + tool + handoff + guardrail |
| Blocking guardrail | "Sequential check" | Guardrail runs first; no token waste on trip |
| Parallel guardrail | "Concurrent check" | Guardrail runs alongside; lower latency, wastes tokens on trip |
