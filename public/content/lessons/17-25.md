# 安全-秘密，API密钥轮换，审计日志，护栏

> 通过集中式保管库（HashiCorp保管库、AWS秘密管理器、Azure密钥保管库）消除秘密蔓延。永远不要将凭证存储在配置文件、VCS中的env文件、电子表格中。在静态密钥上使用IAM角色；CI/CD的OIDC。人工智能网关模式是2026年的解决方案：应用程序→网关→模型提供商，网关在运行时从保险库中提取凭证。在保险库中旋转，所有的应用程序在几分钟内就能恢复-没有重新部署，没有Slack“谁有新密钥”的消息。轮岗政策≤90天；在每次提交时使用TruffleHog / GitGuardian / Gitleaks进行扫描。零信任：MFA、SSO、RBAC/ABAC、短期令牌、设备状态。PII扫描在转发之前使用实体识别来掩盖PHI/PII；一致标记化（Mesh方法）将敏感值映射到稳定的占位符，以便LLM保留代码/关系语义。网络出口：仅限专用VPC/VNet子网白名单中的LLM业务阻止所有其他出站。2026年事件驱动因素：Vercel供应链攻击通过受损的CI/CD凭证泄露了数千个客户部署的环境。

## 这个问题

实习生提交他们很快就删除了。密钥已经在git的历史记录中了——GitGuardian会发现它，你的轮换过程是“放松团队，更新40个配置文件，重新部署所有服务。”8小时后，一半的服务是活动的，一半在等待部署窗口。

另外，用户提示包括“我的SSN是123-45-6789”。提示符转到OpenAI。您有一个BAA，但您的内部策略是在转发之前屏蔽PII。你没有。

另外，您的EKS集群的LLM pod可以访问任何internet主机。有人通过DNS查找将数据泄露到攻击者控制的域。没有东西挡住它。

LLM服务的安全性必须解决这三个方面的问题。Vault-backed凭证。PII擦洗。网络出口过滤。审计日志。

## 这个概念

### 集中式保险库+ IAM-role pull

**保险库**:HashiCorp保险库，AWS秘密管理器，Azure密钥保险库，GCP秘密管理器。真相的一个来源。

**IAM role**: app/gateway通过其IAM身份进行认证，而不是静态密钥。Vault返回令牌生命周期内的秘密。

** ai网关模式**：网关拉旋转跳马；下一个请求获取新密钥。没有重新部署。

### 轮换策略≤90天

所有API密钥，保险库根令牌，CI/CD凭证。在可能的情况下自动旋转。手动旋转记录和跟踪。

### 秘密扫描

- **TruffleHog** -提交时的正则表达式+熵。
- **GitGuardian** -商业，准确性高。
- **Gitleaks** - OSS，运行CI。

每次提交都运行。如果检测到新的秘密，阻塞PR。

### Zero-trust姿势

- 所有帐户都需要MFA。
- 通过SAML/OIDC。
- RBAC（基于角色）或ABAC（基于属性）用于细粒度访问。
- 短期令牌（小时，而不是天）。
- 设备姿态-仅支持磁盘加密的corp设备。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Vault | "secrets store" | Centralized credential management service |
| IAM role | "identity-based auth" | Role assumed by app; returns short-lived creds |
| OIDC for CI/CD | "cloud-issued tokens" | No static keys in CI — identity via OIDC |
| TruffleHog / GitGuardian / Gitleaks | "secret scanners" | Commit-time secret detection |
| RBAC / ABAC | "access control" | Role-based vs attribute-based |
| PII scrubbing | "data masking" | Remove or tokenize sensitive entities |
| Consistent tokenization | "stable placeholders" | Same value → same token each time |
| Mesh approach | "Mesh tokenization" | Semantic-preserving tokenization pattern |
| Egress whitelist | "outbound allowlist" | Only permitted domains reachable |
| Audit log | "immutable history" | Append-only record for compliance |
