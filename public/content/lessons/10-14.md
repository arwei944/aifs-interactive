## This concept

### Unchanging core

All autoregressive open models share:

- Token embedding matrix (vocab_size x hidden_dim).
- Stack of N decoder blocks: norm, self-attention, residual, norm, MLP, residual.
- The final specification and linear head are projected onto vocab_size (usually bound to the embedded weights).
- Causal mask, the next token cross-entropy loss.

This is the shape. The rest are all knobs.

### Six truly moving knobs

In every cutting-edge open model from 2024 to 2026, the same six design options were repeatedly selected:

1. Normalization. LayerNorm -> RMSNorm.
2. Location encoding. Learn the absolute -> rope (with variations: yarn, NTK).
3. “激活”。* * GELU / SwiGLU(或为GeGLU)。
4. Attention head sharing. mha -> gqa -> mqa -> mla.
5. Dense vs. sparse MLP. Dense -> Hybrid Expert.
6. "Pre-norm position." Maintain the previous norms. The post-normative era has passed.

Everything else (learning rate planning, data blending, batch size, context length) exists in the training configuration, not in the architecture. Six knobs.

### Knob 1:RMSNorm

LayerNorm minus the average value, divided by std, scale and shift. RMSNorm only retains scales:

```
RMSNorm(x) = x / sqrt(mean(x^2) + eps) * gamma
```

There is no average subtraction. Without prejudice. Each token reduces one matmul. Zhang and Sennrich (2019) believe that it matches the LayerNorm of machine translation while being 10% faster. Every modern open model runs it.

Cost: None. Advantages: Small throughput wins, and the code is simpler.

### Knob 2: Rope

The learning location embedding is a 1024-slot lookup table in GPT-2. Context 1025 is not at the end of the table. Models cannot infer beyond their training length.

Rotational position embedding (RoPE, Su et al. 2021) injects positions by pairwise rotating each Q and K vector before the dot product of attention. The rotation Angle is a deterministic function of position, so there is nothing to learn and nothing to use up. Using scaling techniques (NTK-aware interpolation, YaRN), models trained on an 8k context can scale up to 128k with a moderate loss of precision.

```
q_rotated = rotate(q, angle(pos))
k_rotated = rotate(k, angle(pos))
score = q_rotated . k_rotated
```

Each alpaca, Mistral, Qwen, DeepSeek and Gemma uses RoPE. "Gemma 2" uses a blending mode (most layers use RoPE, and other layers use a local sliding window).

### Knob 3: SwiGLU

The MLP of GPT-2 was activated by SwiGLU (Shazeer 2020) using gated products instead:

```
SwiGLU(x) = (xW1) * sigmoid(xW1) * xV
```

Two parallel projections, not one, are activated and controlled by Swish. There is stronger confusion about each parameter in terms of experience. Alpaca 2 adopted it, and everyone followed. If GPT-2 is used, the hidden size of the MLP is usually set so that the total parameter number matches the original dense MLP

### Knob 4: Attention Head Sharing

GPT-2 uses ** Head Attention (MHA)** : Each head has its own Q, K, and V projections.

** Multi-query Attention (MQA, Shazeer 2019)** shares one K and one V across all headers. Reduce the KV cache by num_heads, which reduces it by 12 to 32 times on a typical model. The accuracy rate slightly dropped in hard benchmark tests.

** Group query Note (GQA, Ainslie et al., 2023) ** is the middle route: the Q head of group G shares one K and one v. Llama 38b uses GQA with 32 Q headers and 8 KV headers (G=8), so the KV cache is reduced by 4 times compared to full MHA.

** Multi-head latent attention (MLA, DeepSeek 2024)** Compresses K and V into a shared low-rank latent and projects them onto each head. Further reduce the KV cache while retaining the expression of each header. DeepSeek-V2 and V3 rely on its long context performance.

| Scheme | KV Heads | KV Cache | Accuracy |
|--------|----------|----------|----------|
| MHA    | num_heads | full | best |
| GQA    | num_groups (G < num_heads) | num_heads / G reduction | near-MHA |
| MQA    | 1 | num_heads reduction | small hit |
| MLA    | latent, per-head decompression | smaller than MQA | near-MHA |

For any model with parameters higher than ~13B, GQA or MLA is actually mandatory. Large-scale full MHA is a kilovolt cache disaster.

### Knob 5: Expert Mixing

Dense MLP activates all parameters for each token. Each block of a MoE MLP has K experts, and a router selects the first K experts (usually the first 2) for each token. Only the weights of those experts will see the forward passage of this token.

```
router_logits = xW_r
indices, weights = top_k(router_logits, k=2)
output = sum_i weights[i] * expert[indices[i]](x)
```

The attractive part is that you can have 64 experts of size 7B (so the total parameter number is huge), and each token only runs 2 experts (so each token computations a densely matched 7B model). Mixtral 8x7B has a total of 47B parameters, but only 13B parameters are activated for each token. DeepSeek V3 has a total of 671B parameters, but only 37B parameters are activated for each token.

"Mermaid"
"Figure LR

T - > EN[" Expert 64\n (MLP, not used) "]

```

Pros: same compute, more parameters, better capacity. Cons: the expert memory still has to live somewhere (so serving needs more VRAM than a dense equivalent), load-balancing the router is hard, and fine-tuning the router during alignment is its own research area.

### Knob 6: Pre-norm stays

The original transformer applied layer norm after each sublayer. Every open model since GPT-2 puts it *before* each sublayer. Pre-norm is strictly easier to train at depth. Nothing to argue about.

```

Every field corresponds to something you have already implemented.

- `hidden_size`: embedding dimension.
- `intermediate_size`: MLP hidden size (3.5x hidden -- SwiGLU math).
- `num_hidden_layers`: stack depth.
- `num_attention_heads`: Q heads.
- `num_key_value_heads`: KV heads (GQA).
- `max_position_embeddings`: training context length.
- `rope_theta`: RoPE base frequency. Meta scaled it from the default 10k to 500k for long-context extrapolation.
- `rms_norm_eps`: numerical stability.
- `vocab_size`: tokens.

From these alone you compute total parameters, KV cache, and peak activation memory. See `code/main.py` for the exact formulas.

### Activation memory budget

Activations dominate training memory above a few billion parameters. The rule of thumb for pre-training (with gradient checkpointing):

```
Activation_mem ~ batch_size * seq_len * hidden_size * num_layers * bytes_per_element
```

For Llama 3 8B at batch 1, seq 8192, BF16, 32 layers, hidden 4096: roughly 8 GB just for activations with checkpointing, 40 GB without. This is why flash-attention and ring-attention matter -- they rewrite the attention computation so activations fit.

### KV Cache budget

For inference at max context:

```
Kv_cache = 2 * num_layers * num_kv_heads * head_dim * max_seq_len * bytes_per_element
```

Llama 3 8B at 128k context, BF16, head_dim = hidden / num_heads = 128:
`2 * 32 * 8 * 128 * 131072 * 2 = 17.2 GB` per sequence.

The 8B weights are 16 GB in BF16. The KV cache for a single 128k sequence is larger than the weights. This is the memory pressure driving GQA, MLA, and KV cache quantization research.

### When Each Model Wins

- **Single 80GB GPU, no MoE**: Llama 3 8B, Mistral 7B, Gemma 2 9B. Easy to serve, wide tooling.
- **Single node (8x80GB), big capacity**: Llama 3 70B, Qwen 2.5 72B. Highest dense open capability.
- **Biggest open capability, accept MoE complexity**: DeepSeek V3, Mixtral 8x22B. Best capability per active FLOP.
- **Long-context needs**: Llama 3 (128k with RoPE scaling), DeepSeek (MLA advantage).
- **Low-latency serving**: Gemma 2 9B (sliding window cuts long-context compute).

## Key terms

| Term | What people say | What it actually means |
|------|----------------|----------------------|
| RMSNorm | "LayerNorm without the mean" | Normalize by root mean square only, with a learned scale — cheaper and comparable to LayerNorm |
| RoPE | "Rotary positions" | Rotate each Q and K vector in 2D pairs by an angle that depends on position — extrapolates beyond training length with scaling tricks |
| SwiGLU | "The new MLP activation" | Gated linear unit with Swish: `(xW1) * sigmoid(xW1) * xV` — standard in every 2024+ open model |
| GQA | "Middle ground attention" | Grouped-Query Attention: G groups of Q heads share one K and one V head — shrinks KV cache without MQA's accuracy hit |
| MLA | "DeepSeek's attention" | Multi-Head Latent Attention: compress K/V into a shared low-rank latent, decompress per head — smallest KV cache for large models |
| MoE | "Sparse experts" | Mixture of Experts: N MLPs per block, router picks top-k per token — huge total params, small active params |
| Top-k routing | "Pick k experts per token" | The router computes a score per expert and activates the k highest — typical k is 2 (Mixtral) to 8 (DeepSeek) |
| YaRN | "Stretch RoPE" | Yet another RoPE extension — interpolates rotary angles to extend context from 8k to 128k+ at inference time |
| Sliding-window attention | "Don't attend to everything" | Each token attends only to the last W tokens — caps attention cost at O(W) per token, used in Gemma 2 and early Mistral |
| Active params | "What runs per token" | For MoE models, the parameter count that sees a forward pass per token (much smaller than total params) — governs per-token FLOPs |
