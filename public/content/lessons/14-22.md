# 语音代理：Pipecat和LiveKit

> 语音代理是2026年的头等生产类别。Pipecat提供了一个基于Python框架的管道（VAD→STT→LLM→TTS→transport）。LiveKit Agents通过WebRTC将AI模型与用户连接起来。对于高级堆栈，生产延迟目标为450-600ms。

**Type:** Learn
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 · 01 (Agent Loop), Phase 14 · 12 (Workflow Patterns)
**Time:** ~60 minutes

## 学习目标

- 描述Pipecat基于框架的管道：下游（源→汇）和上游（控制）。
- 命名规范的语音管道阶段以及Pipecat支持哪些传输。
- 解释LiveKit agent的两个语音代理类（MultimodalAgent, voicepilineagent）以及何时适合。
- 总结2026生产延迟预期以及它们如何驱动架构选择。

## 这个问题

语音代理不是一个文本循环与TTS螺栓。延迟预算是残酷的（~600ms），部分音频是默认的，转向检测是一个模型，传输范围从电话SIP到WebRTC。要么你构建一个基于框架的管道（Pipecat），要么你依靠一个平台（LiveKit）。

## 这个概念

### Pipecat (pipecat-ai/pipecat)

- 基于Python框架的管道框架。
- 
- 两个流向：
  - **下行** -源→汇（音频输入，TTS输出）。
  - **上游** -反馈和控制（取消，度量，驳船）。
- 

典型的管道:

```
VAD (Silero) → STT → LLM (context alternates user/assistant) → TTS → transport
```

传输：每日，LiveKit, SmallWebRTCTransport, FastAPI WebSocket, WhatsApp。

Pipecat Flows添加了结构化对话（状态机）。Pipecat Cloud是托管运行时。

### LiveKit Agents (livekit/agents)

- 通过WebRTC将AI模型与用户连接起来。
- 关键概念：
- 两个语音代理类：
  - **MultimodalAgent** -直接音频通过OpenAI实时或等效。
  - ** voicepilineagent ** - STT→LLM→TTS级联；提供文本级控制。
- 通过变压器模型进行语义转向检测。
- 本地MCP集成。
- 通过SIP电话。
- 50+模型没有API密钥通过LiveKit推理；200+通过插件。

### 商业平台

Vapi（在优化的高级堆栈上约450-600ms）和Retell（在180个测试调用中端到端约600ms）构建在这些之上。当你想要一个没有WebRTC团队的托管语音堆栈时，选择一个平台。

### 这种模式哪里出错了

- **禁止驳船装卸。**用户中断；特工一直在说话。在Pipecat中需要UPSTREAM取消帧，在LiveKit中等效。
- **STT置信度忽略。**给LLM的低信心成绩单就像福音一样。保密门或请求确认。
- **TTS句中截断。**当管道中途取消语音时，TTS需要知道或切断音频。
- **忽略延迟预算。**每个组件增加50-200ms。发货前汇总你的链条。

### 典型的2026延迟

- VAD: 20–60ms
- STT偏置：100-250ms
- LLM第一个令牌：150-400ms
- TTS首音频：100-200ms
- 传输RTT: 30-80ms

端到端450-600ms为优值。800-1200ms是常见的。任何超过1500毫秒的东西都感觉坏了。

## 使用它

- **Pipecat**用于完全控制自def 处理器，python优先，可插入的提供程序。
- **LiveKit代理**用于webtc优先部署和电话。
- **Vapi / Retell**用于没有WebRTC团队的托管语音代理。
- **OpenAI Realtime / Gemini Live**用于直接音频输入/音频输出（MultimodalAgent）。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Frame | "Event" | Typed unit of data in the pipeline (audio, transcript, text, control) |
| Processor | "Pipeline stage" | Handler with process(frame) |
| DOWNSTREAM | "Forward flow" | Source to sink: audio in, speech out |
| UPSTREAM | "Feedback flow" | Control: cancel, metrics, barge-in |
| VAD | "Voice activity detection" | Detects when user is speaking |
| Semantic turn detection | "Smart end-of-turn" | Model-based decision that the user is done |
| MultimodalAgent | "Direct audio agent" | Audio in, audio out; no text in the middle |
| VoicePipelineAgent | "Cascade agent" | STT + LLM + TTS; text-level control |
