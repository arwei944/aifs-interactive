# LLaVA-OneVision：单图像，多图像，视频在一个模型

> 在LLaVA-OneVision （Li et al., August 2024）之前，开放vlm世界有单独的谱系：LLaVA-1.5用于单图像，多图像模型（如Mantis和VILA），视频模型（如video - llava和video - llama）。每个人都赢得了自己的基准，而在其他方面却失败了。LLaVA-OneVision认为，单一课程可以训练一个模型来主导所有三种场景，并且紧急任务转移效应（将单图像技能导出到视频，将多图像推理导出到单图像）胜过专家的总和。配方看起来很简单：在不同场景下保持不变的视觉标记预算，加上从单图像到多图像再到视频的明确课程。这节课将阅读预算、课程和紧急行为。

**Type:** Build
**Languages:** Python (stdlib, token budget solver + curriculum planner)
**Prerequisites:** Phase 12 · 05 (LLaVA), Phase 12 · 06 (any-resolution)
**Time:** ~180 minutes

## 学习目标

- 设计一个视觉标记预算，使其在单图像、多图像和视频输入中保持不变。
- 订购培训课程，将技能从单幅图像转移到视频中，而不会造成灾难性的遗忘。
- 解释为什么在课程设置正确的情况下，单一模型在相同的参数数量上胜过专家。
- 请说出LLaVA-OneVision报告的三种紧急功能：多摄像头推理、标记集提示、iphone截图代理。

## 这个问题

图像、多图像和视频对模型的强调各不相同。

单图像需要高分辨率令牌（AnyRes， ~2880视觉令牌）来捕捉OCR和精细细节。每个样本预算：一张图像，2880代币。

Multi-image需要几个中等分辨率的图像（每个约576个标记），因此跨图像的推理适合上下文。每个样本预算：4-8张图片，每张576张，2300-4600代币。

视频需要低分辨率的多帧（池化后每帧约196个令牌）来捕捉时间动态。每个样品预算：8-32帧，每个196帧，1600-6200代币。

如果你训练不同的模型，你选择一个预算。如果你训练一个模型，你需要预算在不破坏上下文的情况下合理地跨场景扩展。

在onevision出现之前，默认的答案是“训练一个场景，忽略其他场景。”video - llava将视频改造为具有额外训练阶段的图像模型。LLaVA-NeXT添加了多图像支持与平铺。没有人能干净利落地处理这三件事。

## 这个概念

### OneVision代币预算

LLaVA-OneVision选择统一的视觉令牌预算，每个样本约3000-4000个令牌，每个场景分配不同：

- 单个图像：AnyRes-9 （3x3瓷砖+缩略图），每个瓷砖384，有729个补丁，侵略性双线性池2x2→182每个瓷砖。总数：9 * 182 + 182 = 1820个token。或者AnyRes-4的729 / tile = 2916 + 729。
- 多图像：每个图像以中等分辨率（384，无平铺），729个令牌，无池化。预算6张图片→4374个代币。
- 视频：32帧，384分辨率，积极的3x3双线性池→每帧81个令牌。总数：32 * 81 = 2592个代币。

分配保持大致恒定的令牌总数。法学硕士从来没有见过一批不符合上下文的。编码器在每个场景中产生不同的几何图形，但LLM消耗相同的预算。

### 三阶段课程

LLaVA-OneVision分为三个阶段：

1. 单图像SFT（阶段SI）。所有数据都是单一图像加文本。训练高分辨率AnyRes输入。这教导了感知、OCR和细粒度的理解。使用LLaVA-NeXT数据加上onevision特定的单图像数据。
2. OneVision SFT （OV阶段）。混合单图像+多图像+视频（均匀采样帧）。培训统一的代币预算。这将教会模型处理异构批处理形状。没有重量重置-继续从阶段SI。
3. 任务转移（阶段TT）。继续进行目标任务组合，根据产品的不同，通常更侧重于多图像或视频。可选的部署微调。

关键：课程顺序很重要。训练视频优先或多图像优先比单图像优先产生更差的图像性能，即使使用相同的数据。这篇论文明确地驳斥了这一点。

### 为什么课程有效？

单图像训练建立感知基础。补丁令牌带有细粒度的视觉特征；法学硕士学习将它们与文本相结合。多图像和视频引入了结构性挑战（哪个图像是哪个，先发生了什么），如果没有强大的感知基础，很难学习。

如果你从头开始训练所有场景，模型会欠拟合感知（每批有限的单图像数据）和过拟合结构（大量的多图像/视频数据）。结果：一个遵循交叉图像推理模式的模型，但在视觉上很浅。

课程排序让你从阶段SI获得感知力量，然后从阶段OV获得构图/时间推理，两者都不会丢失。

### 紧急跨场景技能

LLaVA-OneVision的论文报告了三种应急能力：

1. 多幅相机推理。单独对多图像+视频进行训练；在推理中，要求对一个多摄像头驾驶场景进行推理。该模型正确地集成了视图，尽管在训练中从未看到过确切的格式。
2. Set-of-mark提示。用户用编号标记注释图像中的对象；这个模型的原因是“相对于马克7，马克3在做什么？”既不学习标记也不学习注释的；借鉴了空间接地+多图像参考的结合。
3. iPhone-screenshot代理。用户提供iPhone屏幕的截图，并要求计划下一次点击。UI截图，用户工作流程视频，多图像前后配对训练。泛化到代理用例。

这些都不是经过训练的任务；它们来自于课程的作文结构。

### Visual-token池

代币预算需要池化。OneVision在2D patch网格上使用双线性插值：24x24 = 576个patch变成12x12 = 144 （2x因子）或8x8 = 64 （3x因子）。池化是在patch-grid空间（而不是令牌空间）中完成的，以保持局部性。

每个场景的池化因子的选择本身就是一个超参数。更少的池=更多的令牌=更丰富的表示。更多的池=更少的令牌=更多的帧/图像适合。

### llava - onevision 1.5

2025年的后续项目（LLaVA-OneVision-1.5, arXiv 2509.23661）在训练数据、模型权重和代码方面“完全开放”。在某些基准上与专利差距相匹配，并使配方民主化。同样的课程，更多的数据，更好的法学硕士基础。没有架构改变。

### 与Qwen2.5-VL对比

Qwen2.5-VL（第12.09课）做出不同的选择。它使用M-RoPE和动态FPS而不是固定池。它的预算与输入有关——1分钟的视频比5秒的视频使用更多的代币。LLaVA-OneVision修复预算并扩展池。两个工作;他们用可配置性换取可预测性。

## 使用它

Z0给定每个样本的代币预算和目标场景组合（例如40%的单图像，30%的多图像，30%的视频），它：

- 为每个场景分配分辨率、池化因子和帧。
- 检查每个场景是否符合共享预算。
- 报告预期的令牌计数、LLM FLOPs以及哪些场景未进行令牌化。
- 打印每个阶段的训练计划。

使用它来计划OneVision微调或检查VLM部署的每个请求成本。

## 船这

这一课产生了给定目标任务分布和每个样本预算，它会发出AnyRes因子、每帧池、视频帧计数和课程阶段权重。当您训练或微调统一场景VLM时，请使用此方法。

## 练习

1. 您的产品支持80%的单图像，10%的多图像（2-4张图像），10%的视频（8-16帧）。设计令牌预算。你会把不做大量多图像而节省下来的额外预算放在哪里？

2. 阅读LLaVA-OneVision章节4.3（应急能力）。提出该课程可能会开启的第四项紧急技能，但论文没有报道。

3. 交换课程顺序——先训练多图像，再训练单图像，再训练视频。预测哪些基准会下降，为什么会下降。

4. 这篇论文报告了每个样本只训练8帧的视频基准。这也适用于30秒的视频吗？是什么先打破的——令牌预算还是时间推理？

5. 24x24块的双线性池化到12x12是每个dim的4倍减少。在stdlib Python中实现池化，并验证每个2x2块的平均值与双线性输出相匹配。

## 关键术语

| Term | What people say | What it actually means |
|------|-----------------|------------------------|
| OneVision scenario | "Single-image, multi-image, or video" | One of three input shapes the unified VLM handles; the budget stays constant across |
| Token budget | "How many tokens per sample" | Total visual tokens the LLM sees per training / inference sample, typically 3000-4000 |
| Curriculum | "Training order" | Stage ordering (single-image → multi-image → video) chosen for emergent transfer |
| Bilinear pooling | "Token shrink" | Applying bilinear interpolation to the patch grid (2D) to reduce token count while preserving locality |
| Emergent skill | "Not trained, still works" | Capability that appears at inference without matching training data, due to curriculum composition |
| AnyRes-k | "k-tile setup" | k sub-tiles of fixed resolution plus one thumbnail, typical k ∈ {4, 9} |
| Task transfer | "Cross-scenario generalization" | Skills learned on single-image that apply to video (and vice versa) via shared backbone |
