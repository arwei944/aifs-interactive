# 技能库和终身学习（Voyager）

> Voyager （Wang et al., TMLR 2024）将可执行代码视为一种技能。技能通过环境反馈来命名、检索、组合和改进。这是Claude Agent SDK技能、skillkit和2026技能库模式的参考体系结构。

**Type:** Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 · 07 (MemGPT), Phase 14 · 08 (Letta Blocks)
**Time:** ~75 minutes

## 学习目标

- 说出Voyager的三个组成部分——自动课程、技能库、迭代提示——以及每个部分的作用。
- 解释为什么旅行者号的动作是空间代码，而不是原始命令。
- 实现具有注册、检索、组合和故障驱动细化的标准库技能库。
- 将Voyager的模式映射到2026 Claude Agent SDK技能和skillkit生态系统上。

## 这个问题

在每个会话中从头开始重建所有功能的代理会做三件事：

1. * *浪费令牌。每个任务都需要同样的推理。
2. * *失去进步。**在A阶段学到的纠正不会转移到B阶段。
3. **长视距构图失败。**复杂的任务需要能力层次；一次性提示无法表达它们。

Voyager的答案是：将每个可重用功能视为存储在库中的命名代码块，通过相似性检索，与其他技能组合，并通过执行反馈进行改进。

## 这个概念

### 三个组件

Voyager （arXiv:2305.16291）围绕：

1. * *自动课程。**好奇心驱动的提议者根据代理当前的技能集和环境状态选择下一个任务。探索是自下而上的。
2. * *技能库。**每个技能都是可执行代码。任务成功时添加新技能。技能是通过查询到描述的相似性来检索的。
3. **迭代提示机制。**失败时，代理接收执行错误、环境反馈和自我验证输出，然后改进技能。

《我的世界》评估（Wang et al., 2024）： 3.3倍的独特道具，8.5倍的石制工具，6.4倍的铁制工具，2.3倍的地图穿越时间。这些数字是minecraft特有的，但模式是不同的。

### 动作空间=代码

大多数代理发出原始命令。Voyager发出JavaScript函数。技能是：

```
async function craftIronPickaxe(bot) {
  await mineIron(bot, 3);
  await mineStick(bot, 2);
  await placeCraftingTable(bot);
  await craft(bot, 'iron_pickaxe');
}
```

由子技能组成。存储键的描述和嵌入。作为程序检索，而不是提示符。

这是2026克劳德代理SDK技能：一个命名的，可检索的代码块加上代理根据需要加载的指令。

### 检索技能

新任务“制作钻石鹤嘴锄”代理:

1. 嵌入任务描述。
2. 在技能库中查询top-k的相似技能。
3. 检索
4. 从检索到的原语+新逻辑组合新技能。

这是MCP资源（阶段13）和Agent SDK技能实现的模式：在知识/代码表面上检索，范围限定在当前任务。

### 迭代细化

旅行者号的反馈回路：

1. Agent写技能。
2. 技能与环境格格不入。
3. 返回三个信号之一：
4. Agent使用信号作为上下文重写技能。
5. 循环直到成功或最大回合。

这是将Self-Refine（第05课）应用于基于环境的验证的代码生成。批评家（第05课）是使用外部工具作为验证者的相同模式。

### 课程与探索

旅行者号的课程模块会根据探测器已经完成的任务和尚未完成的任务，提出诸如“在湖附近建造一个庇护所”之类的任务。提议者使用环境状态+技能清单来选择一个刚好高于当前能力的任务——探索最佳点。

对于生产代理来说，这意味着“缺少什么”操作符：给定当前的技能库和领域，我们还没有涵盖哪些技能？团队通常将其作为课程审查手动实现。

### 这种模式哪里出错了

- **技能库腐烂。**相同的技能添加10次略有不同的描述。写入时添加重复数据删除；检索只返回一个。
- * * Composed-skill漂移。**父母的技能取决于孩子的教养。版本技能;绑定到v1的父节点不会神奇地拾取v3。
- * *检索质量。**随着库增长超过几百个，技能描述的矢量检索会下降。补充标记过滤器和硬约束（“仅使用”）

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Skill | "Reusable capability" | Named chunk of code + description, retrievable by similarity |
| Skill library | "Agent memory of how-to" | Persistent store of skills, searchable and composable |
| Curriculum | "Task proposer" | Bottom-up goal generator driven by current capability gap |
| Composition | "Skill DAG" | Skills invoking skills; topologically sorted on execution |
| Iterative refinement | "Self-correcting loop" | Env feedback + errors + self-verification fold back into the next version |
| Action-space-as-code | "Programmatic actions" | Emit functions, not primitive commands, for temporally extended behavior |
| Dedup on write | "Skill collapse" | Near-duplicate descriptions collapse to one canonical skill |
