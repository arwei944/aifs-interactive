# ColPali和视觉原生文档RAG

> 传统的RAG将pdf解析为文本，分割成块，嵌入块，存储向量。每一步都失去信号：OCR丢弃图表数据，分组破坏表格行，文本嵌入忽略数字。ColPali （Faysse et al., July 2024）问了一个更简单的问题：为什么要提取文本？通过PaliGemma直接嵌入页面图像，使用colbert风格的后期交互进行检索，并保留文档携带的所有布局、图形、字体和格式信号。发布的基准测试：在视觉丰富的文档上，端到端准确率比text-RAG高20-40%。ColQwen2、ColSmol和VisRAG扩展了该模式。本课将阅读视觉原生的RAG论文，并构建一个小型的类似colpal的索引器。

**Type:** Build
**Languages:** Python (stdlib, multi-vector indexer + MaxSim scorer)
**Prerequisites:** Phase 11 (LLM Engineering — RAG basics), Phase 12 · 05 (LLaVA)
**Time:** ~180 minutes

## 学习目标

- 解释双编码器检索（每个文档一个向量）和后期交互检索（每个文档多个向量）之间的区别。
- 描述ColBERT的MaxSim操作，以及ColPali如何将其从文本令牌推广到图像补丁。
- 构建一个类似colpal的小索引器：page→patch嵌入→MaxSim over查询词嵌入→top-k页面。
- 在发票/财务报告用例上比较ColPali + Qwen2.5-VL生成器与文本- rag + GPT-4。

## 这个问题

pdf上的Text-RAG会丢弃大部分文档。财务报告的第三季度收入增长通常用图表表示；医学报告的结果以带注释的图像显示；法律合同的签名块是一个布局事实，而不是文本事实。

文本- rag管道：

1. PDF→文本通过OCR / pdftotext。
2. 文本→300-500个标记块。
3. 块→双编码器嵌入（一个向量）。
4. 用户查询→嵌入→余弦相似度→top-k块。
5. 块+查询→LLM。

五个有损步骤。没有捕获图表。表被分成多个块。多栏布局扁平化。图注释消失。

ColPali的修复：跳过OCR，直接嵌入页面图像。使用colbert风格的后期交互进行检索，这样模型就可以在查询时处理细粒度的补丁。

## 这个概念

### 科尔伯特(2020)

ColBERT （Khattab & Zaharia, arXiv:2004.12832）是一种文本检索方法。它不是为每个文档生成一个向量，而是为每个标记生成一个向量。在查询时：

- 查询令牌有自己的嵌入（N_q向量）。
- 文档标记获得嵌入（N_d向量，通常缓存）。
- Score =查询标记max对文档标记余弦相似度的求和：Σ_i max_j cos（q_i, d_j）。

这是MaxSim操作。每个查询令牌“选择”最匹配的文档令牌。最后的分数是总和。

优点：强召回，处理术语级语义。缺点：每个文档N_d向量，存储成本高。

### ColPali

ColPali （Faysse et al., arXiv:2407.01449）将ColBERT模式应用于图像。

- 每个页面被PaliGemma （ViT +语言）编码成补丁嵌入：每个页面N_p个向量。
- 每个用户查询（文本）被编码为查询标记嵌入：N_q向量。
- Score = Σ_i max_j cos(q_i, p_j)，即查询-文本标记和页面-图像-补丁的MaxSim。
- 按总分检索前k个页面。

在文档摄取时：用PaliGemma嵌入每个页面，存储所有补丁嵌入。在查询时：嵌入查询令牌，对所有存储的页面嵌入计算MaxSim，返回top-k页面。

优点：在视觉丰富的文档上，端到端比文本- rag高出20-40%。每个补丁向量捕获本地布局和内容。

缺点：N_p补丁× 4字节浮点数×每页D-dim向量=存储增长很快。通过PQ / OPQ量化减轻。

### ColQwen2和ColSmol

ColQwen2（照明技术，2024-2025）将PaliGemma换成了Qwen2-VL。更好的基础编码器，更好的检索。

ColSmol是本地/边缘使用的小规模变体。一个约1B参数的ColSmol检索器在消费级GPU上运行。

### VisRAG

VisRAG （Yu et al., arXiv:2410.10594）是一个不同的变体：不是对补丁进行MaxSim，而是将每个页面用VLM池成单个向量，然后用双编码器检索。更快的索引+更小的存储，更弱的召回。

质量与成本的权衡：ColPali追求质量，VisRAG追求规模。

### M3DocRAG

M3DocRAG （Cho et al., arXiv:2411.04952）将多模态检索扩展到多页多文档推理。检索跨文档的页面，为VLM组成多页面上下文。

### ViDoRe -基准

ColPali的同伴基准。视觉文档检索评估。任务包括财务报告、科学论文、行政文件、医疗记录、手册。度量:nDCG@5。

colpal -v1在ViDoRe上得分~80% nDCG@5；text-RAG在相同文档上的得分~50-60%。

### 端到端RAG管道

对于视觉原生的RAG：

1. 摄取：PDF→页面图像→PaliGemma编码→存储所有补丁嵌入。
2. 查询：用户文本→查询标记嵌入→针对所有索引页面的MaxSim→top-k页面。
3. 生成：top-k页面图片+查询→VLM （Qwen2.5-VL或Claude）→答案。

任何地方都没有OCR。图形、图表、字体、布局都可以融入到答案中。

### 存储的数学

一份50页的财务报告，每页729个补丁，128个模糊嵌入；

- ColPali: 50 * 729 * 128 * 4字节= ~ 18mb原始，~ 4mb后PQ。
- Text-RAG: 50 chunks * 768-dim * 4 bytes = ~ 150kb。

ColPali为每个文档提供了大约30倍的存储空间。在规模上，OPQ / PQ将其降低到~5-10倍，通常是可容忍的。

### 当文本- rag仍然获胜时

- 没有布局信号的纯文本文档（wiki文章，聊天日志）。Text-RAG更简单，存储成本更低。
- 数百万页的档案，存储成本占主导地位。
- 严格的法规要求提取OCR文本以及检索。

对于2026年的其他一切——财务报告、科学论文、法律合同、医疗记录、用户体验文档——视觉原生RAG将胜出。

## 使用它


- 玩具补丁编码器：将“页面”（特征向量的小网格）映射到补丁嵌入数组。
- MaxSim scorer：计算查询令牌嵌入集和页面补丁集之间的colbert式分数。
- 索引5个玩具页面，运行3个查询，返回top-k和分数。

## 练习

1. 一份200页的年度报告，每页729个补丁，128个暗淡字母，4字节浮点数。计算原始存储和pq压缩（8倍）存储。

2. MaxSim为Σ_i max_j cos（q_i, p_j）。这个求和包含了什么简单的均值相似度没有包含的内容？

3. ColPali将页面索引为补丁集。如果我们改为在单词级别进行索引（就像ColBERT那样），会有什么变化？权衡?

4. 为1m页的语料库设计端到端管道，每个查询的延迟预算为500ms。选择ColQwen2 / VisRAG并进行验证。

5. 读取M3DocRAG （arXiv:2411.04952）。描述多页注意力模式以及它与单页ColPali检索有何不同。

## 关键术语

| Term | What people say | What it actually means |
|------|-----------------|------------------------|
| Late interaction | "ColBERT-style" | Retrieval using per-token or per-patch embeddings + MaxSim, not a single doc vector |
| MaxSim | "Max-over-patches" | For each query token, pick the highest-similarity document token; sum across query |
| Bi-encoder | "Single-vector" | One vector per document; faster but loses granularity |
| Multi-vector | "Many-vectors-per-doc" | Store N_p vectors per document / page; storage cost grows but recall improves |
| Patch embedding | "Page feature" | One vector per image patch from a VLM encoder, cached per page |
| ViDoRe | "Vision doc bench" | ColPali's benchmark suite for visual document retrieval |
| PQ quantization | "Product quantization" | Compression that maintains vector similarity while shrinking storage ~8x |
