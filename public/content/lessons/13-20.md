# OpenTelemetry基因跟踪工具调用端到端

> 一个代理调用5个工具、3个MCP服务器和2个子代理。你需要在所有地方进行一次追踪。OpenTelemetry GenAI语义约定（v1.37及更高版本的稳定属性）是2026年的标准，由Datadog、Langfuse、Arize Phoenix、OpenLLMetry和AgentOps原生支持。本课命名所需的属性，遍历跨度层次结构（代理→LLM→工具），并提供一个标准库跨度发射器，您可以将其插入任何OTel导出器。

**Type:** Build
**Languages:** Python (stdlib, OTel span emitter)
**Prerequisites:** Phase 13 · 07 (MCP server), Phase 13 · 08 (MCP client)
**Time:** ~75 minutes

## 学习目标

- 为LLM范围和工具执行范围命名所需的OTel GenAI属性。
- 构建包含代理循环、LLM调用、工具调用和MCP客户机调度的跟踪层次结构。
- 决定捕获什么内容（选择加入）还是编辑什么内容（默认）。
- 在不重写工具代码的情况下，向本地收集器（Jaeger, Langfuse）释放跨度。

## 这个问题

2026年2月的调试：用户报告“我的代理有时需要30秒才能响应；其他时间是3秒。”没有痕迹。日志显示LLM调用，但不显示工具调度，不显示MCP服务器往返，不显示子代理。你猜。最终您会发现：一个MCP服务器偶尔会在冷启动时挂起。

如果没有端到端跟踪，您就无法找到它。OTel GenAI解决了这个问题。

这些约定于2025-2026年在OpenTelemetry语义约定组下确定。它们def 了稳定的属性名，因此Datadog、Langfuse、Phoenix、OpenLLMetry和AgentOps都解析相同的跨度。仪器一次;运送到任何后端。

## 练习

1. 运行计算跨度并确定哪些是CLIENT与INTERNAL。

2. 打开内容捕获（env var）并确认注意对PII的含义。

3. 添加工具执行度量

4. 将来自父代理的跟踪父代理传播到MCP请求的跟踪父代理验证MCP服务器将看到相同的跟踪id。

5. 阅读OTel GenAI semconv规范。找出本课代码没有发出的semconv中列出的一个属性。添加它。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| OTel | "OpenTelemetry" | Open standard for traces, metrics, logs |
| GenAI semconv | "GenAI semantic conventions" | Stable attribute names for LLM / tool / agent spans |
| `gen_ai.*` | "The attribute namespace" | All GenAI attributes share this prefix |
| Span | "Timed operation" | A unit of work with a start, end, and attributes |
| Trace | "Cross-span ancestry" | Tree of spans sharing a trace id |
| SpanKind | "CLIENT / SERVER / INTERNAL" | Hints about span direction |
| OTLP | "OpenTelemetry Line Protocol" | Wire format for exporters |
| Opt-in content | "Prompt / completion capture" | Off by default; env var to enable |
| traceparent | "W3C header" | Propagates trace context across services |
| Exporter | "Backend-specific shipper" | Component that sends spans to Jaeger / Datadog / etc. |
