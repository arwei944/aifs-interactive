# AI网关- LiteLLM， Portkey, Kong AI Gateway, Bifrost

> 网关位于应用程序和模型提供商之间。核心特性是提供商路由、回退、重试、速率限制、秘密引用、可观察性、护栏。2026年的市场分裂：LiteLLM**是MIT OSS，有100多个供应商，兼容openai，但在2000 RPS左右崩溃（8gb内存，发布基准测试中的级联故障）；最适合Python， <500 RPS，开发/原型。**Portkey**是控制平面定位的（护栏，PII编辑，越狱检测，审计跟踪），2026年3月Apache 2.0开源，20-40毫秒延迟开销，49美元/月生产层。**Kong AI Gateway**基于Kong Gateway -在相同的12个cpu上，Kong自己的基准测试：比Portkey快228%，比LiteLLM快859%；每个型号每月100美元（Plus级最多5美元）；企业适合，如果你已经在香港。**Bifrost** (Maxim AI) -自动重试与可配置的后退，退回到OpenAI 429上的Anthropic。**Cloudflare / Vercel AI网关** -管理，零操作，基本重试。数据驻留驱动自托管决策；Portkey和Kong位于中间，OSS +可选管理。

**Type:** Learn
**Languages:** Python (stdlib, toy gateway-routing simulator)
**Prerequisites:** Phase 17 · 01 (Managed LLM Platforms), Phase 17 · 16 (Model Routing)
**Time:** ~60 minutes

## 学习目标

- 列举网关的六个核心特性（路由、回退、重试、速率限制、秘密、可观察性、护栏）。
- 映射四个2026网关（LiteLLM, Portkey, Kong AI, Bifrost）以扩展上限和用例。
- 引用香港基准（228% vs Portkey, 859% vs LiteLLM）并解释为什么它对bb500rps很重要。
- 在给定数据驻留和运营预算的情况下，选择自托管还是托管。

## 这个问题

你的产品叫OpenAI、Anthropic和一个自托管的羊驼。每个提供程序都有不同的SDK、错误模型、速率限制和验证方案。您需要故障转移（如果是OpenAI 429，请尝试Anthropic）、单个凭据存储、统一的可观察性和每个租户的速率限制。

在应用程序层重新设计，将每个服务与每个提供商耦合起来。网关层将其整合到一个带有API（通常与openai兼容）的进程中，并将其扩展到提供商。

## 这个概念

### 六大核心特性

1. **提供商路由** - OpenAI， Anthropic, Gemini，自托管等背后的一个API。
2. **回退** -在429、5xx或质量失败时，在其他地方重试。
3. **重试** -指数后退，有限的尝试。
4. **速率限制** -每个租户，每个密钥，每个型号。
5. **秘密引用** -在运行时从保险库中提取凭证（从不在应用程序中）。
6. **可观察性** - OTel + GenAI属性（第17·13阶段）+成本归因。
7. **护栏** - PII编辑，越狱检测，允许的主题过滤器。

### LiteLLM - MIT OSS, Python

- 100多个提供商，openai兼容，路由器配置，回退，基本的可观察性。
- 在香港的基准中，RPS跌破2000左右；8 GB内存占用，持续负载下的级联故障。
- 最适合：Python应用，<500 RPS，开发/登台网关，实验性路由。
- 成本：开源软件0美元；无云层存在。

### 门钥匙-控制平面定位

- 截至2026年3月的Apache 2.0 OSS。护栏，个人信息编辑，越狱检测，审计跟踪。
- 每个请求的延迟开销为20-40毫秒。
- 生产层每月49美元，包含保留+ SLA。
- 最适合：需要护栏+可观察性捆绑的受监管行业。

### 金刚AI门户——规模游戏

- 基于Kong Gateway（成熟的API网关产品，lua+ openrest）。
- Kong自己在12个cpu上的基准测试：比Portkey快228%，比LiteLLM快859%。
- 定价：每个型号每月100美元，Plus级最多5美元。
- 最适合：已在香港；> 1000数;愿意授权。

### Bifrost (Maxim AI)

- 自动重试，可配置退出。
- OpenAI 429上的回退到Anthropic是一个规范的配方。
- 新进入者;商业。

### Cloudflare AI Gateway / Vercel AI Gateway

- 管理,zero-ops。基本的重试和可观察性。
- 最适合：Cloudflare/Vercel上的边缘服务JavaScript应用。
- 有限的比较，香港/Portkey的护栏和费率限制。

### 自托管vs托管

数据驻留是强制函数。医疗保健和金融默认自主机（LiteLLM或Portkey OSS或Kong）。消费者产品默认管理（Cloudflare AI Gateway）或中间层（Portkey管理）。混合型：为受监管的租户自托管，为其他租户管理。

### 延迟的预算

- LiteLLM：典型的5- 15ms开销。
- 门钥匙：20-40毫秒的开销。
- Kong: 3-8毫秒的开销。
- Cloudflare/Vercel: 1-3毫秒的开销（优势）。

网关延迟直接增加TTFT。对于TTFT P99 < 100 ms SLA， Kong或Cloudflare。对于P99 < 500 ms，任何。

### 速率限制语义很重要

简单的令牌桶工作到中等规模。多租户需要滑动窗口+突发允许+每个租户分层。LiteLLM船代币桶；船舶滑窗；门钥匙船分层。

### 网关+可观察性+路由组合

阶段17·13（可观察性）+ 16（模型路由）+ 19（网关）是生产中的同一层。选择一个涵盖所有这三种工具的工具，或者小心地将它们连接起来：大多数2026部署将Helicone（可观察性）或Portkey（护栏）与Kong（规模）结合起来，用于拆分角色。

### 你应该记住的数字

- LiteLLM：在~2000 RPS， 8gb内存时中断。
- 门钥匙：20-40毫秒的开销；Apache 2.0，从2026年3月开始。
- 比Portkey快228%，比LiteLLM快859%。
- 香港定价：每个型号每月100美元，Plus级最多5美元。
- Cloudflare/Vercel: 1-3毫秒的边缘开销。

## 练习

1. 运行从OpenAI→Anthropic→自托管配置回退。提供者错误率为5%时，预期命中率是多少？
2. 您的SLA是在300ms基线上ttftp99 < 200ms。哪些网关在预算范围内？
3. 医疗保健客户需要自托管+ PII编校+审计。选择Portkey OSS或Kong。
4. 比较LiteLLM和Kong：团队应该在多大的RPS上限上迁移？
5. 为多租户SaaS设计一个速率限制策略：免费层、试用层、付费层。令牌桶还是滑动窗口？
