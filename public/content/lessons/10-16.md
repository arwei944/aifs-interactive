## This question

The standard softmax attention has mathematical properties and becomes an operational challenge in terms of scale. Querying Softmax will never produce an exact zero - each mismatched flag will get some positive mass. This residual mass is noise, which varies with the length of the context. Among the 128,K tokens, even if each mismatched token only has a 0.001% probability, the 127,999 of them together contribute approximately 12% of the total. The model must learn to bypass the noise floor that increases with the environment.

Empirically, this is manifested as attentiveness - head interference: illusory references in long context RAG, intermediate loss failures in 100k tag retrieval tasks, and subtle accuracy drops in ocean crossing benchmark tests over 32k. The differential transformer paper (arXiv:2410.05258, ICLR 2025) measured the gap: compared with the baseline of the same size, DIFF transformers have lower confusion, higher accuracy in long context, and fewer hallucinations.

DIFF V1 has three problems that prevent it from entering the frontier pre-training pipeline. Its value cache must be loaded twice in each decoding step. It requires a custom CUDA kernel, which undermines the compatibility of FlashAttention, and its per capita RMSNorm is unstable during long-term training at a scale of over 70b. DIFF V2 (Microsoft Joint Blog, January 20, 2026) fixed these three issues. This lesson will traverse two versions, construct the difference operator, and conduct a noise cancellation benchmark test on a simple query.

What this model aims for is something similar to hard-top k: the weight of the matching tokens is very high, while the weights elsewhere are close to zero. Softmax is too smooth to do this directly.

### Differential thought

Divide the Q and K projections of each avatar into two: Q = (Q_1, Q_2) and K = (K_1, K_2). Calculate two attention graphs:

```
A_1 = softmax(Q_1 K_1^T / sqrt(d))
A_2 = softmax(Q_2 K_2^T / sqrt(d))
```

Output

```
DiffAttn = (A_1 - lambda * A_2) V
```

Subtraction eliminates any noise distribution shared by the two maps. If two mappings have approximately the same weights on 127k unrelated tags (which they do during random initialization), they will be cancelled. The signal - reaching peak weights on a few actually relevant markers - will only be cancelled out when it appears on two maps at the same order of magnitude, and once the model appears, it will not be cancelled out.

0 0`lambda_init` defaults to a small positive number like 0.8.

### V1 vs V2: Difference

V1 keeps the parameter count equal to the baseline Transformer. To obtain two queries for each header, it halves the dimension of the header. This consumes the expressive power of the heads. What's more painful is that the value cache of each head has been reduced by half. Decode must load the value cache twice at each step (once for each softmax branch). Result: The decoding speed is slower than the baseline, despite the count of matching parameters.

V2 doubles the number of query headers while keeping the KV headers unchanged (borrowing parameters from the above projection). The head size remains the same as the baseline. After subtraction, the additional dimensions are projected downward to match the O_W projection of the baseline Transformer. Three things happened simultaneously:

1. The decoding speed matches the baseline (KV cache is loaded once).
2. FlashAttention runs unchanged (without a custom kernel).
3. The arithmetic intensity during decoding increases (the amount of computation for each byte loaded from HBM increases).

V2 also removed each head RMSNorm used by V1 to stabilize subtraction. In the 70b-level pre-training scale, RMSNorm disrupted the stability of the later training. V2 replaced it with a simpler initialization scheme that maintains training stability without additional modules.

### Step 2: split Q, K into two halves

V1 style: halve the head dimension. V2 style: keep the head dimension and double the number of heads. The toy implementation uses V1 for pedagogical clarity — the math is identical, only the bookkeeping differs.

### Step 3: two softmax branches + subtraction

```python
A1 = [softmax([dot(q1, k) / scale for k in K1]) for q1 in Q1]
A2 = [softmax([dot(q2, k) / scale for k in K2]) for q2 in Q2]
diff_weights = [[a1 - lam * a2 for a1, a2 in zip(r1, r2)] for r1, r2 in zip(A1, A2)]
out = [[sum(w * v[j] for w, v in zip(row, V)) for j in range(d_v)] for row in diff_weights]
```

Note: The output weight can be negative. This is great - the value cache still processes signed contributions. The following V projection absorbs this symbol.

## Key terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Differential attention | "Two softmaxes minus each other" | Split Q, K into two halves, compute two softmax maps, subtract the second (scaled by lambda) from the first, then multiply by V |
| Noise floor | "The non-zero tail of softmax" | The O(1/N) weight softmax puts on every unrelated token, which sums to O(1) across long contexts |
| lambda | "The subtraction scale" | Per-head learnable scalar parameterized as `exp(lq1.lk1) - exp(lq2.lk2) + lambda_init`; can be negative |
| DIFF V1 | "The ICLR 2025 version" | Original Differential Transformer; halves head dim to preserve parameter count, needs custom kernel, slower decode |
| DIFF V2 | "The January 2026 fix" | Doubles Q heads keeping KV heads; matches baseline decode speed and works with FlashAttention |
| Per-head RMSNorm | "The V1 stabilizer" | Extra norm V1 applied after the difference; V2 removed it to prevent late-training instability |
| Signal-to-noise ratio | "How much attention is wasted" | Ratio of weight on the true signal position to average weight on unrelated positions |
| Lost in the middle | "Long-context failure mode" | Empirical phenomenon where retrieval accuracy dips for documents in the middle of a long context — DIFF attention reduces this |
| Arithmetic intensity | "FLOPs per byte loaded" | Ratio V2 increased at decode by doubling queries per KV load; important for memory-bound decode |
