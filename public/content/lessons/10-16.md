# 差异注意（V2）

> Softmax注意将少量概率分散到每个不匹配的令牌上。超过10万个信号叠加起来，淹没了信号。差动变压器（Ye et al., ICLR 2025）通过将注意力计算为两个软最大值的差，减去共享的本底噪声来固定它。DIFF V2（微软，2026年1月）是生产栈重写：将解码延迟匹配到基线Transformer，没有自定义内核，flash注意兼容。本课是V1到V2的端到端，提供了一个可以在stdlib Python中运行的差分操作的工作玩具实现。

## 这个问题

标准的softmax注意力具有数学性质，在规模上变成了操作上的难题。查询Softmax永远不会产生精确的零-每个不匹配的标记都会得到一些正质量。这个残余质量就是噪声，它随上下文长度的变化而变化。在128k个令牌中，即使每个不匹配的令牌只获得0.001%的概率，它们中的127999个合计贡献了大约12%的总数。该模型必须学会绕过随着环境而增长的噪声底。

从经验上看，这表现为注意力-头部干扰：长上下文RAG中的幻觉引用，100k标记检索任务中的中间丢失失败，以及超过32k的大海过海基准测试中的微妙准确性下降。差动变压器论文（arXiv:2410.05258, ICLR 2025）测量了差距：与相同尺寸的基线相比，DIFF变压器的困惑度更低，长上下文准确性更高，幻觉更少。

DIFF V1有三个问题，使它无法进入前沿预训练管道。它的值缓存必须在每个解码步骤中加载两次，它需要自定义CUDA内核，这破坏了FlashAttention的兼容性，并且它的人均RMSNorm在70b以上规模下不稳定的长期训练。DIFF V2（微软联合博客，2026年1月20日）修复了这三个问题。本课将遍历两个版本，构建差异运算符，并对一个简单的查询进行噪声消除基准测试。

## 这个概念

### softmax的噪声底限

查询

```
w_i = exp(q . k_i / sqrt(d)) / sum_j exp(q . k_j / sqrt(d))
```

不如果在softmax规范化之后，每个不相关的标记仍然有贡献不相关令牌的总贡献为

该模型想要的是类似于硬顶k的东西：匹配代币的权重很高，其他地方的权重接近于零。Softmax太平滑了，不能直接这样做。

### 微分思想

将每个头像的Q和K投影分成两个：Q = (Q_1, Q_2)和K = (K_1, K_2)。计算两个注意图：

```
A_1 = softmax(Q_1 K_1^T / sqrt(d))
A_2 = softmax(Q_2 K_2^T / sqrt(d))
```

输出:

```
DiffAttn = (A_1 - lambda * A_2) V
```

减法消除了两个地图共享的任何噪声分布。如果两个映射在127k个不相关的标记上具有大致相同的权重（在随机初始化时，它们会这样做），那么它们就会取消。信号——在少数实际相关的标记上达到峰值权重——只有在两张地图上以相同的量级出现时才会被抵消，而一旦模型出现，它就不会被抵消。

Z0它可以是负的。`lambda_init` defaults to a small positive number like 0.8.

### V1 vs V2：差异

V1保持参数计数等于基线Transformer。为了获得每个头的两个查询，它将头的维度减半。这消耗了头的表达能力，更痛苦的是，每个头的值缓存减少了一半。Decode必须在每一步加载值缓存两次（每个softmax分支一次）。结果：解码速度比基线慢，尽管匹配参数计数。

V2将查询头的数量加倍，并保持KV头不变（从上投影中借用参数）。头部尺寸保持与基线相同。在减法之后，额外的维度被向下投影，以匹配基线Transformer的O_W投影。三件事同时发生：

1. 解码速度匹配基线（KV缓存加载一次）。
2. FlashAttention运行不变（没有自定义内核）。
3. 解码时的算术强度增加（从HBM加载的每个字节的计算量增加）。

V2还删除了V1用来稳定减法的每个头RMSNorm。在70b级训练前量表中，RMSNorm破坏了后期训练的稳定性。V2用一个更简单的初始化方案取代了它，该方案在没有额外模块的情况下保持训练稳定。

### 什么时候伸手去拿

| Workload | Benefit |
|----------|---------|
| Long-context RAG (64k+) | Cleaner attention maps, fewer hallucinated citations |
| Needle-in-haystack benchmarks | Substantial accuracy lift past 32k |
| Multi-document QA | Less cross-document interference |
| Code completion at 8k | Marginal, not worth the architecture change |
| Short chat (< 4k) | Essentially indistinguishable from baseline |

该值随上下文长度增长。对于4k代币，噪音底限足够小，标准注意力就可以了。在128k时，它会伤害你。

### Step 2: split Q, K into two halves

V1 style: halve the head dimension. V2 style: keep the head dimension and double the number of heads. The toy implementation uses V1 for pedagogical clarity — the math is identical, only the bookkeeping differs.

### Step 3: two softmax branches + subtraction

```python
A1 = [softmax([dot(q1, k) / scale for k in K1]) for q1 in Q1]
A2 = [softmax([dot(q2, k) / scale for k in K2]) for q2 in Q2]
diff_weights = [[a1 - lam * a2 for a1, a2 in zip(r1, r2)] for r1, r2 in zip(A1, A2)]
out = [[sum(w * v[j] for w, v in zip(row, V)) for j in range(d_v)] for row in diff_weights]
```

注：输出权值可以为负。这很好——值缓存仍然处理已签名的贡献。接下来的V投影吸收了这个符号。

## 使用它

到2026年4月为止，DIFF V2还没有在每个生产推理服务器中发布，但是正在进行vLLM和SGLang的集成。同时，这种模式出现在：

- 微软内部长上下文生产模型。
- 在针对256k以上环境的几个开放模型训练运行中研究重复。
- 混合架构将DIFF注意与交替层上的滑动窗口注意结合在一起。

当你在2026年达到这个水平时：

- 从头开始训练针对64k +有效上下文的新模型。从一开始就添加不同的注意力；之后的再培训是昂贵的。
- 对长上下文模型进行微调，其中丢失在中间的错误主导了您的计算。在Q投影上的LoRA可以近似DIFF结构。

当你不愿意：

- 您正在提供一个具有稳定的长上下文性能的预训练密集模型。再训练的成本很少能在现有的重量上得到回报。
- 你的上下文总是低于16k。噪声底可以忽略不计。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Differential attention | "Two softmaxes minus each other" | Split Q, K into two halves, compute two softmax maps, subtract the second (scaled by lambda) from the first, then multiply by V |
| Noise floor | "The non-zero tail of softmax" | The O(1/N) weight softmax puts on every unrelated token, which sums to O(1) across long contexts |
| lambda | "The subtraction scale" | Per-head learnable scalar parameterized as `exp(lq1.lk1) - exp(lq2.lk2) + lambda_init`; can be negative |
| DIFF V1 | "The ICLR 2025 version" | Original Differential Transformer; halves head dim to preserve parameter count, needs custom kernel, slower decode |
| DIFF V2 | "The January 2026 fix" | Doubles Q heads keeping KV heads; matches baseline decode speed and works with FlashAttention |
| Per-head RMSNorm | "The V1 stabilizer" | Extra norm V1 applied after the difference; V2 removed it to prevent late-training instability |
| Signal-to-noise ratio | "How much attention is wasted" | Ratio of weight on the true signal position to average weight on unrelated positions |
| Lost in the middle | "Long-context failure mode" | Empirical phenomenon where retrieval accuracy dips for documents in the middle of a long context — DIFF attention reduces this |
| Arithmetic intensity | "FLOPs per byte loaded" | Ratio V2 increased at decode by doubling queries per KV load; important for memory-bound decode |
