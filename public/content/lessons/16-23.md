# 失效模式- MAST，群体思维，单一文化，级联错误

> 2026年的参考分类是**MAST** (Cemri等人，NeurIPS 2025, arXiv:2503.13657)，源自7个最先进的开源MAS的1642条执行轨迹，显示** 41-86.7%的故错率**。三个根类别：**规范问题**(41.77%)-角色模糊，任务定义不明确；**协调失败**(36.94%)-通信故障，状态设计；**验证缺口**(21.30%)-缺失验证，缺失质量检查。**群体思维**家族（arXiv:2508.05687）增加了：单一文化崩溃（相同的基础模型→相关的失败），一致性偏差（代理强化彼此的错误），心智理论缺陷，混合动机动力学，级联可靠性失败。级联示例：重试风暴，其中付款失败触发订单重试，触发库存重试，从而使库存服务不堪重负（秒内负载10倍-需要断路器）。记忆中毒：一个主体的幻觉进入共享记忆，下游主体将其视为事实；准确性逐渐下降，使根本原因诊断变得痛苦。**STRATUS** (NeurIPS 2025)报告通过专门的检测/诊断/验证代理将缓解成功率提高1.5倍。本课将失效模式视为一流的工程目标。

## 问题

多智能体系统在实际任务中失败率为41-86.7% （Cemri等人在2025年对7个开源MAS进行了测量）。这不能通过“添加更多代理”进行调试。这些失败有结构性原因。MAST分类法为您提供了这些类别。本课将每个类别映射到具体的检测、诊断和缓解模式，以便数字不再看起来武断。

2026年的生产实践是将失效模式视为设计输入。在您能够指出每个MAST类别并命名所部署的缓解之前，您的体系结构还不是“足够好”。

## 概念

### 桅杆类别

**规格问题（41.77%的故障）。代理的任务定义得不够严密。例子:

- 角色模糊性：两个代理人都认为自己是审稿人。
- 任务不明确：当用户想要一个特定的角度时，“总结这个”。
- 隐含的成功标准：代理无法判断它是否成功。

Mitigations:
- 编写明确的角色契约。每个代理的提示说明它做什么*和不做什么*。
- 每个任务的验收测试。在代理开始之前，定义“done看起来像x”。
- 飞行前规范检查：一个单独的代理在调度前审查任务定义。

**协调失败（36.94%）。**沟通或状态崩溃。

例子:
- 两个代理不同步地更新共享状态。
- 代理之间的消息丢失（队列失败、超时）。
- 状态漂移：agent A认为任务已经完成；代理B仍在执行。

Mitigations:
- 具有乐观并发性的版本化共享状态。
- 对关键消息的显式确认（重试直到锁定）。
- 周期性状态同步检查点；及早发现漂移。

**验证缺口（21.30%）。**没有独立的输出检查。

例子:
- 一个代理声称成功；没有人验证。
- 每个代理链都信任先前的输出。
- 缺少紧急组合行为的测试覆盖率。

Mitigations:
- 独立验证代理（第13课）。只读，独立的源访问。
- 显式移交契约：“A的输出必须在B开始之前通过检查器C。”
- 用于事后分析的结果记录。

### Groupthink family （arXiv:2508.05687）

agent均质化或相互模仿时的五个相关故障：

**单作崩溃。**相同基础模型或训练数据→相关误差。当三个特工共享一个LLM时，他们共享它的幻觉。

**从众的偏见。**即使错误，代理也会向最大声或最自信的同伴调整。

*汤姆*不足。**代理不能为彼此的信念建立模型；协调性崩溃（第十八课）。

**混合动机动力学。**具有部分一致激励的代理倾向于折中-中间，这不会让任何人满意。

**级联可靠性故障。一个组件的错误模式会触发依赖组件的错误模式。

### 级联示例-重试风暴

2026年的经典事件模式：

```
payment service fails 10% of requests
   ↓
order agent retries payment (exponential backoff but naive)
   ↓
each retry is a new order-inventory check
   ↓
inventory service sees 2x normal load
   ↓
inventory service starts timing out
   ↓
every order retries inventory check
   ↓
inventory service sees 10x normal load
   ↓
cluster goes down
```

解决方法很经典：**断路器**。当下游错误率超过阈值时，使用缓存或默认结果进行短路。加上每个请求的重试预算上限。

断路器是为数不多的直接从分布式系统中借用而无需修改的多代理故障缓解机制之一。

### 记忆中毒（重访）

从第13课开始，一个行为人的幻觉变成了共享记忆的事实；下游代理商的原因是中毒的事实。在MAST术语中，这是共享内存层的验证缺口。

准确度逐渐下降是症状。你不会崩溃；你会得到缓慢的漂移，这很难找到根本原因。

缓解：仅附加日志、来源、不可写的验证器。已经在第13课讲过了。

### STRATUS—专门用于故障检测的代理

STRATUS （NeurIPS 2025）报告，当您部署时，缓解成功率提高1.5倍：

- * *检测代理。**观察症状模式（高度不一致，重试峰值，准确性漂移）。
- * *诊断代理。**给定症状，根据MAST分类推断可能的根本原因。
- * *验证代理。**应用缓解措施后，检查症状是否清除。

这是sre风格的事件响应，应用于代理系统。这三个角色都可以是具有专门提示的LLM代理。

### 失败模式审计

2026的最佳实践是年度（或每个主要版本）失败模式审计：

1. * *跟踪样品。**收集~1000个真实的执行轨迹。
2. * *分类。**对于每个跟踪的失败，映射到MAST + Groupthink类别。
3. **按类别计算故障率。**哪些类别主导你的系统？
4. * *排名移植。**哪个修复可以消除最多的失败？
5. **选择2-3个缓解措施。* *实现;下季度重新审计。

纪律比具体的选择更重要。没有审计，失败就会混入噪音中，永远不会得到系统的解决。

### 当系统静默故障时

最危险的失败类别是无声的正确性失败。可以监视出现严重故障（崩溃、异常、警报）的系统。产生看似合理但错误输出的系统无法通过异常日志检测到。这就是为什么验证间隔是每次失败中最昂贵的类别，尽管它们只占21.30%。

投资:
- 基于样本的人工审查。
- 黄金数据集回归测试。
- 跨代理对重要输出进行交叉检查。

### 失败vs缓慢失败

有些失败是立即发生的；有些很慢。立即失败（超时、模式不匹配、验证错误）的检测成本很低。慢故障（内存中毒、单一文化漂移、角色模糊）的检测和预防成本很高。

2026年的工程举措：使用慢故障代理，这样你就可以在漂移变成明显错误之前发现它。协议率、重试率、输出长度分布和连续代理版本之间的编辑距离都是有用的代理。

## 船这

生产中的失效模式纪律：

- **每季度进行MAST审计。**不是每年一次。分类随着系统的发展而变化。
- 到处都是断路器。**每个呼出到任何依赖的服务。默认打开阈值为5-10%错误率。
- * *金色的数据集。**小，高质量，手工审核。每周对它们进行回归测试。
- * *层云三人。**检测+诊断+验证代理监控生产。只从检测代理开始；当症状不明显时添加诊断。
- * *失败的预算。**按类别显示故障率的SLO。超出预算会引发停运对话。

## 练习

1. 运行确认断路器封盖重试风暴。改变故障阈值并观察权衡。
2. 实现一个**慢故障代理**：跨3个并行代理协议率。当它急剧下降时，触发警报。通过逐渐关联代理输出来模拟单一文化漂移。
3. Read Cemri et al. [j] .中国科学院学报（自然科学版）：253.13657。从他们的7个MAS系统中选择一个，并绘制出其最常见的3个故障类别。这些结果与MAST预测结果相比如何？
4. 阅读Groupthink的论文（arXiv:2508.05687）。确定五个模式中哪一个在生产环境中最难检测。提出一个代理度量。
5. 为您所知道的特定多代理系统设计一个stratus风格的检测-诊断-验证三重奏。检测要注意哪些症状？诊断建议采取哪些缓解措施？验证如何确认它们的工作？

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| MAST | "The 2026 taxonomy" | Cemri 2025; 3 root categories + 14 sub-types of failures. |
| Specification Problem | "Role ambiguity" | Task or role under-defined; agents do not know what to do. |
| Coordination Failure | "State drift" | Communication or sync breakdown between agents. |
| Verification Gap | "No one checked" | Outputs accepted without independent validation. |
| Groupthink family | "Homogeneity failures" | Monoculture, conformity, deficient ToM, mixed-motive, cascading. |
| Monoculture collapse | "Same model, same hallucinations" | Correlated errors from shared base model or training data. |
| Retry storm | "Cascading error amplification" | One failure triggers retries which amplify load downstream. |
| Circuit breaker | "Fail fast on error rate" | Open when error rate exceeds threshold; short-circuit with default. |
| STRATUS | "Incident response trio" | Detection + diagnosis + validation agents. 1.5x mitigation success. |
| Memory poisoning | "Hallucinations propagate" | Shared-memory fact tainted; downstream agents reason on poison. |
