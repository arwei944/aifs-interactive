# 百万代币语境下的长视频理解

> 一个1小时的4K视频，每秒24帧，打补丁和嵌入，产生大约6000万个代币。一集2小时的播客需要3万个代币。一部完整的蓝光长片，即使是经过激烈的池化压缩，也需要成千上万的代币。谷歌的双子座1.5（2024年3月）以1000万个代币的背景开启了这个时代，在长达一小时的视频中进行了可靠的大海捞针式召回。LWM （Liu et al.， 2024年2月）展示了环形注意力的尺度路径。LongVILA和Video-XL进一步扩大了摄取量。VideoAgent为代理检索交换了原始上下文。每种方法在计算、召回和工程复杂性方面都有不同的权衡。本课将它们并列阅读。

**Type:** Build
**Languages:** Python (stdlib, needle-in-haystack simulator + agentic-retrieval router)
**Prerequisites:** Phase 12 · 17 (video temporal tokens)
**Time:** ~180 minutes

## 学习目标

- 计算长视频在不同FPS和池下的总视觉令牌计数。
- 解释三种缩放路径：暴力上下文（Gemini 1.5），环注意（LWM），令牌压缩（LongVILA / Video-XL）。
- 比较原始上下文视频VLMs与代理检索视频VLMs （VideoAgent）的准确性和延迟。
- 为一个30分钟的视频设计一个大海捞针测试，并在特定的一分钟测量记忆。

## 这个问题

在384原生分辨率下，单帧qwen2.5 - v1大小的补丁大约需要729个令牌。在3x3池中，即每帧81个令牌。1 FPS的30分钟片段= 1800帧= 145,800个令牌。2025年开VLMs可行，紧张。在2 FPS下，291,600个令牌——只有最大的上下文才适合。

1帧/秒的2小时电影需要583k个代币。超越大多数2026年开放模型；需要双子座2.5 Pro或更积极地汇集。

出现了三种缩放路径。

## 这个概念

### 路径1:Brute context （Gemini 1.5, Claude Opus）

用硬件解决问题。将上下文扩展到数百万个令牌，在一次向前传递中处理所有内容。

Gemini 1.5 Pro推出，代币数量为1M；双子座1.5 Ultra至10M；2026年的Gemini 2.5 Pro可以可靠地播放数小时的视频。该论文（arXiv:2403.05530）记录了大海捞针的召回率为99.7%，高达约950万个代币。

工程：一个自定义的注意力实现，具有内存层次结构（本地+全局+稀疏）和MoE专家路由，以提高长上下文效率。没有公布全部细节。不开源的。

### 路径2：环形注意（LWM, LongVILA）

环注意将长序列分布在一个“环”中，每个设备持有一个块。整个序列的注意力是通过每个设备以环形模式将其块发送给下一个设备，计算部分注意力和聚合来实现的。

LWM （Liu et al., 2024）以这种方式训练了一个1M-token上下文模型。训练计算随上下文线性扩展，而不是二次扩展-注意力的二次命中在环的设备上平摊。

LongVILA （arXiv:2408.10188）将该模式应用于vlm。每帧192个标记的1400帧视频= 268k上下文，通过8路并行的环形注意力进行训练。

### 路径3：令牌压缩（Video-XL, LongVA）

比暴力上下文便宜：在LLM看到序列之前进行猛烈压缩。

Video-XL （arXiv:2409.14485）使用视觉摘要令牌：N帧的每个片段产生一个单独的“摘要”令牌，该令牌关注N帧。在推理中，LLM每个片段看到一个摘要令牌，大大缩小了上下文。

LongVA通过“长上下文转移”技术将LLM上下文从200k扩展到2M。对长上下文文本进行训练，通过共享表示转移到长上下文视频。

令牌压缩牺牲了特定时间戳的召回，以换取可伸缩性。模型大致知道发生了什么，但有时会漏掉确切的帧。

### 路径四：人工检索（VideoAgent）

不要把完整的视频提供给法学硕士。相反，将视频视为一个数据库，并使用LLM来查询它。

VideoAgent (arXiv: 2403.10517):

1. 法学硕士读问题。
2. LLM要求检索工具检索相关片段（“show me segments with a cat”）。
3. 工具返回匹配的剪辑时间戳。
4. LLM通过VLM读取这些片段。
5. LLM编写答案或询问后续问题。

这是应用于长视频的llm作为代理模式。更便宜的推断（只编码相关片段），更困难的工程（检索质量成为瓶颈）。

### 个大海捞针基准

标准的长上下文测试：在视频中的随机点插入一个唯一的视觉或文本标记，然后询问一个需要召回它的查询。

度量：Recall@k跨越视频长度和标记位置。

Gemini 2.5 Pro在长达90分钟的视频中得分为bb0 99%。打开72B型号（qwen2.5 - v1 -72B, InternVL3-78B）， 30分钟评分~85-90%，60分钟后降级。

VideoAgent可以在2小时以上的时间内匹配或超过原始上下文模型，因为如果工具是好的，检索就会达到目的。

### 选择哪条路径

对于一个15分钟的片段，在前沿精度：打开72B +本地上下文通常工作。选择qwen2.5六世- 72 b。

30分钟至1小时的内容：LongVILA或Video-XL开放；双子座2.5专业关闭。质量酒吧很重要——边界关闭了。

2小时以上的内容：VideoAgent或类似的检索模式。或者，将汇总到更小的块并提供分层摘要。

### 2026年生产格局

实际上，生产长视频管道是混合的：

1. 在整个视频上运行动态fps采样+积极池化（获得100k令牌全局表示）。
2. 传递到72B VLM以获得全局摘要。
3. 如果用户询问详细的问题，则使用摘要作为索引运行代理检索。

它结合了用于全局理解的暴力上下文和用于局部细节的检索。

## 关键术语

| Term | What people say | What it actually means |
|------|-----------------|------------------------|
| Brute context | "Just more tokens" | Scale LLM context to millions of tokens; process everything in one pass |
| Ring attention | "LWM-style parallel" | Distributed attention pattern where each device holds a chunk and rotates |
| Token compression | "Summary tokens" | Reduce per-clip tokens via a learned compressor before the LLM |
| Needle-in-haystack | "NIH test" | Insert a unique marker at a random point, ask model to recall it at test time |
| Agentic retrieval | "LLM as query planner" | LLM asks a retrieval tool for relevant clips, reads them via a VLM, composes answer |
| VideoAgent | "Retrieval pattern for video" | Canonical agentic-retrieval design: question -> tool -> clip -> answer |
