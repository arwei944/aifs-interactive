# 克劳德代码作为自主代理：权限模式和自动模式

> Claude Code公开了七种许可模式。“plan”在每个操作之前都会询问，“default”只会询问有风险的操作，“acceptEdits”会自动批准文件写入，但仍会确认shell执行，“bypassPermissions”会批准所有操作。自动模式（2026年3月24日）用两阶段并行安全分类器取代每个动作的批准：每个动作都运行单令牌快速检查；标记的行动开启了思维链的深度回顾。行动预算是通过Auto Mode作为研究预览版发布——Anthropic已经明确表示，仅使用分类器是不够的。

**Type:** Learn
**Languages:** Python (stdlib, two-stage classifier simulator)
**Prerequisites:** Phase 15 · 01 (Long-horizon agents), Phase 15 · 09 (Coding-agent landscape)
**Time:** ~45 minutes

## 这个问题

机器上的自主编码代理是一个独特的安全类别。攻击面是代理可以到达的所有东西-文件系统，网络，凭据，剪贴板，任何浏览器选项卡，任何打开的终端。Bruce Schneier和其他人已经公开指出了这一点：使用计算机的代理并不是聊天机器人的“功能更新”，它们是一种带有新风险特征的新工具。

Claude Code的许可系统是Anthropic的答案。不是一个“自治/非自治”的开关，而是跨越能力阶梯的七种模式：计划→默认→接受its→…→绕过aspspermissions。每一种模式都是在速度和每次行动审查之间的不同权衡。自动模式（2026年3月）添加了一个两阶段的分类器，将对分类器判断安全的操作的批准移出用户的关键路径，同时为分类器标记的操作保留审查层。

工程问题：这个系统捕获了什么，遗漏了什么，给定的任务实际上需要哪种模式？

## 这个概念

### 七种权限模式

| Mode | Behavior | When to use |
|---|---|---|
| `plan` | Agent proposes a plan; user approves the whole plan; every action is reviewed before execution | Unfamiliar task; prod-adjacent code; first time using the agent on a repo |
| `default` | Agent runs actions; prompts user for any "risky" action (shell exec, destructive operations, network calls) | Most interactive coding sessions |
| `acceptEdits` | File writes auto-approve; shell exec and network calls still prompt | Refactoring pass across many files |
| `acceptExec` | Shell commands auto-approve within a curated allowlist; writes auto-approve | Tight inner loops where every shell command is `npm test` or similar |
| `autoMode` | Two-stage safety classifier; flagged actions elevate to review | Long-horizon unattended runs in a constrained workspace |
| `yolo` | Skips most prompts; still runs tool allowlist / denylist | Ephemeral sandboxes, CI jobs, research scripts |
| `bypassPermissions` | Approves everything | Documented as "only inside ephemeral containers you are willing to throw away" |

（上面的名字与公开的Claude Code文档相符；“yolo”是宽容的中间立场的非正式缩写。）

### 自动模式在一页

自动模式（2026年3月24日推出）是第一种授权模式，将每个操作的审批委托给模型。结构:

1. **阶段1 -单标记分类器。**运行在每一个建议的行动。便宜。返回“安全”或“标志”。设计为与主代理循环并行运行，因此已批准的操作不会位于队列中。
2. **第二阶段-二级政策/安全检讨。**仅在标记的操作上运行。对操作、会话的当前状态和声明的任务执行重点策略和安全评估。如果置信度低，则升级为用户HITL。

### 系统捕获了什么

- 直接的提示注入到工具输入中，注入的指令映射到已知的危险动作形状。
- 重复工具循环——分类器可以连续五次看到动作N+1与动作N几乎相同。
- 在只有文件编辑的会话中，显然超出了shell命令的作用域。

### 这个系统会错过什么

- **微妙的提示注入**，调制行为而不产生单个标记的动作。间接提示注入不是一个完全可修补的漏洞（OpenAI准备头，2025，在浏览器代理上-参见第11课）。
- * *语义层面上的不当行为。**每个单独的动作看起来是安全的，而组合的轨迹是有害的。分类器判断动作；它不会重新派生用户的意图。
- **通过合法渠道泄露。**写数据到你自己的文件，然后

### 研究预览框架

Anthropic发布了自动模式作为研究预览。文档明确地指出分类器是一个层，而不是一个解决方案：期望用户将Auto Mode与预算、允许列表、隔离的工作空间和轨迹审计结合起来（第12-16课）。预览框架还反映了文档中的评估与部署差距（第1课）——传递脱机评估的分类器在用户上下文不明确的真实会话中可能表现不同。

## 使用它

Z0阶段1是针对建议行动的廉价关键词规则；阶段2是一个较慢的多规则审阅者。驱动程序输入一个短的合成轨迹（安全动作、快速注入尝试、重复循环），并显示分类器捕获和错过的位置。

## 练习

1. 运行哪个合成动作类型从未被阶段1标记，但总是被阶段2捕获？哪一个都没有被抓住？

2. 扩展第一阶段的规则集，以捕获特定的已知坏形状(例如，测量良性作用样品的假阳性率。

3. 阅读Anthropic的“代理循环是如何工作的”文档。列出代理在默认情况下接触的每个外部状态你需要在跑步前分别登机吗

4. 设计一个24小时无人值守运行预算：证明每个数字。

5. 描述一个轨迹，其中每个单独的动作都得到了阶段1和阶段2的批准，但组合的行为是不一致的。（第14课将介绍终止开关和金丝雀令牌如何解决这个问题。）
