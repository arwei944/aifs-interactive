# 案例研究和2026年的技术状况

> 端到端研究的三个生产级参考，每个都说明了多智能体工程的不同部分。**Anthropic的Research系统** （orchestrator-worker， 15倍代币，比单代理Opus 4，彩虹部署+90.2%）是典型的监管案例。**MetaGPT / ChatDev**（用于软件工程的soap编码角色专门化；ChatDev的“沟通去幻觉”；MacNet通过dag扩展到bbb1000个代理，arXiv:2406.07155）是典型的角色分解案例。**OpenClaw / Moltbook**（最初是Peter Steinberger的Clawdbot， 2025年11月；更名两次；到2026年3月247k GitHub上线；本地ReAct-loop代理；Moltbook作为一个仅代理的社交网络，在发布后几天内拥有约230万个代理账户，被Meta 2026-03-10收购）说明了在人口规模上发生的事情：新兴的经济活动，即时注入风险，国家级监管（中国限制OpenClaw在政府计算机上使用，2026年3月）。**框架景观2026年4月：** LangGraph和CrewAI主导制作；AG2是社区AutoGen的延续；Microsoft AutoGen处于维护模式（合并到Microsoft Agent Framework， RC 2026年2月）；OpenAI Agents SDK是Swarm的后续产品；b谷歌ADK（2025年4月）是a2a原生进入者。现在每个主要框架都提供了MCP支持；大多数船都是A2A。本课端到端阅读每个案例，并提炼出常见模式，以便您可以为下一个生产系统选择正确的参考。

## 问题

多智能体工程是一门年轻的学科。生产参考很少，每个都涵盖了空间的不同部分。一次读一本是有用的；将它们作为一个集合进行比较更有用。本课程将三个典型的2026案例研究作为端到端的阅读列表，确定常见模式，并绘制框架景观，以便您可以根据知识（而不是市场营销）做出框架选择。

## 概念

### 人类研究系统

生产主管-工人案例。克劳德作品4计划和综合；克劳德十四行诗4个子主体并行研究。发表的工程帖子：https://www.anthropic.com/engineering/multi-agent-research-system。

主要测量结果：

- ***在内部研究评估方面比单剂Opus 4提高90.2%**。
- **80%的BrowseComp方差**仅由**令牌使用解释** -多代理获胜主要是因为每个子代理获得一个新的上下文窗口。
- **每个查询15个令牌**与单代理相比。
- **彩虹部署**，因为代理是长时间运行且有状态的。

设计经验汇编：

1. **调整查询复杂度。**简单→1个座席，3-10个工具呼叫。中等→3剂。复杂研究→10+子代理。
2. 先宽后窄。**子代理进行广泛搜索；领导综合;后续子代理执行目标深度。
3. **彩虹部署。**保持旧的运行时版本存活，直到它们的飞行代理完成。
4. **验证不是可选的。**观察到系统在没有明确验证者角色的情况下产生幻觉。

这是生产规模的主管-工人拓扑（阶段16.05）的参考案例。

### MetaGPT / ChatDev

产品sop -角色分解案例。封面arXiv:2308.00352 （MetaGPT）和arXiv:2307.07924 （ChatDev）。

MetaGPT将软件工程sop编码为角色提示：产品经理、架构师、项目经理、工程师、QA工程师。论文的框架：每个角色都有一个狭窄的、专门的提示；角色间的交接携带结构化的工件（PRD文档、架构文档、代码）。

ChatDev的贡献：消除交际幻觉。代理在回答之前要求详细信息——设计师代理在绘制UI草图之前询问程序员打算使用什么语言，而不是猜测。本文报道了这种方法在多智能体管道中可测量地减少了幻觉。

MacNet （arXiv:2406.07155）通过dag扩展ChatDev到** bbb1000个代理。每个DAG节点都是一个角色专门化；边编码移交契约。这个规模是可能的，因为路由是显式的，并且是离线计算的。

设计经验:

1. 结构比大小更重要。一个紧密的5人SOP团队胜过一个50人的非结构化团队。
2. **书面交接合同。**在角色之间传递的工件遵循模式。
3. 交际性幻觉是一种廉价的、可承受的模式。
4. ** dag的规模比聊天更大。**当流程可知时，对其进行编码。

这是角色专门化（阶段16.08）和结构化拓扑（阶段16.15）的参考案例。

### OpenClaw / Moltbook生态系统

生产人口规模案例。时间轴:

- ** 2025年11月：** Clawdbot （Peter Steinberger的本地react循环编码代理）出货。
- ** 2025年12月- 2026年3月：**更名两次（Clawdbot→OpenClaw→在OpenClaw下继续）。
- ** 2026年2月：** Moltbook作为基于相同原语的纯代理社交网络推出；~ 230万代理账户。
- ** 2026年3月（2026-03-10）：** Meta收购Moltbook。
- ** 2026年3月：**中国限制OpenClaw进入政府电脑。
- ** 2026年3月：** OpenClaw通过247k GitHub星。

当你把数百万个代理放在一个共享的基质上时，这就是多代理的样子：

- **新兴经济活动。**代理使用代币支付相互购买、销售和服务。
- **人群规模的即时注射风险。**病毒代理配置文件中的一个恶意提示在数小时内传播到数千个代理对代理的交互。
- **国家级监管响应。**在发布后的几周内，监管就会影响到生态系统。

从这个案例中得到的设计教训部分是技术方面的，部分是治理方面的：

1. **种群规模下的多智能体是一种新的制度。**个别系统最佳实践（验证、角色明确）仍然适用，但还不够。
2. **提示注入是新的XSS。**默认情况下，将代理配置文件和跨代理消息视为不可信的输入。
3. **法规比设计周期更快。**为此做好计划。
4. **开源+病毒规模化合物。** 4个月247k颗恒星是不寻常的；部署-突发负载的设计。

参见在技术基础上，Clawdbot / OpenClaw reppos公开了本地ReAct循环；Moltbook的公开帖子揭示了顶部的社交图谱结构。

### 这三种情况的共同模式

1. **协调者+工人** （Anthropic明确的监督者，MetaGPT pm -as-监督者，OpenClaw个体代理+网络效应）。
2. 结构化的移交契约（Anthropic子代理任务描述，MetaGPT PRD/架构文档，OpenClaw A2A工件）。
3. **验证作为一级角色** （Anthropic的验证者，MetaGPT的QA工程师，OpenClaw的网络内验证者）。
4. **缩放是拓扑+基板，而不仅仅是更多的代理** （rainbow部署，MacNet dag，人口规模的基板）。
5. **成本是实质性的和公开的**（15倍代币，MetaGPT中的每个角色预算，Moltbook中的每个交互定价）。
6. **安全姿态是明确的** （Anthropic的沙箱，MetaGPT的角色限制，OpenClaw的提示注入作为已知的攻击面）。

### 为下一个项目选择参考

- **生产研究/知识任务→人类研究。**新上下文子代理获胜。
- **工程/工具链工作流→MetaGPT / ChatDev。**角色+ sop +交接合同。
- **网络效应社交产品→OpenClaw / Moltbook。**基质+新兴经济。
- **经典企业自动化→CrewAI或LangGraph**（生产领导者，运行稳定）。

### 2026年最先进的总结

2026年4月油田位置：

- **框架正在融合。** MCP + A2A支持是表赌注。切换语义是剩下的设计选择。
- **评价是硬化的。** sw -bench Pro， MARBLE， STRATUS缓解基准。亲是目前抗污染的现实检查。
- **生产故障率可测量** （Cemri 2025 MAST; 41-86.7%的实际MAS）。该领域已经走出了“看起来很棒的演示”时代。
- **成本是主要的工程约束。**每个任务的令牌成本，每个交互的挂钟，彩虹部署开销。多智能体在准确性上赢了，但在成本上输了——这种交易是商业决策。
- **监管是近期投入，而不是背景问题。**司法管辖区的发展速度快于个人部署周期。

## 船这

2026年生产多agent的启动规则：

- **从案例研究开始，而不是从头开始。**选择最接近的Anthropic Research / MetaGPT / OpenClaw并适应。
- **跨框架的可移植性是有价值的；协议支持是免费的。
- **测量swebench Pro或您的内部Pro等效。**已验证是否被污染。
- **缴纳核查税。**独立的验证器花费约20-30%的代币预算，并购买可测量的正确性。
- **Rainbow部署长时间运行的代理。**预计几个小时的代理运行是常规的。
- **阅读WMAC 2026和MAST后续报道。这个学科发展很快。

## 练习

1. 端到端阅读人类研究系统。确定如果用较小的模型（例如Haiku 4）替换Opus 4，将会改变的三个设计决策。
2. 阅读MetaGPT章节3-4 （arXiv:2308.00352）。根据角色提示，从您自己的域（不是软件）编码一个SOP。SOP暗示了多少个角色？
3. 阅读ChatDev （arXiv:2307.07924）。确定“交流幻觉”的机制。在现有的多代理系统中实现它。
4. 阅读OpenClaw和Moltbook。选择一个特定的失败模式，在人口规模上出现，不会出现在5个代理系统中。你会如何设计来对抗它？
5. 选择当前的多代理项目。这三个案例中哪一个是最接近的参考？你还没有采用案例研究中的哪些设计决策？写下一个你将在本季度采用的方法。
