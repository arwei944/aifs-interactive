# 工具接口——为什么代理需要结构化I/O

> 语言模型产生符号。程序执行操作。两者之间的差距是工具接口：一个允许模型请求操作并由主机执行的契约。每个2026堆栈函数调用OpenAI， Anthropic和Gemini；MCP的A2A的任务部分-是相同的四步循环的不同编码。本课为循环命名并展示运行它的最小机器。

**Type:** Learn
**Languages:** Python (stdlib, no LLM)
**Prerequisites:** Phase 11 (LLM completion APIs)
**Time:** ~45 minutes

## 学习目标

- 解释为什么一个只能生成文本的法学硕士不能自己对现实世界采取行动。
- 绘制四步工具调用循环（描述→决定→执行→观察），并指出每个步骤由谁负责。
- 将工具描述编写为三个部分：名称、JSON Schema输入和确定性执行器函数。
- 区分纯工具和副作用工具，并说明为什么分离对安全很重要。

## 这个问题

LLM发出下一个令牌的概率分布。这是整个输出曲面。如果你问一个聊天模型“现在班加罗尔的天气如何”，它可以写出一个貌似合理的句子，但它不能拨入天气API。这句话可能是碰巧对的，也可能是过时了三天。

工具接口的目的就是缩小这个差距。宿主程序——您的代理运行时、Claude Desktop、ChatGPT、Cursor或自定义脚本——向模型发布一个可调用工具列表。当模型决定需要某个操作时，它会发出一个结构化的有效负载，命名工具及其参数。主机解析该有效负载，实际运行该工具，并反馈结果。循环将继续，直到模型决定不再需要调用为止。

该合同的第一个版本于2023年6月作为OpenAI的“functions”参数发布。Anthropic之后是Gemini补充道现在，每个提供者都公开相同的形式：输入json模式类型的工具列表，输出json有效负载工具调用。模型上下文协议（2024年11月）推广了契约，以便一个工具注册中心为每个模型服务。A2A（2026年4月，v1.0）为代理到代理的委托分层了相同的原语。

四步循环是所有这些下面的不变量。第13阶段的其他一切都是细化。

## 这个概念

### 第一步：描述

主机用三个字段声明每个工具。

- * *的名字。**稳定的，机器可读的标识符。`get_weather`, not "weather thing".
- * *描述。一段自然语言摘要。当用户询问某个特定城市的当前情况时使用。不要用于历史数据。”
- * *输入模式。描述工具参数的JSON Schema对象（草案2020-12）。

模型接收列表。现代提供程序使用特定于提供程序的模板将这些声明序列化到系统提示符中，因此您作为调用者只处理结构化表单。

### 第二步：决定

给定用户的消息和可用的工具，模型从三种行为中选择一种。

1. **直接用文字回答**。没有工具调用。
2. **调用一个或多个工具。发出结构化的调用对象。在
3. * *拒绝。严格模式的结构化输出可以生成类型化的

工具调用有效负载有三个稳定字段：一个调用这个id的存在是为了让主机能够将后面的结果与特定的调用关联起来，这在并行调用乱序返回时很重要。

### 第三步：执行

主机接收调用，根据声明的模式验证参数，并运行执行器。无效参数意味着模型产生了一个字段或使用了错误的类型——这是弱模型中非常常见的失败模式。生产主机对无效参数执行以下三种操作之一：快速失败并向模型显示错误，使用受限解析器修复JSON，或者在提示符中包含验证错误的情况下重试模型。

执行器本身是普通代码。Python, TypeScript， shell命令，数据库查询。它生成一个结果，通常是一个字符串，但可以是任何JSON值或结构化内容块（MCP中的文本、图像或资源引用）。结果必须是可序列化的。

### 第四步：观察

主机将工具结果附加到会话中(作为该模型现在在上下文中具有工具输出，并且可以生成最终答案或请求更多调用。这将持续到模型停止发出调用或主机达到迭代计数的安全限制。

### 信托分割

为了安全起见，工具有两种类型。

- * *纯洁。**只读，确定性，无副作用。`get_weather`, `search_docs`, `get_current_time`. 投机地打电话是安全的。
- * *重要。**改变状态，花钱，接触用户数据。`send_email`, `delete_file`, `execute_trade`. 必须有门控。

Meta的2026年代理安全“二法则”表示，一个回合可能最多包含以下两种情况：不可信的输入、敏感数据、后果性操作。工具接口是执行该规则的地方——通过拒绝调用、要求用户确认或扩大作用域。请参阅阶段13.15了解完整的安全章节，参见阶段14.09了解代理级权限策略。

### 为什么不直接提示模型发出JSON呢？

“请求模型以JSON形式回复”是函数调用前的模式。在前沿模型中失败率为5%到15%在小型模型中失败率更高。失败模式包括缺少大括号、尾随逗号、幻觉字段和错误的类型。然后，您需要一个JSON修复通道、重试或一个受限的解码器。

本机函数调用更好，原因有三。首先，提供者根据精确的调用形状对模型进行端到端训练，因此在严格模式下，有效json率攀升到98%到99%。其次，调用有效负载位于自己的协议槽中，而不是在自由文本中—因此工具调用永远不会泄漏到用户可见的回复中。第三，提供商强制模式遵从约束解码（OpenAI的严格模式，Anthropic的严格模式）保证输出是有效的。

### 断路器

当模型停止发出调用或主机达到最大回合数时，循环终止。生产主机将此设置为5到20个回合之间。除此之外，您几乎肯定处于模型无法退出的循环中。Claude Code默认为20；OpenAI助手增至10人；光标的代理模式为25。

另一种选择——无界循环——每六个月出现一次“代理一夜之间在API调用上花费了400美元”的事后分析。不要不加约束地发货。

第14·12阶段深度覆盖错误恢复和自愈；第17阶段涵盖了产量限制。

## 使用它

Z0一个假的“决定者”函数通过对用户消息进行模式匹配来模拟模型；执行器、模式验证器和观察步骤控制是真实的。运行它以查看具有可打印中间状态的完整请求/响应编排，然后在后面的课程中用任何真实的提供者替换假的决定器。

看点：

- 工具注册表为每个工具保存三个字段：名称、描述、模式和执行器引用。
- 验证器是一个最小的JSON模式子集（类型、required、enum、min/max），仅用stdlib编写。第13·04阶段运送一艘更满的船。
- 循环的边界迭代计数为5。生产代理商需要的正是这种断路器。

## 船这

这一课产生了给定一个工具定义草案（名称+描述+模式+执行器大纲），技能审核它的循环适应性：名称是否机器稳定，描述是否完整的使用简介，模式是否正确使用JSON schema 2020-12，以及纯粹与结果分类是否明确。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Tool | "A thing the model can call" | A triple of name + JSON-Schema-typed input + executor function |
| Function calling | "Native tool use" | Provider-level API support for emitting structured tool calls instead of prose |
| Tool call | "The model's request to act" | A JSON payload with `id`, `name`, `arguments` emitted by the model |
| Tool result | "What the tool returned" | The executor's output, wrapped in a `tool` role message with matching id |
| Parallel tool calls | "Many calls at once" | Multiple call objects in one model turn, independent and orderable by id |
| Strict mode | "Guaranteed JSON" | Constrained decoding that forces the model's output to validate against the declared schema |
| Pure tool | "Read-only tool" | No side effects; safe to re-run |
| Consequential tool | "Action tool" | Mutates external state; requires gate, audit, or user confirmation |
| Four-step loop | "The tool-call cycle" | describe → decide → execute → observe |
| Host | "Agent runtime" | The program that holds the tool registry, calls the model, and runs the executor |
