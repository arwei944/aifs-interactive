# 顶点13 - MCP服务器与注册表和治理

> 模型上下文协议不再是未来，而是在2026年成为默认的工具使用规范。Anthropic、OpenAI、谷歌和每个主要的IDE都提供MCP客户端。Pinterest发布了其内部MCP服务器生态系统。AAIF Registry将功能元数据形式化于AWS ECS发布了参考无状态部署。Block的鹅代理将相同的协议放入托管助手中。2026年的产品形式是：StreamableHTTP传输、OAuth 2.1作用域、OPA策略门控，以及一个允许平台团队发现、验证和启用服务器的注册中心。从头到尾地建造。

**Type:** Capstone
**Languages:** Python (server, via FastMCP) or TypeScript (@modelcontextprotocol/sdk), Go (registry service)
**Prerequisites:** Phase 11 (LLM engineering), Phase 13 (tools and MCP), Phase 14 (agents), Phase 17 (infrastructure), Phase 18 (safety)
**运行阶段：** P11·P13·P14·P17·P18
**Time:** 25 hours

## 问题

MCP成为工具使用的通用语言。Claude Code、Cursor 3、Amp、OpenCode、Gemini CLI和每个托管代理现在都使用MCP服务器。生产方面的挑战不在于编写服务器（FastMCP使这一点变得容易），而在于根据企业需求大规模部署它们：每个租户的OAuth范围、针对破坏性工具的OPA策略、StreamableHTTP无状态扩展、用于发现的注册表、每个工具调用的审计日志。Pinterest的内部MCP生态系统和AAIF注册规范设定了2026年的标准。

您将构建一个MCP服务器，公开10个内部工具（Postgres只读、S3清单、Jira、Linear、Datadog等），一个用于平台发现的注册表UI，以及一个用于破坏性工具的人工审批门。负载测试演示了StreamableHTTP水平扩展。审计跟踪满足企业安全审查。

## 概念

MCP 2026修订版强制将StreamableHTTP作为默认传输。与之前的体育场和sse不同，StreamableHTTP默认情况下是无状态的：单个HTTP端点接受JSON-RPC请求、流响应，并支持长时间的通知连接。无状态意味着在负载平衡器后水平可伸缩。

授权是基于每个工具范围的OAuth 2.1。令牌的作用域如下MCP服务器在工具调用时检查作用域，而不仅仅是在会话开始时。对于高风险工具，服务器拒绝范围未提升到的任何调用

注册中心是一个独立的服务。每个MCP服务器都公开一个注册中心进行轮询、验证和索引。平台团队使用注册表UI来查看可用的工具、需要的范围以及拥有这些工具的团队。


## 堆栈

- 服务器框架：FastMCP （Python）或
- 传输：StreamableHTTP over HTTPS（无状态）
- Auth: OAuth 2.1，通过SPIFFE / SPIRE实现工作负载身份
- 策略：每个工具的OPA / Rego规则；每个请求的策略决策服务
- 注册表：自托管，消费
- 人工批准：破坏性工具的Slack交互式消息
- 部署：AWS ECS Fargate或Fly。Io，每个租户一台服务器或与租户范围共享
- 审计：具有每个调用沿袭的每个租户桶的结构化json

## 构建它

1. * *工具表面。**公开10个内部工具：Postgres只读查询，S3列表对象，Jira搜索/获取，线性搜索/获取，Datadog度量查询，PagerDuty随叫随到查询，GitHub只读，概念搜索，Slack搜索，Salesforce读取。每个工具都有一个类型化的模式和一个范围标签。

2. * * FastMCP服务器。**安装工具。配置StreamableHTTP传输。添加用于OAuth令牌自省和范围实施的中间件。

3. * * OPA政策。**每个工具的Rego策略：允许调用的范围，适用的PII修订，适用的有效负载大小上限。每个工具调用时调用的决策服务。

4. * *注册服务。**独立的Go或TS服务轮询

5. * *能力清单。**每个服务器公开

6. **破坏性工具分离。**改变状态的工具（Jira create, Linear create, Postgres write）存在于具有更严格认证流的第二台MCP服务器上：令牌必须有一个

7. * *审计日志。**每个租户只追加JSONL：PII在撰写前经过Presidio编辑。

8. * *负载测试。** 100个并发客户端在StreamableHTTP。通过添加第二个副本演示水平扩展；显示没有会话粘性的负载均衡器重新分配。

9. * *一致性测试。**在两台服务器上运行官方的MCP一致性套件。通过所有必修部分。

## 关键术语

| Term | What people say | What it actually means |
|------|-----------------|------------------------|
| StreamableHTTP | "2026 MCP transport" | Stateless HTTP + streaming; replaces SSE + stdio for networked servers |
| Capability manifest | "Well-known doc" | `.well-known/mcp-capabilities` with tool list, auth, transport URL |
| OPA / Rego | "Policy engine" | Open Policy Agent for authorizing tool calls against external rules |
| Scope elevation | "Approved-by-human" | Short-lived scope granted via Slack approval, required for destructive tools |
| Registry | "Tool discovery" | Service that indexes MCP servers from their capability manifests |
| Workload identity | "SPIFFE / SPIRE" | Cryptographic service identity for OAuth token issuance |
| Conformance suite | "Spec tests" | Official MCP test battery for StreamableHTTP + tool manifest correctness |
