## This question

Modern master of laws solve difficult problems by generating long chains of reasoning - step-by-step logic with 5,000 symbols is common, and tens of thousands of symbols occur in deep mathematical problems. On the 70B model, 35 tokens are decoded per second, and 50,000 tokens take 24 minutes. This model is not interactive.

Speculative decoding (Stage 10·15) can achieve an acceleration of 3 to 5 times by parallelizing within a sequence. After this, the sequential dependency of autoregressive decoding is a hard ceiling. Each new token depends on each previous token.

An obvious question is: Can we parallelize across sequences? Running multiple copies of the same model on the same problem, making them cooperate and divide the work?

Previous work: Voting integration (running N models and selecting the majority of answers), thought tree (branching reasoning paths and recombination), and multi-agent framework (assigning a sub-task to each agent and using a coordinator). All of these are helpful for specific task areas. They all introduce clear coordination mechanisms - voting rules, branching and pruning logic, and agent-to-agent messaging protocols.

Hogwild ! Reasoning employs different methods. N worker threads share one KV cache. Each worker immediately sees the tokens generated by other workers as if they were its own context. The workers - without any training or fine-tuning - knew how to divide the work. Modern inference models (QwQ, DeepSeek-R1, Claude-family inference mode) can read the shared cache and say, "I see that worker 2 has processed the base case, so I will proceed with the induction step."

As of April 2026, this acceleration depends on the workload and is experimental. But this idea is worth understanding because it opens up a new axis for parallel reasoning.

### Why does coordination occur

The workers share one prompt. It is usually like this: "You are one of the N instances working together to solve this problem." Each instance reads the shared memory and can see what other instances have written. Avoid unnecessary work." It is sufficient to add a shared cache to the prompt. The inference model reads the cache, pays attention to which parts of the problem have been attempted, and then (usually but not always) turns to the unexplored parts.

Hogwild ! The observations reported in the paper (Rodionov et al., 2025) are as follows:

- The staff make plans and communicate with other staff through the cache.
- The workers noticed the mistakes in the reasoning of other workers and pointed them out.
- When the plan fails, employees will make adjustments and propose alternative solutions.
- When prompted to check for redundancy, the workers will notice it and turn around.

None of these require fine-tuning. Emergency actions stem from the reasoning capabilities that the model already possesses.

### When are you going to Hogwarts?

- Long reasoning problems (with thousands of tokens), where tasks can be parallelized across independent sub-objectives.
- The reasoning model has been trained to think step by step. Non-reasoning models cannot perform self-coordination well.
- Single-node deployment with sufficient VRAM to accommodate shared cache and N worker processes. The cache is shared, but each worker has its own activated memory.

### When won't you go

- A brief interactive chat. Coordination expenses play a dominant role.
- Non-parallelized tasks (single linear proof, single compilation). N=1 is the maximum value.
- Non-reasoning model. No coordination emerged.
- Multi-node deployment. Shared caching requires very fast cross-work synchronization. It's very good within the node. Cross-node is a latency disaster.

### Current status of the experiment

Starting from April 2026, Hogwarts! It is a research method implemented using the open-source PyTorch. Production adoption has not yet occurred. Three blockers:

1. Sharing KV cache management across concurrent processes is an important project.
2. Emergency coordination is task-dependent; The benchmark test is still under construction.
3. Compared with the speed provided by speculative decoding, this acceleration is moderate. The two can be combined, but the engineering involved in the combination is on another level.

## Build it

 Simulator

- There are two working processes, each of which is a deterministic "LLM" that generates one of several token categories (working token, observation token, coordinate token) with known probabilities.
- A shared cache (just a token list), which can be read from and written to by both worker threads.
- A simple coordination logic: When a worker sees that another worker has already generated enough work tokens in one category, it will choose a different category.

The simulator runs a fixed step budget and reports:

- The total number of work tokens generated.
- Total wall time (number of worker steps).
- Accelerate effectively on a single worker.
- Which worker wrote the trace of which token.

### Step 1: Shared cache

The list to which both workers are attached. For simple locking (Python), we simulate it using counters.

### Step 2:worker loop

Every worker, at every step:

- Read the current shared cache.
- Determine the category of the token to be written based on the existing content.
- Write a token.

### Step 3: Coordinate the heuristic

If there are already K tokens of category X in the cache and the expected category of the worker is X, then the worker switches to category y. This is a toy alternative to the behavior of the reasoning model that goes, "Note that this has been covered. Please do something else."

### Step 4: Measure the acceleration

The total step budget for running the simulator with N=1 staff member and N=2 staff members is the same. The work token generated by calculation. Due to the coordination-driven task division, N=2 should generate approximately 1.5 to 1.8 times the number of work tokens.

### Step 5: Emphasize coordination

Reduce the sensitivity of the coordination heuristic algorithm. Run again. It is observed that without good coordination, N=2 redundancy generates the same marking and accelerates down to below 1. This is in line with the observation of the paper: this technique is only effective when workers have the ability of self-coordinated reasoning.

## Use it

Hogwild ! As of April 2026, it has been put into production and is of research grade. The reference implementation of Yandex/HSE/IST is based on pytorch and is designed for the single-node multi-process setup on the DeepSeek-R1 and QwQ models.

Practical adoption path

1. Outline the workload of your reasoning tasks. Measure the proportion of exploratory tokens (multiple strategies, case studies, searches) and linear tokens.
2. If exploration takes the lead, run a two-worker Hoggwell! Experiment. Measure improvements around the clock.
3. If the improvement is less than 1.3 times, it is in a coordinated leading state. Restore to a single worker.
4. If the improvement exceeds 1.5 times, push it to N=4 and measure again. The diminishing returns are usually around N=4 to 8.

Combined with Speculative Decoding: Every Hogwarts! Worker can independently use spec decode. Two accelerations multiplied (roughly) bring 3x specification decoding and 1.8x Hogwell! 5.4 times more effective than simple simplex decoding.

## Key terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Hogwild! | "Parallel workers, shared cache" | N instances of the same LLM running concurrently with one shared KV cache; emergent coordination via self-prompting |
| Shared KV cache | "The coordination medium" | A single growing KV buffer that all workers read and write; enables instant token visibility across workers |
| Emergent coordination | "No training needed" | Reasoning-capable LLMs can read the shared cache and divide work without any fine-tuning or explicit protocol |
| Coordination overhead (c) | "Tokens spent orienting" | The per-worker cost of reading the extended cache and deciding what to do; must stay small vs total decode time |
| Parallelizable fraction (p) | "What can run in parallel" | Task-level parallelism: the fraction of the total work that is not intrinsically sequential |
| RoPE enables Hogwild! | "Rotary positions are shift-invariant" | Because positions are rotations, writing into a shared cache does not require recomputing prior tokens |
| Voting ensemble | "Run N, pick the majority" | The simplest parallel inference topology; useful for classification, less for long-form reasoning |
| Tree of thought | "Branch and prune" | Reasoning strategy that explores multiple branches and prunes; explicit coordination logic |
| Multi-agent framework | "Assign sub-tasks" | Each agent gets a role; a coordinator orchestrates; heavy protocol overhead |
