# 异步和霍格沃茨！推理

> 推测解码（阶段10·15）在一个序列中并行化标记。多智能体框架跨整个序列并行化，但强制显式协调（投票、子任务分割）。Hogwild !Inference （Rodionov et al., arXiv:2504.06261）做了其他事情：对共享键值缓存并行运行相同LLM的N个实例。每个工人立即看到其他工人生成的令牌。现代推理模型——QwQ、DeepSeek-R1——可以通过共享缓存进行自协调，无需任何微调。这种方法是实验性的，但它开辟了一个全新的推理并行轴，与规范解码正交。本课实现了一个双worker的霍格沃茨！模拟器，并解释了为什么共享缓存协作是从现有模型的推理能力中产生的。

## 这个问题

现代法学硕士通过产生长推理链来解决难题——5000个符号的逐步逻辑是常见的，在深度数学问题上发生了数万个符号。在70B型号上，35个令牌/秒解码，5万个令牌是24分钟。这个模型不是交互式的。

推测解码（阶段10·15）通过在一个序列内并行化，可以获得3-5倍的加速。在此之后，自回归解码的顺序依赖性是硬天花板。每个新令牌依赖于每个先前的令牌。

一个显而易见的问题是：我们可以跨序列并行化吗？在同一个问题上运行同一模型的多个副本，让它们合作，让它们分工？

先前的工作：投票集成（运行N个模型，选择大多数答案），思想树（分支推理路径和重组）和多智能体框架（分配每个智能体一个子任务，使用协调器）。这些都有助于特定的任务领域。它们都引入了明确的协调机制——投票规则、分支和修剪逻辑、代理到代理的消息传递协议。

Hogwild !推理采用了不同的方法。N个工作线程共享一个KV缓存。每个worker立即看到其他worker生成的令牌，就好像它们是自己的上下文一样。工人们——没有经过任何培训或微调——就知道如何分工。现代推理模型（QwQ, DeepSeek-R1， Claude-family推理模式）可以读取共享缓存，并说“我看到worker 2已经处理了基本情况，所以我将进行归纳步骤。”

截至2026年4月，该加速取决于工作负载，并且是实验性的。但这个想法是值得了解的，因为它打开了推理并行的新轴。

### 为什么会出现协调

工人们共用一个提示。通常是这样的：“你是共同解决这个问题的N个实例之一。每个实例读取共享内存，并可以看到其他实例写了什么。避免多余的工作。”提示加上共享缓存就足够了。推理模型读取缓存，注意问题的哪些部分已经尝试过，然后（通常但不总是）转向未探索的部分。

Hogwild !论文（Rodionov et al., 2025）报告的观察结果如下：

- 工作人员制定计划，并通过缓存与其他工作人员交流。
- 工人们注意到其他工人推理中的错误，并指出来。
- 当计划失败时，员工会做出调整，并提出替代方案。
- 当提示检查冗余时，工人们会发现它并转向。

这些都不需要微调。紧急行为来自于模型已经具备的推理能力。

### 具体的例子

推理问题：思维链的10k代币。假设问题有与

- 串行时间：解码10000步。
- Hogwild !时间：10000 *(0.3 + 0.7 / 4)+ 200 * 4 = 10000 * 0.475 + 800 = 5550解码步数。
- 加速：10000 / 5550 = 1.8倍。

这是适度的。但是对于较长的推理问题（50k个令牌），协调开销会平摊，加速会达到2.5-3倍。Hogwild !是一种语言中与线程级并行性等价的推理，可以让您自然地编写多线程代码。

### 什么时候去霍格沃茨！

- 长推理问题（数千个令牌），其中任务可以跨独立的子目标并行化。
- 推理模型已经被训练成一步一步地思考。非推理模型不能很好地进行自协调。
- 单节点部署，具有足够的VRAM来容纳共享缓存和N个工作进程。缓存是共享的，但是每个worker都有自己的激活内存。

### 什么时候不去

- 简短的互动聊天。协调开销占主导地位。
- 不并行化的任务（单次线性证明，单次编译）。N=1是最大值。
- Non-reasoning模型。没有协调出现。
- 多节点部署。共享缓存需要非常快的跨工作同步。节点内很好；跨节点是延迟灾难。

### 实验现状

从2026年4月起，霍格沃茨！是一种使用开源PyTorch实现的研究方法。生产采用还没有发生。三个阻断剂:

1. 跨并发进程共享KV缓存管理是一项重要的工程。
2. 紧急协调是任务依赖的；基准测试仍在构建中。
3. 与推测解码所提供的速度相比，这种加速是适度的，两者可以结合起来，但结合的工程是另一个层面。

值得了解。值得尝试。还不值得把赌注押在产品上。

## 构建它

Z0模拟器:

- 两个工作进程，每个进程都是一个确定性的“LLM”，它产生具有已知概率的几个令牌类别（工作令牌、观察令牌、坐标令牌）中的一个。
- 一个共享缓存（只是一个令牌列表），两个工作线程都可以读取和写入。
- 一个简单的协调逻辑：当一个工人看到另一个工人已经在一个类别中产生了足够的工作令牌时，它会选择一个不同的类别。

模拟器运行一个固定的步骤预算，并报告：

- 产生的工作令牌总数。
- 总墙时间（工人步数）。
- 在单个工人上有效加速。
- 哪个工人写了哪个令牌的踪迹。

### 步骤1：共享缓存

两个工人都附加到的列表。简单锁定（Python）我们用计数器进行模拟。

### 步骤2:worker循环

每个工人，在每一步上：

- 读取当前共享缓存。
- 根据已经存在的内容决定要写入的令牌的类别。
- 写入一个令牌。

### 第三步：协调启发式

如果类别X在缓存中已经有K个令牌，并且worker的预期类别是X，则worker切换到类别y。这是“注意，这个已经覆盖了，请做其他事情”的推理模型行为的一个玩具替代品。

### 步骤4：测量加速

用N=1个工作人员和N=2个工作人员运行模拟器，总步骤预算相同。计算产生的工作令牌。由于协调驱动的任务划分，N=2应该产生大约1.5-1.8倍的工作令牌。

### 第五步：强调协调

降低协调启发式算法的灵敏度。再次运行。观察到，如果没有良好的协调，N=2冗余地产生相同的标记，并且加速降至1以下。这与论文的观察结果相符：只有当工人有自我协调的推理能力时，这个技巧才有效。

## 使用它

Hogwild !截至2026年4月，已投入生产，为研究级。Yandex/HSE/IST的参考实现是基于pytorch的，针对DeepSeek-R1和QwQ模型上的单节点多进程设置。

务实的采用路径：

1. 概述你的推理任务工作量。衡量探索性令牌（多种策略、案例分析、搜索）和线性令牌的比例。
2. 如果勘探占主导地位，运行两个工人的霍格威尔德！实验。衡量全天候的改进。
3. 如果改进小于1.3倍，则处于协调主导状态。恢复为单worker。
4. 如果改善超过1.5倍，则推至N=4并再次测量。收益递减通常在N=4-8左右。

结合推测解码：每个霍格沃茨！Worker可以独立使用spec decode。两个加速相乘（大致），带来3倍规格解码和1.8倍霍格威尔德！有效的5.4倍于单纯的单工解码。

## 练习

1. 运行确认N=2霍格沃茨！配置在相同的工作时间内产生比N=1基线更多的工作令牌。

2. 减少协调启发式的强度（集合）重新运行。显示加速崩溃。解释一下原因：当工人无法协调时，他们会重复工作。

3. 计算一下预期的霍格沃茨！加速一个50k令牌推理任务对一个k-token聊天任务执行相同的操作为什么一个赢了，另一个输了？

4. 读霍格怀德！论文第4部分（初步评价）。确定作者报告的两种失效模式。描述一个更好的协调提示如何缓解这些问题。

5. 结合Hogwild !在玩具中使用推测解码：每个worker在内部使用一个2令牌规范解码。报告乘法加速。当两个工作线程都想扩展相同的共享缓存前缀时，会出现什么簿记问题？

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Hogwild! | "Parallel workers, shared cache" | N instances of the same LLM running concurrently with one shared KV cache; emergent coordination via self-prompting |
| Shared KV cache | "The coordination medium" | A single growing KV buffer that all workers read and write; enables instant token visibility across workers |
| Emergent coordination | "No training needed" | Reasoning-capable LLMs can read the shared cache and divide work without any fine-tuning or explicit protocol |
| Coordination overhead (c) | "Tokens spent orienting" | The per-worker cost of reading the extended cache and deciding what to do; must stay small vs total decode time |
| Parallelizable fraction (p) | "What can run in parallel" | Task-level parallelism: the fraction of the total work that is not intrinsically sequential |
| RoPE enables Hogwild! | "Rotary positions are shift-invariant" | Because positions are rotations, writing into a shared cache does not require recomputing prior tokens |
| Voting ensemble | "Run N, pick the majority" | The simplest parallel inference topology; useful for classification, less for long-form reasoning |
| Tree of thought | "Branch and prune" | Reasoning strategy that explores multiple branches and prunes; explicit coordination logic |
| Multi-agent framework | "Assign sub-tasks" | Each agent gets a role; a coordinator orchestrates; heavy protocol overhead |
