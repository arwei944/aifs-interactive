# 管理LLM平台- Bedrock， Vertex AI, Azure OpenAI

> 三个超大规模，三个不同的策略。AWS Bedrock是一个模型市场- Claude， Llama, Titan, Stability， coherence在一个API背后。Azure OpenAI是OpenAI的独家合作伙伴关系，加上专用容量的预置吞吐量单元（ptu）。Vertex AI是双子座优先的，具有最佳的长上下文和多模式故事。在2026年，人工分析在Llama 3.1 405B上测量Azure OpenAI的中位数为~50毫秒，Bedrock的中位数为~75毫秒——ptu解释了这一差距，因为专用容量优于按需共享。决策规则不是“哪个最快”，而是“哪个模型目录和FinOps表面与我的产品匹配”。这节课教你如何选择写下来的折衷方案，而不是感觉。

## 学习目标

- 说出三种平台策略（市场vs独家vs双子座优先），并将每种策略与产品用例相匹配。

- 绘制每个平台的FinOps属性图（Bedrock Application Inference Profiles vs Vertex project per team vs Azure scope + PTU reservation）。
- 写下“最少两家供应商”的政策，并解释为什么单一供应商锁定是2026年代价高昂的错误。

## 这个问题

你选了克劳德·十四行诗3.7作为你的产品。现在你需要上菜了。你可以直接调用Anthropic API，或者你可以通过AWS Bedrock调用它，或者你可以通过网关。直接API是最简单的；Bedrock增加了BAAs、VPC端点、IAM和CloudWatch属性。网关增加了故障转移、统一计费和跨提供商的速率限制。

更深层次的问题是目录。如果你需要同一个产品中的Claude、Llama和Gemini，你不能从一个地方购买它们，除非这个地方同时是Bedrock、Vertex和Azure OpenAI。超大规模是不可互换的——它们各自对谁拥有模型层下了不同的赌注。

这堂课描绘了三个赌注：延迟差距、FinOps差距和锁定风险。

## 这个概念

### 三种策略

**AWS Bedrock**——市场。Claude (Anthropic), Llama (Meta), Titan （AWS第一方），Stability（图像），Cohere（嵌入），Mistral，加上图像和嵌入子目录。一个API，一个IAM接口，一个CloudWatch导出。Bedrock的赌注是，客户更想要可选择性，而不是单一模式。

**Azure OpenAI** -独家合作伙伴关系。您可以在Azure数据中心中获得GPT-4 / 40 / 5 / o系列，DALL·E， Whisper和微调OpenAI模型。“Azure OpenAI服务”目录中没有非OpenAI模型-这些模型将进入Azure AI Foundry（单独的产品）。Azure的赌注是OpenAI仍然处于前沿，而客户希望企业控制这种特定的关系。

**顶点AI** -双子座第一，其他一切第二。Gemini 1.5 / 2.0 / 2.5 Flash和Pro，加上Model Garden（第三方）。Vertex的赌注是多模态长上下文——1m代币Gemini上下文是差异化的。

### 大规模延迟差距

人工分析运行连续的基准测试。在同等的Llama 3.1 405B部署（按需共享）上，Azure OpenAI第一个令牌延迟中值约为50毫秒；基岩约75毫秒。这种差距不是AWS的故障，而是容量模型的差异。Azure出售ptu（预置吞吐量单位），它为您的租户保留GPU容量。Bedrock也有类似的服务（provisioning Throughput），但每单位的起价约为每小时21美元，大多数客户都选择按需共享。

按需共享容量与其他客户的流量竞争。专用容量则没有。如果您的产品SLA在P99时TTFT < 100 ms，您可以在Azure上购买ptu，购买Bedrock Provisioned Throughput，或者接受默认的差异。

### 预置吞吐量经济

Azure ptu：一个预留的推理计算块。与可预测的工作负载相比，可节省高达70%的成本。无论交通状况如何，每小时的费用都是固定的——即使在空闲的时候，你也要为预约付费。盈亏平衡通常在持续利用率的40-60%左右。

Bedrock提供的吞吐量：每小时21- 50美元，具体取决于模型和区域。类似的计算——盈亏平衡大约是峰值利用率的一半。需要每月承诺。

Vertex提供的容量按Gemini SKU出售；价格因型号和地区而异，而且很少公开宣传。

### FinOps表面——真正的区别

**Bedrock Application Inference Profiles**是市场上最干净的归属。将配置文件标记为通过它路由所有模型调用；CloudWatch在没有后处理的情况下分解了每个配置文件的成本。再加上2025年，仍然是最颗粒级超大规模的原生产品。

**顶点归属是每个团队的项目加上无处不在的标签。您将每个团队建模为一个GCP项目，在每个资源上放置标签，并使用BigQuery Billing Export + DataStudio进行汇总。更多的工作，但是BigQuery为您提供了关于成本数据的任意SQL。

*Azure**依赖于订阅/资源组范围加上标签，PTU保留作为一级成本对象。标签继承自资源组，而不是请求，因此每个请求归属需要Application Insights自def 指标或标记标头的网关。

模式：Bedrock是最干净的原生资源，Vertex是通过BigQuery最灵活的，Azure是最不透明的，除非你使用仪器。

### 锁定是2026年的风险

当一个模型占主导地位时，单一超大规模的承诺是好的。在2026年，这个前沿每月变动一次——克劳德这个季度3.7，双子座下一个季度2.5，再下一个季度GPT-5。锁在一个平台上，你就被锁在了三分之二的边界之外。

工作团队采用的模式是：对于任何产品关键的LLM调用，至少有两个提供者。Bedrock和Azure OpenAI是一对通用的组合——Claude来自一个，GPT来自另一个，它们之间的故障转移，相同的网关。成本上升可以忽略不计，因为网关路由是最优的；中断期间（如Azure OpenAI 2025年1月事件、AWS us-east-1中断）的可用性提升是决定性的。

### 数据驻留、BAAs和受监管的行业

基岩：大部分地区含BAAs；VPC端点;护栏。常见的金融科技违约。
Azure OpenAI: HIPAA, SOC 2, ISO 27001；欧盟数据居住权；企业监管的违约。
顶点：HIPAA， GDPR，每个地区的数据驻留；谷歌云的遵从性堆栈。

这三个都满足基本复选框。不同之处在于数据保留策略、日志处理方式以及滥用监控是否读取您的流量（大多数情况下默认选择加入；企业可选择退出）。

### 你应该记住的数字

- Azure OpenAI在Llama 3.1 405B上的平均TTFT: ~50 ms（带ptu）。
- 基岩平均TTFT按需：~75毫秒。
- Bedrock提供的吞吐量：每单位21- 50美元/小时。
- Azure PTU盈亏平衡：~40-60%的持续利用率。
- 在高利用率下节省PTU与按需：高达70%。

## 练习

1. 运行对于70B类模型，Azure PTU的持续利用率是多少？计算盈亏平衡，并与广告中的40-60%频段进行比较。
2. 你的产品需要克劳德3.7十四行诗和gpt - 40。设计一个双提供者部署——哪个部署到哪个超大规模服务器，哪个网关位于前端，故障转移策略是什么？
3. 受监管的医疗保健客户需要BAAs、美国东部数据驻留以及低于100ms的P99 TTFT。选择一个平台，用三个特定的功能来证明。
4. 你发现你的Bedrock账单这个月涨了4倍，但流量没有变化。如果没有应用推断配置文件，您将如何找到罪魁祸首？有了侧写，要花多长时间？
5. 阅读Azure OpenAI和Bedrock定价页面。对于每月100万个令牌的Claude工作负载，哪个更便宜-直接Anthropic API， Bedrock按需，还是Bedrock预置吞吐量？

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Bedrock | "AWS LLM service" | Model marketplace across Claude, Llama, Titan, Mistral, Cohere |
| Azure OpenAI | "Azure's ChatGPT" | Exclusive OpenAI models in Azure datacenters with enterprise controls |
| Vertex AI | "Google's LLM" | Gemini-first platform with Model Garden for third-party models |
| PTU | "dedicated capacity" | Provisioned Throughput Unit — reserved inference GPUs, priced per hour |
| Application Inference Profile | "Bedrock tagging" | Per-product cost/usage profile with tags, CloudWatch-native |
| Model Garden | "Vertex catalog" | Vertex AI's third-party model section, separate from Gemini |
| Two-provider minimum | "LLM redundancy" | Policy of running every critical LLM path across ≥2 hyperscalers |
| BAA | "HIPAA paperwork" | Business Associate Agreement; required for PHI; provided by all three |
| Abuse monitoring | "the log watcher" | Provider-side safety scan on prompts/outputs; opt-out in enterprise |
