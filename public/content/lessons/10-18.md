## This question

The next token prediction is the standard LLM training objective. Each hidden state is supervised to accurately predict one thing: the token that follows. This is a surprisingly weak signal. Most of the information in a sequence transcends a single symbol - structure, consistency, fact, arithmetic flow. This model must learn these signals by accumulating many single-token signals on trillions of tokens.

MTP asked: What if each hidden state was supervised to predict multiple future tokens simultaneously? Gloeckle et al. (Meta, 2024) indicated that this is helpful. Their implementation places several independent output heads on the main trunk, and each head predicts a different offset. Parallel, simple, but the brain sees the same hidden state without any level of refinement - and the predictions have no causal chain, so they cannot be used for speculative decoding.

Deepseeking V3 (December 2024) redesigns MTP as sequential modules, maintaining causal chains at each prediction depth. This model predicts that each depth has its own small transformer block. Shared embeddings and shared output headers keep parameter overhead moderate. On the scale of DeepSeek V3, above 671B of the main model weights, there are 14B additional parameters on the MTP module. This 2% expense was spent on purchasing denser training signals and ready-made inference decoding drafts.

### Why is it sequential rather than parallel

Gloeckle's initial parallel MTP had D output heads, each directly applied to each head, indicating that this method was well-trained, but the predictions were not conditional on each other. You can't use it

The sequential design and construction of DeepSeeking -v3 retain the causal chain: prediction is structurally the same as how an autoregressive decoder consumes its own output - making the MTP module directly usable as a speculative decoding drafter.

Inference: Feed duplication. This is the Eagle-style draft, using a trained MTP module as the draft network. The acceptance rate of DeepSeeking -V3 on the first MTP module is over 80%, and the acceleration rate is 1.8 times.

### Guess the rewards of decoding

During the pre-training period, the MTP module reduced the training speed by approximately 10% (more forward computations, additional losses). The rewards for doing so are double:

1. The training signals are denser. Each hidden state sees the D+1 supervised target. The measurement results of MMLU, GSM8K, MATH, and HumanEval: There is an improvement of several percentage points in the ablation of DeepSeek-V3.

2. The draft of free speculation decoding is reasoning. The MTP module has been trained to predict the next few tokens. As a draft network, it offers an acceptance rate of over 80%. At this level, N=3 or N=5 specification decoding provides 1.8 times the throughput. 10% of the training time cost will pay off when you run the inference for the first time.

### The relationship with EAGLE

EAGLE trains a small draft model separately after pre-training. MTP has turned the draft into pre-training. The acceptance rates of these two methods are similar, but through different channels:

| Dimension | EAGLE-3 | MTP (DeepSeek-V3) |
|-----------|---------|------------------|
| When trained | Post-pre-training | During pre-training |
| Backward-compatible with existing weights | Yes | No (need to re-train) |
| Draft params | 1-2 transformer layers | 1 transformer block + projection |
| Acceptance rate | 0.88-0.92 | 0.80+ at depth 1 |
| Benefit beyond speedup | Speculative decoding only | Denser training signal + speedup |

## Use It

MTP is integrated into DeepSeek-V3 (December 2024) and the DeepSeek-R1 series. At inference:

- DeepSeek's own serving stack consumes MTP modules as speculative decoders out of the box.
- vLLM and SGLang have integration paths for DeepSeek-V3 MTP as of April 2026.
- AMD's ROCm SGLang tutorial shows a specific MTP speculative-decoding config with measured 1.8× speedup on the V3 checkpoint.

When to use MTP in a new pre-training run:

- You control the full pre-training pipeline and want to bank denser training signal.
- You know you will serve the model at scale and want speculative decoding for free.
- Your hidden size is at least 4096. At 1B-scale the overhead hurts more than the gain helps.

When not to:

- Fine-tuning an existing pre-trained dense model. The MTP module is not trained.
- Research models where you want a clean baseline to compare against. MTP changes the architecture.

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| MTP module | "Extra loss block" | A small transformer block plus projection that predicts a token `k` positions ahead of the main model |
| Prediction depth | "Which offset" | The integer `k` such that module `k` predicts `t_{i+k}` from prefix through position `i` |
| Parallel MTP | "Gloeckle-style" | D independent heads on the same backbone hidden state, no conditional chain |
| Sequential MTP | "DeepSeek-V3 style" | Each module conditions on the previous depth's hidden state plus the next token's embedding; preserves causal chain |
| Shared output head | "Reuse the main head" | The MTP modules call the main model's LM head, not a separate output projection |
| Shared embedding | "Reuse the main table" | Same vocabulary embedding table is used everywhere; no duplicate parameters |
| Projection matrix M_k | "Combine hidden + next-token" | An `h x 2h` linear layer that folds the previous hidden state and the target-token embedding into the next depth's input |
| Joint loss L_MTP | "Averaged extra losses" | Arithmetic mean of per-depth cross-entropy losses, scaled by `lambda` |
| Acceptance rate at depth 1 | "How often MTP draft is right" | The rate at which the D=1 MTP module's top-1 prediction equals the main model's top-1 prediction; 80%+ on DeepSeek-V3 |
| Lambda weighting | "Extra-loss importance" | Per-depth scaling factor; 0.3 at start of training, 0.1 later on DeepSeek-V3 |
