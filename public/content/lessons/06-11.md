# Real-time audio processing

> Batch processing pipeline processing files. The real-time pipeline processes the next 20 milliseconds before the next 20 milliseconds arrive. The survival of each conversational AI, broadcast studio and phone robot depends on this delay budget.

**Type:** Build
**Languages:** Python, Rust
**Prerequisites:** Phase 6 · 02 (Spectrograms), Phase 6 · 04 (ASR), Phase 6 · 07 (TTS)
**Time:** ~75 minutes

## This question

You want a voice assistant that is full of vitality. The polling delay of human sessions is approximately 230 milliseconds (from silence to response). Anything that lasts more than 500 milliseconds feels like a robot. It feels bad if it's over 1500 milliseconds. The budget for the complete "Listen → Understand → Respond → Speak" cycle in 2026 is:

| Stage | Budget |
|-------|--------|
| Mic → buffer | 20 ms |
| VAD | 10 ms |
| ASR (streaming) | 150 ms |
| LLM (first token) | 100 ms |
| TTS (first chunk) | 100 ms |
| Render → speaker | 20 ms |
| **Total** | **~400 ms** |

The full-duplex clock of Moshi (Kyutai, 2024) is 200 milliseconds. gpt-40 -realtime (2024) clock ~320 milliseconds. The transportation speed of the 2022 grade pipeline is 2,500 milliseconds. The tenfold improvement comes from three technologies: (1) ubiquitous streams, (2) asynchronous pipelines with partial results, and (3) interruptible generation.

## This concept

Z0

*Frame/Block/window. Real-time audio stream fixed-size blocks. Common choice: 20 milliseconds (320 samples at 16 kHz). Everything downstream must keep up with this pace.

*Circular buffer. A fixed-size circular buffer. The producer thread writes a new frame, and the consumer thread reads it. Prevent distribution in the hot path. Size ≈ Maximum delay × sampling rate; A 2-second 16 kHz loop = 32,000 samples.

**VAD (Speech Activity Detection). The door downstream will also work when no one is speaking. Silero VAD 4.0 (2024) runs for less than 1 millisecond per 30-millisecond frame on the CPU. `webrtcvad` is the older alternative.

*"Stream ASR. A model that emits part of the text when the audio arrives. The response rate of the long-tailed parrot ctc-0.6b (NeMo, 2024) in stream mode is 2-5% at a delay of 320 milliseconds. Whisper stream (Macha Cerek et al., 2023) A block of whisper is a near stream with a delay of approximately 2 seconds.

*"Interrupted. When the user is speaking, the assistant is speaking. You must (a) detect intrusions, (b) stop TTS, and (c) discard the remaining LLM output. All must be completed within 100 milliseconds; otherwise, the user will perceive the deaf assistant.

*WebRTC Opus transmission. 20ms frame, 48khz, adaptive bit rate 8-128kbps. Standards for browsers and mobile devices. LiveKit, every day. co and Pion are the 2026 stack for building voice applications.

*"Jitter buffer. Network data packet arrival error/delay. Reorder and smooth the jitter buffer; Too small → audible gap; too large → latency. Typically 60 to 80 milliseconds.

### Common traps

- Thread contention. Python's GIL + heavy model can starve audio threads. Use the c callback audio library (sounddevice, PortAudio) and keep Python away from the hot path.
- Sampling rate conversion delay. Re-sampling within the pipeline increases by 5 to 20 milliseconds. Either re-sample in advance or use a zero-delay re-sampler (PolyPhase)
- TTS starts. Even a fast TTS like Kokoro has a warm-up time of 100 to 200 milliseconds on the first request. Cache model + warm it up with a virtual run before the first real turn.
- Echo elimination. Without AEC, the TTS output re-enters the microphone and triggers the robot's own voice ASR. WebRTC AEC3 is open source by default.

## Pitfalls

- **Buffering 500 ms to be safe.** The buffer *is* your latency floor. Shrink it.
- **Not pinning threads.** Audio callback on a priority-lower-than-UI thread = glitches under load.
- **TTS chunks too small.** Sub-200 ms chunks make vocoder artifacts audible. 320 ms chunks are the sweet spot.
- **No jitter buffer.** Real networks are jittery; without smoothing you get pops.
- **Single-shot error handling.** Audio pipelines must be crash-proof. One exception kills the session.

## Key Terms

| Term | What people say | What it actually means |
|------|-----------------|-----------------------|
| Ring buffer | The circular queue | Fixed-size, lock-free (or SPSC-locked) FIFO for audio frames. |
| VAD | Silence gate | Model or heuristic marking speech vs non-speech. |
| Streaming ASR | Real-time STT | Emits partial text as audio arrives; bounded lookahead. |
| Jitter buffer | Network smoother | Queue reordering out-of-order packets; 60–80 ms typical. |
| AEC | Echo cancellation | Subtracts speaker-to-mic feedback path. |
| Barge-in | User interrupt | System detects user speech mid-TTS; must cancel playback. |
| Full duplex | Simultaneous both ways | User and bot can talk at the same time; Moshi is full duplex. |
