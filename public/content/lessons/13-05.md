# 工具架构设计——命名、描述、参数约束

> 当模型无法判断何时使用正确的工具时，它会无声地失败。在StableToolBench和MCPToolBench++等基准测试中，命名、描述和参数形状会导致工具选择精度出现10到20个百分点的波动。本课命名了设计规则，这些规则将模型可靠地选择的工具与模型失败的工具分开。

## 这个问题

想象一个拥有30个工具的代理。每个用户查询都会触发工具选择：模型读取每个描述并选择一个。失败有两种形式。

**选错了工具。**型号选择原因：两种描述都说“仰视人”。该模型无法消除歧义。

*不择合适的工具。**用户询问股票价格；该模型给出了一个看似合理但令人产生幻觉的数字。原因：描述说“检索财务数据”，但模型没有将“股票价格”映射到该数据。

Composio的2025年实地指南仅通过重命名和重写描述，在内部基准上测量了10到20个百分点的准确性波动。Anthropic的Agent SDK文档也有类似的说法。Databricks的代理模式文档更进一步：在50个描述不明确的工具的注册表中，选择准确率下降到62%；在描述重写之后，相同的注册表达到了89%。

描述和名称质量是你拥有的最便宜的杠杆。

## 这个概念

### 命名规则

1. ****每个提供商的标记器都能干净地处理它。`camelCase` fragments across token boundaries on some tokenizers.
2. * * Verb-noun秩序。**反映自然英语。
3. **没有时态标记。**
4. * *稳定。**重命名是一个突破性的变化。通过添加新名称来版本工具，而不是改变旧名称。
5. **大型注册中心的命名空间前缀。**MCP在服务器名称空间（阶段13.17）中选择了这一点。
6. **名称中没有参数。**

### 描述模式

持续提高选择准确性的两句模式：

```
Use when {condition}. Do not use for {close-but-wrong-cases}.
```

例子:

```
Use when the user asks about current conditions for a specific city.
Do not use for historical weather or multi-day forecasts.
```

“不用于”这一行是用来消除注册表中与竞争对手工具之间的歧义的。

不要超过1024个字符。OpenAI在严格模式下截断较长的描述。

包括格式提示：“接受英文城市名称。返回温度，单位为摄氏度，除非模型使用这些参数来正确填充参数。

### 参数设计

- **枚举每个封闭集。**枚举告诉模型可接受的值的范围。
- **必选vs可选。**标记所需的最小值。其他都是可选的。OpenAI严格模式要求每一个字段加一个
- * *输入id。**
- **没有过度灵活的类型。**避免模型会产生幻觉。
- **描述该领域。**描述是模型提示符的一部分。

### 错误消息作为教学信号

当工具调用失败时，错误消息到达模型。为模型编写错误。

```
BAD  : TypeError: object of type 'NoneType' has no attribute 'lower'
GOOD : Invalid input: 'city' is required. Example: {"city": "Bengaluru"}.
```

好的错误告诉模型下一步该做什么。基准测试显示，在弱模型上，输入错误消息将重试次数减少了一半。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Tool schema | "Input shape" | JSON Schema for the tool's arguments |
| Tool description | "The when-to-use-it paragraph" | The natural-language brief the model reads during selection |
| Atomic tool | "One tool one action" | A tool whose name uniquely identifies its behavior |
| Monolithic tool | "Swiss Army" | Single tool with an `action` string argument; selection accuracy tanks |
| Enum-closed set | "Categorical parameter" | `{type: "string", enum: [...]}` as the correct shape for closed domains |
| Tool poisoning | "Injected description" | Hidden instructions in a tool description that hijack the agent |
| Tool-selection accuracy | "Did it pick right?" | Percentage of queries where the model calls the correct tool |
| Description linter | "CI for schemas" | Automated audit that enforces naming, length, disambiguation rules |
| Namespace prefix | "notes_*" | Shared name prefix that groups related tools in large registries |
| StableToolBench | "Selection benchmark" | Public benchmark for measuring tool-selection accuracy |
