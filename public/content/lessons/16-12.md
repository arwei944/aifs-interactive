# A2A-Agent-to-Agent protocol

> Google announced the A2A in April 2025. In April 2026, the specification published on https://a2a-protocol.org/latest/specification/, there are more than 150 organizations to support it. A2A is a horizontal complement to MCP (Lesson 13) : where MCP is vertical (agent↔ tool), A2A is equivalent (agent↔agent). It defines the Agent card (discovery), tasks with artifacts (text, structured data, video), opaque task lifecycle and authorization. Production systems are increasingly pairing MCP with A2A. Google Cloud will incorporate A2A support into Vertex AI Agent Builder during 2025-2026.

**Type:** Learn + Build
**Languages:** Python (stdlib, `http.server`, `json`)
**Prerequisites:** Phase 16 · 04 (Primitive Model)
**Time:** ~75 minutes

## "Problem"

Your agent needs to call another agent on another system. How about it? You can expose the HTTP endpoint, define a custom JSON schema, and expect the other party to use it. Each pair of agents becomes a custom integration.

A2A is the universal wired protocol for this call. Standard discovery, standard task model, standard transmission, standard artifact. Similar to HTTP+REST, but as a proxy for first-class citizens.

## Concept

### Four key elements

*"Proxy card. JSON documents can be discovered by reading the cards.

```
GET https://agent.example.com/.well-known/agent.json
→ {
    "name": "code-review-agent",
    "skills": ["review-python", "review-typescript"],
    "endpoints": {
      "tasks": "https://agent.example.com/tasks"
    },
    "auth": {"type": "bearer"},
    "modalities": ["text", "structured"]
  }
```

*"Task. "Workplace. An asynchronous, stateful object with a lifecycle: the client sends tasks, votes, or subscribes to updates.

*"Workpiece. The type of result generated by the task. Text, structured JSON, images, videos, audio. Workpieces are typed, so different modes are of one level.

*Opaque life cycle. A2A does not stipulate how remote agents solve tasks. The client sees the state transition and artifacts. The implementation can freely use any framework.

### MCP/A2A split

- **MCP** (Lesson 13) : Agent ↔ Tool. The agent reads/writes to the tool server via JSON-RPC. It is stateless by default.
- "A2A: agent↔agent." Peer-to-peer protocol Both sides are agents and each has their own reasoning.

These two methods are used in the production of multi-agent systems. The A2A peer invokes the MCP tool on its side. This separation kept the two companies clean.

### Discovery stream

```
Client                     Agent server
  ├──GET /.well-known/agent.json──>
  <──Agent Card JSON─────────────
  ├──POST /tasks {skill, input}──>
  <──201 task_id, state=submitted
  ├──GET /tasks/{id}──────────────>
  <──state=working, 42% done──────
  ├──GET /tasks/{id}──────────────>
  <──state=completed, artifacts──
```

Or use streaming media: SSE subscription

### Identity verification

A2A supports three common modes:

- ** Bearer Token ** - OAuth2 or opaque.
- "mTLS - Mutual TLS;" Organizations verify each other's identities.
- ** Signature Request ** - Payload of HMAC.

Authorization is declared in the agent card; The customer discovers and complies.

### By April 2026, there will be over 150 organizations

The adoption by enterprises has driven the A2A scale. Title: A2A Becomes the Way for Enterprise Agent Systems to Cross Trust Boundaries. Google Cloud delivers Vertex AI Agent Builder A2A support; Microsoft Agent Framework support; Most major frameworks (LangGraph, CrewAI, AutoGen) offer A2A adapters.

### A2A wins

- Cross-organizational phone calls. The agent of Company A called the agent of Company b. There is no A2A. Every pair is a custom contract.
- Heterogeneous framework. The LangGraph proxy calls the CrewAI proxy to call the custom Python proxy. Be responsible for standardization.
- A type of workpiece. Video results, structured JSON, audio - all top-notch.
- Long-running tasks. The opaque lifecycle and polling make tasks that last for several hours simple.

### The struggles of A2A

- Latency-sensitive micro-calls. The life cycle of A2A is asynchronous. Sub-millisecond agent-to-agent mismatch; Use direct RPC.
- Tightly coupled in-process agent. If two agents are running in the same Python process, the HTTP round trip of A2A is redundant.
- "Small team. The specification overhead is real; Internal agents may not require formalities.

### A2A vs ACP, ANP, NLIP

Several related norms emerged in 2024-2026:

- **ACP** (IBM/Linux Foundation) - the predecessor of A2A, has a narrower scope.
- **ANP** (Proxy Network Protocol) - Peer-to-peer discovery is heavy, and decentralization is prioritized.
- **NLIP** (Ecma Natural Language Interaction Protocol, standardized in December 2025) - Natural Language Content Type.

As of April 2026, A2A is the most widely adopted peer-to-peer protocol. See arXiv:2505.02279 (Liu et al., "A Survey of Agent Interoperability Protocols") for comparison.

## This ship

Checklist

- Fixed specification version. The A2A is still under development. The proxy card should declare the version of the agreement.
- Create idempotent tasks. Repeated submission (network retry) should generate a task.
- "Workpiece mode." Declare the shape returned by the proxy; Consumers should verify.
- Rate limiting + authorization. A2A is open to the public. Apply standard web security.
- A dead letter from a failed mission. Check the patterns over time to look for recurring fault types.

## Key terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| A2A | "Agent-to-agent" | Peer protocol for agents to call other agents across systems. Google 2025. |
| Agent Card | "The agent's business card" | JSON at `/.well-known/agent.json` describing skills, endpoints, auth. |
| Task | "The unit of work" | Async stateful object with a lifecycle; artifacts produced on completion. |
| Artifact | "The result" | Typed output: text, structured JSON, image, video, audio. First-class media. |
| Opaque lifecycle | "How it's solved is the agent's business" | Client sees state transitions; server is free to choose framework/tools. |
| Discovery | "Finding the agent" | `GET /.well-known/agent.json` returns the card. |
| MCP vs A2A | "Tools vs peers" | MCP: vertical agent ↔ tool. A2A: horizontal agent ↔ agent. |
| ACP / ANP / NLIP | "Sibling protocols" | Adjacent specs; A2A is the most-adopted 2026. |
