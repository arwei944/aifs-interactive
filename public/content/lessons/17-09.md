# 生产量化- AWQ， GPTQ, GGUF K-quants, FP8, MXFP4/NVFP4

> 量化格式不是一种通用的选择——它是硬件、服务引擎和工作负载的功能。GGUF Q4_K_M或Q5_K_M拥有CPU和边缘，通过llama.cpp和Ollama交付。当您需要同一基础上的多lora时，GPTQ会在vLLM中胜出。使用Marlin-AWQ内核的AWQ在7B类模型上提供~741 tok/s，在INT4（2026年数据中心生产的默认值）上提供最好的Pass@1。FP8在霍珀、艾达和布莱克威尔之间保持着中间立场——近乎无损且得到广泛支持。NVFP4和MXFP4 （Blackwell微缩放）是激进的，需要每个区块验证。两个陷阱困扰着团队：校准数据集必须匹配部署域，KV缓存与权重量化是分开的——AWQ的教训“我的模型现在是4gb”忘记了生产批量大小的10- 30gb KV缓存。

**Type:** Learn
**Languages:** Python (stdlib, toy memory and throughput comparison across formats)
**Prerequisites:** Phase 10 · 13 (Quantization foundations), Phase 17 · 04 (vLLM Serving Internals)
**Time:** ~75 minutes

## 学习目标

- 说出六种生产量化格式及其在2026年的最佳点。
- 在给定硬件（CPU vs GPU, Hopper vs Blackwell），引擎（vLLM, TRT-LLM, llama.cpp）和工作负载（常规聊天，推理，多lora）的情况下选择一种格式。
- 计算所选格式所保存的权重内存和KV缓存。
- 说出在域流量上降低量化模型的校准数据集缺陷。

## 这个问题

量化减少了内存和HBM带宽，这正是解码所需要的。FP16 70B型号的重量为140gb。将权重量化为INT4 (AWQ或GPTQ)，模型为35gb -适合一个具有KV缓存空间的H100，这很重要，因为在128个并发序列和2k上下文中，仅KV缓存就有20- 30gb。

但是量化不是免费的。激进的量化会降低质量，特别是在推理繁重的任务上。不同的格式适用于不同的引擎。不同的硬件本身支持不同的精度。2026格式动物园是真实的，你不能复制别人的选择-你必须根据你的堆栈选择。

## 这个概念

### 六种格式

| Format | Bits | Sweet spot | Engines |
|--------|------|-----------|---------|
| GGUF Q4_K_M / Q5_K_M | 4-5 | CPU, edge, laptops | llama.cpp, Ollama |
| GPTQ | 4-8 | Multi-LoRA on vLLM | vLLM, TGI |
| AWQ | 4 | Datacenter GPU production | vLLM (Marlin-AWQ), TGI |
| FP8 | 8 | Hopper/Ada/Blackwell datacenter | vLLM, TRT-LLM, SGLang |
| MXFP4 | 4 | Blackwell multi-user | TRT-LLM |
| NVFP4 | 4 | Blackwell multi-user | TRT-LLM |

### GGUF - CPU/边缘默认值

GGUF是一种文件格式，而不是量化方案本身——它将K-quant变量（Q2_K、Q3_K_M、Q4_K_M、Q5_K_M、Q6_K、Q8_0）捆绑在一个容器中。Q4_K_M和Q5_K_M是生产默认值-接近bf16质量，4-5位。CPU或边缘服务的最佳选择，因为llama.cpp是迄今为止最快的CPU推理引擎。

vLLM中的吞吐量损失：在7B上约93 tok/s -该格式未针对GPU内核进行优化。当部署目标是CPU/边缘时使用GGUF。没有否则。

### GPTQ - vLLM中的多lora

GPTQ是一种训练后量化算法。Marlin内核使其在GPU上速度更快（与非Marlin GPTQ相比加速2.6倍）。7B上~712托克/秒。

独特之处在于：GPTQ-Int4支持vLLM中的LoRA适配器。如果您正在提供一个基本模型加上10-50个微调的变体（每个都作为LoRA），那么GPTQ是您的选择。到2026年初，NVFP4还不支持LoRA。

### AWQ -数据中心GPU默认设置

激活感知权重量化。在量化过程中保护约1%最显著的权重。马林- awq内核：10.9倍的加速。~741 tok/s在7B上，最好Pass@1在INT4格式中。

为新的GPU服务选择AWQ，除非您需要多lora （GPTQ）或激进的Blackwell FP4 （NVFP4）。

### FP8 -可靠的中间

8位浮点数。Near-lossless。广泛支持。Hopper Tensor Cores原生加速FP8。布莱克威尔继承。当质量不可协商（推理、医疗、代码生成）时，FP8是安全的2026默认值。内存节省是INT4的一半，但质量风险要低得多。

### MXFP4 / NVFP4 - Blackwell侵略性

微尺度FP4。每个权重块都有自己的比例因子。在Blackwell张量核上进行硬件加速。与FP8相比，每个令牌的字节减少一半——阶段17.07的经济优势。

警告:
- 目前还不支持LoRA（2026年初）。
- 在推理繁重的工作负载上，质量明显下降。
- 对每个模型的eval集进行验证。

### 校准陷阱

AWQ和GPTQ需要一个校准数据集-通常是C4或WikiText。对于领域模型（代码、医疗、法律），在通用的web文本上进行校准会让算法在保护权重方面做出错误的决定。Pass@1上的HumanEval可以下降几个点。

解决方法：校准域内数据。数百个域样本通常就足够了。发货前对eval集进行测试。

### 千伏高速缓存陷阱

AWQ将权重缩小到4位。KV缓存是独立的，保持在FP16/FP8。对于带有AWQ的70B型号：

- 重量：~ 35gb（从140gb改为INT4）。
- 千伏高速缓存在128并发× 2k上下文：~ 20gb。
- 激活：~ 5gb。
- 总共：~ 60gb -适合H100 80GB。

天真地“我将模型量化为4gb”忘记了其他30- 50gb。全面预算HBM。

另外，KV缓存量化（FP8 KV或INT8 KV）是一种不同的选择，有其自身的权衡——它直接影响注意力准确性，并不是免费的。

### AWQ INT4对推理是有害的

思维链、数学、长上下文的代码生成——这些都明显受到激进量化的影响。AWQ INT4在数学上损失了3-5分。对于推理繁重的工作负载，船FP8或BF16；接受内存成本。

### 2026采摘指南

- CPU/边缘服务器：GGUF Q4_K_M。完成了。
- GPU服务，常规聊天，无LoRA: AWQ。
- GPU服务，多lora: GPTQ与马林。
- 推理工作负载：FP8。
- Blackwell数据中心，验证质量：NVFP4 + FP8 KV。
- 模棱两可：对每个候选格式运行1,000个样本的eval。

## 船这

这一课产生了给定硬件、模型大小、工作负载类型和质量公差，选择一种格式并生成校准/验证计划。

## 练习

1. 运行对于128并发的70B模型和2k上下文，计算每种格式的总HBM。哪种格式可以在一台H100 80GB上使用？
2. 你有一个7B编码模型。选择一个格式并证明。如果你对质量容忍度的看法是错误的，那么补救的途径是什么？
3. 计算校准医学领域模型AWQ所需的校准数据集大小。为什么数据并不总是越多越好？
4. 阅读马林- awq内核论文或发行说明。用三句话解释为什么在7B上AWQ达到741 tok/s，而原始GPTQ达到~712。
5. 什么时候将AWQ权重与FP8 KV缓存结合起来比保持KV在BF16更有意义？

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| GGUF | "llama.cpp format" | File format bundling K-quant variants; CPU/edge default |
| Q4_K_M | "Q4 K M" | 4-bit K-quant medium; the production GGUF default |
| GPTQ | "gee pee tee q" | Post-train INT4 with calibration; supports LoRA in vLLM |
| AWQ | "a w q" | Activation-aware INT4; Marlin kernels; best Pass@1 at INT4 |
| Marlin kernels | "fast INT4 kernels" | Custom CUDA kernels for INT4 on Hopper; 10x speedup |
| FP8 | "eight-bit float" | Safe precision default on Hopper/Ada/Blackwell |
| MXFP4 / NVFP4 | "microscaling four" | Blackwell 4-bit FP with per-block scale factors |
| Calibration dataset | "cal data" | Input text used to pick quantization parameters; must match domain |
| KV cache quantization | "KV INT8" | Separate choice from weights; affects attention accuracy |
