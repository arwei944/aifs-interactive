# Capstone 02 -基于代码库的RAG （Cross-Repo语义搜索）

> 2026年，每个严肃的工程组织都会进行内部代码搜索，以理解含义，而不仅仅是字符串。Sourcegraph Amp， Cursor的代码库答案，Augment的企业图，Aider的reomap， Pinterest的内部MCP -相同的形状。摄取许多仓库，用树-sitter解析，嵌入函数和类级别的块，混合搜索，重新排序，用引用回答。这个顶点要求你构建一个在10个repos中处理200万行代码的代码，并且在每次git推送时都能承受增量重新索引。

**Type:** Capstone
**Languages:** Python (ingestion), TypeScript (API + UI)
**Prerequisites:** Phase 5 (NLP foundations), Phase 7 (transformers), Phase 11 (LLM engineering), Phase 13 (tools), Phase 17 (infrastructure)
**运行阶段：** P5·P7·P11·P13·P17
**Time:** 30 hours

## 问题

到2026年，每个前沿编码代理都会附带一个代码库检索层，因为仅靠上下文窗口无法解决交叉回购问题。Claude的1M-token上下文有帮助；它并没有消除对排序检索的需要。对原始块的朴素余弦搜索会对生成的代码、单点重复和很少导入的符号的长尾产生影响。生产的答案是混合（密集+ BM25）搜索ast感知块，带有重新排序器，由符号引用图支持。

您可以通过索引一个真正的舰队（而不是一个教程库）并测量MRR@10、引用忠实度和增量新鲜度来学习这一点。故障模式是基础结构的：一个100k文件的单线程，一个修改了一半文件的推送，一个需要跨越四个线程才能正确回答的查询。

## 概念

ast感知的摄取管道使用树-sitter解析每个文件，提取函数和类节点，以及节点边界处的块，而不是固定的令牌窗口。每个块有三种表示：密集的嵌入（Voyage-code-3或nomic-embed-code）、稀疏的BM25术语和简短的自然语言摘要。摘要添加了第三种可检索的模式——用户询问“X是如何被授权的”，摘要提到“authz”，即使代码只有

检索是混合的。查询同时触发密集搜索和BM25搜索，合并top-k，并将联合交给交叉编码器重新排序器（coherence重新排序器-3或big -rerank -v2- gma -2b）。重新排序的列表进入一个长上下文合成器（带有提示缓存的Claude Sonnet 4.7，或自托管的Llama 3.3 70B），并指示按文件和行范围引用每个声明。没有引用的答案将被后过滤器拒绝。

增加新鲜度是基础设施问题。Git push会触发diff：哪些文件改变了，哪些符号改变了。只有受影响的块才会重新嵌入。受影响的跨文件符号边缘（导入、方法调用）被重新计算。索引保持一致，不需要每次提交重新处理2M行。

## 体系结构

```
git push --> webhook --> ingest worker (LlamaIndex Workflow)
                           |
                           v
             tree-sitter parse + AST chunk
                           |
            +--------------+----------------+
            v              v                v
          dense        BM25 index       summary (LLM)
        (Voyage / bge)  (Tantivy)        (Haiku 4.5)
            |              |                |
            +------> Qdrant / pgvector <----+
                            |
                            v
                      symbol graph (Neo4j / kuzu)
                            |
  query --> LangGraph agent (retrieve -> rerank -> synth)
                            |
                            v
                 Claude Sonnet 4.7 1M context
                            |
                            v
                 answer + file:line citations
```

## 堆栈

- 解析：17种语言语法（Python， TS, Rust, Go, Java， c++等）的树保姆。
- 密集嵌入：Voyage-code-3（托管）或nomic-embed-code-v1.5（自托管），big -code-v1回退
- 稀疏索引：带有BM25F的简略索引（Rust），符号名称与主体的字段加权
- Vector DB: Qdrant 1.12与混合搜索，或pgvector + pgvectorscale用于50M矢量以下的团队
- 块汇总模型：Claude Haiku 4.5或Gemini 2.5 Flash，即时缓存
- 重新排名：连贯重新排名-3或大重新排名-v2- gma -2b自托管
- 编排：LlamaIndex工作流用于摄取，LangGraph用于查询代理
- 合成器：带有提示缓存的Claude Sonnet 4.7 （1M上下文）
- 符号图：用于导入和调用边缘的Neo4j（托管）或kuzu（嵌入）
- 可观察性：每个检索+合成步骤的Langfuse跨度

## 构建它

1. * *摄入沃克。**在每个push钩子上迭代git历史记录。收集更改的文件。对于每个文件，使用tree-sitter进行解析，提取函数和类节点及其完整的源跨度。发出块记录

2. * *块史书。**批处理块到Haiku 4.5调用，并在系统序言上进行提示缓存。提示：“用一句话概括这个功能，说出它的公共契约和副作用。”将摘要与数据块一起存储。

3. * *嵌入池。**两个并行队列：dense （Voyage-code-3 batch 128）和summary（相同的模型，但在summary字符串上）。将矢量写入带负载的Qdrant

4. * * BM25指数。**字段加权坦提维指数：符号名称权重4，符号主体权重1，摘要权重2。启用“查找名为X的函数”查询和“查找执行X的函数”查询。

5. * *符号图。**对于每个块，记录边缘：导入（这个文件使用符号Y从repo Z），调用（这个函数在类C上调用方法M），继承。储存在kuzu。在查询时用于跨回购边界扩展检索。

6. * *查询代理。**三个节点的LangGraph。`retrieve` fires dense + BM25 in parallel, deduplicates by (repo, path, symbol). `rerank` runs the cross-encoder on top-50 and keeps top-10. `synth` calls Claude Sonnet 4.7 with the reranked chunks in context, caches the system prompt, requires file:line citations.

7. * *引用执行。**解析模型输出；任何没有向用户返回仅引用的答案。

8. * *增量索引。**在每个webhook上，计算符号级别的差异。只重新嵌入文本改变的块。重新计算导入更改的块的符号边缘。度量：对于2M-LOC的船队，在60秒内重新索引50个文件的推送。

9. * * Eval。**用金文件标记100个交叉回购问题：行答案。测量MRR@10、nDCG@10、引文忠实度（具有可验证锚点的声明的比例）和p50/p99延迟。

## 船这

可交付技能给定一个回购语料库，它会启动摄取管道、混合索引和查询代理，并为任何交叉回购问题返回引用的答案。标题:

| Weight | Criterion | How it is measured |
|:-:|---|---|
| 25 | Retrieval quality | MRR@10 and nDCG@10 on a 100-question held-out set |
| 20 | Citation faithfulness | Fraction of answer claims with verifiable file:line anchors |
| 20 | Latency and scale | p95 query latency at 10k QPS on the indexed corpus size |
| 20 | Incremental indexing correctness | Time from git push to searchable on a 50-file commit |
| 15 | UX and answer formatting | Citation clickability, snippet previews, follow-up affordance |
| **100** | | |

## 练习

1. 将Voyage-code-3替换为nomic-embed-code自托管。测量MRR@10。报告启用重新排序后差距是否缩小。

2. 将20%生成的代码（llm生成的样板）注入语料库并重新评估。观察恢复中毒。在有效载荷中添加“生成”标志，并降低这些命中的重量。

3. 基准Qdrant混合搜索vs pgvector + pgvectorscale在您的语料库大小。报告批大小为1的p99。

4. 添加基于抽样的漂移检查：每周重新运行100个问题的计算。警告MRR@10下降> 5%。

5. 扩展到跨语言符号解析：一个通过gRPC调用Go服务的Python函数。使用符号图形将它们连接起来。

## 关键术语

| Term | What people say | What it actually means |
|------|-----------------|------------------------|
| AST-aware chunking | "Function-level splits" | Cutting code at tree-sitter node boundaries instead of fixed token windows |
| Hybrid search | "Dense + sparse" | Run BM25 and vector search in parallel, merge top-k, rerank |
| Cross-encoder rerank | "Second-stage rank" | Model that scores each (query, candidate) pair together, more accurate than cosine |
| Prompt caching | "Cached system prompt" | 2026 Claude / OpenAI feature that discounts repeat prefix tokens up to 90% |
| Symbol graph | "Code graph" | Edges for imports, calls, inheritance across files and repos |
| Citation faithfulness | "Grounded answer rate" | Fraction of claims a user can verify by clicking the anchor and reading the referenced span |
| Incremental re-index | "Push-to-search time" | Wall-clock from git push to the changed symbols being queryable |
