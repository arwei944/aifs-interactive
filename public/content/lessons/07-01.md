# Why is it Transformers - the rnn problem

> rnn processes one token at a time. Transformers process all tokens at once. After 2017, this architectural bet changed every expansion curve of deep learning.

**Type:** Learn
**Languages:** Python
**Prerequisites:** Phase 3 (Deep Learning Core), Phase 5 · 09 (Sequence-to-Sequence), Phase 5 · 10 (Attention Mechanism)
**Time:** ~45 minutes

## This question

Before 2017, every most advanced sequence model on Earth - language, translation, speech - was a recurrent neural network. lstm and gru have achieved translation benchmarks comparable to imagenet over the past five years. They are the only tools for everyone.

They have three fatal weaknesses. Sequential computation means that you cannot parallelize 1024 token sequences along the timeline, which means that 1024 serial steps on the GPU can perform 1,000,000 floating-point operations per cycle. On the hardware designed in parallel, the training time of the wall clock is linearly proportional to the sequence length.

The vanishing gradient means that the information after 50 symbols has undergone 50 nonlinear compressions. The gated circulation unit (LSTM, GRU) softens the crush but never eliminates it. Long-term dependence - "The book I read on the plane to Kyoto last summer..." -- It usually fails.

A fixed-width hidden state means that the encoder compresses the entire source sequence into a single vector before the decoder sees anything. It doesn't matter whether the source is 5 tokens or 500 tokens. The shape of the bottleneck is the same.

The 2017 paper "Attention Is All You Need" put forward some radical suggestions: Give up relapse completely. Make each position parallel to the others. Train a large matrix multiplication instead of 1024 consecutive matrix multiplications.

By 2026, its results will dominate all models. Language (GPT-5, Claude 4, Llama 4), vision (ViT, DINOv2, SAM 3), audio (Whisper), biology (AlphaFold 3), Robotics (RT-2). The same block, but different inputs.

## This concept


*The recurrence as a bottleneck. Each step of RNN calculation depends on the previous one. You wouldn't calculate on a modern gpu with over 10,000 parallel cores, which wastes 99% of silicon on long sequences.

*Attention is a kind of broadcast. Self-focus computes the entire N×N attention matrix and fills it into a batch processing matrix. No step depends on another. The gpu likes it.

*Acceleration is not a constant. This is the difference between the two. In practice, on the matching hardware with N=512, the transformer's training speed per epoch is 5 to 10 times faster, and the gap expands with the sequence length until it reaches

*The cost of the transformer. Note that the memory scale is fine for 2K. For the 128K context, you need sliding Windows, RoPE extrapolation, Flash attention tiling, or linear attention variants. Recurrence is when a transformer trades time for memory and then wins back time through parallelism.

*Inductive bias shift. rnn assumes locality and immediacy. Transformers assume nothing - every pair is an object worth paying attention to. This is why transformers need more data for training, but once there is data, they can be further expanded. Chinchilla (2022) formalized this: given a sufficient number of tokens, the transformer always beats the RNN with the same parameter count.

## Build it

There is no neural network here - we use digital simulation of the core bottleneck so that you can feel the gap on your laptop.

### Step 1: Measure the serial depth

See how we build two functions. One approach is to encode the sequence as a series of additions (serial, like RNN). One way is to encode it as parallel reduction (broadcasting, just like attention). The same mathematics, but different dependency graphs.

We time both on sequences up to 100,000 elements. The RNN version is O(N) and a single CPU pipeline. Even in pure Python, the attention-style reduction beats it at length ≥ 1,000 because Python's `sum()` is implemented in C and iterates without interpreter overhead per step.

### Step 2: count theoretical operations

Both algorithms do N adds. The difference is *dependency depth*: how many operations must happen sequentially before the next can start. RNN depth = N. Attention depth = log(N) with a tree reduction, or 1 with a parallel scan. Depth, not op count, decides GPU time.

### Step 3: empirical scaling on long sequences

We print a timing table that makes the O(N) gap visible. On a 2026 Mac laptop, sequences under 1,000 elements are too fast to measure. Sequences of 100,000 show a clean linear scan. Scale that to a 16,384-token transformer with a 12-layer LSTM equivalent and you see why training wall-clock was a blocker in 2016.

## Use It

When to still pick an RNN in 2026:

| Situation | Pick |
|-----------|------|
| Streaming inference, one token at a time, constant memory | RNN or state-space model (Mamba, RWKV) |
| Very long sequences (>1M tokens) where attention memory explodes | Linear attention, Mamba 2, Hyena |
| Edge device with no matmul accelerator | Depthwise-separable RNN still wins on FLOPs/watt |
| Anything else (training, batched inference, context up to 128K) | Transformer |

State-space models (SSMs) like Mamba are essentially RNNs with structured parameterization that gives them the best of both: `O(N)` scan memory, parallel training via selective scan. They recover 90% of transformer quality with better long-context scaling. In 2026 most frontier labs train hybrid SSM+transformer models (e.g. Jamba, Samba) — recurrence is not dead, it is a component.

## Key Terms

| Term | What people say | What it actually means |
|------|-----------------|-----------------------|
| Recurrence | "RNNs are sequential" | Computation where step `t` depends on step `t-1`, forcing serial execution along the time axis. |
| Serial depth | "How deep the graph is" | Longest chain of dependent ops; bounds wall-clock even on infinite hardware. |
| Attention | "Let tokens look at each other" | Weighted sum `sum_j a_ij v_j` where `a_ij` comes from a similarity score between positions i and j. |
| Context window | "How much the model sees" | Number of positions an attention layer can take as input; quadratic memory cost scales here. |
| Inductive bias | "Assumptions baked into the architecture" | Prior about what the data looks like; CNNs assume translation invariance, RNNs assume recency. |
| State-space model | "RNN with algebra behind it" | Recurrence parameterized for parallel training via structured state-space matrices. |
| Quadratic bottleneck | "Why context costs so much" | Attention memory = `O(N²)` in sequence length; Flash Attention hides the constants, not the scaling. |
