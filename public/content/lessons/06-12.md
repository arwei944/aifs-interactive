## This question

Build an end-to-end assistant

1. Capture microphone input (16 kHz mono).
2. Detect the start/end of the user's voice.
3. Transcriptional flow.
4. Pass the text to an LLM that can invoke tools (timers, weather, calendars).
5. Stream LLM text to TTS.
6. Play the audio to the user.
7. If the user is interrupted during the response process, stop.

Latency target: The first TTS audio byte within 800 milliseconds after the user completes their speech on the laptop CPU. Quality objectives: No missing words, no illusory subtitles, no voice clone leakage, no prompt for successful injection.

## This concept

Z0

### Seven components

1. Audio capture. Mic→16 kHz mono →20 ms block. Usually
2. "VAD (Lesson 11). ** Silero VAD@ threshold 0.5, minimum voice 250 milliseconds, silent overhang more than 500 milliseconds. Indicates "beginning" and "end".
3. Streaming STT (Lessons 4-5). Whisper Stream, Long-Tailed Parrot tdt, or Deepgram Nova 3 (API). Partial + final transcript.
4. LLM and Tool Invocation. gpt-40 / Claude 3.5 / Gemini 2.5 Flash. The JSON mode of the tool. The token of the flow.
5. Streaming TTS (Lesson 7) Kokoro-82M (fastest opening) or Cartesia Sonic (commercial). Launch TTS after 20 LLM tokens.
6. "Replay. "Speech;" opus encoding for low-bandwidth networks.
7. Interrupt handler. If VAD is triggered while playing TTS, please stop playing, cancel LLM and restart STT.

### The three failure modes you will encounter

1. The first word. The VAD startup rhythm is too late. The user's "hey" is missing. The starting threshold is 0.3, not 0.5.
2. The intermediate response interruption is chaotic. After the user interrupts, the LLM continues to generate. The assistant is talking to the user. Connect VAD→ Cancel - llm.
3. Silent illusion. Output "Thank you for watching" on the silent warm-up frame. Always VAD-gate.

### Step 2: VAD-gated turn capture

```python
def capture_turn(stream, vad, pre_roll_ms=300, silence_ms=500):
    buf, pre, triggered = [], collections.deque(maxlen=pre_roll_ms // 20), False
    silent = 0
    for chunk in stream:
        pre.append(chunk)
        if vad(chunk):
            if not triggered:
                buf = list(pre)
                triggered = True
            buf.append(chunk)
            silent = 0
        elif triggered:
            silent += 20
            buf.append(chunk)
            if silent >= silence_ms:
                return b"".join(buf)
```

## Pitfalls

- **Logging PII forever.** Full-turn audio is PII in most jurisdictions. 30-day retention, encrypted at rest.
- **No barge-in.** Users will interrupt. Your assistant must stop talking.
- **TTS that blocks.** Synchronous TTS blocks the event loop. Use async or a separate thread.
- **No tool-call error handling.** Tools fail. LLM must get back the error + retry once, then gracefully degrade.
- **Overzealous hallucination filters.** Over-filter and the assistant repeats "I can't help with that." Under-filter and it says anything. Calibrate on a held-out set.
- **No wake-word option.** Always-listening is a privacy liability. Add a wake-word gate (Porcupine or openWakeWord).

## Key Terms

| Term | What people say | What it actually means |
|------|-----------------|-----------------------|
| Turn | A user + assistant round-trip | One VAD-bounded user speech + one LLM-TTS response. |
| Barge-in | Interruption | User speaks while assistant talks; assistant stops. |
| Wake word | "Hey assistant" | Short keyword detector; Porcupine, Snowboy, openWakeWord. |
| End-pointing | Turn ending | VAD + min-silence decision that user has finished. |
| Pre-roll | Pre-speech buffer | Keep 200-400 ms of audio before VAD fires to avoid first-word clip. |
| Tool call | Function invocation | LLM emits JSON; runtime dispatches; result feeds back in-loop. |
