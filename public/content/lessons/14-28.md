# 编排模式：主管、群、分层

> 四种编排模式在2026个框架中反复出现：监督-工人、群/点对点、分层、辩论。Anthropic的指导：“这是关于为你的需求建立正确的系统。”开始简单;只有当单个代理加上五个工作流模式不够用时才添加拓扑。

**Type:** Learn + Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 · 12 (Workflow Patterns), Phase 14 · 25 (Multi-Agent Debate)
**Time:** ~60 minutes

## 学习目标

- 命名四种重复出现的业务流程模式，以及每种模式适合的时间。
- 描述2026年的LangChain建议：基于工具调用的监督vs监督库。
- 解释Anthropic的“构建正确的系统”规则，以及它如何限制拓扑选择。
- 在标准库中针对一个通用的脚本化LLM实现所有四个。

## 这个问题

团队在需要之前就开始使用“多代理”。四种模式在框架中反复出现；一旦您可以命名它们，您就可以选择正确的拓扑—或者完全跳过拓扑。

## 这个概念

### Supervisor-worker

- LLM发送给专业代理的中央路由。
- 决定：循环回自己，交给专家，终止。
- 专家们互不交谈；所有的路由都要经过主管。

框架：LangGraph

**2026 LangChain建议：**通过直接调用工具进行监管，而不是提供更精细的上下文工程控制-您可以准确地决定每个专家看到的内容。

### 群/点对点

- 代理通过共享的工具界面直接交接。
- 没有中央路由器。
- 延迟比上级低（跳数少）。
- 更难推理（没有单点控制）。

框架：LangGraph群拓扑，OpenAI Agents SDK移交（当所有代理都可以移交给所有其他代理时）。

### 分层

- 主管管理下属主管管理员工。
- 在LangGraph中实现为嵌套子图；在CrewAI筑巢的船员。
- 以操作复杂性为代价扩展到大型代理种群。

当你需要它时：当单个主管的上下文预算无法容纳所有专家的描述时。

### 辩论

- 平行提议者+迭代交叉批评（第25课）。
- 不是真正的编排——更多的是验证——而是在框架中作为拓扑选择出现。

### 船员vs心流

CrewAI正式def 了两种部署模式：

- **流**用于确定性事件驱动的自动化（推荐用于生产的起点）。
- **Crew**用于自主的基于角色的协作。

这与上述四种模式是正交的，但映射到拓扑结构：流通常是主管或分层的；Crew通常是拥有LLM路由器的主管。

### 人为的指导

“LLM领域的成功并不在于构建最复杂的系统。而是要根据你的需求建立合适的系统。”

决定顺序:

1. 单个代理+工作流模式（第12课）-从这里开始。
2. 主管-工人——当你有2-4个专家时。
3. 蜂群——当延迟比推理清晰更重要的时候。
4. 分级-仅当主管上下文预算失败时。
5. 辩论——当准确性比成本更重要的时候。

### 这种模式哪里出错了

- ** Topology-first思考。**在确定多智能体解决什么问题之前，“我们需要多智能体”。
- **跳跃的交接在蜂群。** A -> B -> A -> B.使用跳数计数器。
- **假的层次结构。**三层因为“企业”；两个真正的团队。崩溃。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Supervisor-worker | "Router + specialists" | Central LLM dispatches to specialists; they don't talk to each other |
| Swarm | "Peer-to-peer" | Direct handoffs via shared tools; no central router |
| Hierarchical | "Supervisors of supervisors" | Nested subgraphs for large populations |
| Debate | "Proposer + critique" | Parallel proposers, cross-critique (Lesson 25) |
| Tool-call-based supervision | "Supervisor without a library" | Implement supervisor as direct tool calls for context control |
| Crew | "Autonomous team" | CrewAI's role-based collaboration mode |
| Flow | "Deterministic workflow" | CrewAI's event-driven production mode |
