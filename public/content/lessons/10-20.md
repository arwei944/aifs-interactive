## 这个问题

DeepSeek-V3是第一个前沿开放模型，其架构与Llama系列有很大不同。羊驼3405b是“GPT-2与六个旋钮转动。”DeepSeek-V3是GPT-2，所有六个旋钮加上四个。阅读Llama 3配置是阅读DeepSeek配置的热身，但是深层结构——注意力块的形状、路由逻辑、训练时间目标——是非常不同的，因此您需要单独的演练。

学习它的回报：DeepSeek-V3的开放权重释放改变了开放模型中“前沿能力”的含义。这个架构是许多2026年训练项目正在复制的蓝图。理解它对于任何涉及前沿法学硕士培训或推理的角色都是至关重要的。

## 这个概念

### 不变核心

DeepSeek-V3仍然是自回归的。它仍然会堆叠解码器块。每个块仍然有注意力加上MLP加上两个rms规范。它仍然在MLP中使用SwiGLU。它仍然使用RoPE。Pre-norm。Weight-tied嵌入。和羊驼和西北风的基线一样。

### 改变：用MLA代替GQA

从第10.14阶段你知道GQA通过在Q个头的组中共享K和V来缩小KV缓存。多头潜在注意（MLA）更进一步：K和V被压缩成一个共享的低秩潜在表征（MLA）KV缓存只存储潜在的——通常每层每个令牌512个浮点数，而不是8 × 128 = 1024个浮点数。

在128k环境下，DeepSeek-V3与MLA（一个共享潜势）

```
kv_cache = num_layers * kv_lora_rank * max_seq_len * bytes_per_element
         = 61 * 512 * 131072 * 2
         = 7.6 GB
```

假设的GQA基线（羊驼3 70B形状，8 KV头部，头部亮度128）将支付：

```
kv_cache = 2 * 61 * 8 * 128 * 131072 * 2
         = 30.5 GB
```

MLA比lama-3- 70b风格的GQA缓存在128k上下文下小4倍。

权衡：MLA增加了每个注意力计算（每个头）的解压步骤。与节省的带宽相比，额外的计算是很小的。长上下文推理的净胜利。

### 路由：辅助-无丢失负载均衡

MoE路由器决定哪k个顶级专家处理每个令牌。一个幼稚的路由器把太多的工作集中在少数专家身上，而让其他人闲着。标准修正：增加一个辅助损耗项，惩罚负载不平衡。这是有效的，但会略微降低主要任务的性能。

DeepSeek-V3引入了一种辅助无损耗方案。每个专家的偏差项被添加到路由器logits中，在训练期间通过一个简单的规则进行调整：如果专家如果负载不足，就增加它。无额外损失条款。训练保持干净。专家负载保持平衡。

对主要损失的影响：不可测量。对MoE架构的影响：更干净，没有辅助损耗超参数可调。

### MTP：密集训练+免费选秀

从第10·18阶段你知道DeepSeek-V3增加了D=1 MTP模块，可以预测前面两个位置的令牌。在推理时，训练模块被重新用作具有80%以上接受度的推测解码草案。在训练时，每个隐藏状态在D+1 = 2个目标上进行监督，从而提供更密集的信号。

参数：14B上671B主。开销:2.1%。

### 培训：DualPipe

从阶段10.19开始，你知道DualPipe是一个双向管道，它将向前和向后的块与跨节点的所有对所有通信重叠。在DeepSeek-V3的2,048-H800规模下，它恢复了大约245k gpu小时，而1F1B可能会因为管道气泡而损失。

### 参数的会计

完整的计算在标题:

- 嵌入：
- 前3个密集块：注意与MLA（每块~144M） +密集MLP（每块~260M） +规范。总共约12亿。
- 58个MoE块：关注MLA (~144M) + 256个专家（每个30M） + 1个共享专家(30M) + norm。合计~7.95B /块，包括所有专家。58个MoE区块共461B。
- MTP模块：14B。

总的来说：核心架构的476B + MTP的14B +显然，公布的671B数字包含了额外的结构参数（偏置张量、专家特定组件、共享专家缩放等）。我们在计算器中复制的数字在公布的3-5%以内——增量来自DeepSeek报告文档的细粒度会计，在其附录的第2节中。

每转发活动参数：

- 注意：每层144M * 61 = 8.8B（所有层火）。
- MLP活动：前3层密集（3 * 260M = 780M）， 58个MoE层每层活动，8路由+ 1共享+路由开销。每层有效MLP: ~260M。合计：3 * 260M + 58 * 260M = ~15.9B。
- 嵌入+规范：1.2B。
- 总活跃：大约26B核心+ 14B MTP（训练但不总是在推理时运行）≈37B。

### 671B / 37B比率

18倍稀疏比（活动参数占总数的5.5%）。DeepSeek-V3是已经交付开放权重的最稀疏的前沿MoE模型。比例为13/47（28%）的混合色8x7B密度更大。羊驼4号小牛的比率是17B/400B（4.25%）。DeepSeek的赌注是：在前沿规模上，更多的专家，更低的激活率，每次激活- flop的质量就会更好。

### 接下来，R1, V4

DeepSeek-R1（2025）是在V3主干上运行的推理训练。R1使用相同的架构。改变的是训练后配方（可验证任务上的大规模强化学习），而不是训练前架构。

DeepSeek- v4（如果发布的话）预计将保留MLA + MoE + MTP，并添加DSA (DeepSeek Sparse Attention)，这是第10.17阶段NSA的继任者。谱系是稳定的：架构级创新不断积累；每个版本都有额外的旋钮。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| MLA | "Multi-Head Latent Attention" | Compress K and V into a shared low-rank latent (kv_lora_rank, typically 512), decompress per head on-the-fly; KV cache stores only the latent |
| kv_lora_rank | "MLA compression dim" | The size of the shared latent for K and V; DeepSeek-V3 uses 512 |
| First k dense layers | "Early layers stay dense" | The first few MoE-model layers skip the MoE router and run a dense MLP for stability |
| num_experts_per_tok | "Top-k routing" | How many routed experts fire per token; DeepSeek-V3 uses 8 |
| Shared experts | "Always-on experts" | Experts that process every token regardless of routing; DeepSeek-V3 uses 1 |
| Auxiliary-loss-free routing | "Bias-adjusted load balance" | Per-expert bias terms adjusted during training to keep expert load balanced without adding a loss term |
| MTP module | "Extra prediction head" | Transformer block predicting t+2 from h^(1) and E(t+1); denser training, free speculative-decoding draft |
| DualPipe | "Bidirectional pipeline" | Training schedule that overlaps forward/backward compute with cross-node all-to-all |
| Active parameter ratio | "Sparsity" | active_params / total_params; DeepSeek-V3 hits 5.5% |
| FP8 training | "8-bit training" | Training storage and many compute ops in FP8; roughly halves memory vs BF16 at a small quality cost |
