# Role specialization - planner, critic, executor, validator

> The most common multi-agent decomposition in 2026: one agent plans, one agent executes, and one agent criticizes or validates. MetaGPT (arXiv:2308.00352) formalizes it as sopChatDev encoded as role prompts (product manager, architect, project manager, engineer, QA engineer) (arXiv:2307.07924) Connect designers, programmers, reviewers, and testers through a "chat chain" with "communication illusions" (the agent explicitly requests missing details). Validators are load-bearing: Cemri et al. (MAST, arXiv:2503.13657) demonstrated that each multi-agent failure can be traced back to a missing or damaged validator. PWC reported a 7-fold precision gain (from 10% to 70%) in the structured validation cycle of CrewAI.

## "Problem"

General multi-agent systems generate general outputs. Three programmers wrote three mediocre codes of the same style in a group chat. You can add more agents and more rounds, but still not exceed the quality threshold.

The solution is not to increase the potion, but to use "different" potions. Assign different roles. Give critics and planners tools they don't have. Provide the verifier with an objective test suite. Now there are differences within the system regarding ground correction, not just parallel guesses.

## Concept

### Four typical roles

*"Plan. Read the target and generate a list of steps or specifications. Tools: Knowledge retrieval, documentation. Output: Structured plan.

*"Executor. Read one planned step at a time to generate the workpiece. Tools: Practical working tools (code compiler, shell, API client). Output: Workpiece.

*"Critic. The output of the reader is contrary to the intention of the planner. Tool: Read-only access to workpieces, static analysis. Output: accept/reject and provide the reason.

*"Verification. Read the workpiece and run deterministic checks. Tools: Test runner, Type Checker, pattern validator. Output: pass/fail with evidence.

Critics are subjective, opinionated and usually hold a master's degree in law. Validators are objective and deterministic, and are usually code-based. They are not the same character.

### The communication illusion of ChatDev

ChatDev has added a crucial step: when the executor needs specific details that are not in the plan, it will explicitly ask the designer before proceeding. This avoids the typical failure of a master of Laws, which is to fabricate details ambiguously.

Implementation: The role prompt includes "When you need specific information that is not provided, please ask the relevant role by name before generating the output."

### Why is the validator the most important

Cemri et al. (MAST) tracked 1,642 multi-agent execution failures. 21.3% is a verification vulnerability - the system sent an answer that no one had checked. The remaining 79% can usually be traced back to "a check failed silently or never ran". Verification plays a crucial role.

PWC Report (CrewAI Deployment, 2025) : Adding a structured verification cycle has increased accuracy from 10% to 70%. Get 7 times the benefit from one character.

### Critics and verifiers

- The critic is a master of laws who is responsible for reviewing the quality of the workpieces. Subjective. One might be fooled by seemingly reasonable prose.
- The validator is a deterministic program running on the workpiece. Objective. Provide evidence of pass/fail.

Use simultaneously. The critic seized upon the problem that the witness was unable to express. The validator catches errors that critics cannot see because they only occur at runtime.

### The anti-pattern

Every character in the system is an LLM, and the output of each character is "looks good to me". A typical MAST failure mode. Add at least one validator whose pass/fail is determined by the code, not by the LLM.

## This ship

Checklist

- At least one deterministic validator. Not all are master of Laws.
- The explicit I/O mode for each character. The planner returns a specification instead of a prose. The execution program reads this mode.
- "Communicative dehallucination. When information is lost, the executor must consult the planner. Never invent it.
- Critics/verifiers order. First, run the critic (cheap, catching design issues), and then run the validator (slow, catching bugs).
- "Circular budgeting. Before upgrading to human, a maximum of two key executor revision rounds are required.

## Practice

1. Run and add a static analysis check (the number of occurrences of the count). What does it capture that the runtime test missed?
2. Add a fifth role: "Requirements Analyst", to transform users' wishes into planned and ready specifications. Which requests for communication disillusionment should be submitted to it?
3. Read Section 3 of MetaGPT (" Proxy "). List the input/output modes of the five characters in MetaGPT.
4. Read the chat chain diagram of ChatDev (arXiv:2307.07924 Figure 3). Identify where the communicative illusion breaks a cycle; otherwise, it would be infinite.
5. PWC's 7-fold increase in accuracy comes from the verification cycle. Suppose there are three tasks in which adding a validator is of no help - in these tasks, deterministic checks for correctness are either impossible or costly.

## Key terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Role specialization | "Different agents, different jobs" | Distinct system prompts tuned for planner/executor/critic/verifier roles. |
| SOP pattern | "Encoded standard operating procedure" | MetaGPT's framing: strict I/O schemas per role turn a team into a pipeline. |
| Communicative dehallucination | "Ask before inventing" | ChatDev pattern: executor asks planner when a detail is missing rather than making one up. |
| Critic | "LLM reviewer" | Subjective, opinionated reviewer. Catches taste issues. Can be fooled by plausible prose. |
| Verifier | "Deterministic check" | Code-based pass/fail. Test runner, type checker, schema validator. Cannot be fooled. |
| Verification gap | "No one checked" | 21.3% of MAST failures. Answer shipped without a check that would have caught the bug. |
| Revision loop | "Critic sends it back" | Critic rejection triggers executor re-run with feedback. Needs a budget. |
| All-LLM anti-pattern | "Looks good to me" | Every role is an LLM, no deterministic check. Classic MAST failure. |
