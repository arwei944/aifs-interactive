# 星型，v型，安静型-自学推理

> 最小的自我完善循环存在于理论基础之中。一个模型会产生一连串的想法，保留那些得到正确答案的想法，并对这些想法进行微调。这是STaR。V-STaR增加了一个验证器，因此可以更好地选择推断时间。Quiet-STaR将基本原理推到了每个代币上。这三种方法都有效。它们都不是魔法——循环保留了任何碰巧达到正确答案的捷径。

**Type:** Learn
**Languages:** Python (stdlib, bootstrap-loop simulator)
**Prerequisites:** Phase 13 · 01-03 (Reasoning and CoT), Phase 15 · 01 (long-horizon framing)
**Time:** ~60 minutes

## 这个问题

教模型推理的最直接的方法是收集人类书写的推理痕迹。这是昂贵的，缓慢的，并且受限于人们愿意写多少高质量的思想链。

STaR （Self-Taught Reasoner, Zelikman et al., 2022）问：如果模型写出自己的基本原理，并根据已知答案对其进行评分，会怎么样？循环是：

1. 抽样推理轨迹加答案。
2. 如果最后的答案是正确的，就留下痕迹。
3. 对保留的痕迹进行微调。
4. 重复。

它的工作原理。GSM8K和CommonsenseQA在没有新的人工注释的情况下都得到了改进。但这个循环有一个固有的偏见：任何产生正确答案的理论基础都会被保留下来，而不管推理本身是否合理。V-STaR （Hosseini et al., 2024）用学习验证器修补了这个问题；Quiet-STaR （Zelikman et al., 2024）将这个想法推广到每个令牌的内部原理。

## 这个概念

### STaR：引导工作

从推理能力较弱的基础模型开始。在每个训练问题上，抽样一个基本原理和答案。如果答案符合标签，保留（问题，理由，答案）三倍。在保留的设备上微调模型。重复。

一个转折很重要。如果模型永远不能正确地解决问题，那么循环就无法对其进行学习。STaR增加了合理化：对于模型失败的问题，注入正确的答案作为提示，并重新提示模型生成导致该问题的基本原理。合理化的基本原理被添加到训练集中。

原始论文的结果（Zelikman et al., 2022）： GPT-J基础模型通过重复的STaR轮和合理化，在GSM8K上从5.8%提高到10.7%，绝对提高了约5个百分点。在CommonsenseQA上，star训练的GPT-J 6B达到了72.5%，与经过微调的GPT-3 175B（~73%）相当，后者是在手动注释基础上训练的大约30倍大的模型。

### V-STaR：用DPO培训审核员

STaR抛弃了不正确的理由。Hosseini等人（2024）观察到这些也是数据：每一对（基本原理，“这是正确的吗”）都可以训练一个验证者。他们在正确和不正确的解决方案上使用直接偏好优化来构建排名。在推理时，抽样N个基本原理，并选出验证者的首选。

报告的增量：与GSM8K和MATH上先前的自我改进基线相比+4到+17个百分点，其中大部分增益来自使用验证器进行推理时间选择，而不是用于额外的生成器微调。

### Quiet-STaR：每个令牌的内部基本原理

Zelikman等人（2024）问：如果模型学会在每个标记位置生成简短的内部基本原理，而不仅仅是在问题和答案之间？Quiet-STaR训练一个模型，在每个预测标记之前发出一个隐藏的“想法”，然后通过学习权重将思想感知预测与基线预测混合。

结果：在没有特定任务微调的情况下，Mistral 7B在GSM8K上从5.9%提高到10.9%，CommonsenseQA从36.3%提高到47.2%。这个模型学会了“什么时候该思考”——硬符号的内在原理变得更长；容易的人几乎没有。

### 为什么三者都有安全隐患

这三种方法都使用最终答案作为梯度信号。通过有缺陷的推理——利用捷径、猜测或使用非泛化模式——得出正确答案的理论基础会得到积极的强化。在分配问题上，捷径是有效的。在发行之外的问题上，它会无声地中断。

V-STaR的验证器通过学习对基本原理进行排序来减轻问题，但是验证器是在相同的标签集上进行训练的。它可以学会更喜欢格式良好的错误推理，而不是诚实的不确定性。更安全的设计是将star风格的数据与(a)过程监督的奖励模型（奖励中间步骤，而不仅仅是答案）和(b)打破简单捷径的持久OOD评估结合起来。

### 比较

| Method | Training signal | Inference cost | Data waste | Known failure mode |
|---|---|---|---|---|
| STaR | keep (rationale, answer) if correct | 1x | discards all incorrect rationales | shortcut rationales |
| STaR + rationalization | above + correct-answer hinted retries | 1x | less | rationalized rationales may be implausible |
| V-STaR | STaR + DPO verifier from both classes | Nx (best-of-N) | minimal | verifier can reinforce confident wrongness |
| Quiet-STaR | per-token rationale + mixing weight | 1.5-3x | minimal | still answer-conditioned gradient |

### 它在2026年的堆栈中是什么位置

星星老了。但在2025-2026年，这种模式会在所有地方重现。可验证数学问题（DeepSeek-R1, Kimi-k1.5, 01）上的RL是STaR的应答条件梯度信号，按比例放大。过程奖励模型（Lightman et al., 2023； OpenAI的“让我们一步一步验证”）是过程监督的替代方案。AlphaEvolve（第3课）是代码的STaR，使用程序求值器而不是标签。达尔文哥德尔机（第4课）是agent脚手架本身的STaR。

了解STaR使所有这些都成为可能。这是最小可行的自我完善循环。

## 练习

1. 运行模拟器。将快捷频率设置为0，然后设置为0.4。即使在训练分布上都达到了90%，两次运行之间的最终准确率差异有多大？

2. 向模拟器添加一个伸出的OOD测试。从不同的分布中绘制问题，并在分布内集和OOD集上评估自举模型。量化差距。

3. 阅读Quiet-STaR论文（arXiv:2403.09629）。用三句话分别解释“思想结束”符号和混合权重头。

4. 将STaR的keep-if-correct过滤器与一个过程监督的替代方案进行比较，后者独立地奖励每个基本原理步骤。识别标签成本差异和合理的质量差异。

5. 设计一个能够在已部署模型中捕获快捷原理的评估。它不必是完美的——它必须打破STaR循环会加强的最简单的捷径。

## 关键术语

| Term | What people say | What it actually means |
|---|---|---|
| STaR | "Self-Taught Reasoner" | Fine-tune on model-generated rationales that land correct answers; repeat |
| Rationalization | "Hinted retry" | Inject the correct answer and re-prompt for a rationale on problems the base model fails |
| V-STaR | "Verifier STaR" | DPO-train a verifier on both correct and incorrect rationales, use it for inference-time selection |
| Quiet-STaR | "Per-token rationales" | Generate hidden thoughts at every token position; mix with baseline prediction |
| Answer-conditioned gradient | "Outcome-based signal" | The training loop rewards final answers, not reasoning steps |
| Process reward model | "Step-level verifier" | Reward model trained on per-step correctness, not outcome — contrasts with STaR |
| Shortcut rationale | "Right answer, wrong reasoning" | A rationale that reaches the label via a non-generalizing pattern; STaR keeps these |
