# 基于HTN和进化搜索的规划

> 符号规划处理计划可证明是正确的情况。进化代码搜索处理适应度函数是机器可检查的情况。ChatHTN（2025）和AlphaEvolve（2025）展示了与LLM配对时各自解锁的内容。

**Type:** Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 · 02 (ReWOO and Plan-and-Execute)
**Time:** ~75 minutes

## 学习目标

- 解释分层任务网络：任务、方法、操作符、前提条件、效果。
- 描述ChatHTN的混合循环符号搜索与LLM回退分解。
- 解释一下AlphaEvolve的进化循环，以及为什么它只能与程序评估器一起工作。
- 在stdlib中实现一个玩具HTN规划器和一个玩具进化搜索。

## 这个问题

ReWOO（第02课）、计划-执行和ReAct涵盖了大多数代理计划。他们没有很好地涵盖两种情况：

1. **具有可证明正确性的计划。**调度，飞行路径，合规工作流程-计划必须在施工时健全。一个流畅的LLM计划有时会产生幻觉，这是不可接受的。
2. **优化与机器可检查的适应度功能。**矩阵乘法、调度启发式、编译器通过——目标不是“正确的计划”，而是“最佳计划”。

HTN规划和AlphaEvolve解决了两个不同的问题。两者都使用llm作为放大器，而不是替代品。

## 这个概念

### 分层任务网络

HTN是：

- **任务** -复合（分解）和原始（直接执行）。
- **方法** -将复合任务分解为子任务的方法，带有先决条件。
- **操作符** -具有前提条件和效果的基本操作。
- **状态**—一组事实。

规划：给定目标任务和初始状态，按顺序将其分解为满足前提条件的原语算子。

HTN比llm更古老，仍然是可证明正确的计划的参考。

### chathn （Gopalakrishnan et al., 2025）

ChatHTN （arXiv:2505.11814）将符号HTN与LLM查询交织在一起：

1. 尝试用现有方法分解当前的复合任务。
2. 如果没有适用的方法，问法学硕士：“你将如何分解
3. 将LLM响应转换为候选子任务。
4. 对操作符模式进行验证；拒绝无效的分解。
5. 递归。

这篇论文的核心主张是：每一个产生的计划都是可靠的，因为法学硕士的建议只作为候选分解，而不是直接的计划编辑。符号层拥有正确性；LLM扩展方法库。

在线学习方法（OpenReview）

### AlphaEvolve （Novikov等人，2025）

AlphaEvolve （arXiv:2506.13131, DeepMind， 2025年6月）是一个不同的野兽：由Gemini 2.0 Flash/Pro集成编排的进化代码搜索。

循环:

1. 从一个种子程序+一个程序化的评估器（返回一个适合度分数）开始。
2. llm集合提出突变。
3. 通过评估器运行突变。
4. 保留最好的；变异了。

发表成功:

- 56年来首次改进Strassen的4x4复矩阵乘法（48次标量乘法）。
- 0.7%通过Borg调度启发式恢复谷歌计算。
- 在前沿工作负载上加速32%的FlashAttention。

硬约束：适应度函数必须是机器可检查的。对散文答案的进化搜索并没有趋同。

### 什么时候用哪个

| Problem class | Use | Why |
|---------------|-----|-----|
| Scheduling with hard constraints | HTN + ChatHTN | Provable soundness |
| Compiler optimization | AlphaEvolve | Machine-checkable fitness |
| Multi-step task execution | ReAct / ReWOO | LLM in the loop, no formal guarantees |
| Code improvement with tests | AlphaEvolve | Tests are the evaluator |
| Policy-bound automation | HTN | Preconditions encode policy |

### 这种模式哪里出错了

- **HTN不带操作符。**如果没有前提条件/效果模式，那么可靠性声明就会失效。chathn的“LLM建议分解”要求模式拒绝无效的移动。
- **AlphaEvolve没有真正的评估器。**“询问LLM代码是否更好”不是适应度函数。评估器必须是确定的和快速的。
- * *过度设计。**大多数代理任务都不需要。首先使用ReAct或ReWOO。

## 练习

1. 用回溯扩展HTN计划器：当操作符的后置条件在运行时失败时，回滚并尝试下一个方法。
2. 当LLM分解任务时，向ChatHTN：添加LLM方法缓存下次调用时首先重新检查方法库。
3. 将进化搜索评估器替换为真实的测试套件。进化一个通过20个测试用例的排序函数；向收敛报告代。
4. 阅读AlphaEvolve的评估器设计说明。为您关心的领域（SQL查询优化、测试套件最小化、部署YAML）设计一个评估器。
5. 组合：使用HTN将复合任务分解为子任务，然后对每个子任务的原语操作符使用进化搜索。它在哪里发光，在哪里过度设计？

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| HTN | "Hierarchical planner" | Task decomposition with operators, preconditions, effects |
| Method | "Decomposition rule" | Way to break a compound task into subtasks |
| Operator | "Primitive action" | Concrete step with precondition and effect |
| ChatHTN | "LLM + HTN" | Symbolic planner asks LLM when no method matches |
| AlphaEvolve | "Evolutionary code search" | Ensemble LLMs mutate code; deterministic evaluator selects |
| Fitness function | "Evaluator" | Deterministic, machine-checkable score over outputs |
| Online method learning | "Cached LLM decomposition" | Store + generalize LLM plans to cut query cost |
