# AlphaEvolve -进化编码代理

> 将前沿编码模型与进化循环和机器可检查的求值器配对。让循环运行足够长的时间。它发现了一个使用48次标量乘法的4x4复杂矩阵乘法过程——这是56年来对Strassen的第一次改进。它还发现了一个google范围内的Borg调度启发式，可以恢复生产中约0.7%的集群计算。建筑故意让人觉得无聊。成功来自于评估者的严谨。

**Type:** Learn
**Languages:** Python (stdlib, evolutionary-loop toy)
**Prerequisites:** Phase 15 · 01 (long-horizon framing), Phase 15 · 02 (self-taught reasoning)
**Time:** ~60 minutes

## 这个问题

大型语言模型可以编写代码。进化算法可以搜索代码。几十年来，两人都分别受审；两者都触顶了。法学硕士的上限是虚构的：该模型编写的看似合理的代码并没有达到它声称的效果。进化上限是搜索成本：语法上的随机突变很少产生可编译的程序，更不用说更好的程序了。

AlphaEvolve （Novikov et al., DeepMind, arXiv:2506.13131, 2025年6月）将它们结合起来。法学硕士提出有针对性的编辑程序数据库；自动评估器对每个变体进行评分；高分变异成为后代的父母。LLM处理编写合理代码的昂贵步骤；求值器捕获虚构。这个循环持续数小时到数周。

结果报告：48次标量乘法4x4复矩阵乘法（Strassen的1969界是49），谷歌生产中的Borg调度启发，FlashAttention内核加速32.5%，Gemini训练吞吐量提高。

该体系结构之所以有效，是因为计算器是机器可检查的。它不能在评估者不在的地方工作。这种不对称就是教训。

## 这个概念

### 循环

1. 从种子计划开始
2. 维护一个不同程序的数据库，每个程序由评估员打分。
3. 从数据库中抽取一个或多个父母的样本（地图精英式或岛屿式）。
4. 提示LLM（许多候选人使用Gemini Flash，较难的候选人使用Gemini Pro）生成父级的修改变体。
5. 编译、运行并在暂存求值器上求值该变量。
6. 按其分数和特征向量插入数据库。
7. 重复。

有两个细节很重要。首先，提示LLM的不仅仅是父程序——通常是数据库中的几个顶级变体，加上评估器签名，再加上简短的任务描述。该模型的工作是提出一个可能提高分数的有针对性的改变。其次，数据库是结构化的（地图精英网格，基于岛屿），因此循环探索多样性，而不仅仅是当前的领导者。

### 是什么让评估者不可协商

AlphaEvolve的胜利都来自于评估器快速、确定性强、难以被打败的领域：

- **矩阵乘法算法**：一个单元测试，乘以矩阵并检查相等的位。
- **Borg调度启发式**：一个生产级模拟器，重播历史集群负载和测量浪费的计算。
- **FlashAttention内核**：在真实硬件上进行正确性测试和挂钟基准测试。
- **双子座训练吞吐量**：测量gpu秒每一步。

在每一种情况下，求值器都会捕捉到一类LLM错误，否则这些错误将占主导地位：虚构的正确性声明、在硬件上消失的性能声明和边缘情况故障。移除求值器，循环就会为漂亮的代码进行优化。

### 奖励黑客是这句话的另一面

无论评估者测量什么，进化都会优化。如果评估器不完美，循环将发现不完美之处。在一个未经验证的领域，循环将优化表面特征，而不是预期的行为。DeepMind在论文中明确指出了这一点：AlphaEvolve的成功只会转移到评估者的严格程度与搜索目标相匹配的领域。

2025-2026年代码搜索循环中奖励黑客的具体例子：

- 优化目标奖励“完成时间”，奖励提交空的解决方案。
- 基准分数奖励测试下的正确性，奖励记忆测试和过度拟合。
- “代码质量”代理奖励删除注释和重写变量名，而不改变语义。

AlphaEvolve的修复：发布一个LLM从未见过的评估器，并在评估时生成输入。即便如此，DeepMind还是建议对任何拟议的部署进行严格审查。

### 为什么LLM +搜索优于单独搜索

LLM可以生成可编译的、语义上合理的修改。在2000行Python文件上的随机变异GA几乎总是会产生语法错误。LLM还将搜索集中在合理的邻域上（改变一个函数，而不是随机的字节），这大大减少了浪费的求值器调用。

评估者，反过来，捕捉法学硕士的虚构。法学硕士会自信地宣称一个函数“在极限是O（n log n）”，而实际上它是O(n^2)；一个挂钟基准可以解决这个问题。

### AlphaEvolve在前沿堆栈中的位置

| System | Generator | Evaluator | Domain | Example win |
|---|---|---|---|---|
| AlphaEvolve | Gemini | correctness + benchmark | algorithms, kernels, schedulers | 48-mul 4x4 matmul |
| FunSearch (DeepMind, 2023) | PaLM / Codey | correctness | combinatorial math | cap-set lower bounds |
| AI Scientist v2 (Sakana, L5) | GPT/Claude | LLM critique + experiment | ML research | ICLR workshop paper |
| Darwin Godel Machine (L4) | agent scaffolding | SWE-bench / Polyglot | agent code | 20% → 50% SWE-bench |

这四种方法都是相同方法的变体：生成器+求值器，循环。不同之处在于评估者的评分和严格程度。

## 练习

1. 运行注意最好的分数轨迹。禁用搁置计算器（标志）量化过拟合。

2. 阅读AlphaEvolve关于地图精英网格的论文的第三部分。为新问题（例如编译器优化）设计一个特征向量描述符，以保持搜索的多样性。

3. 48乘4x4的结果在Strassen的49乘边界上改进了56年。阅读论文的附录F，用三句话解释为什么这个问题的评估器特别容易正确，以及为什么大多数领域都不像它。

4. 提出一个AlphaEvolve会失败的领域。准确地确定评估员在哪里出错以及为什么出错。

5. 对于您了解的域，请编写您将使用的评估器签名。包括(a)正确性条件，(b)性能度量，(c)保留输入生成规则，(d)至少一个反奖励黑客检查。

## 关键术语

| Term | What people say | What it actually means |
|---|---|---|
| AlphaEvolve | "DeepMind's evolutionary coding agent" | Gemini + program database + machine-checkable evaluator |
| MAP-elites | "Diversity-preserving archive" | Grid keyed by feature vectors; each cell holds the best variant with that descriptor |
| Island model | "Parallel evolution subpopulations" | Independent populations that migrate periodically; prevents premature convergence |
| Machine-checkable evaluator | "Deterministic oracle" | A unit test, simulator, or benchmark the LLM cannot fake — a prerequisite for this loop |
| Reward hacking | "Optimizing the measure, not the goal" | Loop finds a way to maximize score without doing the intended task |
| Seed program | "The starting point" | An initial correct-but-suboptimal program the loop evolves from |
| Held-out evaluator | "Evaluation data the LLM never saw" | Inputs generated at evaluation time to prevent memorization |
