# 多区域LLM服务和KV缓存局部性

> 循环负载平衡对缓存的LLM推理是有害的。如果请求没有到达持有其前缀的节点，则需要支付全部预填充成本——在P50长提示下大约为800 ms，而在缓存命中时约为80 ms。在2026年，生产模式是一个缓存感知路由器（Rust中的vLLM路由器，llm-d路由器），它在前缀哈希匹配上消耗KV-cache事件和路由。最近的研究（GORGO）使跨区域网络延迟成为路由目标中的一个显式术语。商业“跨区域推理”产品（Bedrock跨区域推理，GKE多集群网关）将推理视为不透明的——它们处理可用性，而不是TTFT。摩根大通和梅奥诊所在2024年11月运行了us-east-1故障转移，耗时约22分钟。容灾现实：32%的LLM容灾失败是因为团队备份了权重，但忘记了标记器文件或量化配置。

## 这个问题

您的服务以us-east-1、us-west-2和eu-west-1运行。你把一个ALB放在循环的前面。生产中的前缀缓存命中率下降到8%。TTFT P50三倍。您的vLLM日志显示每个请求都在支付全部预填充成本。

轮询是无状态服务的最佳选择。LLM推理在设计上是有状态的——KV缓存编码模型所看到的一切。路由盲是路由到错误的缓存。

另外，您的团队有一个容灾计划。将模型权重跨区域备份到S3。区域性停电；您尝试故障转移；副本拒绝启动。你忘了标记器。json、量化配置和RoPE缩放配置在一个单独的桶中，你没有同步。

多区域LLM服务是一个缓存问题、路由问题和dr卫生问题——而不是负载平衡问题。

## 这个概念

### 支持缓存路由

请求到达时带有提示。路由器对前缀进行散列（比如，前512个令牌）；它询问每个副本“是否缓存了这个前缀？”副本在分配和退出块时在pub/sub通道上发布KV-cache事件。路由器选择匹配的副本，如果没有人这样做，则通过基于gpu效用的决胜机制。

**vLLM路由器** （Rust， 2026生产栈）：订阅当没有匹配时，降至最小队列深度。

**llm-d router**：相同的模式，Kubernetes-native。通过ControlPlane API发布事件。

**SGLang RadixAttention**（阶段17.06）是副本内部的等效物。跨副本路由是严格的上游路由。

### 数字

TTFT P50在2k代币提示下，Llama 3.3 70B FP8, H100：
- 缓存命中（相同副本，前缀驻留）：~80毫秒。
- 缓存丢失（冷预填充）：~800 ms。

10倍的差距。如果您的路由器在多个副本上达到60-80%的前缀缓存，则单个副本的性能大约为n个副本的容量。如果它达到10%，你就近似于初始缩放。

### 跨区域有一个新的约束条件——网络延迟

开放型RTT:
- Us-east-1↔us-west-2: ~ 65ms。
- Us-east-1↔eu-west-1: ~ 75ms。
- 美国-东-1↔美国-东南-1:~220 Ms

如果路由将来自us-east-1的请求发送到ap- southeastern -1中的热前缀，则节省的预填充（800→80 ms）与440 ms的往返相比相形见绌。GORGO（2026年的研究）明确指出了这一点——最小化通常，答案是保持路由区域性，除非在大量的多mb前缀中，预填充占主导地位。

### 商业的“跨地区推断”在这里没有帮助

AWS Bedrock跨区域推理在容量压力下自动将请求路由到其他区域。它优化可用性，而不是TTFT，并将推理视为不透明的。GKE多集群网关是相同的服务级故障转移，没有KV缓存的意识。

即使使用这些，你仍然需要一个应用层缓存感知路由器。他们处理“美国东部一号着火”的案子。缓存感知路由处理TTFT情况。

### DR卫生——32%的文件丢失问题

被广泛引用的2026年数据：32%的LLM DR失败是因为团队备份了权重，但忘记了：

- Z0
- 量化配置(
- 特定于模型的配置（RoPE缩放、注意力掩码、聊天模板）
- 引擎配置(

修复是一个最小三个文件的DR清单：

1. HF模型仓库下的所有文件（权重+配置+标记器）。
2. 特定于引擎的服务配置。
3. 部署清单（K8s YAML, Dockerfile，依赖锁）。

另外：每季度运行一次DR演练。摩根大通us-east-1钻井在2024年11月实现了22分钟的采收率，只是因为演练了剧本。

### 数据驻留是正交的

欧盟客户PHI不能离开欧盟。如果您的缓存感知路由器向us-east-1发送巴黎发起的请求以获得前缀匹配，那么无论TTFT获得多少，您都违反了GDPR。在优化缓存之前按驻留边界划分路由器。

### 你应该记住的数字

- 缓存命中与未命中TTFT差距：~10倍（80ms vs 800ms在2K提示）。
- 跨区域RTT US-EU: ~75 ms。
- DR失败：32%的标记器/量化配置丢失。
- JPMorgan us-east-1故障转移2024年11月：22分钟（30分钟SLA）。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Cache-aware routing | "smart LB" | Route on prefix-hash match to KV-cache-holding replica |
| KV-cache events | "cache pub-sub" | Replicas publish block add/evict; router indexes |
| Prefix hash | "cache key" | Hash of first N tokens used as router lookup |
| GORGO | "cross-region routing research" | arXiv 2602.11688; network latency as explicit term |
| Cross-region inference | "Bedrock CRI" | AWS product; availability failover, not TTFT awareness |
| DR manifest | "the backup list" | Every file needed to restore — not just weights |
| Data residency | "GDPR boundary" | Legal constraint on which region sees user data |
| RTT | "round-trip time" | Network latency; 75 ms US-EU, 220 ms US-APAC |
| LLM-aware LB | "cache-hit LB" | Cache-aware router as a product category |
