# A/B测试LLM功能- GrowthBook， Statsig和Vibes问题

> 传统的A/B测试不是为不确定的llm构建的。关键的区别是：评估回答“模型能胜任工作吗？”A/B测试回答“用户关心吗？”两者都是必需的；感应检查的运输结束了。2026年的测试内容：快速工程（措辞），模型选择（GPT-4 vs GPT-3.5 vs OSS；准确性vs成本vs延迟），发电参数（温度，顶压）。真实案例：聊天机器人奖励模型变体提供了70%的对话长度和30%的留存率；Nextdoor AI主题行实验在奖励函数细化后实现了+1%的点击率；Khan Academy Khanmigo在一个延迟vs数学精度轴上迭代。平台分割：Statsig**（于2025年9月被OpenAI以11亿美元收购）-顺序测试，CUPED，一体化。**GrowthBook** -开源，仓库原生，贝叶斯+频率+顺序引擎，CUPED， SRM检查，Benjamini-Hochberg + Bonferroni更正。您可以根据对仓库sql的偏好以及“被OpenAI收购”对您的组织是否重要进行选择。

## 学习目标

- 区分评估（“模型能完成工作吗”）和A/B测试（“用户关心吗”）。
- 列举三个可测试的轴（提示、模型、参数），并为每个轴选择度量。
- 解释CUPED、顺序测试和Benjamini-Hochberg多重比较修正。
- 根据仓库- sql姿态和公司收购姿态选择Statsig或GrowthBook。

## 这个问题

您手动调整了一个系统提示符。感觉好多了。你发货。转换随噪声变化。你会责怪度量标准。或者你发布了一个新模型，但转换没有进展——是模型退化了，还是变化太小而无法检测？你不知道，因为你发货时没有A/B。

eval回答模型是否可以在一个标记集上执行任务。它们不回答用户是否喜欢输出。只有一个受控的在线实验才能回答这个问题，而且只有当实验有足够的能力，控制非确定性，并对多重比较进行修正时。

## 这个概念

### 评估vs A/B测试

**评估** -离线，标记集，裁判（rubric或LLM-as-judge或人类）。答案：“在这个固定的发行版上输出是正确的/有用的/安全的吗？”

**A/B测试** -在线，实时用户，随机。答案是：“新变体是否改变了重要的用户级别指标？”

这两个要求。评估在暴露前捕获回归；A/B确认产品影响后。

### 要测试什么

1. **提示工程-措辞，系统提示结构，示例。指标：任务成功、用户留存、成本/请求。
2. **型号选择** - GPT-4 vs GPT-3.5-Turbo vs Llama-OSS。度量：准确性（任务）+成本/请求+延迟P99。多目标。
3. **生成参数** -温度，top-p, max_tokens。指标：特定于任务（输出多样性vs确定性）。

### CUPED -减少方差

使用实验前数据的对照实验。在比较期后之前，先回归期前方差。典型方差减少：30-70%。有效样本量免费增加。

实现：Statsig和GrowthBook实现。

### 连续测试

经典A/B假设固定的样本量。顺序测试（“先看后决定”）控制重复检查下的假阳性率。始终有效的顺序程序（mSPRT，霍华德的信心序列）可以让您提前停止明确的赢家。

### 多重比较修正

以95%置信度运行20个A/B测试会偶然产生一个假阳性。Bonferroni校正收紧每测试α；benjamin - hochberg控制错误发现率。GrowthBook两者都实现了。

### SRM -样品比例不匹配

分配散列将用户随机分配到变量。如果50/50分割交付47/53，则有些东西坏了- SRM检查标记它。两个平台都实现了。

### Statsig vs GrowthBook

** Statsig **:
- 2025年9月被OpenAI以11亿美元收购。主持,SaaS。
- 顺序测试，CUPED，滞留人群。
- 一体化：功能标志+实验+可观察性。
- 最适合：团队已经想要一个捆绑产品，不关心OpenAI的所有权。

** GrowthBook **:
- 开源(麻省理工学院);warehouse-native（直接从Snowflake/BigQuery/Redshift读取）。
- 多种引擎：贝叶斯引擎、频率引擎、顺序引擎。
- CUPED， SRM, Bonferroni， BH校正。
- 自托管或托管云。
- 最适合：仓库- sql商店，数据团队控制度量层，需要OSS。

### 非决定论使权力复杂化

相同的提示符产生不同的输出。传统的功率计算假设IID观测值。在LLM不确定性下，有效样本量低于标称样本量。将所需的样本量乘以1.3-1.5倍作为安全边际。

### 真实案例结果

- 聊天机器人奖励模式的变体：增加70%的对话时长，增加30%的留存率。
- Nextdoor主题：奖励功能改进后的点击率+1%。
- 可汗学院：迭代延迟vs数学精度交易。

### 反模式：根据振动发货

每个高级工程师都能说出一个功能，因为在没有a /B的情况下“感觉更好”。他们中的大多数人回归了团队几个月都没有注意到的产品指标。A/B为强制函数。

### 你应该记住的数字

- Statsig被OpenAI收购：11亿美元，2025年9月
- GrowthBook：开源MIT；贝叶斯+频率论+序列论。
- CUPED方差降低：30-70%。
- LLM不确定性→+30-50%样本大小缓冲。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Eval | "offline test" | Labeled-set evaluation of model capability |
| A/B test | "experiment" | Live randomized comparison on users |
| CUPED | "variance reduction" | Pre-period regression to reduce variance |
| Sequential test | "peek-ok test" | Always-valid procedure allowing early stop |
| Multiple comparison | "the family error" | Running many tests inflates false positives |
| Bonferroni | "tight correction" | Divide α by number of tests |
| Benjamini-Hochberg | "BH FDR" | False-discovery-rate control, less conservative |
| SRM | "bad split" | Sample ratio mismatch; assignment bug |
| Statsig | "OpenAI owned" | Commercial all-in-one, acquired 2025 |
| GrowthBook | "the OSS one" | MIT warehouse-native platform |
| mSPRT | "sequential probability ratio test" | Classical sequential procedure |
