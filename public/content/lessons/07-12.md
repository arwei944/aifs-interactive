## 这个问题

一个朴素的自回归解码器可以对于一个4k令牌响应，即1600万次注意操作，其中大多数是多余的。一旦计算出来，前缀令牌的每个隐藏状态都是确定的——您只需要针对之前所有内容的缓存键和值运行新令牌的查询。

最重要的是，注意力本身会移动大量数据。标准注意力具体化了N×N得分矩阵，N×d softmax输出，N×d最终输出-对HBM的读取和写入太多。当N≥2K时，注意力先为记忆约束，再为flop约束。经典注意力内核对现代gpu的使用不足4 - 10倍。

Dao等人的两项优化将边界推理从“慢”推到了“快”：

1. ** KV缓存。**存储每个前缀标记的K和V向量。每个新令牌的关注点都是对缓存键的一次查询。推理由
2. ** Flash的注意。**平铺注意力计算，使完整的N×N矩阵永远不会击中HBM。所有的softmax + matmul都发生在SRAM中。A100上2 - 4倍挂钟加速；5 - 10倍在H100与FP8。

到2026年，两者都将普及。每个生产推理堆栈（vLLM, TensorRT-LLM, SGLang, llama.cpp）都假设它们。每一个前沿模型船与闪光注意启用。

## 这个概念


### 千伏缓存数学

每个解码器层，每个令牌，每个头：

```
bytes_per_token_per_layer = 2 * d_head * dtype_size
                          ^
                          K and V
```

对于具有32层，32个头的7B模型，d_head=128, fp16：

```
per token per layer = 2 * 128 * 2 = 512 bytes
per token (32 layers) = 16 KB
per 32K context = 512 MB
```

对于Llama 370b（80层，d_head=128， GQA与8 KV头）：

```
per token per layer = 2 * 8 * 128 * 2 = 4096 bytes (4 KB)
per 32K context = 10.4 GB
```

这10 GB就是为什么Llama 370b在128K环境下需要40 GB A100的大部分，只是为了批大小为1的KV缓存。

**GQA是KV-cache的胜利。** 64个磁头的MHA将是32gb。MLA进一步压缩。

### 闪光注意力——平铺技巧

标准的关注:

```
S = Q @ K^T          (HBM read, N×N, HBM write)
P = softmax(S)       (HBM read, HBM write)
O = P @ V            (HBM read, HBM write)
```

三次HBM往返。在H100上，HBM带宽为3tb /s；SRAM为30tb /s。每次HBM行程都是10倍于保持所有芯片上的速度。

Flash的注意:

```
for each block of Q (tile size ~128 × 128):
    load Q_tile into SRAM
    for each block of K, V:
        load K_tile, V_tile into SRAM
        compute S_tile = Q_tile @ K_tile^T     (SRAM)
        running softmax aggregation             (SRAM)
        accumulate into O_tile                  (SRAM)
    write O_tile to HBM
```

每个瓷砖一个HBM行程。总内存占用从向后传递从向前传递中重新计算一些值，而不是存储它们-另一个内存胜利。

**数值技巧。**运行softmax维护不是近似值- Flash Attention计算与标准Attention相同的位输出（模fp16非结合性）。

**版本演化:**

| Version | Year | Key change | Speedup on reference hardware |
|---------|------|-----------|-------------------------------|
| Flash 1 | 2022 | Tiled SRAM kernel | 2× on A100 |
| Flash 2 | 2023 | Better parallelism, causal-first ordering | 3× on A100 |
| Flash 3 | 2024 | Hopper asynchrony, FP8 | 1.5–2× on H100 (~740 TFLOPs FP16) |

### 连续配料

经典的批处理推理：等待最慢的序列完成，然后开始一个新的批处理。当短响应提前完成时浪费GPU。

连续批处理（最初在Orca中发布，现在在vLLM， TensorRT-LLM， SGLang中发布）：在旧请求完成后立即将新请求交换到批处理中。典型聊天工作负载的吞吐量增加5 - 10倍。

### KV缓存作为虚拟内存

vLLM的主要特性。KV缓存按16个令牌块分配；页表将逻辑位置映射到物理块。允许您跨并行样本共享KV（波束搜索、并行采样）、用于提示缓存的热插拔前缀和内存碎片整理。吞吐量比原始连续分配提高4倍。

### Step 2: tiled softmax

```python
def tiled_softmax_dot(q, K, V, tile=4):
    """Flash-attention-style softmax(qK^T)V with running max/sum."""
    m = float("-inf")
    s = 0.0
    out = [0.0] * len(V[0])
    for start in range(0, len(K), tile):
        k_block = K[start:start + tile]
        v_block = V[start:start + tile]
        scores = [sum(qi * ki for qi, ki in zip(q, k)) for k in k_block]
        new_m = max(m, *scores)
        exp_old = math.exp(m - new_m) if m != float("-inf") else 0.0
        exp_new = [math.exp(sc - new_m) for sc in scores]
        s = s * exp_old + sum(exp_new)
        for j in range(len(out)):
            out[j] = out[j] * exp_old + sum(e * v[j] for e, v in zip(exp_new, v_block))
        m = new_m
    return [o / s for o in out]
```

## 练习

1. **容易。**运行确认原始解码器和缓存解码器产生相同的输出；注意运算计数的差异。
2. **介质。**实现前缀缓存：给定一个提示P和几个完成，在P上运行一个前向传递来填充KV缓存，然后每个完成分支。测量每个加速与重新编码P。
3. **难。**实现一个玩具PagedAttention: KV缓存在固定的16个令牌块与一个自由列表。当序列结束时，将其块返回到池中。模拟1000个不同长度的聊天完成。比较内存碎片和连续分配。

## 关键术语

| Term | What people say | What it actually means |
|------|-----------------|-----------------------|
| KV cache | "The trick that makes decoding fast" | Stored K and V from every prefix token; new queries attend to them instead of recomputing. |
| HBM | "GPU main memory" | High Bandwidth Memory; 80 GB on H100, 192 GB on B200. ~3 TB/s bandwidth. |
| SRAM | "On-chip memory" | Per-SM fast memory, ~256 KB per SM on H100. ~30 TB/s bandwidth. |
| Flash Attention | "Tiled attention kernel" | Computes attention without materializing N×N in HBM. |
| Continuous batching | "No-wait batching" | Swap finished sequences out, new ones in, without draining the batch. |
| PagedAttention | "vLLM's headline" | KV cache allocated in fixed blocks with a page table; eliminates fragmentation. |
| Prefix caching | "Reuse long prompts" | Cache KV for a shared prefix across requests; major cost cut for agents. |
| Speculative decoding | "Draft + verify" | Cheap draft model proposes tokens; big model verifies k in one pass. |
