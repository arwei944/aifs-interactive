# 子词标记- BPE， WordPiece, Unigram, sentencepece

> 单词标记器会被看不见的单词卡住。字符标记器增加了序列长度。子词标记器消除了差异。每个现代LLM都有一个。

**Type:** Learn
**Languages:** Python
**Prerequisites:** Phase 5 · 01 (Text Processing), Phase 5 · 04 (GloVe / FastText / Subword)
**Time:** ~60 minutes

## 这个问题

你的词汇量有5万个单词。用户输入“untokenizable”。您的标记器返回这个模型现在没有关于这个词的信号。更糟糕的是：语料库中第90百分位的文档有40个罕见的单词，这意味着每个文档有40位丢失的信息。

子词标记化解决了这个问题。常用的单词保持单个标记。稀有词分解成有意义的片段：训练数据涵盖了所有内容，因为任何字符串最终都是字节序列。

2026年的每个前沿LLM都使用三种算法（BPE, Unigram, WordPiece）中的一种，封装在三个库（tiktoken, sentencepece, HF Tokenizers）中的一种。如果没有选择一个语言模型，就不能发布一个语言模型。

## 这个概念


**BPE（字节对编码）。**从字符级词汇开始。计算每个相邻的对。将最频繁的对合并到一个新的令牌中。重复，直到达到目标词汇量。优势算法：GPT-2/3/4， Llama, Gemma, Qwen2, Mistral。

**字节级的BPE测试。**相同的算法，但使用原始字节（256个基本令牌）而不是Unicode字符。保证零GPT-2使用50,257个令牌（256字节+ 50,000个合并+ 1个特殊）。

** Unigram。从丰富的词汇量开始。为每个标记分配一个单位概率。迭代地修剪那些删除次数最少的标记，增加语料库的对数似然。推断的概率：可以采样标记化（通过子词正则化对数据增强有用）。T5, mBART， ALBERT, XLNet， Gemma使用。

**小零件。**合并对最大化训练语料库的可能性，而不是原始频率。BERT, DistilBERT， ELECTRA使用。

** sentencepece vs tiktoken。** sentencepece是直接在原始Unicode文本上*训练*词汇表（BPE或Unigram）的库，将空白编码为tiktoken是OpenAI针对预构建词汇表的快速“编码器”；它不训练。

经验法则：

- **训练新词汇：** sentencepece（多语言，无预标记化）或HF标记器。
- **对GPT词汇的快速推理：** tiktoken （cl100k_base, o200k_base）。
- **两者：** HF Tokenizers -一个库，培训+服务。

参见循环:

合并= []
For _in range(num_merges)：
pairs = Counter（）
对于符号，在vocabulary .items（）中的频率：
对于zip（symbols, symbols[1:]）中的a， b：
对[(a, b)] += freq
如果不是成对的：

Best = pairs.most_common(1)[0][0]

Vocab = apply_merge（Vocab, best）

```

Three facts the algorithm encodes. `</w>` marks word end so "low" (suffix) and "lower" (prefix) stay distinct. Frequency weighting makes high-frequency pairs win early. The merge list is ordered — inference applies merges in training order.

### Step 2: encode with the learned merges

```python
def encode_bpe(word, merges):
    symbols = list(word) + ["</w>"]
    for a, b in merges:
        i = 0
        while i < len(symbols) - 1:
            if symbols[i] == a and symbols[i + 1] == b:
                symbols = symbols[:i] + [a + b] + symbols[i + 2:]
            else:
                i += 1
    return symbols
```

天真的O (n·| |合并)。生产实现（tiktoken, HF tokenizer）使用优先级队列合并排序查找，并在近线性时间内运行。

### Step 4: tiktoken for OpenAI-compatible vocabs

```python
import tiktoken
enc = tiktoken.get_encoding("o200k_base")
print(enc.encode("untokenizable"))        # [127340, 101028]
print(len(enc.encode("Hello, world!")))   # 4
```

Encoding-only。快速（Rust后端）。与GPT-4/5标记化精确匹配，用于字节计数，成本估计，上下文窗口预算。

## 这些陷阱到2026年仍会出现

- **记号赋予器漂移。**针对词汇A进行培训，针对词汇b进行部署。令牌id不同；模型输出垃圾。检查
- **空白歧义。** BPE “hello”和“hello”产生不同的令牌。一定要注明
- **多语言训练不足。**偏重英语的语料库产生的词汇将非拉丁文字分成5-10倍以上的符号。在GPT-3.5上，同样的提示语在日语/阿拉伯语中要贵5-10倍。O200k_base部分修复了这个问题。
- ** Emoji分裂。**一个表情符号可以有5个代币。预算时的检查点表情处理。

## 使用它

2026年的堆栈：

| Situation | Pick |
|-----------|------|
| Training a monolingual model from scratch | HF Tokenizers (BPE) |
| Training a multilingual model | SentencePiece (Unigram, `character_coverage=0.9995`) |
| Serving an OpenAI-compatible API | tiktoken (`o200k_base` for GPT-4+) |
| Domain-specific vocab (code, math, protein) | Train custom BPE on domain corpus, merge with base vocab |
| Edge inference, small model | Unigram (smaller vocabularies work better) |

词汇表的大小是一个缩放决定，而不是一个常数。粗略的启发式：<1B参数为32k， 1-10B为50-100k，多语言/前沿为200k+。

## Key Terms

| Term | What people say | What it actually means |
|------|-----------------|-----------------------|
| BPE | Byte-Pair Encoding | Greedy merge of most-frequent character pairs until target vocab size hit. |
| Byte-level BPE | No unknown tokens ever | BPE over raw 256 bytes; GPT-2 / Llama use this. |
| Unigram | Probabilistic tokenizer | Prunes from a large candidate set using log-likelihood; used by T5, Gemma. |
| SentencePiece | The whitespace one | Library that trains BPE/Unigram on raw text; space encoded as `▁`. |
| tiktoken | The fast one | OpenAI's Rust-backed BPE encoder for pre-built vocabs. No training. |
| Merge list | The magic numbers | Ordered list of `(a, b) → ab` merges; inference applies in order. |
| Character coverage | How rare is too rare? | Fraction of characters in training corpus the tokenizer must cover; ~0.9995 typical. |
