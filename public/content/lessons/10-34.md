### All checkpoints for naivety

Divide the network into sections that only store the "input" of each segment during the forwarding period. When intermediates are needed backward, re-run the forward pass of the section to achieve them, and then make a distinction.

For example, a 32-layer transformer is divided into 32 sections, with each section having one layer.

- Memory: 32-layer input (small) vs 32 * (activation amount per layer) (large).
- Additional calculation: Each segment moves forward an extra time, meaning the total forward FLOPs increases by 33% (since moving backward is twice as much as moving forward, the complete step becomes 1 + 1 + 2 = 4 units instead of 1 + 2 = 3).

This is the original formula of Chen et al. in 2016: for L=64, there are 8 checkpoints for each checkpoint.

### Selective Checkpoints (Korthikanti 2022)

Not all activations have the same cost. Note that the softmax output is FFN hidden activation. For long sequences, softmax is dominant.

Selective checkpoints retain cheap stored activations (linear projections, residuals) and only recalculate expensive activations (attention). The FLOPs required for recalculation are the least, but it saves O (L^2) of memory.

Megatron Core implements this as a "selective" activation recalculation. Used in most 2024+ frontline training sessions.

### Uninstall

An alternative to recalculation: Send the activation to the CPU RAM between forward and backward. PCIe bandwidth is required; It is beneficial when the idle bandwidth exceeds the cost of rematerialization. A hybrid strategy is very common: checkpoint certain layers and offload others.

FSDP2 will uninstall as the first-level option. When the GPU encounters a bottleneck in memory but there is space for CPU-GPU transmission, offloading will come to light.

### Recalculate the cost model

Every step of FLOPs and the naive checkpoint

```
flops_fwd_normal = L * f_layer
flops_bwd_normal = 2 * L * f_layer
flops_total_normal = 3 * L * f_layer

flops_fwd_ckpt = L * f_layer
flops_recompute = L * f_layer  # one extra forward per layer in the segment
flops_bwd_ckpt = 2 * L * f_layer
flops_total_ckpt = 4 * L * f_layer
overhead = 4 / 3 - 1 = 0.33 = 33%
```

With selective checkpoints, you only need to recalculate the attention core instead of the entire layer:

```
flops_recompute_selective = L * f_attention ~= L * f_layer * 0.15
overhead_selective = (3 + 0.15) / 3 - 1 = 0.05 = 5%
```

### When is it not checked

- The innermost layer of the pipeline stage is already in flight. They must finish it no matter what.
- If the first and last layers control the calculation of the stage (which is rare in transformers).
- Note that the kernel has already used FlashAttention - Flash has quickly recalculated softmax, so the additional hierarchical checkpoints are added very little at the top.

### Implementation mode

1. ** Function Wrapper ** : Encapsulates a segment in PyTorch for storage only

2. ** Based on decorator:** The label layer serves as the checkpointable; The trainer decides which parts to package when configuring.

3. ** Manual explicit recalculation ** Write reverse passing yourself and call custom ones

These three functions all give the same functional result. The wrapper is the standard idiomatic usage.

### Interact with TP/PP/FP8

- ** Tensor parallelism ** : Checkpoint inputs must be collected or redistributed during recalculation; Handle communication expenses.
- Pipeline parallelism: A typical pattern is to check the progress of each pipeline stage, so that the micro-batches in reverse order can reuse the activated memory.
- FP8 recalculation: The updated amax history during the recalculation must match the original forward; otherwise, the FP8 scale will drift. Most frameworks take snapshots of the scale.

### Step 2: Naive Backward Needing All Activations

```python
def model_backward(grad_output, activations, params):
    grads = [None] * len(params)
    g = grad_output
    for i in range(len(params) - 1, -1, -1):
        w1, b1, w2, b2 = params[i]
        x_in = activations[i]
        h_pre = linear_forward(x_in, w1, b1)
        h = relu(h_pre)
        gh = g @ w2.T
        gw2 = h.T @ g
        gb2 = g.sum(axis=0)
        g_pre = gh * (h_pre > 0)
        gx = g_pre @ w1.T
        gw1 = x_in.T @ g_pre
        gb1 = g_pre.sum(axis=0)
        grads[i] = (gw1, gb1, gw2, gb2)
        g = gx
    return g, grads
```

### Step 4: Cost Model

```python
def checkpoint_cost(n_layers, segment_size, flops_per_layer=1.0):
    fwd = n_layers * flops_per_layer
    recompute = n_layers * flops_per_layer
    bwd = 2 * n_layers * flops_per_layer
    return {
        "fwd": fwd,
        "recompute": recompute,
        "bwd": bwd,
        "total": fwd + recompute + bwd,
        "overhead_vs_no_ckpt": (fwd + recompute + bwd) / (fwd + bwd) - 1.0,
    }


def selective_checkpoint_cost(n_layers, attention_fraction=0.15,
                              flops_per_layer=1.0):
    fwd = n_layers * flops_per_layer
    recompute = n_layers * attention_fraction * flops_per_layer
    bwd = 2 * n_layers * flops_per_layer
    return {
        "fwd": fwd,
        "recompute": recompute,
        "bwd": bwd,
        "total": fwd + recompute + bwd,
        "overhead_vs_no_ckpt": (fwd + recompute + bwd) / (fwd + bwd) - 1.0,
    }

## Use It

- **torch.utils.checkpoint**: `from torch.utils.checkpoint import checkpoint` — the canonical wrapper in PyTorch. Wraps a function; stores only inputs, recomputes on backward.
- **Megatron-Core activation recomputation**: supports `selective`, `full`, and `block` modes. Standard in 2024+ frontier training.
- **FSDP2 offload**: `module.to_empty(device="cpu")` with `offload_policy` in FSDP2 shards activations to CPU instead of recomputing.
- **DeepSpeed ZeRO-Offload**: CPU offload for optimizer states and activations, complementing checkpointing.

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|----------------------|
| Gradient checkpointing | "Save memory by redoing forward" | Store segment inputs only; recompute intermediates during backward to get gradient-support tensors |
| Activation recomputation | "Same as checkpointing" | The HPC-flavored name for the same technique |
| Segment size (k) | "How many layers per checkpoint" | Number of layers whose intermediates are dropped and rematerialized together |
| Selective checkpointing | "Korthikanti's trick" | Recompute only expensive-to-store activations (attention softmax); keep cheap ones |
| Full checkpointing | "The naive version" | Recompute every layer's intermediates in every segment |
| Block checkpointing | "Coarse-grained" | Checkpoint whole transformer blocks; largest granularity |
| FLOP overhead | "The compute tax" | Extra FLOPs per step = (recompute FLOPs) / (fwd + bwd FLOPs); 33% naive, 5% selective |
| Activation offload | "Ship to CPU" | Move activations to CPU RAM across forward->backward; alternative to recompute |
| sqrt-L rule | "The classical optimum" | For uniform-cost layers, optimal checkpoint spacing is sqrt(L) layers |
| Attention-softmax volume | "The O(L^2) problem" | L^2 * heads * batch floats; dominates activation memory at long contexts |
