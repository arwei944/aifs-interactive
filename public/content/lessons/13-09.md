## 这个问题

第一个MCP远程传输（2024-11）是HTTP+SSE：两个端点，一个用于客户端post，一个用于服务器到客户端流的Server-Sent-Events通道。它工作。它也很笨拙：每个会话两个端点，一些cdn前面的缓存损坏，以及对长寿命SSE连接的硬依赖，一些waf会主动终止。

2025年3月26日的规范将其替换为可流式HTTP：一个端点，POST用于客户端请求，GET用于建立会话流，两者共享一个此后构建或迁移的每个服务器都使用Streamable HTTP。旧的SSE模式已被弃用- Atlassian Rovo于2026年6月30日将其移除；2026年4月1日；到2026年底，大多数剩余的企业服务器。

对于本地服务器来说，工作室仍然很重要。克劳德桌面，VS Code，和每一个ide形状的客户端刷出服务器通过stdio。正确的思维模式是：工作室代表“这台机器”，流媒体HTTP代表“通过网络”。没有交叉。

### Streamable HTTP

单端点支持三种HTTP方法：

- **职位/ mcp。**客户端发送JSON-RPC消息。服务器使用单个JSON响应或一个或多个响应的SSE流进行响应（对于批处理响应和与该请求相关的通知很有用）。
- ** / mcp。**客户打开一个长期SSE通道。服务器将其用于服务器到客户机的请求（采样、通知、触发）。
- **删除/ mcp。**客户端显式终止会话。

类标识会话会话id必须是加密随机的（128位以上）；出于安全考虑，拒绝客户端选择的id。

### 单端点vs两个端点

旧规范中的双端点模式在2026年仍然是可调用的——规范声明它是“遗留兼容的”。但是所有的新服务器都应该是单端点。官方sdk发布单端点；仅在与未迁移的远程通信时使用遗留模式。

### Cloudflare、ngrok和托管

2026年的生产远程MCP服务器将运行在Cloudflare Workers（及其MCP代理SDK）、Vercel Functions或容器化Node/Python上。关键：您的主机必须支持SSE GET的长期HTTP连接。维塞尔的自由等级上限是10秒，不合适。Cloudflare Workers支持无限流。

### 网关组成

当您在多个MCP服务器前使用网关（阶段13·17）时，网关是一个单一的可流HTTP端点，它重写会话id和多路复用。工具在网关层合并；客户端只看到一个逻辑服务器。

### 传输失效模式

- ** stdio SIGPIPE。**子进程在写入过程中死亡引发SIGPIPE；服务器应该干净地退出。客户端应该检测到EOF并将会话标记为死亡。
- ** http 502 / 504。** Cloudflare， nginx和其他代理在上游失败时会发出这些。可流式传输的HTTP客户端应该在短暂退出后重试一次。
- **SSE连接断开。** TCP RST，代理超时，或客户端网络变化关闭流。客户端重新连接
- **会话撤销。**服务器使会话id无效；客户端在下一个请求时看到404。客户端必须重新握手。
- **时钟歪斜。**客户端上的资源ttl计算与服务器上的不一致。客户端应该将服务器时间戳视为权威的。

### 何时绕过可流式HTTP

一些企业在自己的网络中部署gRPC或消息队列传输后的MCP服务器。这是非标准的- MCP的规格没有正式def 这些。网关可以在内部使用gRPC的同时向MCP客户端公开可流的HTTP表面。保持外表面规格符合；网关拥有翻译。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| stdio transport | "Local child process" | JSON-RPC over stdin/stdout, newline-delimited |
| Streamable HTTP | "The remote transport" | Single-endpoint POST + GET + optional SSE, 2025-03-26 spec |
| HTTP+SSE | "Legacy" | Two-endpoint model being removed in mid-2026 |
| `Mcp-Session-Id` | "Session header" | Server-assigned random id echoed on every subsequent request |
| `Origin` allowlist | "DNS-rebinding defense" | Reject requests whose Origin is not approved |
| Single endpoint | "One URL" | `/mcp` handles POST / GET / DELETE for all session operations |
| `last-event-id` | "SSE replay" | Header used to resume a dropped stream without missing events |
| Backwards-compat probe | "Old vs new detection" | Client response-shape check that auto-selects transport |
| Long-lived HTTP | "SSE streaming" | Server pushes events for minutes or hours on one TCP connection |
| Session revocation | "Force re-init" | Server invalidates a session id; client must handshake again |
