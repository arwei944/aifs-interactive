# 基准测试：sw -bench， GAIA, AgentBench

> 2026年锚定代理评估的三个基准。sw工作台测试代码补丁。GAIA测试通用工具的使用。AgentBench测试多环境推理。了解它们的成分，它们的污染情况，以及它们没有测量的东西。

**Type:** Learn
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 · 06 (Tool Use)
**Time:** ~60 minutes

## 学习目标

- 命名sw -bench的测试工具（FAIL_TO_PASS），并解释为什么它会在单元测试上出错。
- 解释为什么sw -bench Verified （OpenAI， 500个任务）存在，以及它删除了什么。
- 描述GAIA的设计：对人类来说简单，对AI来说困难；三个难度等级。
- 命名AgentBench的8个环境和开源llm的主要阻塞器。
- 总结SWE-bench+污染发现及其意义。

## 这个问题

排行榜会告诉你哪种模式在某个基准上获胜。他们不会告诉你：

- 基准是否被污染（解决方案中训练数据、测试泄漏）。
- 基准测试是否衡量你所关心的内容（代码vs浏览vs通才）。
- 评估器是否健壮（AST匹配、状态检查、人工审查）。

在引用数字之前，先了解三个锚定基准和它们的失败模式。

## 这个概念

### sw -bench （Jimenez et al., ICLR 2024 oral）

- 来自12个流行Python仓库的2294个真正的GitHub问题。
- 代理获取：修复提交前的代码库+自然语言问题描述。
- 代理生产：一个补丁。
- 评估者：应用补丁，运行repo的测试套件。补丁必须在不破坏PASS_TO_PASS测试的情况下翻转FAIL_TO_PASS测试（以前失败，现在通过）。

sw -agent （Yang et al., 2024）通过强调代理-计算机接口（文件编辑器命令，模型理解的搜索语法），发布时达到12.5%。

### SWE-bench验证

OpenAI， 2024年8月。人工管理的500个任务子集。删除不明确的问题、不可靠的测试和不清楚修复的任务。“你的代理是否发布了真正的补丁？”

### 污染

- 超过94%的sw -bench问题早于大多数模型截止日期。
- ** sw -bench+**发现32.67%的成功补丁在问题文本中泄露了解决方案（模型在描述中看到了修复），31.08%的补丁由于测试覆盖率较低而可疑。
- 经过验证是更清洁但不是无污染的。

实际意义：一个在sw -bench上得分50%的模型可能在sw -bench+上得分35%。如果您声明sw bench性能，请务必同时报告这两种性能。

### GAIA （Mialon等人，2023年11月）

- 466个问题;在huggingface.co/gaia-benchmark的私人排行榜上保留了300个。
- 设计理念：“对人类来说概念简单（92%），但对人工智能来说很难（GPT-4带插件：15%）。”
- 测试推理，多模态，web，工具使用。
- 三个难度等级；第3级需要跨模式的长工具链。

GAIA是你用来衡量“通才能力”的工具。不要与特定于代码的基准测试混淆。

### AgentBench （Liu et al., ICLR 2024）

- 8种环境，包括代码（Bash、DB、KG）、游戏（Alfworld、LTP）、网络（WebShop、Mind2Web）和开放式生成。
- 多回合，~4k-13k回合每分裂。
- 主要发现：长期推理、决策和指令遵循是OSS llm赶上商业的障碍。

### 这些都不能衡量什么

- 实际操作成本（令牌、挂钟）。
- 对抗条件下的安全行为。
- 在您的领域中的表现（使用您自己的评估，第30课）。
- 尾部故障（基准平均；生产操作人员关心最坏的1%）。

### 基准管理哪里出错了

- * *单个数字固定。** sw -bench 50%告诉您低于P50/P75/P95成本+步骤分布。
- * *被污染的要求。**报告sw -bench而不提及Verified或sw -bench+是误导。
- * * Benchmark-as-development-target。**对基准的优化偏离了生产有用性。

## 构建它

Z0

- 合成bug修复任务（3个任务）。
- 提出补丁的脚本化“代理”。
- 检查FAIL_TO_PASS （bug现已修复）和PASS_TO_PASS（没有损坏）的测试运行器。
- 基于问题分解深度的gaia风格难度分类器。

运行该程序:

```
python3 code/main.py
```

输出显示每个任务的解决率+每个难度，并使评估器规则具体化。

## 使用它

- ** sw -bench验证**的代码代理。始终报告验证分数。
- **GAIA**适用于通才代理。使用私人排行榜分割。
- **AgentBench**用于多环境比较。
- **自定义评估**（第30课）为您的产品的实际形状。

## 练习

1. 移植玩具线束运行在一个真正的回购（选择你的一个）。为已知的bug编写3个FAIL_TO_PASS测试。
2. 添加一个步数度量。在您的3个任务中，每个解决方案需要多少代理步骤？
3. 阅读sw -bench+论文。实现解决方案泄漏检查（根据diff对问题文本进行模式匹配）。
4. 从公共分裂下载一个GAIA问题。追踪gpt -4级探员会做什么。它需要什么工具？
5. 阅读AgentBench的每个环境分解。哪种环境反映了你的产品表面？“SOTA”在那里看起来像什么？

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| SWE-bench | "Code agent benchmark" | 2,294 GitHub issues; patch must flip FAIL_TO_PASS tests |
| SWE-bench Verified | "Clean SWE-bench" | 500 human-curated tasks, OpenAI |
| FAIL_TO_PASS | "Fix gate" | Tests previously failing that must pass after the patch |
| PASS_TO_PASS | "No-regression gate" | Tests that were passing and must still pass |
| GAIA | "Generalist benchmark" | 466 human-easy / AI-hard multi-tool questions |
| AgentBench | "Multi-env benchmark" | 8 environments; long-horizon multi-turn |
| Contamination | "Training-set leak" | Benchmark tasks present in model training |
| SWE-bench+ | "Contamination audit" | 32.67% solution leakage found in successful SWE-bench patches |
