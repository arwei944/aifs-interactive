## 这个问题

“苹果在美国就iPhone搜索协议起诉b谷歌。”五大实体：苹果（Apple）、bb0 （bb0）、iPhone （PRODUCT）、搜索交易（可能）、美国（GPE）。一个好的NER系统可以用正确的类型提取出所有的信息。一个不好的名字会漏掉iPhone，把苹果这个水果和苹果这个公司搞混，把“US”标为“人”。

NER是每个结构化抽取管道下面的主力。简历解析，合规日志扫描，医疗记录匿名化，搜索查询理解，聊天机器人响应接地，法律合同提取。你永远看不清；你总是依赖它。

本课将经典路径（基于规则的，HMM， CRF）引入现代路径（BiLSTM-CRF，然后是Transformer）。每一步都解决了前一步的一个特定限制。模式就是教训。

## 这个概念

**BIO标记**（或BILOU）将实体提取转化为序列标记问题。将每个标记标记为

```
Apple    B-ORG
sued     O
Google   B-ORG
over     O
its      O
iPhone   B-PRODUCT
search   O
deal     O
in       O
the      O
US       B-GPE
.        O
```

多令牌实体链：理解BIO的模型可以提取任意跨度。

建筑进程：

- **规则。**正则表达式+地名词典查找。对已知实体的精度很高，对新实体的覆盖率为零。
- **嗯。**隐马尔可夫模型。给定标签的令牌发射概率，标签到标签的转移概率。维特比解码。对标记数据进行训练。
- ** CRF。**条件随机场。像HMM一样，但有区别，所以你可以混合任意特征（单词形状，大写，相邻单词）。仍然是2026年低资源部署的经典生产主力。
- ** BiLSTM-CRF。**神经功能代替手工制作。LSTM从两个方向读取句子，顶部的CRF层强制一致的标签序列。
- 比起**的基于Transformer。**带有标记分类头的微调BERT。最好的准确性。大多数计算。

### Step 3: a simple rule-based + dictionary baseline

```python
ORG_GAZETTEER = {"Apple", "Google", "Microsoft", "OpenAI", "Meta", "Amazon", "Netflix"}
GPE_GAZETTEER = {"US", "USA", "UK", "India", "Germany", "France"}
PRODUCT_GAZETTEER = {"iPhone", "Android", "Windows", "ChatGPT", "Claude"}


def rule_based_ner(tokens):
    labels = []
    for token in tokens:
        if token in ORG_GAZETTEER:
            labels.append("B-ORG")
        elif token in GPE_GAZETTEER:
            labels.append("B-GPE")
        elif token in PRODUCT_GAZETTEER:
            labels.append("B-PRODUCT")
        else:
            labels.append("O")
    return labels

### Step 5: what a BiLSTM-CRF adds

Features become learned. Inputs: token embeddings (GloVe or fastText). LSTM reads left-to-right and right-to-left. Concatenated hidden states go through a CRF output layer. The CRF still enforces tag-sequence consistency; the LSTM replaces hand-crafted features with learned ones.

```python
import torch
import torch.nn as nn


class BiLSTM_CRF_Head(nn.Module):
    def __init__(self, vocab_size, embed_dim, hidden_dim, n_labels):
        super().__init__()
        self.embed = nn.Embedding(vocab_size, embed_dim)
        self.lstm = nn.LSTM(embed_dim, hidden_dim, bidirectional=True, batch_first=True)
        self.fc = nn.Linear(hidden_dim * 2, n_labels)

    def forward(self, token_ids):
        e = self.embed(token_ids)
        h, _ = self.lstm(e)
        emissions = self.fc(h)
        return emissions
```

对于CRF层，使用与手工编写的CRF相比，这种增益是可测量的，但比您预期的要小，除非您有成千上万个标记句子。

### 基于llm的NER（2026年选项）

现在，零采样和少采样LLM NER在许多领域与微调模型竞争，并且在标记数据稀缺时表现得更好。

- ** Zero-shot提示。**给LLM一个实体类型列表和一个示例模式。请求JSON输出。开箱即用；在新领域中，准确度是中等的。
- ** ZeroTuneBio-style提示。**将任务分解为候选项提取→意义解释→判断→复核。多阶段提示（而不是一次提示）大大提高了生物医学NER的准确性。同样的模式也适用于法律、金融和科学领域。
- **动态提示与RAG。**为每个推理调用从一个小的带注释的种子集中检索最相似的标记示例；在运行中构建几个镜头提示。在2026年的基准测试中，GPT-4生物医学NER F1比静态提示提高了11-12%。
- ** Per-entity-type分解。**对于长文档，一次提取所有实体类型的单个调用随着长度的增长而失去召回。对每个实体类型运行一次提取通道。更高的推理成本，实质上更高的准确性。这是临床记录和法律合同的标准格式。

截至2026年的生产建议：在收集训练数据之前，从LLM零射击基线开始。通常F1已经足够好了，你不需要进行微调。

### 古典NER在哪里胜出

即使有llm可用，经典NER在以下情况下获胜：

- 延迟预算低于50ms。
- 你有成千上万个标记的例子，需要98%+ F1。
- 该领域具有稳定的本体，预训练的CRF或BiLSTM可以很好地传输。
- 监管约束需要一个本地的、非生成的模型。

### 当它分崩离析的时候

- **领域转变。**经过conll培训的NER在法律合同方面的表现比地名词典还差。微调你的域名。
- **嵌套的实体。**“美国银行大厦”同时是一个ORG和FACILITY。标准BIO不能表示重叠的跨度。您需要嵌套NER（多通道或基于跨度的模型）。
- **长实体。**“美国联邦存款保险公司”令牌级模型有时会将其拆分。使用
- **稀疏的类型。**医疗NER标签，如DRUG_BRAND， ADVERSE_EVENT， DOSE。通用模型不知道。Scispacy和BioBERT是这里的起点。

## Key Terms

| Term | What people say | What it actually means |
|------|-----------------|-----------------------|
| NER | Extract names | Label token spans with types (PERSON, ORG, GPE, DATE, ...). |
| BIO | Tagging scheme | `B-X` begins, `I-X` continues, `O` outside. |
| BILOU | Better BIO | Adds `L-X` (last), `U-X` (unit) for cleaner boundaries. |
| CRF | Structured classifier | Models transitions between labels, not just emissions. Enforces valid sequences. |
| Nested NER | Overlapping entities | One span is a different entity than a sub-span of it. BIO cannot express this. |
| Entity-level F1 | Proper NER metric | Predicted span must match true span exactly. Token-level F1 overstates accuracy. |
