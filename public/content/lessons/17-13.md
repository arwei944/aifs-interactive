# LLM可观测性堆栈选择

> 2026年的可观测性市场分为两类。开发平台（LangSmith、Langfuse、Comet Opik）将监控与评估、提示管理、会话回放捆绑在一起。网关/仪器工具（Helicone, SigNoz, OpenLLMetry, Phoenix）专注于遥测。Langfuse是麻省理工学院授权的核心，具有强大的OSS平衡（50K事件/月免费云）。Phoenix是基于Elastic License 2.0的opentelemetri -native——非常适合于漂移/RAG可视化，而不是持久的生产后端。Arize AX使用零复制冰山/Parquet集成，声称比单片可观察性便宜100倍。LangSmith领导的LangChain/LangGraph， 39美元/用户/月，仅在企业中自托管。螺旋酮是基于代理的，15-30分钟的设置，100K的要求/月自由，但较少深度的代理痕迹。常见的生产模式：网关(Helicone/Portkey) + eval平台（Phoenix/TruLens），由OpenTelemetry粘接。

**Type:** Learn
**Languages:** Python (stdlib, toy trace-sampling simulator)
**Prerequisites:** Phase 17 · 08 (Inference Metrics), Phase 14 (Agent Engineering)
**Time:** ~60 minutes

## 学习目标

- 区分开发平台（捆绑：评估+提示+会话）和网关/遥测工具（仅跟踪+度量）。
- 将六个主要工具（Langfuse、LangSmith、Phoenix、Arize AX、Helicone、Opik）映射到它们的许可、定价和最佳用例中。
- 解释openteltry -glue模式，该模式允许您将网关工具与单独的eval平台组合在一起。
- 说出2026年的成本差异（alize AX的零复制方法与单片摄取），并说明大约100倍的乘数。

## 这个问题

你发布了一个LLM特性。它的工作原理。您无法看到提示故障、工具循环、延迟回归、成本峰值或提示缓存命中率。你获得了“LLM可观察性”，并获得了8个工具，它们都声称它们以3个不同的价格点解决了同样的问题。

它们解决不了同一个问题。LangSmith回答“为什么这个LangGraph运行失败了？”凤凰回答：“我的RAG管道在漂移吗？”Helicone回答“哪个应用程序正在燃烧代币？”Langfuse回答：“我可以自己托管整个项目吗？”不同的工具，不同的受众。

采摘涉及四个轴：堆栈（长链）？生SDK吗?多供应商？)，许可容忍(仅MIT ？弹性好吗?商业罚款？)，预算(免费层？100美元/莫?$1000/月？)和自托管(必须？可有可无吗?从来没有吗?)

## 这个概念

### 两类

**开发平台**捆绑可观察性与eval，提示管理，数据集版本控制，会话回放。你运行实验，看看哪个提示有效，数据回归一个新的提示对旧的赢家。LangSmith, Langfuse, Comet Opik。

**网关/遥测工具**仪器推断调用-提示，响应，令牌，延迟，模型，成本。Helicone, sign - z, OpenLLMetry，凤凰城。极简主义者。可以通过OpenTelemetry与单独的eval工具结合使用。

### Langfuse - OSS平衡

- Core Apache / MIT授权；self-host通过Docker。
- 云免费层：5万事件/月。付费：团队每月29美元。
- 评估，及时管理，跟踪，数据集。合理覆盖所有四个开发平台功能。
- 最佳点：您想要langsmith类功能，但必须自托管或使用OSS许可证。

### 菲尼克斯（Phoenix）——遥测优先，opentelmetry原生

- 弹性License 2.0；self-host微不足道。
- 优秀的RAG和漂移可视化。嵌入空间散点图作为一等发货。
- 不是作为持久的生产后端设计的——主要是开发时的可观察性。
- 最佳点：RAG流水线开发，漂移调试，配独立网关进行生产。

### arise AX -规模游戏

- 商业。通过Iceberg/Parquet集成零副本数据湖。
- 声称在规模上比单片可观察性（datadog级）便宜100倍。数学：你将痕迹存储在S3上自己的Parquet中；Arize直接读取。
- 最佳点：>10M跟踪/天，现有的数据湖，想要llm特定的仪表板，没有Datadog定价。

### LangSmith - LangChain/LangGraph优先

- 商业、39美元/ user /月。仅在企业上自托管。
- 一流的LangChain和LangGraph堆栈。如果你不是其中之一，它就不那么引人注目了。
- 甜蜜点：团队致力于朗链，愿意付出。

### 螺旋酮代理的最小可行性

- 15-30分钟的设置，通过交换你的
- MIT许可;每月10万免费，每月支付20美元以上。
- 包括故障转移、缓存、速率限制——也充当网关。
- 减少特工/多步追踪的深度。
- 最佳点：快速启动，单栈应用，需要网关+可观察性。

### Opik (Comet) - OSS开发平台

- Apache 2.0，完全OSS。
- 与Langfuse相似的特性集，具有Comet的传统。
- 最佳点：ML团队已经在Comet上，希望LLM在同一窗格中具有可观察性。

### sign - openentry -first完整APM

- Apache 2.0。通过OpenTelemetry处理一般APM和LLM。
- 最佳点：跨服务和LLM调用的统一可观察性。

### 粘合剂：OpenTelemetry + GenAI语义约定

OpenTelemetry于2025年底发布了GenAI语义约定(使用OTel的工具可以互操作。正在形成的生产模式：

1. 从每个LLM呼叫中发出带有GenAI约定的OTel。
2. 路由到网关（Helicone / Portkey）的日常。
3. 双船到评估平台（Phoenix / Langfuse）进行回归。
4. 存档在数据湖（Iceberg）中，通过arisax或DuckDB进行长期分析。

### 陷阱：在错误的层进行检测

在代理框架内进行检测（例如，添加LangSmith跟踪）将您与该框架耦合在一起。在HTTP/OpenAI-SDK层（通过OpenLLMetry或您的网关）进行检测是可移植的。

### 抽样——你不可能保留所有东西

在100万请求/天的情况下，全跟踪保留的成本高于LLM调用的成本。按规则取样：100%错误，100%高成本，5%成功。始终保持聚合；长尾要保持生的。

### 你应该记住的数字

- Langfuse免费云：5万事件/月。
- LangSmith: 39美元/ user /月。
- 不含螺旋酮：每月100K。
- 声称：在规模上比单片便宜100倍。
- openelementetry GenAI公约：2025年出货，2026年广泛采用。

## 练习

1. 你在LangChain上的团队想要OSS自托管的可观察性。选择Langfuse或Opik并证明。
2. 根据Datadog的报价15万美元/月，以每天500万次为基准，计算alize AX的盈亏平衡。
3. 设计一个OpenTelemetry GenAI属性集，您的组织的指导方针应该在每个LLM调用中强制执行。
4. 争论菲尼克斯是否足以生产。什么时候还不够？
5. Helicone的代理开销为20ms。在P99 TTFT 300 ms时，可以接受吗？如果SLA是100毫秒呢？
