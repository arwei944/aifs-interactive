# 反射：语言强化学习

> 基于梯度的强化学习需要数千次试验和一个GPU集群来修复故障模式。反射（Shinn et al., NeurIPS 2023）用自然语言来做：每次失败的试验后，智能体写一个反射，将其存储在情景记忆中，并在该记忆中设置下一次试验的条件。这是Letta的睡眠时间计算模式，Claude Code的Claude。Md学习和pro-workflow的学习规则。

**Type:** Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 · 01 (Agent Loop), Phase 14 · 02 (ReWOO)
**Time:** ~60 minutes

## 学习目标

- 说出反射的三个组成部分（行动者，评估者，自我反射者）和情景记忆的作用。
- 实现一个带有二进制求值器、反射缓冲区和重新尝试的标准库反射循环。
- 在给定任务的标量、启发式和自我评估反馈源之间进行选择。
- 解释为什么语言强化会捕捉到基于梯度的强化学习需要成千上万次试验才能修复的错误。

## 这个问题

座席任务失败。在标准的强化学习中，你会运行数千次试验，计算梯度，更新权重。昂贵、缓慢，而且大多数生产代理没有针对每次失败的培训预算。

反射（Shinn et al., arXiv:2303.11366）提出了一个不同的问题：如果代理只是考虑为什么它失败了，并在提示中再次尝试该想法会怎么样？没有体重更新。没有梯度。只是在试验之间存储的自然语言。

结果是：在ALFWorld上，它击败了ReAct和其他非微调基线。在HotpotQA上，它比ReAct有所改进。在代码生成（HumanEval/MBPP）上，它设置了当时的技术状态。所有这些都不需要一个梯度步骤。

## 这个概念

### 三个组成部分

```
Actor         : generates a trajectory (ReAct-style loop)
Evaluator     : scores the trajectory — binary, heuristic, or self-eval
Self-Reflector: writes a natural-language reflection on the failure
```

加上一个数据结构：

```
Episodic memory: list of prior reflections, prepended to the next trial's prompt
```

一个试验运行Actor。评估员评分。如果分数低，Self-Reflector会产生一个反思（“我选错了工具，因为我把问题误解为问X，而不是问Y”）。反射进入情景记忆。下一次审判重新开始，但看到了倒影。

### 三种评估者类型

1. **标量** -外部二进制信号。ALFWorld成功或失败。HumanEval测试通过或失败。简单,highest-signal。
2. **启发式** -预def 的故障签名。“如果代理连续两次产生相同的动作，则标记为卡住。”“如果轨迹超过50步，就标记为低效。”
3. **自我评估** -LLM评分自己的轨迹。当没有确凿的事实时需要。弱信号;与基于工具的验证很好地搭配（第05课- CRITIC）。

2026的默认值是一种混合：可用时为标量，不可用时为自求值，启发式作为安全轨。

### 为什么这可以概括

与其说反射是一种新算法，不如说是一种命名模式。几乎每个产品的“自我修复”代理都运行一些变体：

- Letta的睡眠时间计算（第08课）：一个单独的代理反映过去的对话并写入内存块。
- Claude Code
- pro-workflow
- LangGraph的反射节点：一个对输出进行评分并在需要时进行优化的节点。

所有这些都源于同样的见解：自然语言是一种足够丰富的媒介，可以在运行之间传递“我从失败中学到的东西”。

### 什么时候有效，什么时候无效

反射在以下情况下起作用：

- 有明显的故障信号（测试失败、工具错误、错误答案）。
- 任务类是可重复的（可以再次询问相同类型的问题）。
- 反思在轨迹上还有改进的空间（足够的行动预算）。

在以下情况下，反射不起作用：

- 代理第一次尝试就成功了。
- 故障是外部的（网络坏了，工具坏了）——对“网络坏了”的反思对未来的运行没有帮助。
- 这种反思变成了迷信——储存了一种关于一次性不稳定运行的叙述。

2026陷阱：记忆腐烂。反思积累；有些是过时的或错误的；随着情节缓冲的增长，重播的速度会变慢。缓解：周期性压缩（第06课）、反射TTL或单独的睡眠时间清理代理（Letta）。

## 练习

1. 从二进制切换到返回距离度量（距离目标有多远）的标量求值器。收敛得更快吗？
2. 为反射增加10次试验的TTL。在那之后，旧的回忆是伤害还是帮助？
3. 实施启发式评估器：如果相同的动作重复，则将试验标记为卡住。它是如何与自我反射器相互作用的？
4. 使用无视反射的敌对Actor运行反射。迫使Actor注意到它们的最小反射提示工程是什么？
5. 阅读关于AlfWorld的反思论文的第4部分。从概念上再现130%的成功率改进：与普通ReAct相比，关键的增量是什么？

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Reflexion | "Self-correction" | Shinn et al. 2023 — Actor, Evaluator, Self-Reflector plus episodic memory |
| Verbal reinforcement | "Learning without gradients" | Natural-language reflection prepended to the next trial's prompt |
| Episodic memory | "Per-task reflections" | Bounded buffer of prior reflections for one task class |
| Scalar evaluator | "Binary success signal" | Pass/fail or numeric score from ground truth |
| Heuristic evaluator | "Pattern-based detector" | Predefined failure signatures (e.g. stuck-loop, too-many-steps) |
| Self-evaluator | "LLM-as-judge on own trace" | Lower-signal fallback when no ground truth — pair with tool-grounded verification |
| Memory rot | "Stale reflections" | Episodic buffer fills with obsolete entries; fix with compaction/TTL |
| Sleep-time reflection | "Async self-reflection" | Run Self-Reflector off the hot path so primary agent stays fast |
