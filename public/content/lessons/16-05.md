# Supervisor/Coordinator - Worker model

> A major agency plan and commission; Specialized workers perform and report in a parallel context. This is the pattern behind Anthropic's research system (with Claude's work 4 as the dominant and sonnet 4 as the secondary subject), which was 90.2% higher than the single-subject work 4 in internal research evaluations. Anthropic's engineering post reports that 80% of the differences on BrowseComp are explained separately by the use of tokens - multi-agent victories are largely due to each sub-agent obtaining a new context window. This lesson builds the supervisor model from the source language and covers the 2026 engineering course in production deployment.

## "Problem"

Research is a typical task for the failure of single-agent systems. You asked, "What changes will there be in multi-agent systems between 2023 and 2026?" A single agent reads five papers in sequence, fills half of the context with their texts, and then must reason about all these papers together. By the fifth part, it will have forgotten the first one. It cannot be parallelized.

The supervisor mode solves this problem: a leader agent plans to search, delegates each sub-problem to a staff member, and then synthesizes them. For a narrow problem, each staff member has their own 200,000 token window. Leaders never look at the original manuscripts but only at the workers' summaries.

Anthropic's production research system report +90.2% internal research assessment with a single Opus 4. The same article points out that 80% of the BrowseComp differences are explained by "using tokens alone". The new context of each sub-agent is the main mechanism.

### Engineering Course (Anthropic 2025)

Anthropic's post listed several production experiences that are still relevant in 2026:

- Adjust the complexity of the query. Simple query: One agent, 3 to 10 tool calls. Complex queries: 10+ proxies. The leader must estimate this, not the caller.
- Start wide and then narrow. First, break it down into a wide range of sub-problems. Then, if the answer ensures depth, each sub-problem generates more workers.
- "Rainbow deployment. An agent is long-running and stateful. The traditional blue-green color won't work. Anthropic uses Rainbow: gradually roll out new versions as the old ones run out.
- Token usage dominates. Multi-proxy tokens are 15 times as powerful as single-proxy tokens. Run it only when the task value matches the cost.

### Failure mode

- Lead had an illusion about the plan. If the sub-problems generated by the introduction do not break down the real problem, then the staff have conducted precise research on the wrong target.
- Workers over-explore. If there is no clear scope boundary, the staff will deviate from the specified subproblems and contaminate the synthesis steps.
- "Synthetic conflict. The two workers returned contradictory facts. The leader must restate the requirements (add another round) or clearly point out the differences. Silently choosing one side is the worst failure: users never know that a disagreement has occurred.

### When a supervisor makes a mistake

- Sequential tasks. If step 2 does indeed require the output of step 1, parallelism buys nothing. Use pipelines (CrewAI sequence, LangGraph linear graph).
- "Simple query. A single agent is faster and cheaper to handle them. Before the egg-laying workers, use the leader's "scale effort" check.
- Strict determinism. The supervisor uses the llm to select the commission. Static graphs are better when auditing/replay is more important than adaptability.

## This ship

Checklist before deploying the supervisor mode:

- "Pairing mode." Leadership Reasoning layer model (Opus class); Workers are in a faster and cheaper mode (sonnet)
- Workers work overtime. Any worker thread that exceeds twice the median running time will be killed. Lead is either regenerated in a narrower range or there is no lead at all.
- The token limit for each worker. Hard limits (such as 10 times the expected synthetic input) can prevent out-of-control workers from overspending.
- Observability. Track the leader's plan, each worker's tool invocation, and synthesis. This is the foundation of any post-event debugging.
- "Rainbow is launched. Stateful long-running agents require progressive version transitions rather than hot plugging.

## Practice

1. Run and observe the wall clock effect. In this demonstration, what is the number of workers whose brushing overhead exceeds the parallel savings?
2. Implement a worker timeout: Kill any worker that runs for more than 0.5 seconds and have the lead synthesize the remaining results. How much observational ability do you need to know that a worker has been cut?
3. Add a conflict detection step to the leader's synthesis: If two staff members return contradictory answers, the leader will notice the disagreement instead of choosing one of them. How to identify contradictions without being called a Master of Laws?

## Key terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Supervisor | "Lead agent" | An orchestrator agent that plans, delegates, and synthesizes. Does not do the work itself. |
| Worker | "Subagent" | A focused agent invoked by the supervisor with narrow scope and its own context window. |
| Orchestrator-worker | "Supervisor pattern" | Same thing, different name. The 2026 literature uses both. |
| Fresh context | "Clean window" | A worker's context starts from its system prompt and assigned question, not the lead's history. |
| Rainbow deployment | "Gradual rollout" | Long-running stateful agents need versioned drain-and-replace, not blue-green. |
| Token dominance | "Context is the variable" | 80% of research-eval variance comes from total tokens used, not model choice, per Anthropic. |
| Scale effort | "Match agent count to complexity" | Lead estimates query difficulty, spawns 1 vs 10+ workers accordingly. |
| Synthesis conflict | "Workers disagree" | Two workers return contradictory facts; the lead must surface disagreement, not silently pick one. |
