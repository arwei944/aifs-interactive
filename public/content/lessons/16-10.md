# Group chat and speaker selection

> AutoGen GroupChat and AG2 GroupChat share a session on N proxies. The selector function (LLM, polling, or custom) selects the next speaker. This is the prototype of an emergency multi-agent dialogue - the agents do not know their role in the static graph; they merely react to the shared pool. The GroupChat semantics of AutoGen v0.2 are retained in the AG2 branch; AutoGen v0.4 rewrote it as an event-driven participant model. Microsoft placed AutoGen in maintenance mode in February 2026 and merged it with Semantic Kernel into the Microsoft Proxy Framework (RC February 2026). The GroupChat primitive exists in both AG2 and the Microsoft Agent Framework - learn it once and use it anywhere.

**Type:** Learn + Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 16 · 04 (Primitive Model)
**Time:** ~60 minutes

## "Problem"

Static graphs (LangGraph) are very useful when the workflow is known. Real conversations are not static: sometimes programmers ask reviewers, sometimes researchers, and sometimes authors. Hard-coding every possible switch will generate an edge explosion. You want an agent to respond to the shared pool and use some functions to determine who will speak next.

This is exactly what AutoGen GroupChat has done.

## Concept

### The shape

```
              ┌─── shared pool ────┐
              │   m1  m2  m3  ...  │
              └─────────┬──────────┘
                        │ (everyone reads all)
      ┌───────┬─────────┼─────────┬───────┐
      ▼       ▼         ▼         ▼       ▼
    Agent A  Agent B  Agent C  Agent D  Selector
                                           │
                                           ▼
                                  "next speaker = C"
```

Each agent can see every piece of information. A selector function is called in each round to select the next speaker.

### Three flavors of selectors

*"Loop. "Fixed period. Sure. Linearly expand in N, but ignore the context - even if the topic is legal review, programmers will still get their turn.

** LLM-selected. The call to the LLM reads the nearest pool and returns the best next speaker. Context-aware but slow: Add an LLM call in each round. The default of AutoGen.

*"Customized. A Python function with any logic you want. Typically: The llm chose the concession rule (for example, "always let the validator come after the coder's turn").

### ConversableAgent API

```
agent = ConversableAgent(
    name="coder",
    system_message="You write Python.",
    llm_config={...},
)
chat = GroupChat(agents=[coder, reviewer, tester], messages=[])
manager = GroupChatManager(groupchat=chat, llm_config={...})
```

When a proxy completes a round, the manager calls the selector, and the selector returns the next proxy. The loop continues until the termination condition is met.

### Termination

Three common patterns:

- Max wheel. Total revolutions hard cap.
- "Termination" card. The agent can send sentinel messages. When a person appeared, the manager stopped.
- The goal of **. A lightweight validator runs each round and stops chatting when it is completed.

### AutoGen→AG2 split and merged with Microsoft's proxy framework

In early 2025, Microsoft began a major rewrite of AutoGen (v0.4) around an event-driven participant model. The community forked the GroupChat semantics of AutoGen v0.2 into AG2, retaining the API integrated by early adopters.

In February 2026, Microsoft announced that AutoGen would enter maintenance mode and the event-driven actor model would be merged into the **Microsoft Agent Framework** (RC in February 2026, now merged with Semantic Kernel). The concept of GroupChat exists in both aspects; The implementation details are different. AG2 is the preferred upstream for V0.2-compatible code.

### When is GroupChat suitable

- "Urgent conversation. You don't want to pre-connect every possible next speaker.
- ** Role-mixing task. The programmer asked the researcher, the researcher asked the archivist, and the archivist asked the programmer. Flow is not DAG.
- Exploratory problem-solving. Think about "brainstorming meetings" rather than "assembly lines".

### When it fails

- Strict determinism. LLM selectors can be inconsistent. The same prompt, different routes, and different next speakers.
- "Flattery Waterfall. The agent will follow whoever speaks with the most confidence. The counterprompt is clear.
- Context inflation. Each agent reads each message; After ten rounds, the background of the game is very vast. Use projection (Lesson 15) to determine the scope of the view.
- Hot speaker. An agent leads the conversation because the selector likes its expertise. Introduce speaker balance as a selector function.

### Group chat vs. Supervisor

The same primitive, but different default values:

- Supervisor: One person is responsible for planning, while the others are responsible for execution. The selector is "Ask the planner what to do."
- Group chat: All seats are companions. A selector is a function on a shared pool.

Both use the four primitives from Lesson 04. The default status of group chats is the business process selected by the llm and the shared status of the entire pool.

Checklist

- Speaker-balance metric. Track the turns of each agent; An alarm will be triggered when the imbalance exceeds the threshold.

## Key terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| GroupChat | "Agents in one chat room" | Shared message pool + selector function. AutoGen / AG2 primitive. |
| Speaker selection | "Who talks next" | The function that picks the next agent. Round-robin, LLM-selected, or custom. |
| GroupChatManager | "The meeting host" | AutoGen component that owns the selector and loops over turns. |
| ConversableAgent | "The base agent" | AutoGen base class; an agent that can send and receive messages. |
| Termination token | "The 'stop' word" | Sentinel string (usually `TERMINATE`) that ends the chat. |
| Hot speaker | "One agent dominates" | Failure mode where the selector keeps picking the same agent. |
| Context bloat | "Pool grows unbounded" | Each agent reads every prior message; context grows with turns. |
| Projection | "Scoped view" | Role-specific view into the shared pool to prevent context bloat. |
