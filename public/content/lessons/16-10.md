# 群组聊天和发言人选择

> AutoGen GroupChat和AG2 GroupChat在N个代理上共享一个会话；选择器函数（LLM、轮询或自定义）选择下一个发言的人。这是紧急多代理对话的原型——代理不知道它们在静态图中的角色，它们只是对共享池做出反应。AutoGen v0.2的GroupChat语义保留在AG2分支中；AutoGen v0.4将其重写为事件驱动的参与者模型。微软在2026年2月将AutoGen置于维护模式，并将其与Semantic Kernel合并到微软代理框架（RC 2026年2月）中。GroupChat原语在AG2和Microsoft Agent Framework中都存在——学习一次，随处使用。

**Type:** Learn + Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 16 · 04 (Primitive Model)
**Time:** ~60 minutes

## 问题

当工作流已知时，静态图形（LangGraph）非常有用。真实的对话不是静态的：有时是程序员问审稿人，有时是研究人员，有时是作者。硬编码每一个可能的切换会产生一个边缘爆炸。您希望*个代理对共享池*作出反应，并使用一些函数决定谁接下来发言。

这正是AutoGen GroupChat所做的。

## 概念

### 的形状

```
              ┌─── shared pool ────┐
              │   m1  m2  m3  ...  │
              └─────────┬──────────┘
                        │ (everyone reads all)
      ┌───────┬─────────┼─────────┬───────┐
      ▼       ▼         ▼         ▼       ▼
    Agent A  Agent B  Agent C  Agent D  Selector
                                           │
                                           ▼
                                  "next speaker = C"
```

每个代理都能看到每条信息。每个回合调用一个选择器函数来选择下一个发言的人。

### 三种选择器口味

**循环。**固定周期。确定的。在N中线性扩展，但忽略了上下文-即使主题是法律审查，程序员也会轮到。

** LLM-selected。**对LLM的调用，读取最近的池并返回最好的下一个演讲者。上下文感知但缓慢：每个回合都添加一个LLM调用。AutoGen的默认。

**自定义。一个Python函数，有你想要的任何逻辑。典型的：llm选择了退让规则（例如，“总是让验证者在编码者之后轮到”）。

### ConversableAgent API

```
agent = ConversableAgent(
    name="coder",
    system_message="You write Python.",
    llm_config={...},
)
chat = GroupChat(agents=[coder, reviewer, tester], messages=[])
manager = GroupChatManager(groupchat=chat, llm_config={...})
```

Z0当一个代理完成一个回合时，管理器调用选择器，选择器返回下一个代理。循环继续，直到达到终止条件。

### 终止

三种常见的模式：

- * *马克斯轮。**总转数硬帽。
- * *“终止”牌。**代理可以发出哨兵信息；当一个人出现时，经理停了下来。
- * *的目标。**一个轻量级的验证器运行每个回合，并在完成时停止聊天。

### AutoGen→AG2分裂和微软代理框架合并

在2025年初，微软开始围绕事件驱动的参与者模型对AutoGen （v0.4）进行重大重写。社区将AutoGen v0.2的GroupChat语义分叉为AG2，保留了早期采用者集成的API。

在2026年2月，微软宣布AutoGen将进入维护模式，事件驱动的actor模型合并到**Microsoft Agent Framework** （RC 2026年2月，现在与Semantic Kernel合并）。GroupChat的概念在这两方面都存在；实现细节有所不同。AG2是v0.2兼容代码的首选上游。

### 什么时候适合GroupChat

- * *紧急对话。**您不希望预先连接每个可能的下一个扬声器。
- * * Role-mixing任务。**程序员问研究员，研究员问档案保管员，档案保管员问程序员。心流不是DAG。
- * *探索性解决问题。想想“头脑风暴会议”，而不是“装配线”。

### 当它失败时

- * *严格的决定论。** LLM选择器可以不一致。同样的提示，不同的路线，不同的下一位演讲者。
- * *谄媚瀑布。**谁说话最自信，代理人就听从谁。Counter-prompt明确。
- * *上下文膨胀。**每个代理读取每条消息；10个回合后，游戏的背景非常庞大。使用投影（第15课）确定视图的范围。
- * *热扬声器。一个代理主导对话，因为选择器喜欢它的专长。引入扬声器平衡作为选择器功能。

### 群聊vs主管

相同的原语，不同的默认值：

- 主管：一人负责计划，其他人负责执行。选择器是“问计划者该做什么。”
- 群聊：所有座席都是同伴；选择器是共享池上的一个函数。

两者都使用了第04课的四个原语。群聊默认为llm选择的业务流程和全池共享状态。

## 船这

检查表:

- **最大回合上限。**总是。典型任务10-20。
- * * Speaker-balance指标。**跟踪每个代理的转弯；当不平衡超过阈值时发出警报。
- * *终止令牌。**
- **投影或作用域记忆。在大约10条消息之后，考虑只给每个代理一个作用域视图，以防止上下文膨胀。
- * *选择器日志记录。**对于llm选择的变体，记录选择器的输入和选择。否则调试是不可能的。

## 练习

1. 运行比较在循环和llm选择下的对话。哪一个主体占主导地位？
2. 在选择器中添加“max-speaks-per-agent”规则。它是如何影响成绩单的？
3. 实现目标达成的终止：当审稿人返回“已批准”时停止。它在圆帽之前触发一次？
4. 在GroupChat上阅读AutoGen稳定文档（https://microsoft.github.io/autogen/stable/user-guide/core-user-guide/design-patterns/group-chat.html）。使用的默认选择器
5. 阅读AG2回购（https://github.com/ag2ai/ag2），并将其v0.2 GroupChat与v0.4事件驱动版本进行比较。v0.4增加了哪些具体的属性（吞吐量、容错性、可组合性）？

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| GroupChat | "Agents in one chat room" | Shared message pool + selector function. AutoGen / AG2 primitive. |
| Speaker selection | "Who talks next" | The function that picks the next agent. Round-robin, LLM-selected, or custom. |
| GroupChatManager | "The meeting host" | AutoGen component that owns the selector and loops over turns. |
| ConversableAgent | "The base agent" | AutoGen base class; an agent that can send and receive messages. |
| Termination token | "The 'stop' word" | Sentinel string (usually `TERMINATE`) that ends the chat. |
| Hot speaker | "One agent dominates" | Failure mode where the selector keeps picking the same agent. |
| Context bloat | "Pool grows unbounded" | Each agent reads every prior message; context grows with turns. |
| Projection | "Scoped view" | Role-specific view into the shared pool to prevent context bloat. |
