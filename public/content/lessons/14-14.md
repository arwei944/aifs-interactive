# AutoGen v0.4：参与者模型和代理框架

> AutoGen v0.4 （Microsoft Research， 2025年1月）围绕参与者模型重新设计了代理编排。异步消息交换、事件驱动代理、故障隔离、自然并发。该框架现在处于维护模式，而微软代理框架（2025年10月公开预览版）将成为其继任者。

**Type:** Learn + Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 · 01 (Agent Loop), Phase 14 · 12 (Workflow Patterns)
**Time:** ~75 minutes

## 学习目标

- 描述参与者模型：代理作为参与者，消息作为唯一的IPC，每个参与者的故障隔离。
- 命名AutoGen v0.4的三个API层- Core， AgentChat， Extensions -以及每个层的用途。
- 解释为什么将消息传递与处理解耦可以实现故障隔离和自然并发性。
- 在Python中实现一个stdlib actor运行时，并将一个双代理代码审查流移植到它上面。

## 这个问题

大多数代理框架都是同步的：在调用堆栈中，一个代理生成，一个代理消费。失败会使堆栈崩溃。并发性是固定的。发行需要重写。

AutoGen v0.4的答案是：参与者模型。每个代理都是一个具有私有收件箱的参与者。消息是唯一的交互。运行时将交付与处理解耦。故障孤立于一个参与者。并发性是原生的。分销只是不同的运输方式。

## 这个概念

### 演员

一个演员有：

- 一个私有状态（从不从外部直接接触）。
- 收件箱（消息队列）。
- 处理程序：

两个演员不能共享记忆。它们只能发送消息。

### AutoGen v0.4中的三个API层

1. **核心。**低级actor框架。`AgentRuntime`, `Agent`, `Message`, `Topic`. 异步消息交换，事件驱动。
2. ** AgentChat。任务驱动的高级API（替代v0.2的ConversableAgent）。`AssistantAgent`, `UserProxyAgent`, `RoundRobinGroupChat`, `SelectorGroupChat`.
3. **扩展。**集成- OpenAI， Anthropic, Azure，工具，内存。

### 为什么脱钩很重要

在v0.2模型中，调用在v0.4中，运行时稍后交付。三种后果:

- **故障隔离。**代理B崩溃不会使代理A崩溃——运行时在B的处理程序中捕获失败并决定做什么（日志，重试，死信）。
- **自然并发性。**同时发送多封邮件；参与者并发地处理他们的收件箱。
- **适合自己。**无论参与者是在进程中还是在另一台主机上，Inbox + transport都是相同的抽象。

### 拓扑

- ** RoundRobinGroupChat。**代理在固定的旋转中轮流。
- ** SelectorGroupChat。**选择代理根据会话上下文选择下一个对象。
- ** Magentic-One。**参考多代理团队的网页浏览，代码执行，文件处理。建立在AgentChat。

### 可观察性

OpenTelemetry支持是内置的。每条消息发出一个span；工具呼叫携带

### 状态：维护模式

2026年初：AutoGen v0.7。X对于研究和原型是稳定的。微软已经将积极的开发转移到微软代理框架（2025年10月1日公开预览；1.0 GA目标在2026年第一季度结束）。AutoGen模式清晰地向前移植——参与者模型是持久的想法。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Actor | "Agent" | Private state + inbox + handler; no shared memory |
| Message | "Event" | Typed payload; the only way actors interact |
| Inbox | "Mailbox" | Per-actor queue of pending messages |
| Runtime | "Agent host" | Event loop that routes messages and isolates failures |
| Topic | "Channel" | Named publish-subscribe route between actors |
| Fault isolation | "Let it crash" | One actor failing does not crash others |
| RoundRobinGroupChat | "Fixed-rotation team" | Agents take turns in order |
| SelectorGroupChat | "Context-routed team" | Selector picks who goes next |
| Magentic-One | "Reference team" | Multi-agent squad for web + code + files |
