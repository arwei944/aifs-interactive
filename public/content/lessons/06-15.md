# Streaming voice-to-speech - Moshi, Hibiki and full-duplex dialogue

> Redefine voice AI from 2024 to 2026. Moshi offers a single model that can listen and speak simultaneously with a delay of 200 milliseconds. Hibiki can perform voice translation block by block. Both have abandoned the ASR→LLM→TTS pipeline and implemented a unified full-duplex architecture on Mimi codec tokens. This is the new reference design.

**Type:** Learn
**Languages:** Python
**Prerequisites:** Phase 6 · 13 (Neural Audio Codecs), Phase 6 · 11 (Real-Time Audio), Phase 7 · 05 (Full Transformer)
**Time:** ~75 minutes

## This question

Each voice agent built from Lesson 11 + 12 has a basic delay floor of approximately 300-500 milliseconds: VAD fire, STT process, LLM cause, TTS generation. Each stage has its own minimum delay. You can adjust and parallelize, but the shape of the pipeline limits you.

Moshi (Kyutai, 2024-2026) raised a different question: What if there were no pipes? What if a mode directly and continuously receives and emits audio, using text as the "inner monologue" in the middle rather than the necessary stage?

The answer is full-duplex voice-to-speech. The theoretical delay is 160 milliseconds (80 milliseconds Mimi frame + 80 milliseconds acoustic delay). The actual latency on a single L4 GPU is 200ms. This is half of a first-class pipeline voice agent.

## This concept


### Moshi Architecture

*"Input. Two Mimi codec streams, both at 12.5Hz × 8 codebooks:

- Stream 1: User audio (mini encoded, constantly arriving)
- Stream 2:Moshi's own audio (generated by Moshi)

*Transformer. The 7b parametric time converter processes streams and text "inner monologue" streams. In every 80-millisecond step, it:

1. Use the latest user Mimi token (8 codebooks).
2. Consume the latest Moshi Mimi tokens (8 generated codebooks).
3. Generate the next Moshi text tag (inner monologue).
4. Generate the next Moshi Mimi token (via a small depth transformer 8-codebook).

All three streams - user audio, Moshi audio, and Moshi text - run in parallel. Moshi can hear what users are saying. When a user interrupts, they can interrupt themselves. It can be transmitted in reverse (" um ") without interrupting its main pronunciation.

*Depth transformer. Within a frame, the eight codebooks are not predicted in parallel - they have dependencies among the codebooks. A small two-layer "depth transformer" predicts them one by one within 80 milliseconds. This is the standard decomposition of the AR codec lm (also used by VALL-E and VibeVoice).

### Why are inner monologue texts helpful

If there is no explicit text, the model must implicitly model the language in its acoustic flow. Moshi's insight is: Force it to emit text tags while sending audio. The text stream is essentially the text of what Moshi said. This enhances semantic consistency, makes it easier to change the language model header, and provides text for free.

### Hibiki: Streaming voice to voice translation

The same framework, train the translation correctly. The source audio input and the target language audio output are continuous. Hibiki-Zero (February 2026) eliminates the need for word-level alignment training data - using sentence-level data + GRPO reinforcement learning for delay optimization.

Initially, four language pairs were supported; It takes about 1,000 hours to adapt to a new language.

### A broader nine-platform stack (2026)

- **Moshi** - Full-duplex Dialogue (French preferred, good support for English)
- "Hibiki/Hibiki-Zero" - Simultaneous interpretation
- ** kyyutai STT** - Streaming ASR (500 ms or 2.5 s forward view)
- **Kyutai Pocket TTS** - 100m Parameter TTS Running on CPU (January 2026)
- ** Unmute ** - Combine these complete pipelines on public servers

Throughput on the L40S GPU: 64 concurrent sessions, 3 times real-time.

### Sesame CSM - Cousin

Sesame CSM (2025) employed a similar idea - the alpaca-3 trunk with the Mimi codec head. However, CSM is unidirectional (accepting context + text and generating voice), rather than full-duplex. It is the best "voice presentation" TTS on the market. It's not quite the same as Moshi's full-duplex function.

### Step 2: the full-duplex loop

```python
async def stream_mic_to(ws):
    async for chunk_80ms in mic_stream_at_12_5_hz():
        mimi_tokens = encode_audio_mimi(chunk_80ms)
        await ws.send(serialize(mimi_tokens))

async def stream_from_to_speaker(ws):
    async for msg in ws:
        mimi_tokens, text_token = deserialize(msg)
        audio = decode_audio_mimi(mimi_tokens)
        await play(audio)
```

Run simultaneously in both directions. Python asyncio or Rust future is the standard transmission method.

### Step 4: Where did Moshi win and where did he lose

The success of ramie

- On inexpensive hardware, it takes less than 250 milliseconds end-to-end.
- Natural reverse channels and interruptions.
- No pipe glue codes.

Moshi didn't win

- Tool invocation (untrained; you need a separate LLM path).
- Long reasoning (Moshi is an 8B-ish dialogue model, not Claude/GPT-4).
- The factual accuracy of niche topics.
- Most manufacturing enterprise use cases (pipes will still be used in 2026).

## Trap

- Limited tool invocation. Moshi is a dialogue model, not a proxy framework. Combine pipes as tools.
- Specific-voice regulation. Moshi uses a single training character; Cloning is a separate training run.
- Language coverage. Excellent in French and English; Other restrictions. Hibiki-Zero is helpful, but you still need training data.
- The resource cost of **. A complete Moshi session holds one GPU slot; It is not a cheap shared tenant deployment model.

## Key terms

| Term | What people say | What it actually means |
|------|-----------------|-----------------------|
| Full-duplex | Hear-and-speak at once | Two audio streams active simultaneously on the same model. |
| Inner monologue | Model's text stream | Moshi emits text tokens alongside its audio output. |
| Depth transformer | Inter-codebook predictor | Small transformer that predicts 8 codebooks within one 80 ms frame. |
| Mimi | Kyutai's codec | 12.5 Hz × 8 codebooks; semantic+acoustic; powers Moshi. |
| Streaming S2S | Audio → audio live | Chunk-by-chunk translation/dialogue, no pipeline stages. |
| Back-channeling | "Mhm" reactions | Moshi can emit small acknowledgments without breaking its turn. |
