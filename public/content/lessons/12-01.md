# 视觉变形器和补丁令牌原语

> 在任何多模式之前，图像必须成为转换器可以吃的符号序列。2020年的ViT论文用16x16像素的补丁、线性投影和位置嵌入来回答这个问题。五年后，每个2026前沿模型（Claude Opus 4.7 at 2576px native, Gemini 3.1 Pro, Qwen3.5-Omni）仍然以这种方式开始-编码器从ViT变为DINOv2到SigLIP 2，添加了寄存器令牌，位置方案变为2D-RoPE，但原始保留。本课端到端阅读补丁令牌管道，并在stdlib Python中构建它，以便第12阶段的其余部分对“可视化令牌”有一个具体的心智模型。

**Type:** Learn
**Languages:** Python (stdlib, patch tokenizer + geometry calculator)
**Prerequisites:** Phase 7 (Transformers), Phase 4 (Computer Vision)
**Time:** ~120 minutes

## 学习目标

- 将HxWx3图像转换为具有正确位置编码的补丁标记序列。
- 计算给定（补丁大小、分辨率、隐藏亮度、深度）的ViT的序列长度、参数计数和FLOPs。
- 请说出使ViT从2020年的研究到2026年的生产的三个升级：自监督预训练（DINO / MAE）、注册令牌和原生分辨率打包。
- 在CLS池、平均池和为下游任务注册令牌之间进行选择。

## 这个问题

Transformer作用于向量序列。文本已经是一个序列（字节或记号）。图像是由三个颜色通道组成的二维像素网格，而不是序列。如果您将每个像素都扁平化，那么224x224 RGB图像将变成150,528个标记，并且在该长度上的自注意力是不可能的（序列长度为二次元）。

2020年之前的方法将CNN特征提取器固定在前面：ResNet生成2048个dim向量的7x7特征图，将这49个令牌馈送到Transformer。这是有效的，但继承了CNN的偏见（翻译等方差，局部接受场），并失去了Transformer对规模的胃口。

Dosovitskiy等人（2020）提出了一个直截了当的问题：如果我们跳过CNN会怎么样？将图像分割成固定大小的小块（比如16x16像素），将每个小块线性投影到向量中，添加位置嵌入，并将序列馈送到普通转换器。在当时，这是异端邪说——没有复杂的视觉。有了足够的数据（JFT-300M，然后是LAION），它在ImageNet上击败了ResNet，并不断改进。

到2026年，ViT原始是毫无疑问的基础。每个开权重VLM的视觉塔都是一些后代（DINOv2, SigLIP 2， CLIP， EVA, intervit）。问题不再是“我们应该使用补丁吗？”而是“什么补丁大小，什么分辨率计划，什么预训练目标，什么位置编码”。

## 这个概念

### 补丁作为令牌

给定一个图像每个补丁都是一个将每个立方体压成a应用一个共享的线性投影

对于vitb /16规范配置：
- 分辨率224，补丁大小16→网格14x14→196个补丁令牌。
- 每个补丁都是
- 添加一个可学习的

patch投影在数学上与具有核大小的2D卷积相同这就是生产代码实际实现它的方式“线性投影”框架是概念性的；内核帧是有效的。

### 位置嵌入

补丁没有固有的顺序——Transformer把它们看作一个袋子。早期的vit添加了一个可学习的1D位置嵌入（每个位置一个768-dim向量，共197个）。工作，但将模型绑定到训练分辨率：在推理中，如果您更改网格，则必须插入位置表。

现代视觉主干使用2D- rope （Qwen2-VL的M-RoPE， SigLIP 2的默认值）或分解的2D位置。2D- rope根据patch的（行、列）索引旋转查询和键向量，因此模型从旋转角度推断相对2D位置。没有位置表。该模型在推理时处理任意网格大小。

### CLS令牌、池化输出和注册令牌

什么是图像级表示？三种选择并存：

1. Z0在patch序列前加入一个可学习的向量。在所有转换器块之后，CLS令牌的隐藏状态是图像表示。遗传自BERT。原装ViT、CLIP使用。
2. 意思是池。取patch令牌输出隐藏状态的平均值。用于SigLIP， DINOv2，大多数现代vlm。
3. 注册标记。Darcet等人（2023）观察到，在没有明确sink令牌的情况下训练的vit会开发出劫持自我注意力的高规范“工件”补丁。添加4-16个可学习的寄存器令牌吸收了这个负载，提高了密集预测的质量（分割，深度）。DINOv2和SigLIP 2都带有寄存器。

选择对下游任务很重要。CLS可以很好地进行分类。对于向LLM提供补丁令牌的vlm，可以完全跳过池化—每个补丁都成为LLM输入令牌。寄存器在移交之前被丢弃（它们是脚手架，而不是内容）。

### 预训练：监督式、对比式、蒙面式、自蒸馏式

在JFT-300M上对2020 ViT进行监督分类预训练。很快被：

- CLIP (2021): 400M对的对比图像-文本。12.02课。
- MAE (2021, He et .)：掩码75%的patch，重构像素。自我监督，纯图像工作。
- DINO (2021) / DINOv2(2023)：自蒸馏与学生-教师，没有标签，没有说明文字。2023 DINOv2 vitg /14是最强的纯视觉支柱，也是“密集功能”用例的默认配置。
- SigLIP / SigLIP 2(2023,2025)：具有s形损失和原生宽高比的NaFlex的CLIP。主导视觉塔在2026年开放VLMs （Qwen, Idefics2, LLaVA-OneVision）。

预训练的选择决定了主干的优点：CLIP/SigLIP用于与文本的语义匹配，DINOv2用于密集的视觉特征，MAE作为下游微调的起点。

### 比例法

ViT缩放（Zhai et al. 2022）建立了ViT的质量在模型大小、数据大小和计算上遵循可预测的规律。固定计算：
- 更大的模型+更多的数据→更好的质量。
- 补丁大小是序列长度与保真度的杠杆。补丁14（典型的DINOv2/SigLIP SO400m）给每个图像更多的令牌比补丁16；对OCR和密集任务更好，对速度更差。
- 决心是另一个重要的杠杆。从224到384再到512几乎总是有帮助的，在FLOPs中代价是二次的。

viti -g/14 （1B params, patch 14，分辨率224→256令牌）和SigLIP SO400m/14 （400M params, patch 14）是2026开放VLMs的两个主要编码器。

### ViT的参数计数

完整的计算在ViT-B/16在224：

```
patch_embed = 3 * 16 * 16 * 768 + 768  =  591k
cls + pos    = 768 + 197 * 768          =  152k
block        = 4 * 768^2 (QKVO) + 2 * 4 * 768^2 (MLP) + 2 * 2*768 (LN)
             = 12 * 768^2 + 3k          =  7.1M
12 blocks    = 85M
final LN    = 1.5k
total       ≈ 86M
```

在你装载检查点之前，把每个ViT都放在这里。主干大小在任何下游VLM中设置VRAM层。

### 2026生产配置

2026年最开放的vlm编码器是原生分辨率（NaFlex）的SigLIP 2 SO400m/14。它有:
- 400的参数。
- 补丁大小14，默认分辨率384→每个图像729个补丁令牌。
- 图像级任务的平均池；所有729个补丁都流入VQA的LLM。
- 4个注册令牌，在LLM移交之前被丢弃。
- 2D-RoPE与图像级缩放原生宽高比。

这个配置中的每一个决定都可以追溯到一篇你可以阅读的论文。

## 使用它

Z0它需要（图像H， W, patch P, hidden D, depth L）并报告：

- 网格形状和修补后的序列长度。
- 合成8x8像素玩具图像的令牌序列（遍历flatten +项目路径）。
- 按补丁嵌入、位置嵌入、Transformer块和磁头划分的参数计数。
- 在目标分辨率下，每个正向传递的FLOPs。
- viti - b /16 @ 224, viti - l /14 @ 336, DINOv2 viti -g/14 @ 224， SigLIP SO400m/14 @ 384的比较表。

运行它。将参数计数与发布的号码进行匹配。使用补丁大小和分辨率来感受令牌计数成本。

## 船这

这一课产生了给定一个ViT配置（补丁大小、分辨率、隐藏亮度、深度），它会产生一个令牌计数、参数计数和VRAM估计。当你为VLM选择一个视觉支柱时，使用这个技能——它可以防止“令牌爆炸，我的LLM上下文被填满”的意外。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Patch | "16x16 pixel square" | A fixed-size non-overlapping region of the input image; becomes one token |
| Patch embedding | "Linear projection" | A shared learned matrix (or Conv2d with stride=P) mapping flattened patch pixels to D-dim vectors |
| CLS token | "Class token" | Prepended learnable vector whose final hidden state represents the whole image; optional in 2026 |
| Register token | "Sink token" | Extra learnable tokens that absorb the high-norm attention artifacts ViTs develop during pretraining |
| Position embedding | "Positional info" | Per-position vector or rotation making the sequence-order-aware; 2D-RoPE is the modern default |
| Grid | "Patch grid" | The (H/P) x (W/P) 2D array of patches for a given resolution and patch size |
| NaFlex | "Native flexible resolution" | SigLIP 2 feature: single model serves multiple aspect ratios and resolutions without retraining |
| Backbone | "Vision tower" | The pretrained image encoder whose patch-token outputs feed the LLM in a VLM |
| Pooling | "Image-level summary" | Strategy to turn patch tokens into one vector: CLS, mean, attention pool, or register-based |
| Patch 14 vs 16 | "Finer vs coarser grid" | Patch 14 produces more tokens per image, better fidelity for OCR, slower; patch 16 is the classic default |
