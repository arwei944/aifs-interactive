# 工具使用和函数调用

> Toolformer （Schick et al., 2023）开始了自监督工具标注。伯克利函数调用排行榜V4 （Patil et al, 2025）设定了2026年的标准：40%的代理，30%的多回合，10%的实时，10%的非实时，10%的幻觉。解决了单匝。记忆、动态决策和长期工具链则不是。

**Type:** Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 · 01 (Agent Loop), Phase 13 · 01 (Function Calling Deep Dive)
**Time:** ~60 minutes

## 学习目标

- 解释Toolformer的自监督训练信号：只有在执行减少下一个令牌损失时才保留工具注释。
- 说出BFCL V4的五个评估类别以及每个评估类别的衡量标准。
- 实现具有模式验证、参数强制转换和执行沙箱的标准库工具注册表。
- 诊断2026年的三个开放问题：长期工具链，动态决策和记忆。

## 这个问题

早期的工具使用问：模型能预测正确的函数调用吗？现代工具的使用提出了这样的问题：模型能否将工具链过40个步骤，具有记忆，具有部分可观察性，能够从工具故障中恢复，而不会产生不存在的工具的幻觉？

Toolformer建立了基线：模型可以通过自我监督学习何时调用工具。BFCL V4def 了2026年评估目标。它们之间的差距就是生产代理生存的空间。

## 这个概念

### 工具训练（Schick等人，NeurIPS 2023）

想法：让模型用候选API调用注释自己的预训练语料库。对于每个候选项，执行它。只有当包含工具结果减少了下一个标记的损失时，才保留注释。对过滤后的语料库进行微调。

工具涵盖：计算器，QA系统，搜索引擎，翻译，日历。自我监督信号纯粹是关于该工具是否有助于预测文本，而不是人类标签。

规模结果：工具使用在规模上出现。较小的模型受到工具注释的伤害；更大的模型。这就是为什么2026前沿模型具有强大的工具使用，而大多数7B模型需要明确的工具使用微调才能可靠。

### 伯克利函数调用排行榜V4 （Patil et al., ICML 2025）

BFCL是2026年的实际评估。V4组成:

- **代理(40%)** -全代理轨迹：记忆，多回合，动态决策。
- **多回合(30%)** -与工具链的互动对话。
- **Live(10%)** -用户提交的真实提示（更难分发）。
- **Non-Live(10%)** -合成测试用例。
- **幻觉(10%)** -当不需要调用工具时检测。

V3引入了基于状态的评估：在一个工具序列之后，检查API的实际状态(例如：“文件创建了吗？”)而不是匹配工具调用的AST。V4增加了web搜索、内存和格式敏感性类别。

关键2026发现：单轮函数调用接近解决。失败集中在记忆（在回合中携带上下文），动态决策（基于先前结果选择工具），长视界链（在20多个步骤后漂移）和幻觉检测（当没有合适的工具时拒绝调用）。

### 工具模式

每个提供者都有一个模式。它们在细节上不同，但形状相同：

```
name: string
description: string (what it does, when to use it)
input_schema: JSON Schema (properties, required, types, enums)
```

人为利用OpenAI使用两者都接受JSON模式。描述是承载的——模型读取它们来选择正确的工具。错误的工具描述是错误选择工具失败的首要原因。

### 参数验证

不要相信工具命令。验证:

1. **类型强制转换。**模型可能返回一个字符串“5”，而模式是int。强迫如果不明确；如果不是，请拒绝。
2. ** Enum验证。**如果模式说
3. **必填字段。**缺少必需的字段->立即错误观察返回到模型，而不是崩溃。
4. **格式验证。**日期，电子邮件，url -验证具体的解析器，而不是正则表达式。

每次验证失败都应该返回一个结构化的观察结果，这样模型就可以用正确的形状进行重试。

### 并行工具调用

现代供应商支持在一个辅助回合中并行调用工具。循环:

1. 模型发出3个不同的工具调用
2. 运行时执行它们（如果独立，则并行执行）。
3. 每个结果作为a返回

工程规则：将相关id视为承重。交换它们，你会得到错误的工具到错误的结果路由。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Function calling | "Tool use" | Structured-output tool invocation with validated schema |
| Toolformer | "Self-supervised tool annotation" | Schick 2023 — keep tool calls whose results reduce next-token loss |
| BFCL | "Berkeley Function Calling Leaderboard" | 2026 benchmark: 40% agentic, 30% multi-turn, 10% live, 10% non-live, 10% hallucination |
| Tool schema | "Function signature for the model" | name, description, JSON Schema of arguments |
| tool_use_id | "Correlation ID" | Ties a tool call to its result; essential for parallel dispatch |
| Hallucination detection | "Know when not to call" | V4 category: refuse to call when no tool fits |
| Argument coercion | "String-to-int repair" | Narrow fixes for predictable schema-mismatch; reject if ambiguous |
| Sandboxing | "Tool execution boundary" | Per-tool read/write surface, network, timeout, memory cap |
