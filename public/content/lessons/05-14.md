## 这个问题

用户输入“如果有人为了赚钱而撒谎会发生什么”，并期望找到真正涵盖这一点的法规：“IPC第420条”。关键字搜索完全忽略了它（没有共享词汇表）。如果嵌入没有经过法律文本的训练，语义搜索就会错过它。真正的搜索必须同时处理这两者。

IR是每个RAG系统、每个搜索栏、每个文档站点的模糊查找下的管道。在生产环境中工作的2026架构并不是一个单一的方法。它是一系列互补的方法，每一个方法都弥补了前一个方法的失败。

这一课构建了每个部分，并命名了每个捕获的失败。

## 这个概念

Z0

四层。选择你需要的。

1. **稀疏检索（BM25）**快速，精确匹配，糟糕的语义。运行一个倒排索引。对数百万个文档的每次查询少于10毫秒。让你的法律参考，产品代码，错误信息，命名实体正确。
2. * *密集的检索。**将查询和文档编码为向量。最近邻搜索。捕捉释义和语义相似性。错过相差一个字符的精确关键字匹配。使用FAISS或矢量DB的每个查询50-200ms。
3. * *融合。**合并稀疏和密集的排名列表。互惠排名融合（RRF）是一种简单的默认设置，因为它忽略了原始分数（存在于不同的尺度中），并且只使用排名位置。加权融合是一种选择，当你知道一个信号主导你的领域。
4. * * Cross-encoder rerank。**前30名来自核聚变。运行交叉编码器（查询+文档一起，对每一对进行评分）。保留前5名。交叉编码器每对比双编码器慢，但更准确。你只在前30名中运行它们来摊销。

在2026年的基准测试中，三向检索（BM25 +密集+像SPLADE一样的学习稀疏）优于双向检索，但需要为学习稀疏索引提供基础设施。对于大多数团队来说，双向加上交叉编码器重新排名是最佳选择。

### Step 2: dense retrieval with a bi-encoder

```python
from sentence_transformers import SentenceTransformer
import numpy as np


def build_dense_index(corpus, model_id="sentence-transformers/all-MiniLM-L6-v2"):
    encoder = SentenceTransformer(model_id)
    embeddings = encoder.encode(corpus, normalize_embeddings=True)
    return encoder, embeddings


def dense_search(encoder, embeddings, query, top_k=10):
    q_emb = encoder.encode([query], normalize_embeddings=True)
    sims = (embeddings @ q_emb.T).flatten()
    order = np.argsort(-sims)[:top_k]
    return [(float(sims[i]), int(i)) for i in order]
```

l2归一化嵌入所以点积等于余弦。`all-MiniLM-L6-v2` is 384-dim, fast, and strong enough for most English retrieval. 对于多语言工作，使用为了达到最高的精确度，

The `k=60` constant comes from the original RRF paper. Higher `k` flattens the contribution of rank differences; lower `k` makes top ranks dominate. 60 is the published default and rarely needs tuning.

### Step 4: hybrid search + rerank

```python
from sentence_transformers import CrossEncoder

reranker = CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2")


def hybrid_search(query, bm25, encoder, dense_embeddings, corpus, top_k=5, pool_size=30, reranker=reranker):
    sparse_ranking = bm25.rank(query, top_k=pool_size)
    dense_ranking = dense_search(encoder, dense_embeddings, query, top_k=pool_size)
    fused = reciprocal_rank_fusion([sparse_ranking, dense_ranking])[:pool_size]

    pairs = [(query, corpus[doc_idx]) for _, doc_idx in fused]
    scores = reranker.predict(pairs)
    reranked = sorted(zip(scores, [doc_idx for _, doc_idx in fused]), reverse=True)
    return reranked[:top_k]
```

三个阶段组成。BM25查找词汇匹配。Dense查找语义匹配。RRF在不需要分数校准的情况下合并了两个排名。交叉编码器使用查询文档对一起重新检索前30个，这捕获了双编码器错过的细粒度相关性。保持前五名。

### 第五步：评估

| Metric | Meaning |
|--------|---------|
| Recall@k | Of queries where the correct document exists, how often is it in the top-k? |
| MRR (Mean Reciprocal Rank) | Average of 1/rank of first relevant document. |
| nDCG@k | Accounts for relevance gradations, not just binary relevant/not. |

具体到RAG，寻回犬的**Recall@k**是最重要的数字。如果正确的文章不在检索集中，读者就无法回答。

调试提示：对于失败的查询，区分稀疏和密集的排名。如果其中一个找到了正确的文档，而另一个没有，那么就出现了词汇表不匹配（修复：添加缺失的那一半）或语义模糊（修复：更好的嵌入或重新排序）。

## 使用它

2026年的堆栈：

| Scale | Stack |
|-------|-------|
| 1k-100k docs | In-memory BM25 + `all-MiniLM-L6-v2` embeddings + RRF. No separate DB. |
| 100k-10M docs | FAISS or pgvector for dense + Elasticsearch / OpenSearch for BM25. Run in parallel. |
| 10M+ docs | Qdrant / Weaviate / Vespa / Milvus with hybrid support. Cross-encoder rerank on top-30. |
| Best-quality frontier | Three-way (BM25 + dense + SPLADE) + ColBERT late-interaction reranking |

无论你选择什么，预算评估。在对端到端RAG准确性进行基准测试之前对检索召回率进行基准测试。阅读器无法修复猎犬错过的东西。

### 来之不易的教训，从2026年生产RAG

- **80%的RAG故障归咎于摄取和分块，而不是模型。**团队花费数周时间交换llm和调优提示，而检索每三次查询就悄悄地返回错误的上下文。先解决分块问题。
- **分块策略比块大小更重要。**固定大小拆分表，代码和嵌套头。句子感知是默认的；语义或基于法学硕士的分块处理对技术文档和产品手册是有益的。
- * * Parent-doc模式。**检索小的“子”块的精度。当出现来自同一父节的多个子节时，在父块中交换以保留上下文。这可以在不进行再培训的情况下持续提高回答质量。
- **k_rerank=3通常是最优的。**每一个额外的块过去，增加令牌成本和生成延迟，而不提高回答质量。如果k=8对你来说仍然比k=3好，那么重新排名者表现不佳。
- **HyDE /查询扩展。**从查询中生成一个假设的答案，嵌入，检索。弥合短问题和长文档之间的措辞差距。免费精密升降，无需培训。
- **背景预算低于8K代币。**在这个限制下的持续命中意味着重新排名的门槛太松了。
- * *所有版本。**提示，分块规则，嵌入模型，重新排序。任何漂移都无声地破坏了回答质量。CI在用户看到它们之前，对忠实度、上下文精度和未回答问题率进行限制。
- **在2026年的基准测试中，三向检索（BM25 +密集+像SPLADE一样的学习稀疏）优于双向检索，特别是对于混合专有名词和语义的查询。在基础设施支持SPLADE索引时发布它。

根据2026年的行业测量，适当的检索设计可以减少70-90%的幻觉。大多数RAG性能提升来自更好的检索，而不是模型微调。

## Key Terms

| Term | What people say | What it actually means |
|------|-----------------|-----------------------|
| BM25 | Keyword search | Okapi BM25. Scores documents by term frequency, IDF, and length. |
| Dense retrieval | Vector search | Encode query + doc into vectors, find nearest neighbors. |
| Bi-encoder | Embedding model | Encodes query and doc independently. Fast at query time. |
| Cross-encoder | Reranker model | Encodes query + doc together. Slow but accurate. |
| RRF | Rank fusion | Combine two rankings by summing `1/(k + rank)`. |
| Recall@k | Retrieval metric | Fraction of queries where a relevant doc is in the top-k. |
