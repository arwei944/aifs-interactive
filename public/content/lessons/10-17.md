# Native Sparse Attention (DeepSeek NSA)

> At 64k tokens, attention consumed 70-80% of the decoding delay. Every Open model laboratory has a solution. DeepSeek's NSA (ACL 2025 Best Paper) is one of them: three parallel attention branches - compressed coarse-grained tokens, selectively retained fine-grained tokens, and a sliding window of local context - are combined through a learning gate. It is hardware-aligned (kernel-friendly), natively trainable (working in pre-training rather than binding in inference), and at 64k decoding, it runs faster than FlashAttention while matching or exceeding full attention quality. This lesson will build these three branches end-to-end and explain why sparsity is end-to-end differentiable.

## This question

Full focus at the cost of sequence length N for 64k tokens is disastrous in terms of computational and memory bandwidth figures. The measurement theory from the NSA paper estimates that at 64k, attention accounts for 70-80% of the total decoding delay. Everything downstream - TTFT, tokens per second, cost per million tokens - is dominated by the cost of attention.

Distraction is the obvious answer. Previous attempts can be divided into two categories. Fixed pattern sparsity (sliding window, step, block local) will discard information and fail in remote recall tasks. Inference time sparsity (KV cache pruning, H2O, StreamingLLM) is applied to models with intensive attention pre-training. Since the models have never been required to route information through sparse patterns, only a small portion of the potential acceleration is restored.

Native sparse attention (Yuan et al., DeepSeek + PKU + UW, ACL 2025 Best Paper, arXiv:2502.11089) has both: sparse patterns learned by the model during pre-training, implemented as a kernel alignment algorithm, actually providing computational savings during inference. Two years from now, the NSA or its immediate descendants will become the default focus of every cutting-edge long-term background model.

## This concept

### Three parallel branches

For each query, NSA runs attention three times against the three different views of the KV cache:

1. "Compress branches." The token is divided into large and small blocks, and each block is compressed into a single summary token through a small learning MLP. Query and process these compressed tokens to obtain a coarse-grained view of the entire sequence.

2. Select a branch. Use the attention score from the compressed branch to identify the top-k blocks that are most relevant to the current query. Read fine-grained (uncompressed) tokens from these blocks and then query and process all these tokens. The compressed branch attention can be regarded as the selected routing signal.

3. "Sliding window branch." The query focuses on the recent branch capturing short-range schemas (syntax, local co-references) of restructures that the other two branches might have missed.

The three branch outputs are combined through each position gate learned:

```
out = g_cmp * out_cmp + g_sel * out_sel + g_win * out_win
```

### Why is this "naturally trainable"

The selection steps (top-k blocks) are discrete. Discrete operations break the gradient flow. Previous sparse attention works either chose to skip reverse support (restricted training) or used continuous relaxation, which could not provide true sparsity during inference.

The NSA evades this point: compressed branch attention is a differentiable coarse-grained attention over the entire sequence. The top-k operation merely reuses the highest attention score from the compressed branch to select the fine-grained block to be loaded. The gradient flows through the compression branch fraction (affecting the compression output and selection logic), and the contribution of the selected block to the final output is also differentiable. This is why NSA can be used for end-to-end pre-training. This model learns to route information through three branches together, generating a sparse pattern that actually provides promised acceleration during inference.

### Hardware-aligned kernel

The core of NSA is designed for the modern GPU memory hierarchy. The kernel loads the query through GQA groups (external loop), each group (internal loop) acquires the corresponding sparse KV block, and runs the attention on SRAM. Because each query group sees the same selection block (selections are made by query group rather than by query header), the KV load is evenly distributed within the group. The arithmetic intensity remains very high.

The paper reports that the Triton kernel is 9 times faster than FlashAttention at 64k decoding, and the speedup ratio increases with the growth of sequence length. It provides both forward and backward kernels.

### Step 2: compressed-branch attention

Run softmax attention of the query against the compressed keys. The compressed-branch scores double as the signal for top-k selection.

### Step 3: top-k block selection

Pick the indices of the `k` highest-scoring compressed blocks. Load the original uncompressed tokens from those blocks and run attention on them.

### Step 4: sliding-window attention

Take the last `w` tokens and run standard attention against them.

### Step 5: gate + combine

A small MLP on the query produces three gate weights. The final output is a weighted sum of the three branch outputs.

### Step 6: compute counting

Print the number of keys attended per query for each branch and the total. Compare to `N` (full attention). On a 1024-token synthetic with `l = 32, k = 4, w = 128`, NSA sees `32 + 128 + 128 = 288` keys per query versus 1024 for full attention — 3.5x fewer.

## Use It

NSA is shipping in DeepSeek's own long-context pre-training pipeline. Integration status in public inference stacks as of April 2026:

- **DeepSeek internal**: native, published weights use NSA or its successor DSA (Deepseek Sparse Attention).
- **vLLM**: experimental NSA support in development for DeepSeek-V3.x weights.
- **SGLang**: NSA benchmarks published; production path follows vLLM.
- **llama.cpp / CPU**: not supported; overhead of the kernel decomposition is not worth it at CPU throughput.

When to reach for NSA:

- Pre-training or continued-training run targeting 64k-plus context with a serious compute budget.
- Inference of DeepSeek's own long-context checkpoints. The weights are NSA-native.

When not to:

- Serving an existing dense-attention pre-trained model. You cannot retrofit NSA without continued training.
- Context under 16k. The three-branch overhead dominates the savings.
- Batch-1 interactive chat. Latency-sensitive decode benefits, but only at long contexts.

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Compressed branch | "Coarse view" | Attention over block-averaged keys that provides global context in O(N/l) keys per query |
| Selected branch | "Top-k blocks" | Fine-grained attention over the `k` blocks with highest compressed-branch scores |
| Sliding window | "Local context" | Attention over the last `W` tokens for short-range patterns |
| Native trainability | "Pre-train with the sparsity on" | The sparsity pattern is learned during pre-training, not bolted on at inference |
| Compression block size l | "Group size for coarse view" | How many tokens get merged into one summary; 32-64 typical |
| Top-k | "Blocks to keep" | Number of compressed blocks whose uncompressed tokens get read; 16 typical |
| Sliding window W | "Local attention radius" | Typically 512; shorter hurts local coherence, longer wastes compute |
| Branch gate | "How to mix the three" | Per-position MLP output that weights the three branches' contributions |
| Hardware alignment | "Kernel-friendly sparsity" | Sparse pattern chosen so that the actual GPU kernel achieves the theoretical speedup |
| DSA | "NSA's successor" | Deepseek Sparse Attention, the architecture that followed NSA in DeepSeek's lineage |
