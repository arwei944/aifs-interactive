# 人工智能的SRE -多代理事件响应，Runbooks，预测性检测

> AI SRE通过RAG使用基于基础设施数据（日志、运行簿、服务拓扑）的llm来自动化调查、文档和协调阶段。2026架构模式是多代理编排——由主管协调的专门代理（日志、指标、运行簿）；人工智能提出假设和疑问，人类批准判断。Datadog Bits AI和Azure SRE Agent作为托管产品发布。runbook在不断发展：NeuBird Hawkeye使用对抗性评估（两种模型分析同一事件；一致=信心，不一致=不确定性）；操作记忆在团队变更期间持续存在。自动修复保持谨慎：人工智能建议，人类批准。完全自主的行动是狭窄的（重启pod，回滚特定部署），有严格的限制——任何卖“设置后就忘了”的人都是超卖。新兴前沿：事件前预测。麻省理工学院的研究报告称，经过历史日志+ GPU温度+ API错误模式训练的LLM提前10-15分钟预测了89%的中断。预测：到2026年底，95%的企业法学硕士将实现自动故障转移。

**Type:** Learn
**Languages:** Python (stdlib, toy multi-agent incident triage simulator)
**Prerequisites:** Phase 17 · 13 (Observability), Phase 17 · 24 (Chaos Engineering)

## 学习目标

- 绘制多代理AI SRE架构图：主管+专门代理（日志、指标、运行手册）+人工审批门。
- 解释为什么自动修复是狭义的（重启pod，恢复部署）而不是广义的（重新架构师服务）。
- 命名对抗性评价模式（NeuBird Hawkeye）：两个模型一致=置信度；不同意=升级。
- 以麻省理工学院89%的早期检测结果和操作约束为例：没有驱动的预测只是仪表板。

## 这个问题

一个随叫随到的工程师在凌晨3点被传呼。“结帐错误率高。”他们检查数据狗，洛基，三本运行日志，部署日志。30分钟后，他们意识到根本原因是千伏缓存尖峰产生的vLLM OOM。他们重新启动舱；清除错误。

2026年，调查的前20分钟是自动化的。按服务对日志进行分组，与最近的部署相关联，与运行本进行匹配——所有这些都是RAG +工具使用。受监督的代理可以在人类打开Datadog之前进行第一次筛选并提出假设。

完全自主的补救是另一个问题。重启pod：安全。缩放GPU池：在策略允许的情况下安全。重新构建服务：绝对不行。纪律是划清界限的。

## 这个概念

### 多代理体系结构

```
          Incident
             │
             ▼
        Supervisor
        /    |    \
       ▼     ▼     ▼
  Log agent  Metric agent  Runbook agent
       │     │     │
       └─────┴─────┘
             │
             ▼
        Hypothesis + evidence
             │
             ▼
        Human approval
             │
             ▼
        Action (narrow set)
```

Supervisor将事件分解为子查询。专门的代理具有工具访问权限（日志搜索、PromQL、文档检索）。管理者综合，向人提出假设+证据。人工批准或重定向。

### Auto-remediation范围

**安全（窄）**：重启pod，恢复特定部署，在预先批准的范围内扩展池，启用预先批准的功能标志。

**不安全（广泛）**：更改服务拓扑，修改资源限制，部署新代码，更改IAM，更改数据库。

任何兜售“设定了就忘了”的人都是过度销售。安全组随着人工智能SRE的成熟而增长，但边界是真实存在的。

### 对抗性评估（新鸟鹰眼）

两个模型独立分析同一事件。如果他们在根本原因上达成一致，信心就会很高。如果他们不同意，升级到人类，两种假设都可见。简单的模式，有效过滤幻觉的根源。

### 运行内存

团队更替是传统SRE部落知识叶的无声杀手。AI SRE将运行手册和事后分析存储在矢量数据库中；探员对每一个新事件都进行检索。当新工程师加入时，人工智能就有了完整的历史。

### 事前预测

麻省理工学院2025研究：LLM通过历史日志、GPU温度、API错误模式进行训练，在测试集中发生故障前10-15分钟预测89%的故障。

现实检查：没有行动的预测是仪表板。操作性问题是“当我们预测时，我们该怎么做？”先发制人的流失?寻呼机?自动扩展吗?答案是特定于策略的。

### 2026年产品展望

- **Datadog Bits AI**管理的SRE副驾驶在Datadog。
- **Azure SRE代理** - Azure native。
- **新鸟鹰眼** -对抗评估+操作记忆。
- **PagerDuty AIOps** -分类+重复数据删除。
- * *事件。自动驾驶** -事件指挥官+协调。

### runbook作为代码

runbook从汇流页演变为带有结构化部分（症状、假设、验证、行动）的版本标记。结构化的runbook提供了更好的RAG检索。通过将非结构化的runbook转换为结构化来启动任何AI-SRE的推出。

### 你应该记住的数字

- MIT早期检测：89%的中断，10-15分钟的提前期。
- 多代理分类：主管+（日志、指标、运行手册）+人。
- 安全的自动修复集：重新启动pod，恢复部署，在限定范围内扩展。
- 对抗性评估：两种模型独立；同意=信任。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| AI SRE | "agent for on-call" | LLM-backed incident investigation + coordination |
| Supervisor agent | "the orchestrator" | Top-level agent breaking incidents into sub-queries |
| Specialized agent | "domain agent" | Sub-agent with tool access (logs, metrics, runbooks) |
| Auto-remediation | "AI fixes it" | Narrow pre-approved action; NOT broad re-architecture |
| Operational memory | "vector runbooks" | Post-mortems + runbooks in vector DB for RAG |
| Adversarial eval | "two-model check" | Independent analyses; agreement = confidence |
| NeuBird Hawkeye | "the adversarial one" | Product with adversarial-eval + memory pattern |
| Bits AI | "Datadog's SRE agent" | Datadog-managed AI SRE |
| Pre-incident prediction | "early detection" | 10-15 min lead time on outage prediction |
