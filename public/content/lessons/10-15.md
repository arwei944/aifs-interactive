### Two years of progress

*Vanilla Speculation (Leviathan, 2023). The draft model is a smaller LLM independently trained from the same family. It's very easy to connect

*EAGLE-1 (Li et., 2024). Draft is a very small transformer - usually one or two layers - that takes the last layer of the validator's hidden state as input and directly predicts the next token. Because the draft has seen the feature representation of the validator, its distribution is closer to that of the validator. `α` climbs to 0.7–0.8.

*EAGLE-2 (Li et., 2024). A dynamic draft tree has been added: instead of proposing a single sequence, the draft length at each step has become adaptive. `α` per accepted-path token climbs above 0.85.

*EAGLE-3 (Li et al., 2025, NeurIPS). There are still two changes. Firstly, completely abandon the feature prediction loss - EAGLE-1/2 training draft to match the hidden state of the validator, which limits the help of the data. EAGLE-3 is trained directly on token prediction. Second, Training Time Test (TTT) : During the draft training period, the draft's own previous predictions are used as input feedback for multiple steps, operating in the same way as during inference. This will align the training and test distributions and prevent error accumulation. Measurement acceleration: Up to 6.5 times on chat and a 38% increase in the 64th batch throughput in SGLang on H100.

### Kilovolt cache rollback

Verification extends the validator's KV cache to two common implementations if a rejection occurs at a location: write to a temporary buffer and commit upon acceptance (vLLM, TensorRT-LLM), or retain the physical KV cache plus the logical length and truncate upon rejection. No matter which way it is, the rollback cost is the number of bytes per layer and per header, which can be ignored compared with the forward passing cost.

For EAGLE-2 tree search, the validator runs attention using a non-causal mask that respects the tree topology. Engineering is meticulous, but the calculation is a standard flash attention call with a custom mask.

When to reach for speculative decoding:

- Any interactive chat workload where p50 latency matters more than peak throughput.
- Code generation and structured output (JSON, SQL). `α` is above 0.9 because the target distribution is highly predictable.
- Long-form generation (thousands of tokens). The amortized speedup keeps paying.

When not to:

- Very small models (< 3B). The draft is not that much cheaper than the verifier.
- Tiny batch-1 CPU deployments. Memory overhead of the draft model may not be worth it.
- Very-high-temperature creative sampling where `α` collapses.

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Leviathan rule | "min(1, q over p)" | Bernoulli accept/reject with probability `min(1, q(d)/p(d))`, preserves the verifier distribution exactly when you sample from the residual on rejection |
| Residual distribution | "(q minus p) plus, normalized" | `(q - p)_+` clamped at zero and renormalized — the correct distribution to sample from on rejection |
| Acceptance rate α | "how often the draft is right" | Expected per-token Bernoulli-success probability under the rejection rule; governs all speedup math |
| EAGLE-1 | "hidden-state draft" | Tiny transformer draft conditioned on the verifier's last-layer hidden state (Li et al., 2024) |
| EAGLE-2 | "dynamic draft tree" | EAGLE-1 plus a tree of candidate continuations scored with tree attention in one verifier pass |
| EAGLE-3 | "training-time test" | Drops the feature-prediction loss, trains on direct token prediction with the draft fed its own outputs during training |
| Training-time test (TTT) | "exposure bias fix" | Run the draft autoregressively during training so train and test input distributions match — the direct analog of scheduled sampling |
| KV rollback | "undo rejected drafts" | Bookkeeping that resets the verifier's KV cache to the accepted-prefix length after a rejection |
| Bonus token | "the free one" | When all `N` drafts accept, sample one extra from `q_{N+1}` at no additional verifier cost |
| Tree attention | "verify many candidates at once" | Attention with a non-causal mask that respects the topology of a draft tree; computes `q_i` for every node in the tree in one forward pass |
