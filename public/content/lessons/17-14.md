# 提示缓存和语义缓存经济学

> ** 2026-04年的价格快照。**下面的数字索赔反映了本课出版时捕获的供应商费率卡；在将链接的文档引用到下游之前，对其进行验证。

> 缓存发生在两层。L2（提供商级）提示/前缀缓存重用注意KV，用于重复的前缀——Anthropic的提示缓存文档宣称，对于长提示，可以减少高达90%的成本和85%的延迟；对于Claude 3.5十四行诗缓存读取为0.30美元/M，而新鲜的5分钟TTL为3.00美元/M， 1小时TTL选项为2倍的写入溢价（docs.anthropic.com, 2026-04）。OpenAI提示缓存自动应用于提示≥1024个令牌，并以大约90%的折扣缓存输入与新鲜（platform.openai.com, 2026-04）；确切的每个模型缓存速率取决于实时速率卡。L1（应用程序级）语义缓存在嵌入相似点时完全跳过LLM。供应商的“95%准确度”指的是匹配正确性，而不是命中率——报告的生产命中率范围从10%（开放式聊天）到70%（结构化常见问题解答）；这两个提供者都没有发布官方基线，因此将它们视为社区遥测而不是保证。生产陷阱：并行化会破坏缓存（在第一次写入缓存之前发出的N个并行请求可能会使开销增加几倍），前缀中的动态内容完全阻止缓存命中。ProjectDiscovery报告说，通过将动态文本移出可缓存前缀，命中率从7%提高到74%（2025-11）。

## 学习目标

- 区分L2提示/前缀缓存（在提供商处重用KV）和L1语义缓存（在类似提示上绕过LLM）。
- 解释人类的
- 根据命中率、及时/响应组合和代币价格计算预期的每月节省。
- 命名使账单膨胀5-10倍的并行化反模式和降低命中率的动态内容反模式。

## 这个问题

您向您的RAG服务添加提示缓存。账单保持不变。你测量命中率；是7%。您的提示看起来是静态的，但实际上并非如此——系统提示包括以分钟为单位的当前日期、请求ID和为了多样性而随机化的重新排序示例。每个请求写入一个新的缓存条目，读取0。

另外，您的代理为每个用户问题运行10个并行工具调用。所有这些都在第一次缓存写完成之前到达提供程序。10个写，0个读。你的账单是“使用缓存”应该花费的5-10倍。

缓存是一种协议，而不是标志。两层，两种不同的失效模式。

## 这个概念

### L2 -提供程序提示/前缀缓存

Provider为一个可缓存前缀存储注意力KV，并在匹配该前缀的下一个请求中重用它。你付一次写的费用，读几乎是免费的。

**Anthropic （Claude 3.5 / 3.7 / 4系列）**：明确标记哪些块是可缓存的。TTL: 5分钟（写入成本1.25倍基数）或1小时（写入成本2x基数）。缓存读取：克劳德3.5十四行诗$0.30/M比新鲜的$3.00/M便宜10倍（docs.anthropic.com，截至2026-04年）。每个模型的费率不同（单独出版的作品/俳句）；总是反复检查实时定价页面。

**OpenAI**：自动缓存提示≥1024个令牌（platform.openai.com, 2026-04）。没有明确的标志。在当前的gpt- 40 /gpt-5速率卡上，缓存输入大约比刷新便宜10倍。文档和发行说明都没有公布官方的点击率基线；通过精心的提示设计，社区报告集中在30-60%左右。监视器

**谷歌(Gemini)**：通过显式API进行上下文缓存；1m -令牌上下文意味着缓存支付更多。

**自托管(vLLM, SGLang)**：阶段17.06涵盖RadixAttention -在您自己的计算中相同的模式。

### L1 -应用程序级语义缓存

在调用LLM之前，对提示符进行散列，嵌入它，并查找类似的缓存请求（余弦相似度高于阈值，通常为0.95+）。点击后，返回缓存的响应。如果失败，调用LLM并缓存结果。

开源：Redis矢量相似性，GPTCache, Qdrant。商业广告：Portkey Cache， Helicone Cache。

供应商的准确性声明指的是返回的缓存响应在语义上是合适的频率，而不是您命中的频率。生产命中率：

- 开放式聊天：10-15%。
- 结构化FAQ /支持：40-70%。
- 代码问题：20-30%（小变体杀死命中）。
- 语音代理重复提示：50-80%（语音规范化固定设置）。

### 并行化反模式

您的代理同时调用10个工具。所有10个都有相同的4k令牌系统提示符。人为缓存写入是按请求进行的；第一次缓存写入在提供者看到提示符后大约300毫秒完成。请求2-10在同一毫秒窗口内到达，每个请求都看到缓存缺失。您支付10个写溢价，0个读折扣。

修复：批处理顺序优先-单独发出请求1，然后触发2-10一旦1的缓存已填充。第一次工具调用增加300毫秒；节省5-10倍的账单。

### 动态内容反模式

您的系统提示符看起来像：

```
You are a helpful assistant. The current time is 14:32:17.
User ID: abc123. Today is Tuesday...
```

每个请求都是独一无二的。每个请求都写。0支安打。

修正：移动所有真正静态的可缓存前缀；在缓存边界后追加动态内容：

```
[cacheable]
You are a helpful assistant. [rules, examples, instructions]
[/cacheable]
[dynamic, not cached]
Current time: 14:32:17. User: abc123.
```

ProjectDiscovery通过这种方式将缓存命中率从7%提高到74%，并发布了解剖图。

### 堆栈批处理+缓存用于夜间工作负载

批量api（第17·15阶段）在24小时周转时提供50%的折扣。在顶部缓存输入可以使您的速度提高10倍。通过堆叠，一夜之间分类、标记和报告生成工作负载可以降低到同步非缓存成本的10%左右。

### 你应该记住的数字

从链接的供应商文档中获取2026-04年的定价点，每隔几个月就会发生变化——在依赖它们之前要重新检查一下。

- Anthropic缓存读取：克劳德3.5十四行诗$0.30/M，大约比新输入便宜10倍（docs.anthropic.com）。
- 人为缓存写入溢价：1.25倍（5分钟TTL）或2x（1小时TTL）。
- OpenAI自动缓存：适用于≥1024个令牌的提示；缓存输入的价格大约是当前费率卡上新输入的10%。
- 语义缓存命中率（社区报告）：~10%开放聊天；高达70%的结构化常见问题解答。没有供应商记录的基线。
- ProjectDiscovery：通过动态移出前缀，达到7%→74%的命中率（项目博客，2025-11）。
- 并行化反模式：当N个并行请求错过第一次缓存写入时，典型的5 - 10倍的账单膨胀报告。

## 练习

1. 运行切换并行化标志。账单会改变多少？
2. 您的系统提示有一个日期。把它搬出去。显示之前/之后的命中率数学。
3. 给定请求到达率，计算1小时TTL（2倍写）vs 5分钟TTL（1.25倍写）的收支平衡。
4. 语义缓存在0.95阈值时达到20%。在0.85时，它达到50%，但您会看到不正确的缓存响应。选择正确的阈值并证明。
5. 对每个用户问题批处理10个并行子查询。重写缓存友好性，而不增加端到端延迟。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| L2 prompt cache | "prefix cache" | Provider stores KV for repeated prefix |
| `cache_control` | "Anthropic cache marker" | Explicit attribute marking cacheable blocks |
| Cache write premium | "write tax" | Extra cost for first miss-to-cache (1.25x or 2x) |
| L1 semantic cache | "embedding cache" | App-level hash-and-embed before calling LLM |
| GPTCache | "LLM caching lib" | Popular OSS L1 cache library |
| Cache hit rate | "hits / total" | Fraction of requests served from cache |
| Parallelization anti-pattern | "the N-write trap" | N parallel requests miss cache N times |
| Dynamic content trap | "the time-in-prompt trap" | Dynamic bytes in prefix kill hit rate |
| RadixAttention | "intra-replica cache" | SGLang's prefix-cache implementation |
