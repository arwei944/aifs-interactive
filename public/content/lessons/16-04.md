# 多智能体原语模型

> 2026年发布的每一个多代理框架——AutoGen、LangGraph、CrewAI、OpenAI代理SDK、微软代理框架——都是四维设计空间中的一个点。四个基本元素，仅此而已：代理、切换、共享状态、编排器。本课从零开始构建它们，在所有四个框架上运行一个玩具系统，然后将每个主要框架映射到相同的轴上，这样您就可以在一个段落中阅读任何新版本。

**Type:** Learn
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 (Agent Engineering), Phase 16 · 01 (Why Multi-Agent)
**Time:** ~60 minutes

## 问题

每六个月就会发布一个新的多代理框架。2023年的AutoGen。2024年。2024年的LangGraph和OpenAI Swarm。到2025年4月。微软代理框架RC在2026年2月。每个新闻稿都声称是“正确的抽象”。

如果你试图一次学一个，你会精疲力尽的。api看起来不同。医生们对什么是“代理人”意见不一。一个框架将其共享内存称为“黑板”，另一个框架将其称为“消息池”，第三个框架将其称为“状态图”。你开始怀疑磁场只是在搅动。

事实并非如此。在市场营销之下，这四个基本要素是稳定的。学习一次，在一个段落中阅读每一个新的框架。

## 概念

### 四个基本要素

1. **Agent** -一个系统提示加上一个工具列表。无状态;每次运行都从其系统提示符和当前消息历史记录开始。
2. 移交——将控制权从一个代理转移到另一个代理。从机械上讲，一种工具调用，它返回一个新的代理或一个符合条件的图边。
3. 共享状态——任何一个以上的代理可以读（有时写）的数据结构。消息池，黑板，键值存储，矢量存储器。
4. **指挥**——决定下一个发言的人。选项：显式图（确定性），LLM演讲者选择器（软），最后一个演讲者的移交调用（OpenAI Swarm），或队列上的调度程序（群架构）。

这就是整个设计空间。每个框架为每个轴选择默认值；其余的是表面语法。

### 每个2026框架如何映射到它

| Framework | Agent | Handoff | Shared state | Orchestrator |
|-----------|-------|---------|--------------|--------------|
| OpenAI Swarm / Agents SDK | `Agent(instructions, tools)` | tool returns Agent | caller's problem | the LLM's next handoff call |
| AutoGen v0.4 / AG2 | `ConversableAgent` | speaker-selector on GroupChat | message pool | selector function (LLM or round-robin) |
| CrewAI | `Agent(role, goal, backstory)` | `Process.Sequential / Hierarchical` | Task outputs chained | manager LLM or static order |
| LangGraph | node function | graph edge + condition | `StateGraph` reducer | the graph, deterministic |
| Microsoft Agent Framework | agent + orchestration patterns | pattern-specific | thread / context | pattern-specific |
| Google ADK | agent + A2A card | A2A task | A2A artifacts | host decides |

### 为什么这很重要？

一旦你看到了这些原语，框架比较就变成了一个简短的清单：

- 编排器信任LLM路由（Swarm）还是在代码中固定路由（LangGraph）？
- 是共享状态的完整历史记录（GroupChat）还是投影（statgraph reducer）？
- 代理可以修改彼此的提示（CrewAI管理器）或只移交（Swarm）？

这三个问题回答了80%的框架适合给定的问题。你不再去寻找“最好的多代理框架”，而是开始为你真正关心的轴心进行设计。

### 无状态洞察

除了共享状态之外，所有原语都是无状态的。代理是（提示，工具）的功能。切换是一个函数调用。Orchestrator是一个调度器。**系统中唯一有状态的东西是共享状态。**所有有趣的bug都存在于此：内存中毒（第15课）、消息排序、版本控制、写争用。

隐藏共享状态（Swarm）的框架将问题推给了调用者。集中它的框架（LangGraph检查点，AutoGen池）使其可检查，但将协调成本转移到共享状态实现上。

### 单个原始人的解剖

#### 代理

```
Agent = (system_prompt, tools, model, optional_name)
```

没有记忆。没有状态。具有相同系统提示符和工具的两个代理是可互换的。所有看起来像每个代理状态的东西实际上都处于共享状态或切换协议中。

#### 切换

```
Handoff = (from_agent, to_agent, reason, payload)
```

主要有三种实现：

- **函数返回** -工具返回下一个代理。这是OpenAI Swarm模式。代理在其工具模式中携带路由。
- **图边** - LangGraph。边是声明性的。LLM产生一个值；条件选择下一个节点。
- **演讲者选择** - AutoGen群聊。选择器函数（有时本身就是一个LLM调用）读取池并选择下一个发言的人。

#### 共享状态

```
SharedState = { messages: [], artifacts: {}, context: {} }
```

至少要有一个消息列表。通常更多：结构化工件（CrewAI任务输出），类型化上下文（LangGraph reducer），外部存储器（MCP，矢量DB）。

两种拓扑：**全池**（每个代理看到每条消息）和**投影**（代理看到一个角色范围的视图）。满池很简单，可扩展性很差。预计池可扩展，但需要预先进行模式设计。

#### 协调器

```
Orchestrator = ({state, last_speaker}) -> next_agent
```

四个口味:

- **静态** -图在构建时是固定的（LangGraph确定性，CrewAI顺序）。
- LLM-selected** - LLM读取池并选择下一个演讲者（AutoGen, CrewAI Hierarchical）。
- 切换驱动** -当前代理通过调用切换工具（Swarm）来决定。
- **队列驱动** -工作人员从共享队列中提取；没有明确的下一个发言者（群架构，矩阵）。

### 框架之间有什么变化

一旦这些原语固定了，剩下的设计决策是：

- **内存策略** -短暂与持久的检查点（LangGraph检查点）。
- **安全边界** -谁可以批准移交（人在环）。
- **成本会计** -每代理代币预算。
- **可观察性** -跟踪切换，持久状态重放。

所有这些都可以在原语之上实现。它们都不是新的原语。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Agent | "An LLM with tools" | A `(system_prompt, tools, model)` triple. Stateless. |
| Handoff | "Transfer of control" | A structured call that names the next agent and optional payload. Three implementations: function return, graph edge, speaker selection. |
| Shared state | "Memory" / "context" | The only stateful part of a multi-agent system. Message pool or blackboard. |
| Orchestrator | "Coordinator" | Whoever decides who runs next. Static graph, LLM selector, handoff-driven, or queue-driven. |
| Primitive | "Abstraction" | One of the four axes every framework parameterizes. Not a framework feature. |
| Message pool | "Shared chat history" | Full-history shared state. Easy to reason about, scales badly. |
| Projected state | "Scoped view" | Role-specific view into shared state. Scales, requires schema design. |
| Speaker selection | "Who talks next" | Orchestrator pattern where a function (often an LLM) picks the next agent from a group. |
