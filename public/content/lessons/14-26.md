# 失效模式：座席中断的原因

> MASFT （Berkeley, 2025）将14种多智能体失效模式分为3类。微软的分类法记录了现有的人工智能失败如何在代理环境中放大。工业现场数据集中在五种反复出现的模式：幻觉行为、范围蔓延、级联错误、上下文丢失、工具误用。

**Type:** Learn + Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 · 05 (Self-Refine and CRITIC), Phase 14 · 24 (Observability)
**Time:** ~60 minutes

## 学习目标

- 列出MASFT的三种故障类别，每种类别中至少有四种特定模式。
- 解释为什么代理失败会放大现有的AI失败模式（偏见、幻觉）。
- 描述五种行业循环模式及其缓解措施。
- 实现一个stdlib检测器，用故障模式标签标记代理跟踪。

## 这个问题

团队交付的代理可以处理90%的跟踪。这10%的失败并不是随机的噪音——它们属于少数反复出现的类别。一旦您可以命名它们，您就可以监视它们并修复它们。

## 这个概念

### MASFT (Berkeley, arXiv:2503.13657)

多代理系统故障分类法。14种故障模式分为3类。注释者Cohen的Kappa 0.88——类别是可靠可区分的。

中心观点：失败是多智能体系统的基本设计缺陷，而不是LLM限制，可以用更好的基础模型来修复。

### 微软代理人工智能系统故障模式分类

- 现有的人工智能失败（偏见、幻觉、数据泄露）在代理环境中会放大。
- 新的失败出现在自治中：大规模的意外行动、工具误用、任务漂移。
- 白皮书是代理产品的风险登记簿。

### agent AI中的故障表征[j] .中文信息学报（自然科学版）：2603.06847。

- 故障来自编排、内部状态演变和环境交互。
- 不仅仅是“糟糕的代码”或“糟糕的模型输出”。

### LLM药剂幻觉调查（arXiv:2509.18970）

两种主要表现：

1. **指令遵循偏差** -代理不遵循系统提示。
2. **远程上下文误用** -代理忘记或误用先前回合的上下文。

次意图错误：遗漏（遗漏步骤），冗余（重复步骤），无序（无序步骤）。

### 五种行业循环模式

Arize, Galileo， NimbleBrain 2024-2026领域分析集中于：

1. * *时动作。** Agent调用一个不存在的工具或捏造参数。
2. * *蠕变范围。**代理扩展任务超出用户的要求（创建额外的pr，发送额外的电子邮件）。
3. * *级联错误。**一个错误的调用触发下游效应。幻影SKU幻觉触发四个API调用-一个多系统事件。
4. * *环境损失。**长期任务忘记了早期回合的限制。
5. * *工具滥用。**使用错误的参数调用正确的工具，或者完全使用错误的工具。

层叠是致命的。智能体无法区分“我失败了”和“任务不可能完成”，并且经常在出现400个错误时产生成功信息来关闭循环。

### 缓解：每个步骤的闸门

在推理链的每一步都有自动验证门，根据环境状态检查事实基础。具体:

- 每步安全分类器（第21课）。
- 工具调用参数验证（第06课）。
- 对照已知事实交叉检查检索到的内容（第05课，批评家）。
- 通过重新探测状态（是否实际创建了文件？）来检测成功幻觉。

### 故障监控哪里出错了

- **只标记崩溃。**大多数代理失败产生看起来有效的输出。需要内容级检查。
- * *没有基线。**漂移检测需要最后已知的结果；没有它，你就不能说“情况越来越糟了”。
- * * Over-alerting。**每次失败都会生成一个页面。集群和速率限制。

## 练习

1. 为“成功幻觉”添加检测器：代理返回成功，但目标状态不变。
2. 标记100个你制造的产品的真实痕迹。哪种模式占主导地位？修理它要花多少钱？

5. 将一个检测器连接到CI作业中：如果>=5%的跟踪标记为模式，则构建失败。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| MASFT | "Multi-agent failure taxonomy" | Berkeley 14-mode categorization |
| Cascading error | "Ripple failure" | One early mistake propagates through N steps |
| Context loss | "Forgot the constraint" | Long-horizon turn drops early-turn facts |
| Tool misuse | "Wrong tool / wrong args" | Valid call, wrong invocation |
| Success hallucination | "Faked completion" | Agent claims success on a 400; state unchanged |
| Scope creep | "Overreach" | Agent does more than asked |
| Instruction-following deviation | "Disobedience" | Ignores system prompt or user constraint |
| Sub-intention errors | "Plan bugs" | Omission, redundancy, disorder in plan execution |
