# 生产运行时：队列、事件、Cron

> 生产代理在六种运行时形式上运行：请求-响应、流、持久执行、基于队列的后台、事件驱动和调度。在选择框架之前选择形状。可观察性在任何形状上都是承重的。

**Type:** Learn
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 · 13 (LangGraph), Phase 14 · 22 (Voice)
**Time:** ~60 minutes

## 学习目标

- 命名六个生产运行时形状，并将每个形状与框架/产品模式相匹配。
- 解释为什么持久执行（LangGraph）对长期任务很重要。
- 描述事件驱动的运行时，以及克劳德托管代理何时适合。
- 解释多步骤代理的可观察性作为承载的主张。

## 这个问题

生产代理失败的方式是Jupyter笔记本不会出现的：第37步网络超时，用户在语音通话中挂断电话，重启机器时cron任务死亡，后台工作程序内存不足。运行时形状决定了哪些故障是可存活的。

## 这个概念

### 请求-响应

- 同步HTTP。用户等待完成。
- 仅适用于短任务（<30）。
- 栈：Agno (Python + FastAPI), master （TypeScript + Express/Hono/ fasttify /Koa）。
- 可观察性：标准HTTP访问日志+ OTel跨度。

### 流媒体

- SSE或WebSocket用于渐进式输出。
- LiveKit将此扩展到用于语音/视频的WebRTC（第22课）。
- 栈：任何支持流的框架+处理SSE/WS的前端。
- 可观察性：每块计时，第一个令牌延迟，尾部延迟。

### 持久的执行

- 每一步后都有状态检查点；失败时自动恢复。
- AutoGen v0.4参与者模型将故障隔离到一个代理（第14课）。
- LangGraph的核心区别（第13课）。
- 当步数未知且回收成本高时非常重要。

### 基于队列/后台

- 作业进入队列，工作人员接收，结果通过webhook或pub/sub流回。
- 对于长视界代理至关重要（每个任务需要几十到几百个步骤，根据Anthropic的计算机使用公告）。
- 堆栈：芹菜（Python）， BullMQ (Node), SQS + Lambda (AWS)，自定义。
- 可观察性：队列深度、每个作业延迟分布、DLQ大小。

### 事件驱动的

- 代理订阅触发器：新邮件，PR打开，cron fire。
- 克劳德管理代理涵盖了这个开箱（第17课）。
- CrewAI流程（第15课）构建事件驱动的确定性工作流。
- 可观察性：触发源、事件到启动的延迟、代理延迟。

### 计划

- 周期性运行的cron型代理。
- 与持久执行相结合，使失败的夜间运行在下一秒恢复。
- 栈：Kubernetes CronJob +一个持久框架；托管（渲染cron， Vercel cron）。

### 2026部署模式

- CrewAI流程**用于事件驱动的生产。
- Python微服务的无状态FastAPI。
- ** mastera **服务器适配器（Express, Hono, fasttify, Koa）用于嵌入。
- **Pipecat Cloud / LiveKit Cloud**用于管理语音（第22课）。
- **托管代理**用于托管长时间运行的异步。

### 可观察性是承重的

如果没有OpenTelemetry GenAI span（第23课）和Langfuse/Phoenix/Opik后端（第24课），您就无法调试在第40步失败的多步代理。这在生产中是不可选的。这就是“我们快速调试”和“我们从头开始重播并添加更多日志记录”之间的区别。

### 生产运行时失败的地方

- **错误的形状选择。**为一个5分钟的任务挑选请求-响应。用户挂机；工人堆积如山；重试化合物。
- * *没有DLQ。**没有死信的队列工人。失败的工作消失了。
- **不透明的背景工作。**后台代理运行无痕迹导出。故障在用户报告之前是不可见的。
- **跳过持久状态。**任何运行> 30秒，你不能重新启动需要持久执行。

## Use It

- **Request-response** for chat-style UX.
- **Streaming** for progressive responses.
- **Durable** for long-horizon tasks.
- **Queue** for batch / async / long-running.
- **Event** for agent reactivity.
- **Cron** for housekeeping (memory consolidation, evals, cost reports).

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Request-response | "Synchronous" | User waits; short tasks only |
| Streaming | "SSE / WS" | Progressive output; better UX; latency observable per chunk |
| Durable execution | "Resume from failure" | Checkpointed state; restart at last step |
| Queue-based | "Background jobs" | Producer / worker pool / DLQ |
| Event-driven | "Trigger-based" | Agent reacts to external events |
| DLQ | "Dead-letter queue" | Parking lot for failed jobs |
| Claude Managed Agents | "Hosted harness" | Anthropic-hosted long-running async with caching + compaction |
