# LangGraph：有状态图和持久执行

> LangGraph是低级有状态编排的2026参考。Agent是一种状态机；节点是函数；边是过渡；状态是不可变的，并且在每一步之后都有检查点。从任何失败的地方恢复。

### 持久的执行

在每个节点返回后，运行时序列化状态并将其写入检查指针（SQLite, Postgres, Redis, custom）。在步骤N失败时，运行时可以

LangGraph文档明确强调了重要的生产用户：Klarna、Uber、J.P. Morgan。结论不是图形形状；就是图形形状加上检查点使得恢复成本低廉。

### 流媒体

每个节点都可以产生部分输出。图形将每个节点的增量事件流式传输给调用者，以便ui在图形运行时更新。

### Human-in-the-loop

检查和修改节点之间的状态。实现：在关键节点前暂停，向人显示状态，接受修改，恢复。检查指针使这很容易，因为状态已经序列化了。

### 内存

短期（在运行会话历史记录中）和长期（跨运行—通过检查指针和单独的长期存储进行持久化）。LangGraph通过工具与外部存储系统（Mem0，定制）集成。

### 三种拓扑结构

1. **主管。**中央路由器LLM分派给专门的子代理。`create_supervisor()` in `langgraph-supervisor` (though the LangChain team in 2026 recommends doing this through tool calls directly for more context control).
2. **群/点对点。**代理直接通过共享工具界面进行交接。没有中央路由器。
3. **等级。**管理员管理子管理员，实现为嵌套子图。

### 这种模式哪里出错了

- **关卡太小。**只有检查点会话才会离开工具状态和内存写入不可恢复。必须序列化完整状态。
- **不确定的节点。Resume假设节点输入产生相同的状态更新。随机种子，挂钟，外部api必须捕获。
- **过度使用条件边。一个每条边都有条件的图是一个无法推理的状态机。喜欢偶尔有分支的线性链。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| State graph | "Agent as state machine" | Typed state + nodes + edges + reducers |
| Checkpointer | "Persistence backend" | Serializes state after every node; enables resume |
| Reducer | "State merger" | Function that combines current state with a node's update |
| Conditional edge | "Branch" | Edge chosen by a function of state |
| Subgraph | "Nested graph" | A graph used as a node inside another graph |
| Durable execution | "Resume from failure" | Restart at the last successful node with exact state |
| Supervisor | "Router LLM" | Central dispatcher for specialist subagents |
| Swarm | "P2P agents" | Agents hand off via shared tools; no central router |
