# Speculative decoding and EAGLE

> Generating a forward LLM for a token requires complete forward passing of billions of parameters. This forward pass is heavily overconfigured: in most cases, a much smaller model can correctly guess the next 3-5 tokens, while a larger model only needs to "verify" this guess. If you guess correctly, you can get five tokens at the price of one token. Speculative decoding (Leviathan et al. 2023) made this accurate, and EAGLE-3 (2025) increased the acceptance rate to approximately 4.5 tokens per validation - accelerating 4-5 times under the matching output distribution.

## This question

The decoding throughput of the 70b class model on the H100 is typically 40 to 80 tokens per second. Each token requires a complete forward pass to read all model weights from HBM. You can't make the model smaller without changing the output. The batch size cannot be increased beyond the memory range. This gets stuck - unless you can make the model output multiple tokens each time it is passed forward.

Autoregressive generations seem essentially sequential: but there is a concurrent opportunity here. If you have a cheap predictor that says, "The next four tokens might be [a, b, c, d]", you can validate all five positions in a single forward pass of the large model and accept the longest matching prefix.

Leviathan, Kalai, Matias (2023, "Quick Inference from Transformers through Speculative Decoding") achieved this through a smart accept/reject rule that retains the sampling distribution of the target model. With the same output distribution, the speed is 2 to 4 times faster.

### Training draft: Distillation

A random small model will produce a bad draft. The standard method is distilled from the target substance:

1. Choose a small architecture (the target for 70B is ~1B, and for 7B it is ~500M).
2. Run the target model on a large text corpus; Store its next token distribution.
3. Train a draft with KL divergence based on the distribution of the target (not based on truth tokens).

The result is that the production speed has increased by 2 to 3 times.

### EAGLE: Tree Drafting + Function Reuse

Li, Wei, Zhang, Zhang (2024, "EAGLE: Speculative Sampling Requires Reconsidering Feature Uncertainty") observed two inefficiencies in standard speculative decoding:

1. The draft performs K consecutive steps, each of which is a full stack. However, the draft can reuse the features (hidden states) of the most recent validation of the target - the target has already calculated the rich representations that the draft has re-derived from scratch.
2. The draft outputs a linear chain. If the draft can output a candidate "tree" (with multiple guesses at each node), a single forward pass of the target can verify multiple candidate paths in parallel through the attention mask of a tree and select the longest acceptable branch.

EAGLE-1 changes:
- Draft input = The final hidden state of the target at position t, not the original mark.
- The draft architecture = 1 transformer decoder layer (not a separate small model).
- Output: 4 to 8 candidate trees per depth K, with a depth of 4 to 6.

EAGLE-2 (2024) added a dynamic tree topology: where the draft is uncertain, the tree widens; where the draft is definite, the tree Narrows. Salary increase

EAGLE-3 (Li et al. 2025, "EAGLE-3: "Expanding the inference acceleration of large language models through training time testing" eliminates fixed top-level feature dependencies and uses a new "test time simulation" loss to train drafts - drafts are trained on outputs that match the target test time distribution, rather than on a teacher-forced training distribution. The acceptance rate rose from 0.75 (EAGLE-2) to 0.82 (EAGLE-3), and the average token/validation rate increased from 3.0 to 4.5.

### Tree attention verification

When the draft outputs the tree, the target model uses a tree attention mask to validate it in a single forward pass - a causal mask that encodes the tree topology rather than pure lines. Each token only focuses on the ancestors in the tree. The verification is still one forward and the other backward. The topological mask only requires a few additional KV entries.

```
        root
       /    \
      a      b

## Use It

- **vLLM** and **SGLang** ship first-class speculative decoding. Flags: `--speculative_model`, `--num_speculative_tokens`. EAGLE-2/3 support via the `--spec_decoding_algorithm eagle` flag.
- **NVIDIA TensorRT-LLM** supports Medusa and EAGLE trees natively.
- **Reference draft models**: `Qwen/Qwen3-0.6B-spec` (drafts for Qwen3-32B), `meta-llama/Llama-3.2-1B-Instruct-spec` (drafts for 70B).
- **Medusa heads** (Cai et al. 2024, "Medusa: Simple LLM Inference Acceleration Framework with Multiple Decoding Heads"): instead of a draft model, add K parallel prediction heads to the target itself. Simpler to deploy, slightly lower acceptance than EAGLE.

## Key Terms

| Term | What people say | What it actually means |
|------|-----------------|------------------------|
| Target model | "The big model" | The slow, high-quality model you want samples from (p distribution) |
| Draft model | "The speculator" | The small, fast predictor (q distribution); 5-30x smaller |
| K / draft length | "Look-ahead" | Number of speculated tokens per verify pass |
| α / acceptance rate | "Hit rate" | Per-token probability that the draft's proposal is accepted |
| Exact rejection rule | "The accept test" | r < p/q compare that preserves target's distribution |
| Residual distribution | "Corrected p-q" | (p - q)+ / ||(p - q)+||_1, the distribution to sample from on rejection |
| Tree drafting | "Branching speculation" | Draft outputs a tree of candidates, verified in one pass with tree-structured attention mask |
| Tree attention mask | "Topological mask" | Causal mask encoding the tree topology so each node attends only to its ancestors |
| Medusa heads | "Parallel heads" | K extra prediction heads on the target itself; no separate draft model |
| EAGLE feature reuse | "Hidden-state draft" | Draft input is target's last hidden state, not raw tokens, shrinking the draft |
| Test-time simulation loss | "EAGLE-3 training" | Train draft on outputs matching target's test-time distribution, not teacher forcing |
