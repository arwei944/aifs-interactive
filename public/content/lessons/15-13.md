# 行动预算、迭代上限和成本控制

> 在团队启用了“订单跟踪”技能后，一家中型电子商务代理的每月LLM费用从1200美元跃升至4800美元。这不是价格上的错误。这是一个发现新循环并在其中持续消费的代理。Microsoft的代理治理工具包（Agent Governance Toolkit， 2026年4月2日）编纂了针对此类的防御：按请求进行防御Anthropic的Claude Code Agent SDK以不同的名称提供相同的原语。金融速度限制——例如在10分钟内切断b> $50的访问——比每月上限更快地捕获循环。

**Type:** Learn
**Languages:** Python (stdlib, layered cost-governor simulator)
**Prerequisites:** Phase 15 · 10 (Permission modes), Phase 15 · 12 (Durable execution)
**Time:** ~60 minutes

## 这个问题

自主代理每次都花真金白银。聊天机器人的糟糕输出是一个糟糕的回复；特工的恶性循环就是账单。业界记录的故障模式术语是“拒绝钱包”——代理一直在推理，一直在调用工具，一直在计费，没有任何东西可以阻止它，因为没有任何东西被设计成这样。

解决办法不是一个数字。它是一堆不同时间尺度和粒度的限制：每个请求、每个任务、每小时、每天、每月。设计良好的堆栈可以在几分钟内捕获失控循环，在几小时内捕获缓慢泄漏，在一天内捕获不良释放。当代理是长视界和自治的时候，相同的堆栈保留了一个预算。

这是工程学上的一课：数学是微不足道的，纪律是团队失败的原因。下面的限制列表都在Microsoft代理治理工具包或Anthropic Claude Code代理SDK文档中命名。

## 这个概念

### 成本调控器堆栈

1. ****简单。防止任何调用发出无界完成。
2. **每任务令牌预算。**在整个运行过程中，不要超过N个token。停在瓶盖上。
3. **每个任务的美元预算。**与代币相同，但使用货币。`max_budget_usd` in Claude Code.
4. **每个工具调用上限。**不超过N个
5. **迭代上限(**总代理循环迭代；防止无限的推理循环。
6. **每分钟/每小时/每天/每月上限。**摇窗。在不同的时间尺度捕获泄漏。
7. **金融流通速度限制。例如，“如果在10分钟内花费超过50美元，就切断访问。”在每月封顶前捕获循环燃烧。
8. **分层模型路由。**默认为较小的模型；只有当分类器判断任务需要时，才会升级到更大的范围。
9. **提示缓存。**系统提示和稳定的上下文存储在提供商缓存中；重新发送代币的成本接近于零。
10. **上下文窗口。**压缩/汇总以保持活动上下文低于阈值；直接降低代币成本。
11. **昂贵操作的HITL检查点。**在已知代价昂贵的操作（长时间的工具调用，大量下载，昂贵的模型升级）之前，需要人工点击。
12. **预算违约的终止开关。当任何帽触发时会话终止。记录帽；需要一个单独的重新启用路径。

### 为什么是一堆，而不是一顶

一个月的上限只会在钱包消失后抓住一个逃跑的特工。单个的每个请求上限在会话级别上什么也捕捉不到。不同的失效模式需要不同的时间尺度：

- **失控循环**（代理卡在5秒重试）：捕获速度限制。
- **慢泄漏**（代理在每个任务中完成预期工作的2倍）：按每日上限捕获。
- **糟糕的发布**（新版本使用5x代币）：按周/月上限捕获。
- **合法的激增**（真正的需求，而不是bug）：按小时/日上限捕获，并有明确的日志。

### 观察到$1,200→$4,800的案例

微软文档中的真实案例是：一个电子商务代理在添加了一个新工具后，每月的成本增加了两倍。该工具允许代理在每个会话期间轮询订单状态。无环路检测。没有每个工具的上限。没有每周增长的警报。解决方法是设置每个工具的上限和每日增长警报。这是一个模板：每一个新的工具表面都是一个新的潜在循环；每个新工具都需要自己的上限和警报。

## 练习

1. 运行在轮询循环轨迹的迭代上限之前确认速度限制。现在禁用速度限制，并测量代理在迭代上限捕获它之前“花费”了多少。

2. 为浏览器代理设计每个工具的上限集（第11课）。哪个工具需要最紧的盖子？哪个工具可以无界运行而没有风险？

3. 阅读Microsoft Agent Governance Toolkit文档。列出每个帽类型的工具包名称。将每个故障模式映射到其中一种故障模式（失控回路、慢泄漏、不良释放、浪涌）。

4. 为一个现实的任务（例如，“在一个回购中分类50个问题”）定价一个夜间无人值勤的运行。集合证明2x是正确的。

5. Claude Code设计一个互补的速度限制，你可以在外部强制执行。是什么触发了截止，重新启用是什么样子的？

## 关键术语

| Term | What people say | What it actually means |
|---|---|---|
| Denial of Wallet | "Runaway bill" | Agent loop generating spend with no cap to stop it |
| max_tokens | "Per-request cap" | Ceiling on a single completion's size |
| max_turns | "Iteration cap" | Ceiling on agent loop iterations in a session |
| max_budget_usd | "Dollar kill switch" | Session cost cap; aborts on breach |
| Velocity limit | "Rate cap" | Limit on spend per short window (e.g., $50 / 10 min) |
| Tiered routing | "Small model first" | Cheap model default; escalate only when classifier warrants |
| Prompt caching | "Cached system prompt" | Provider-side cache reduces re-send token cost to near zero |
| HITL checkpoint | "Human approval gate" | Human tap required before expensive action |
