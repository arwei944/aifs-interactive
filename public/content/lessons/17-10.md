# 针对无服务器llm的冷启动缓解

> 一张20gb的模型图片从冷到上桌需要5-10分钟（7B）到20+分钟（70B）。在真正的无服务器世界中，这不是预热，而是中断。缓解措施在五层运行：预种子节点映像（AWS上的Bottlerocket，双卷arch）、模型流（NVIDIA Run:ai model Streamer，原生vLLM）、GPU内存快照（模态检查点，重启速度提高10倍）、热池(Modal发布了2-4s冷启动作为地板；默认5-10秒为基础，分秒预热。这节课教你衡量、预算和堆叠这五层。

## 这个问题

您的无服务器LLM端点一夜之间伸缩为零。早上8点交通高峰。第一个请求等待：

1. Karpenter提供了一个GPU节点：45-60s。
2. 容器提取一个30 GB的图像，权重为120-300。
3. 引擎根据模型大小和存储速度将权重加载到HBM: 45-120秒。
4. vLLM或TRT-LLM初始化CUDA图形，KV缓存池，标记器：10-30s。

总共需要220-510秒（大约3-8分钟）才能返回一个令牌。你的SLA是2s。你运了一个暖水池(如果你的服务有5个产品，每个产品都有一个温暖的副本，那就是5 × 24 × 30 = 3600 gpu小时/月，无论是否有单个用户调用。

冷启动缓解是指如何在保持无服务器经济性的同时，近似于始终在线的延迟。

## 这个概念

### 第1层-预播种节点映像（Bottlerocket）

在AWS上，Bottlerocket的双卷架构将操作系统与数据分离。使用预拉的容器映像对数据卷进行快照；中引用快照ID新节点启动时已经在本地NVMe上设置了权重——步骤2和步骤3的一部分将消失。与Karpenter一起工作。典型的节省：2-4分钟每次冷启动大型模型。

在GCP上等效：自定义带有预焙容器层的VM映像。在Azure上：具有相同模式的托管磁盘快照。

### 第2层-模型流（运行：ai模型流）

而不是在回答第一个请求之前加载完整的文件，将权重逐层流式传输到GPU内存中，并在第一个变压器块驻留后立即开始处理。NVIDIA Run:ai模型流媒体船原生在vLLM 2026。工作与S3， GCS，和本地NVMe。通过将I/O与计算设置重叠，将大型模型的权重加载时间减少了大约一半。

### Layer 3 - GPU内存快照（Modal）

Modal在第一次加载后对GPU状态（权重，CUDA图，KV缓存区域）进行检查点。随后的重启直接反序列化到HBM——比重新初始化快10倍。这是最接近于“在2秒内启动一个温暖的GPU”的事情。权衡：快照是基于gpu拓扑的，因此如果Karpenter将您迁移到不同的SKU，则需要重新检查点。

### 第4层-热池（min_workers=1）

最简单的缓解方法：始终保持一个副本就绪。成本是一个GPU的小时速率24x7。对于小型模型来说，这个算法是残酷的（你需要支付0.85- 1.50美元/小时来避免30分钟的冷启动），而对于大型模型来说则是仁慈的（支付4美元/小时来避免5分钟的冷启动）。强制使用热池的SLA阈值：通常在70B+型号上TTFT P99 < 60s。

### 第5层-分层加载（ServerlessLLM）

ServerlessLLM将存储视为一个层次结构：NVMe（快但大），DRAM（中等但分层），HBM（小但即时）。权重被预加载到DRAM中；按需加载到HBM。论文报告了与初始磁盘到hbm相比，冷负载的延迟减少了10-200倍。产品采用还很早，但是与vLLM的集成已经存在。

### 第6层-实时迁移（奖励模式）

当一个节点不可用时（点退出、节点流失），传统模式是冷启动另一个副本并流失请求队列。实时迁移将输入令牌（千字节）移动到加载了模型的目的地，并在目的地上重新计算KV缓存。重新计算比在网络上传输GB KV缓存更便宜。适用于分解部署。

|-------|------|-----------|

### 你应该记住的数字

- 模态冷启动：2-4s（带GPU快照）。
- 基准默认冷启动：5-10秒；预热不到一秒。
- 生70B冷启动：3-8分钟。
- 运行：ai模型Streamer: ~2倍负重加速。
- ServerlessLLM分层加载：延迟减少10-200倍（论文数）。

## 练习

1. 运行计算盈亏平衡请求率，在该比率之上，热副本比通过在SLO上的额外请求下降支付冷启动税更便宜。
2. 您部署了一个具有3级P99 TTFT SLA的13B模型。选择可实现此目标的最小缓解堆栈（最少层）。
3. Bottlerocket预播种消除了图像拉取，但权重仍然从快照加载到HBM。如果快照支持的NVMe读取速度为7gb /s，则计算70B型号的挂钟。
4. 您的无服务器提供商提供GPU快照（Modal），但您的团队拒绝，因为“快照泄露PII”。争论双方——现实的风险是什么，缓解措施是什么（临时快照、加密、名称空间隔离）？
5. 设计分层热池策略：付费用户、试用用户和批处理工作负载有多少热池副本？展示数学。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Cold start | "the big pause" | Time from request to first token on a fresh replica |
| Warm pool | "always-on minimum" | `min_workers >= 1` to keep at least one replica ready |
| Pre-seeded image | "baked AMI" | Node image with container weights pre-resident |
| Bottlerocket | "AWS node OS" | AWS container-optimized OS with dual-volume snapshot support |
| Model streamer | "streaming load" | Overlap weights I/O with compute setup |
| GPU snapshot | "checkpoint to HBM" | Serialize post-load GPU state; deserialize on restart |
| Tiered loading | "NVMe + DRAM + HBM" | Hierarchy of storage tiers; load on demand |
| Live migration | "move tokens" | Transfer input (KB), recompute KV on destination |
| `min_workers` | "warm replicas" | Serverless minimum keep-alive count |
| Scale-to-zero | "full serverless" | No cost when idle; accept full cold-start tax |
