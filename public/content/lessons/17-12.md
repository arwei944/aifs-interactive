# 边缘推理-苹果神经引擎，高通Hexagon， WebGPU/ weblm, Jetson

> 核心边缘约束是内存带宽，而不是计算。移动DRAM的速度为50- 90gb /s；数据中心HBM3清除2-3 TB/s - 30-50倍的差距。解码是受记忆限制的，所以差距是决定性的。到2026年，情况将分成四种。Apple M4/A18神经引擎最高可达38 TOPS，具有统一内存（无CPU↔NPU副本）。Qualcomm Snapdragon X Elite / 8 Gen 4 Hexagon达到45 TOPS。WebGPU + weblm在M3 Max上运行Llama 3.1 8B (Q4)，速度约为41 tok/s（大约为本机的70-80%）；17.6k GitHub stars， openai兼容API， ~70-75%移动覆盖率。NVIDIA Jetson Orin Nano Super （8GB）适合Llama 3.2 3B / Phi-3；AGX Orin通过vLLM以~40 tok/s的速度运行gpt- loss -20b；Jetson T4000 （JetPack 7.1）是2倍AGX Orin。TensorRT Edge-LLM支持EAGLE-3， NVFP4，块预填充-博世，迅雷软件，联发科在CES 2026上展示。

## 学习目标

- 解释为什么移动LLM推理受内存带宽限制，而计算是次要的。
- 列举四个边缘目标（Apple ANE, Qualcomm Hexagon, WebGPU/WebLLM, NVIDIA Jetson），并将每个目标与用例进行匹配。
- 说出2026年WebGPU覆盖的差距（Firefox Android赶超）和Safari iOS 26的登陆。
- 为每个目标选择量化格式（Core ML INT4 + FP16适用于ANE， QNN INT8/INT4适用于Hexagon， WebGPU Q4适用于浏览器，NVFP4适用于Jetson Thor）。

## 这个问题

客户想要一个设备上的聊天机器人：语音优先，默认私有，离线工作。在MacBook Pro M3 Max上，Llama 3.1 8B Q4的运行速度约为55 tok/s——很好。在iPhone 16 Pro上，同样的型号运行速度为3 tok/s——不太好。在配备骁龙8 Gen 3的中档安卓系统上，7 tok/s。在浏览器中通过WebGPU在Chrome Android v121+， 4-8 tok/s取决于设备。

吞吐量差异不是移植问题。它是带宽间隙乘以量化格式乘以NPU是否可以从用户空间访问。2026年的边缘推断是四个不同的问题，有四个不同的解决方案。

## 这个概念

### 带宽才是真正的上限

Decode读取每个令牌的完整权重集。第四季度的一款7B手机容量为3.5 GB。以50gb /s的速度读取3.5 GB的数据需要70毫秒——理论上上限为~14 tok/s。在90 GB/s（高端移动DRAM）时，上限移动到~25 tok/s。低于这个数字，再多的计算也无济于事。

数据中心HBM3以3tb /s的速度在1.2 ms内清除相同的3.5 GB，上限为830tok /s。同样的模型，同样的权重。不同的内存子系统。

### Apple Neural Engine （M4 / A18）

- 最多38个TOPS。统一内存（CPU和ANE共享同一个池）—没有复制开销。
- 通过Core ML +访问
- Llama.cpp金属后端使用MPS，而不是直接使用ANE；原生ANE需要Core ML转换。
- 2026年iOS应用的最佳实践路径：带有INT4权重+ FP16激活的核心ML。

### 高通Hexagon （Snapdragon X Elite / 8 Gen 4）

- 最多45顶。在SoC中集成CPU和GPU，但单独的内存域。
- QNN（高通神经网络）SDK和AI Hub提供从PyTorch/ONNX的转换。
- 聊天模板，羊驼3.2，Phi-3都是AI Hub上的一流工件。

### Intel / AMD npu （Lunar Lake, Ryzen AI 300）

- 40 - 50。软件落后于苹果/高通；OpenVINO正在改进，但还处于小众市场。
- 最适合Windows ARM副驾驶应用程序；本机在AMD/Intel台式机本地优先。

### WebGPU + WebLLM

- 通过WebGPU计算着色器在浏览器中运行模型；没有安装。
- Llama 3.1 8B Q4在M3 Max上的速度约为41 tok/s，大约是原生版本的70-80%。
- 17.6k GitHub星在weblm；兼容openai的JS API；Apache 2.0。
- 2026年覆盖：Chrome Android v121+， Safari iOS 26 GA， Firefox Android仍在追赶。总体移动覆盖率为70-75%。

### NVIDIA Jetson系列

- Orin Nano Super (8GB)：适合Llama 3.2 3B, Phi-3，速度快。
- AGX Orin：通过vLLM以~40 tok/s的速度运行gpt-oss-20b。
- Thor / T4000 (JetPack 7.1): 2倍AGX Orin性能，支持EAGLE-3和NVFP4。
- TensorRT edge - llm（2026）支持EAGLE-3推测解码，NVFP4权重，块预填充-数据中心优化移植到edge。

### 每个目标的量化选择

| Target | Format | Notes |
|--------|--------|-------|
| Apple ANE | INT4 weights + FP16 activations | Core ML conversion path |
| Qualcomm Hexagon | QNN INT8 / INT4 | AI Hub converters |
| WebGPU / WebLLM | Q4 MLC (q4f16_1) | Use `mlc_llm convert_weight` + compiled `.wasm`; GGUF is not supported |
| Jetson Orin Nano | Q4 GGUF or TRT-LLM INT4 | Memory-bound |
| Jetson AGX / Thor | NVFP4 + FP8 KV | Edge-LLM path |

### 长期背景陷阱处于边缘

Llama 3.1的128K上下文是一个数据中心特性。在具有8 GB RAM， 4 GB模型+ 2 GB KV缓存32K令牌+操作系统开销= OOM的手机上。边缘部署将上下文保持在4K-8K，除非接受激进的KV量化（q4kv）。

### 语音是杀手级应用

语音代理对延迟敏感（第一个令牌< 500 ms）。本地推理完全消除了网络延迟。结合语音到文本（Whisper Turbo变体在边缘上运行）和边缘推理成为生产质量的语音循环。

### 你应该记住的数字

- 苹果M4 / A18 ANE: 38顶。
- 高通Hexagon SD X Elite: 45 TOPS。
- 在Llama 3.1 8B Q4上，weblm M3 Max: ~41 tok/s。
- AGX Orin: ~40 tok/s on gpt-oss-20b via vLLM.
- 数据中心边缘带宽缺口：30-50倍。
- WebGPU移动覆盖率：~70-75% （Firefox Android滞后）。

## 练习

1. 运行对于第四季度采用骁龙8 Gen 3 （~77 GB/s带宽）的7B型号，计算解码上限。与观察到的6-8 tok/s相比，运行时效率高吗？

4. Jetson AGX Orin以40 tok/s的速度运行gpt- loss -20b。Jetson Nano只适合3B。如果您的产品同时针对这两个目标，那么如何统一推理堆栈？

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| ANE | "Apple neural engine" | On-device NPU in M-series and A-series; unified memory |
| Hexagon | "Qualcomm NPU" | Snapdragon NPU; QNN SDK for access |
| WebGPU | "browser GPU" | W3C-standardized browser GPU API; Chrome/Safari 2026 |
| WebLLM | "browser LLM runtime" | MLC-LLM project; Apache 2.0; OpenAI-compatible JS |
| Jetson | "NVIDIA edge" | Orin Nano / AGX / Thor / T4000 family |
| TRT Edge-LLM | "edge TensorRT" | 2026 edge port of TensorRT-LLM; EAGLE-3 + NVFP4 |
| Unified memory | "shared pool" | CPU and NPU see same RAM; no copy overhead |
| Bandwidth-bound | "memory limited" | Decode gated by bytes/sec reading weights |
| Core ML | "Apple conversion" | Apple framework for ANE-native models |
| QNN | "Qualcomm stack" | Qualcomm Neural Network SDK |
