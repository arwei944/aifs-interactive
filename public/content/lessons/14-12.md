# Anthropic的工作流程模式：简单胜于复杂

> Schluntz和Zhang （Anthropic, Dec 2024）将工作流（预定义路径）与代理（动态工具使用）区分开来。五种工作流模式涵盖了大多数情况。从直接调用API开始。仅在无法预测步骤时添加代理。

**Type:** Learn + Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 · 01 (Agent Loop)
**Time:** ~60 minutes

## 学习目标

- 说出Anthropic的五种工作流程模式：提示链接、路由、并行化、协调者-工作者、评估者-优化者。
- 解释代理与工作流的区别以及每一种的工程成本。
- 确定何时选择工作流而不是代理（反之亦然）。
- 在标准库中针对脚本化的LLM实现所有五种模式。

## 这个问题

团队使用多代理框架来解决需要单个函数调用的问题。代价是真实的：框架增加了模糊提示、隐藏控制流和导致过早复杂性的层。Schluntz和Zhang在2024年12月发表的文章是被引用最多的行业反击：从简单开始，只有在赚回成本的时候才增加复杂性。

## 这个概念

### 工作流与代理

- * *工作流程。**通过预定义的代码路径编排的llm和工具。工程师拥有图形。
- * *代理。llm动态地指导自己的工具并采取自己的步骤。模型拥有图。

两者都有各自的位置。工作流更便宜、更快、更容易调试。代理解开了开放式的问题，但使失效模式更难推理。

### 增强型LLM

所有五种模式的基础：一个LLM与三种功能连接在一起——搜索（检索）、工具（操作）、记忆（持久性）。任何API调用都可以使用这些。

### 五种模式

1. * *提示链接。**呼叫1的输出为呼叫2的输入。当一个任务有一个清晰的线性分解时使用。步骤之间的可选编程门。

2. * *路由。**分类器LLM选择调用哪个下游LLM或工具。当不同的输入需要不同的处理时使用（一级支持vs退款vs漏洞vs销售）。

3. * *并行化。**同时运行N个LLM调用，汇总结果。两种形式：分段（不同的块）和投票（相同的提示，N次运行，多数/合成）。

4. * * Orchestrator-workers。**编排器LLM动态地决定运行哪些工作器（也是LLM）并合成它们的输出。类似于代理循环，但编排器不会无限循环。

5. * * Evaluator-optimizer。**一个法学硕士提出一个答案，另一个法学硕士评估它。迭代直到求值器通过。这是自我完善（第05课）的概括。

### 工作流在哪里胜过代理

- * *可预测的任务。如果你能列举出这些步骤，你应该这么做。
- * * Cost-bound任务。**工作流有有限的步骤计数；代理人可以螺旋式上升。
- * * Compliance-bound任务。**审核员想要阅读图表，而不是从轨迹中推断。

### 代理在哪里胜过工作流

- * *的研究。**下一步何时执行取决于上一步返回的内容。
- * *变长的任务。**步数未知的工作分钟到小时。
- * *小说领域。**当你还不知道正确的工作流程时——先探索，再编码。

### 上下文工程伙伴

“人工智能代理的有效上下文工程”（Anthropic 2025）将相邻的学科正式化：20万窗口是一个预算，而不是一个容器。包括什么，什么时候精简，什么时候让上下文发展。在第14阶段关于上下文压缩的课程中有详细介绍（本课程第06课之前的第14阶段）。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Workflow | "Predefined flow" | Engineer-owned graph of LLM and tool calls |
| Agent | "Autonomous AI" | Model-owned graph; dynamic tool direction |
| Augmented LLM | "LLM with tools" | LLM + search + tools + memory; the atomic unit |
| Prompt chaining | "Sequential calls" | Output of call N is input to call N+1 |
| Routing | "Classifier dispatch" | Pick which chain/model handles the input |
| Parallelization | "Fan out" | N concurrent calls; aggregate by sectioning or voting |
| Orchestrator-workers | "Dispatcher agent" | Orchestrator LLM picks specialist LLMs dynamically |
| Evaluator-optimizer | "Proposer + judge" | Iterate until evaluator passes; Self-Refine generalized |
