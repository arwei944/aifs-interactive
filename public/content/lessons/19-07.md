# 顶点07 -端到端微调管道（数据到SFT到DPO服务）

> 一个基于您自己的数据训练的8B模型，与您自己的偏好一致的dpo，量化，投机解码，并以可测量的美元/ 100万代币提供服务。2026开放堆栈为Axolotl v0.8, TRL 0.15， Unsloth用于迭代，GPTQ/AWQ/GGUF用于量化，vLLM 0.7与EAGLE-3用于服务。顶点是可重复地运行整个管道——YAML输入，服务端点输出——并在2026模型开放框架下发布模型卡。

**Type:** Capstone
**Languages:** Python (pipeline), YAML (configs), Bash (scripts)
**Prerequisites:** Phase 2 (ML), Phase 3 (DL), Phase 7 (transformers), Phase 10 (LLMs from scratch), Phase 11 (LLM engineering), Phase 17 (infrastructure), Phase 18 (safety)
**运行阶段：** P2·P3·P7·P10·P11·P17·P18
**Time:** 35 hours

## 问题

2026年，每个严肃的人工智能团队都有一个微调管道。不是因为他们提供了前沿基础模型，而是因为下游的适应——域SFT，针对标记偏好的DPO，用于推测解码的精炼草案，与EAGLE-3一起服务——是可测量的胜利所在。Axolotl v0.8处理多gpu SFT配置。TRL 0.15处理DPO和GRPO。Unsloth可以让你快速进行单gpu迭代。vLLM 0.7与EAGLE-3推动解码吞吐量2-3x没有质量损失。工装；工艺在于yaml、数据卫生和评估规程。

您将通过SFT运行8B基础（Llama 3.3， Qwen3或Gemma 3），然后对特定于任务的数据进行DPO，量化服务，并测量lm-evaluation-harness， RewardBench-2， MT-Bench-v2和MMLU-Pro的收益。您将在2026模型开放框架下制作一个模型卡。关键在于再现性——一个命令可以从头到尾地重新运行整个管道。

## 概念

这条管道有五个阶段。**数据**:dedup (MinHash / Datatrove)，质量过滤器（Nemotron-CC风格的分类器），PII刷洗，针对公共基准污染的分裂卫生检查。**SFT**: Axolotl YAML， 0 -3对8xH100，余弦时间表，包装序列，2-3 epoch。**DPO或GRPO**: TRL配置，1 epoch，偏好对，人工标记或模型判断，beta调优。**量化**:GPTQ + AWQ + GGUF部署灵活性。**服务**:vLLM 0.7与EAGLE-3投机头（或SGLang与SpecForge）， K8s部署，HPA队列等待。

消融是可交付的：仅SFT vs SFT+DPO vs SFT+GRPO在三个特定任务基准上。服务指标：第1 / 8 / 32批代币/秒，EAGLE-3接受率，$/ 100万代币。安全评估：羊驼守卫4合格率。模型卡：偏差评估，可重复性种子，数据许可。

## 堆栈

- 数据：用于dedup的Datatrove，用于质量的Nemotron-CC分类器，用于PII的Presidio
- 基地：羊驼3.3 8B, Qwen3 14B，或杰玛3 12B
- Axolotl v0.8 with ZeRO-3, Flash Attention 3，打包序列
- 偏好调整：DPO或GRPO的TRL 0.15；单gpu迭代的非sloth
- 量化：GPTQ（马林），AWQ， GGUF通过llama.cpp
- 服务：vLLM 0.7与EAGLE-3推测解码（或SGLang 0.4 + SpecForge）
- 评估：lm-evaluation-harness， RewardBench-2, MT-Bench-v2, MMLU-Pro
- 安全评估：羊驼守卫4号，盾牌2号
- 基础设施：Kubernetes + NVIDIA设备插件，HPA队列等待度量
- 可观察性：W&B用于训练，Langfuse用于推理

## 构建它

1. **的数据管道。**在原始语料上运行Datatrove dedup。采用nemotron - cc风格的质量分类器。Presidio擦洗PII。用显式种子写train/val拆分。

2. **污染检查。**对于每个验证分割，针对MMLU-Pro， MT-Bench-v2， RewardBench-2测试集计算MinHash。拒绝任何重叠。

3. **蝾螈平米。** YAML与0 -3，FA3，序列包装。8 × h100, 2-3次。到W&B。

4. ** trl dpo / grpo。**以SFT检查点为例，在偏好对上运行一个DPO epoch（或在数学/代码上运行具有可验证奖励的GRPO）。扫描测试。

5. **数字转换。**为llama.cpp产生GPTQ-INT4-Marlin、AWQ-INT4、GGUF-Q4_K_M三个量化。记录大小和标称吞吐量。

6. **提供推测解码。** vLLM 0.7配置EAGLE-3草案头通过红帽投机者训练。测量第1 / 8 / 32批的接受率和尾延迟。报告$/ 100万代币与Anthropic / OpenAI的相同评估。

7. ** Eval矩阵。**运行lm-eval-harness， RewardBench-2, MT-Bench-v2, MMLU-Pro, SFT-only, SFT+DPO, SFT+GRPO。生成一个表。

8. **安全eval。**开发集的《羊驼守卫4》通过率。ShieldGemma-2输出滤波器。

9. 卡**模型。** MOF 2026模板：数据，培训，评估，安全，许可，可复制部分与yaml和提交sha。

## 使用它

```
$ ./pipeline.sh config/llama3.3-8b-domainX.yaml
[data]    300k deduped, 12k filtered, 280k accepted (seed=7)
[SFT]     3 epochs, 8xH100, 6h12m, val loss 1.42 -> 1.03
[DPO]     1 epoch, beta=0.08, 4xH100, 1h40m
[quant]   GPTQ-INT4 4.6 GB, AWQ-INT4 4.8 GB, GGUF-Q4_K_M 5.1 GB
[serve]   vLLM 0.7, EAGLE-3 acceptance 0.74, p99 126ms @ bs=8
[eval]    MMLU-Pro +3.2, MT-Bench-v2 +0.41, RewardBench-2 +0.08
[card]    model-card.md generated under 2026 MOF
```

## 练习

1. 在相同的任务特定基准上运行SFT-only vs SFT+DPO vs SFT+GRPO。报告哪种首选方法获胜以及获胜多少。

2. 把羊驼3.3 8B换成qwen314b。以匹配的质量测量$/ 100万代币。

3. 衡量EAGLE-3对域数据的接受率与通用ShareGPT的接受率。报告增量及其对延迟预算的意义。

4. 注入1%的污染（将MMLU-Pro答案泄漏到训练数据中）并重新运行评估。看MMLU-Pro的准确性跳不现实。建立一个污染检查CI门来捕获这个。

5. 添加LoRA SFT作为完全微调的替代方案。在低10倍的内存下测量质量差距。

## 关键术语

| Term | What people say | What it actually means |
|------|-----------------|------------------------|
| Axolotl | "SFT trainer" | Unified YAML-driven trainer for SFT, DPO, and distillation |
| TRL | "Preference tuner" | Hugging Face library for DPO, GRPO, PPO on LLMs |
| GRPO | "Group-relative policy optimization" | DeepSeek R1's RL recipe with verifiable rewards |
| EAGLE-3 | "Speculative decoding draft" | Draft heads that predict N tokens ahead; vLLM verifies with target model |
| MOF | "Model Openness Framework" | 2026 standard for grading model releases on data, code, license |
| Contamination check | "Split hygiene" | MinHash-based detection of test-set leakage into training |
| Acceptance rate | "EAGLE / MTP metric" | Fraction of drafted tokens the target model accepts |
