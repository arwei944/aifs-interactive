# FIPA-ACL与言语法的传承

> 在MCP和A2A之前，有FIPA-ACL。2000年，IEEE智能物理代理基金会批准了一种代理通信语言，它包含20种行为体、两种内容语言和一组交互协议——contract net、subscribe/notify、request-when。由于本体开销对于web来说过于沉重，它逐渐淡出了工业界，但是多代理系统的LLM复苏正在悄悄地重新实现没有正式语义的相同思想：JSON契约代表执行，自然语言代表本体。本课认真阅读FIPA-ACL，以便您可以了解2026年哪些协议决策是重新发明，哪些是新颖性，以及当前浪潮将重新发现2000年代已经解决的问题。

**Type:** Learn
**Languages:** Python (stdlib)
**Prerequisites:** Phase 16 · 01 (Why Multi-Agent)
**Time:** ~60 minutes

## 问题

2026年的代理协议前景非常繁忙：MCP用于工具，A2A用于代理，ACP用于企业审计，ANP用于分散信任，NLIP用于自然语言内容，再加上CA-MCP和二十多个研究提案。每个规范都宣称自己是基础。

诚实的解读是，他们中的大多数人都在重新发现一个非常具体的20年前的决策树。Austin（1962）和Searle（1969）的言语行为理论告诉我们“话语即行为”。KQML（1993）把它变成了一个有线协议。FIPA-ACL（2000年批准）产生了参考标准化：20个行为体，内容语言SL0/SL1，合同网络和订阅通知的交互协议。JADE和JACK是Java参考平台。这种努力在2010年左右消退，因为本体开销太大，而web正在取得胜利。

当你看MCP的时候了解传统可以告诉你两件事：哪些新的“创新”实际上是重新发明，哪些旧的失败模式将被新的规范重新发现。

## 概念

### 言语行为，在一个段落中

奥斯汀注意到有些句子并不是描述世界，而是改变世界。“我保证。”“我请求。”“我宣布。”他称这些为表演性话语。塞尔将其分为五类：自信型、指示型、委托型、表达型和陈述型。KQML （Finin et al., 1993）为软件代理实现了这一操作：消息是一个执行（动作）加内容（动作是关于什么的）。FIPA-ACL消除了KQML的差距，并标准化了大约20个执行体。

### 二十个FIPA执行体（部分列表）

| Performative | Intent |
|---|---|
| `inform` | "I tell you P is true" |
| `request` | "I ask you to do X" |
| `query-if` | "Is P true?" |
| `query-ref` | "What is the value of X?" |
| `propose` | "I propose we do X" |
| `accept-proposal` | "I accept the proposal" |
| `reject-proposal` | "I reject the proposal" |
| `agree` | "I agree to do X" |
| `refuse` | "I refuse to do X" |
| `confirm` | "I confirm P is true" |
| `disconfirm` | "I deny P" |
| `not-understood` | "Your message did not parse" |
| `cfp` | "Call for proposals on X" |
| `subscribe` | "Notify me when X changes" |
| `cancel` | "Cancel the ongoing X" |
| `failure` | "I tried X and failed" |

完整的名单已经出来了重点不是要记住它——重点是每一个都对应于LLM协议最终重新添加的原语。

### 规范的FIPA-ACL消息

```
(inform
  :sender       agent1@platform
  :receiver     agent2@platform
  :content      "((price IBM 83))"
  :language     SL0
  :ontology     finance
  :protocol     fipa-request
  :conversation-id   conv-42
  :reply-with   msg-17
)
```

七个字段携带协议信封；一场(其余的字段正是每次将重试、线程和本体绑定到JSON协议时重新创建的字段。

### 两个遗留平台

**JADE** （Java Agent DEvelopment framework， 1999 - 2020年代）是最常用的符合fipa的运行时。代理扩展基类，交换ACL消息，在容器内运行，并使用“行为”进行协调。与contract-net、subscribe-notify、request-when和proposal -accept一起提供的交互协议库。

**JACK** （Agent Oriented Software，商业）强调在FIPA消息之上的BDI （Belief-Desire-Intention）推理。更正式，更少被采纳。

一旦web堆栈出现了多代理用例，这两种情况都有所下降。MCP和A2A是2026年的运行时“容器”。

### FIPA为何衰落

- * *本体开销。** FIPA需要共享本体来解析就本体达成一致是一个长达数年的标准过程。web只是使用HTTP + JSON。
- **没有人使用的形式语义。** SL （Semantic Language）给出了严格的真值条件，但大多数生产系统使用自由形式的内容而忽略了形式主义。
- * *工具锁定。** JADE仅支持java；杰克很商业化。精通多种语言的队伍绕过了这两个地方。
- **互联网赢了。** REST，然后JSON-RPC，然后gRPC取代了ACL的传输。

### LLM的复兴是FIPA-lite

比较FIPA

```
(request                                {
  :sender  agent1                         "jsonrpc": "2.0",
  :receiver tool-server                   "method":  "tools/call",
  :content "(lookup stock IBM)"           "params":  {"name":"lookup_stock",
  :ontology finance                                   "arguments":{"symbol":"IBM"}},
  :conversation-id c42                    "id": 42
)                                        }
```

相同的信封，不同的语法。两者都带有：who， who, intent, payload, correlation id。两者都不是对另一个的革命——它们是在同一设计上的不同权衡。

Liu等人在2025年的调查（“智能体互操作性协议的调查：MCP， ACP, A2A， ANP”，arXiv:2505.02279）明确表明了这一谱系：MCP对应于工具使用语音行为，A2A对应于智能体对等语音行为，ACP对应于审计跟踪语音行为，ANP对应于分散的身份扩展。新的规范是具有JSON语法和更松散语义的ACL后代。

### 权衡，说得很清楚

*FIPA给你什么和现代规格下降：**

- 形式语义——你可以证明
- 一个规范的行动力目录——你不需要再争论"我们应该有一个
- 几十年的交互协议模式——契约-网络、订阅-通知、提议-接受——具有已知的正确性属性。

*现代规格给你什么，而FIPA没有：**

- 与所有现代工具兼容的json原生有效负载。
- llm可以在没有手工编码本体的情况下解释的自然语言内容。
- web栈传输（HTTP， SSE, WebSocket）。
- 通过自描述文档（MCP）发现能力

更宽松的意图语义，更容易实现。这就是交易。

### 值得移植的交互协议

FIPA发布了大约15个交互协议。有三个值得在LLM多智能体系统中发扬：

1. 合同网络协议（CNP）。**经理问题投标人的回应是经理接受/拒绝。这是典型的任务市场模式（第16·16阶段谈判）。
2. * *订阅/通知。**用户发送发布者发送这是2026年的每一件大事。
3. * *时要求。**“当条件Y成立时执行X。”带有先决条件的延迟行动。2026年的模拟是持久工作流引擎中的延迟任务（阶段16·22生产缩放）。

每个都清晰地映射到现代消息队列、HTTP +轮询或SSE流。

### 当你放弃本体论时，什么会破裂

如果没有共享的本体，智能体就会从自然语言内容中推断出意义。文档中的2026故障模式是**语义漂移**：两个代理使用相同的单词(FIPA的本体需求会在解析时拒绝该消息。

不使用完整本体的缓解：

- JSON模式
- 类型化工件（A2A）——拒绝错误的模态。
- 在信封中明确的表现-使意图明确，即使内容是自然语言。

### 2026年的规格，映射到语言行为遗产

| Modern spec | FIPA analog | What it keeps | What it drops |
|---|---|---|---|
| MCP `tools/call` | `request` | explicit intent, correlation id | formal semantics, ontology |
| MCP `resources/read` | `query-ref` | explicit intent, correlation id | formal semantics |
| A2A Task lifecycle | contract-net + request-when | async lifecycle, state transitions | formal completeness guarantees |
| A2A streaming events | subscribe/notify | async push | typed-predicate subscription |
| CA-MCP shared context | blackboard (Hayes-Roth 1985) | multi-writer shared memory | logical consistency model |
| NLIP | natural-language content | LLM-native | schema |

从上到下阅读表格，模式是：保持结构原始，放弃形式主义，让法学硕士掩盖歧义。

## 船这

不要把FIPA-ACL带回来。把它的清单拿回来：

- 每个消息的意图原语是什么？
- 请求-响应和取消是否有关联id ？
- 是否存在显式内容语言（JSON-RPC、纯文本、结构化类型工件）？
- 交互协议是一流的，还是从头开始重新实现契约网？
- 当两个代理在内容意义（语义漂移）上意见不一致时会发生什么？

在将任何新协议发布到生产环境之前，将这五个问题记录下来。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Speech act | "An utterance that does something" | Austin/Searle: utterances as actions. The theoretical parent of ACL. |
| FIPA | "That old XML thing" | IEEE Foundation for Intelligent Physical Agents. Standardized ACL in 2000. |
| ACL | "Agent Communication Language" | FIPA's envelope format: performative + content + metadata. |
| Performative | "The verb" | The intent class of a message: `inform`, `request`, `propose`, `cfp`, etc. |
| KQML | "FIPA's predecessor" | Knowledge Query and Manipulation Language (1993). Simpler, narrower. |
| Ontology | "Shared vocabulary" | A formal definition of the concepts the content language talks about. |
| SL0 / SL1 | "FIPA content languages" | Semantic Language levels 0 and 1 — the formal content language family. |
| Contract Net | "Task market" | Manager issues cfp; bidders propose; manager accepts. The canonical interaction protocol. |
| Interaction protocol | "Pattern of messages" | A sequence of performatives with known correctness: request-when, subscribe-notify, etc. |
