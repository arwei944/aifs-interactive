# FIPA-ACL and the Inheritance of Speech Law

> Before MCP and A2A, there was FIPA-ACL. In 2000, the IEEE Foundation for Intelligent Physical Agents approved a proxy communication language, which includes 20 actors, two content languages and a set of interaction protocols - contract net, subscribe/notify, request-when. Due to the excessive burden of ontology overhead on the web, it has gradually faded out of the industrial sector. However, the revival of LLMS in multi-agent systems is quietly re-implementing the same idea without formal semantics: JSON contracts represent execution, and natural language represents ontology. In this lesson, carefully read FIPA-ACL so that you can understand which protocol decisions are reinvented in 2026, which are novel, and that the current wave will rediscover problems that were solved in the 2000s.

## "Problem"

The outlook for proxy protocols in 2026 is very busy: MCP for tools, A2A for proxies, ACP for enterprise audits, ANP for decentralized trust, NLIP for natural language content, plus CA-MCP and over twenty research proposals. Each norm claims to be the foundation.

An honest interpretation is that most of them are rediscovering a very specific decision tree from 20 years ago. The speech act theory of Austin (1962) and Searle (1969) tells us that "speech is action". KQML (1993) turned it into a wired protocol. FIPA-ACL (approved in 2000) has produced reference standards: 20 actors, content languages SL0/SL1, contract networks, and interaction protocols for subscription notifications. JADE and JACK are Java reference platforms. This effort waned around 2010 because the ontology cost was too high, while the web was winning.

When you look at MCP, understanding tradition can tell you two things: which new "innovations" are actually reinventions, and which old failure patterns will be rediscovered by new norms.

## Concept

### Speech acts, within a paragraph

Austin noticed that some sentences do not describe the world but change it. "I promise." "I request." " "I declare." " He called these performative remarks. Searle classified them into five types: confident type, indicative type, delegating type, expressive type and declarative type. KQML (Finin et al., 1993) implemented this operation for software agents: a message is an execution (action) plus content (the action is about what). FIPA-ACL eliminates the gap of KQML and standardizes approximately 20 executors.

### Twenty FIPA executors (Partial list)

| Performative | Intent |
|---|---|
| `inform` | "I tell you P is true" |
| `request` | "I ask you to do X" |
| `query-if` | "Is P true?" |
| `query-ref` | "What is the value of X?" |
| `propose` | "I propose we do X" |
| `accept-proposal` | "I accept the proposal" |
| `reject-proposal` | "I reject the proposal" |
| `agree` | "I agree to do X" |
| `refuse` | "I refuse to do X" |
| `confirm` | "I confirm P is true" |
| `disconfirm` | "I deny P" |
| `not-understood` | "Your message did not parse" |
| `cfp` | "Call for proposals on X" |
| `subscribe` | "Notify me when X changes" |
| `cancel` | "Cancel the ongoing X" |
| `failure` | "I tried X and failed" |

The complete list has come out. The key point is not to remember it - the key point is that each one corresponds to the primitives that the LLM protocol eventually re-added.

### Standardized FIPA-ACL messages

```
(inform
  :sender       agent1@platform
  :receiver     agent2@platform
  :content      "((price IBM 83))"
  :language     SL0
  :ontology     finance
  :protocol     fipa-request
  :conversation-id   conv-42
  :reply-with   msg-17
)
```

Seven fields carry the agreement envelope; One field (the rest of the fields are precisely the ones recreated each time retries, threads, and ontologies are bound to the JSON protocol).

### Two legacy platforms

**JADE** (Java Agent DEvelopment framework, 1999-2020s) is the most commonly used runtime compliant with fipa. The agent extends the base class, exchanges ACL messages, runs within the container, and is coordinated using "behaviors". The interaction protocol library provided along with contract-net, subscrib-notify, request-when and proposal-accept.

**JACK** (Agent Oriented Software, Business) emphasizes BDI (Belief-Desire-Intention) reasoning on top of FIPA messages. More formal and less adopted.

Both situations declined once multi-agent use cases emerged in the web stack. MCP and A2A are the runtime "containers" for 2026.

### Why has FIPA declined

- "Ontology overhead." FIPA requires a shared ontology to resolve. Reaching an agreement on the ontology is a standard process that lasts for several years. The web merely uses HTTP + JSON.
- Formal semantics that no one uses. SL (Semantic Language) provides strict truth conditions, but most production systems use free-form content and ignore formalism.
- "Tool lock." JADE only supports java; Jack is very commercialized. Teams proficient in multiple languages bypassed these two places.
- The Internet has won. REST, then JSON-RPC, and then gRPC replaced ACL transmission.

### The revival of LLM is FIPA-lite

Compare FIPA

```
(request                                {
  :sender  agent1                         "jsonrpc": "2.0",
  :receiver tool-server                   "method":  "tools/call",
  :content "(lookup stock IBM)"           "params":  {"name":"lookup_stock",
  :ontology finance                                   "arguments":{"symbol":"IBM"}},
  :conversation-id c42                    "id": 42
)                                        }
```

The same envelope, but different grammars. Both come with: who, who, intent, payload, correlation id. Neither is a revolution over the other - they are different trade-offs on the same design.

The 2025 investigation by Liu et al. (" Investigation of Agent Interoperability Protocols: MCP, ACP, A2A, ANP ", arXiv:2505.02279) clearly indicates this lineage: MCP corresponds to tool usage voice behavior, A2A corresponds to agent peer-to-peer voice behavior, ACP corresponds to audit trail voice behavior, and ANP corresponds to decentralized identity expansion. The new specification is a descendant of ACL with JSON syntax and looser semantics.

### The trade-off is very clear

*What does FIPA offer you and the modern specification decline: **

- Formal semantics - you can prove it
- A standardized action directory - you don't need to argue anymore, "We should have one.
- Decades of interaction protocol patterns - contract-network, subscription-notification, proposal-acceptance - have known correctness attributes.

*What do modern specifications offer you that FIPA doesn't: **

- A native json payload compatible with all modern tools.
- Natural language content that LLMS can interpret without manually encoding the ontology.
- web stack transfer (HTTP, SSE, WebSocket).
- Discover capabilities through self-describing documents (MCP)

More lenient intent semantics are easier to achieve. This is a transaction.

### An interaction protocol worth porting

FIPA has released approximately 15 interaction protocols. There are three points worth promoting in LLM multi-agent systems:

1. Contract Network Protocol (CNP) The bidder's response to the manager's question is that the manager accepts/rejects. This is a typical task-market model (Negotiation Stage 16·16).
2. Subscription/Notifications. User-sent and publisher sent - this is every major event in 2026.
3. It is required at that time. "Execute X when condition Y is met." Delayed action with preconditions. The simulation for 2026 is a delayed task in the persistent workflow engine (Phase 16.22 Production scaling).

Each one is clearly mapped to modern message queues, HTTP + polling, or SSE streams.

### What breaks when you abandon ontology

If there is no shared ontology, the agent will infer the meaning from the natural language content. The 2026 failure mode in the document is ** semantic drift ** : Two agents use the same word (FIPA's ontology requirements will reject this message during parsing)

Mitigation without using the complete ontology:

- JSON mode
- Typed artifacts (A2A) - Reject incorrect modes.
- Clear expression in the envelope - make the intention clear, even if the content is natural language.

### The 2026 specifications are mapped to the language behavior legacy

| Modern spec | FIPA analog | What it keeps | What it drops |
|---|---|---|---|
| MCP `tools/call` | `request` | explicit intent, correlation id | formal semantics, ontology |
| MCP `resources/read` | `query-ref` | explicit intent, correlation id | formal semantics |
| A2A Task lifecycle | contract-net + request-when | async lifecycle, state transitions | formal completeness guarantees |
| A2A streaming events | subscribe/notify | async push | typed-predicate subscription |
| CA-MCP shared context | blackboard (Hayes-Roth 1985) | multi-writer shared memory | logical consistency model |
| NLIP | natural-language content | LLM-native | schema |

Read the table from top to bottom. The pattern is: keep the structure original, abandon formalism, and let the Master of Laws cover up the ambiguity.

## This ship

Don't bring FIPA-ACL back. Bring back its list

- What is the intent primitive of each message?
- Are there associated ids for request-response and cancellation?
- Are there explicit content languages (JSON-RPC, plain text, structured type artifacts)?
- Is the interaction protocol first-class or is the contract network reimplemented from scratch?
- What happens when two agents disagree on content meaning (semantic drift)?

Before releasing any new protocol to the production environment, record these five questions.

## Key terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Speech act | "An utterance that does something" | Austin/Searle: utterances as actions. The theoretical parent of ACL. |
| FIPA | "That old XML thing" | IEEE Foundation for Intelligent Physical Agents. Standardized ACL in 2000. |
| ACL | "Agent Communication Language" | FIPA's envelope format: performative + content + metadata. |
| Performative | "The verb" | The intent class of a message: `inform`, `request`, `propose`, `cfp`, etc. |
| KQML | "FIPA's predecessor" | Knowledge Query and Manipulation Language (1993). Simpler, narrower. |
| Ontology | "Shared vocabulary" | A formal definition of the concepts the content language talks about. |
| SL0 / SL1 | "FIPA content languages" | Semantic Language levels 0 and 1 — the formal content language family. |
| Contract Net | "Task market" | Manager issues cfp; bidders propose; manager accepts. The canonical interaction protocol. |
| Interaction protocol | "Pattern of messages" | A sequence of performatives with known correctness: request-when, subscribe-notify, etc. |
