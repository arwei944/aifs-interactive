# Handover and routines - Stateless orchestration

> OpenAI's Swarm (October 2024) distills multi-agent orchestration into two fundamental elements: ** routines ** (instructions + tools as system prompts) and ** handover ** (tools that return to another agent). There is no state machine, no branch DSL - LLM routes by calling the correct switching tool. The OpenAI Agents SDK (March 2025) is the successor product for production. Swarm itself remains the cleanest conceptual reference - its entire source code is only a few hundred lines. This pattern is viral because the API surface is roughly "agent = prompt + tool;" "Switch = Function returns proxy." Limitation: Stateless, so memory is the caller's problem.

**Type:** Learn + Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 16 · 04 (Primitive Model)
**Time:** ~60 minutes

## "Problem"

Every multi-agent framework expects you to learn its DSLS: LangGraph nodes and edges, CrewAI people and Tasks, AutoGen GroupChat and Manager. DSLS are true abstractions, but they make things seem heavier than they actually need.

Swarm is moving in the opposite direction: leveraging the tool-calling capabilities that the model already possesses. The handover turned into a tool call. The coordinator is the agent that currently holds the dialogue. The state machine is implicitly contained in the system prompt of the agent.

## Concept

### Two primitives

*"Routine. Define the system prompt for agent roles and available tools. You can imagine it as a set of instructions with a limited scope: "You are a triage agent; If the user requests a refund, it should be handed over to the refund agent.

*Switch. A tool that an agent can invoke, which returns a new agent object. The Swarm runtime detects the return value of the Agent and switches the active agent for the next round.

This is the entire abstract concept.

```
def transfer_to_refunds():
    return refund_agent  # Swarm sees Agent return → switch active agent

triage_agent = Agent(
    name="triage",
    instructions="Route the user to the right specialist.",
    functions=[transfer_to_refunds, transfer_to_sales, transfer_to_support],
)
```

The system prompt of the triage agent enables it to select the correct switch based on the user message. The tool call of LLM has completed the routing.

### Why is it viral

- "Small API. Learn two concepts.
- Use the existing functions of the model. Tool invocation has already reached the production level across providers.
- There is no burden from the state machine. Do not describe the graphics; The agent's hint described to whom they handed it over.

### Stateless trade

Swarm is explicitly stateless between runs. The framework retains the message history during its operation but does not persist anything. Memory, continuity, and long-running tasks - all are problems for the caller.

In production (OpenAI Agents SDK, March 2025), this is one of the major changes: the SDK adds built-in session management, guardrails, and tracking while maintaining the switching primitives.

### When the colony/handover is appropriate

- "Classification mode. Frontline agents transfer users to experts.
- The transmission of skills. If the task requires code, please call the coder; If research is needed, just call the researchers.
- Short and limited conversations. Customer support, frequently asked questions to tickets, simple workflow.

### When Swarm is struggling

- Long sessions using shared memory. Switch the prompt to reset the session status to a new agent along with the history record. There is no persistent state between proxies without caller-managed memory.
- "Parallel execution." The switch is one at a time - a master-agent switch. Parallelism requires the caller to coordinate multiple Swarm operations.
- Audit and replay. Stateless operation is difficult to replay precisely. The handover choice for a master of Laws is not definite.

### OpenAI Agents SDK (March 2025)

The production successor added:

- "Session status. "Across running persistent threads."
- Guardrail. Input/output validation hook.
- "Tracking. Each tool call and handover is recorded.
- Switch the filter. Control the context transmission during switching.

The source language was retained. Production ergonomics is added around it.

### Group chat vs group chat

Both use LLM-driven routing, but they differ in which aspect to choose the next:

- GroupChat: The selector (function or LLM) selects the next speaker from the outside.
- Swarm: The current agent selects its successor by invoking the handover tool.

## This ship

Checklist

- Switch log recording. Each time the write trace event is switched, it takes a context snapshot from proxy to proxy.
- Context transfer rules. Decide what to move at the time of handover: complete history records (expensive), the last N messages, or summaries.
- Guardrail handover. Handovers with experts having different tool permissions must be authenticated - otherwise, prompt injection may force unnecessary handovers.
- Cyclic detection. It is a common fault for two agents to pass back and forth. Use a simple final K-loop check for detection.
- "Rollback agent." If the switching target does not exist, revert to the safe default value.

## Practice

1. The active agent for the second round of operation confirmation is refund.
2. Add a loop detection rule: If the same two agents are passed three times consecutively, force exit. Design a fallback plan.
3. Read the switching filters in the OpenAI Agents SDK documentation. Implement the "Summary at handover" version: The outgoing agent compresses the context into a bullet point summary before the incoming agent takes over.

## Key terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Routine | "The agent prompt" | System prompt + tool list. Defines role and available handoffs. |
| Handoff | "Transfer to another agent" | A tool the active agent can call that returns a new Agent. The runtime switches active agent. |
| Stateless | "No memory between runs" | Swarm does not persist anything; memory is the caller's responsibility. |
| Active agent | "Who's speaking now" | The agent currently holding the conversation. Handoff changes this. |
| Context transfer | "What moves on handoff" | Policy for what history the incoming agent sees: full, last N, or summarized. |
| Handoff loop | "Agents ping-pong" | Failure mode where two agents keep handing back to each other. |
| OpenAI Agents SDK | "Production Swarm" | March 2025 successor; adds sessions, guardrails, tracing on top of the handoff primitive. |
| Handoff filter | "Gate on transfer" | SDK feature to inspect and modify context at the handoff boundary. |
