# MIO和任意对任意流多模态模型

> gpt - 40提供了一种大多数开放模型无法复制的产品：一种可以听到声音、看到视频并实时回复的代理。到2024年底，开放生态系统的答案是MIO （Wang et al.， 2024年9月）。MIO对文本、图像、语音和音乐进行标记，在交错的序列上训练一个因果转换器，并为任何模态生成任何模态。AnyGPT （Zhan et al.， 2024年2月）是概念验证；MIO是按比例放大；统一io 2 （Allen AI， 2023年12月）是视觉+行动基础的表兄弟。本课将阅读任意到任意模式——四个标记器、一个转换器、流友好解码。

**Type:** Learn
**Languages:** Python (stdlib, four-modality token allocator + streaming decode loop)
**Prerequisites:** Phase 12 · 11 (Chameleon), Phase 6 (Speech and Audio)
**Time:** ~120 minutes

## 学习目标

- 设计一个共享词汇表，其中包含文本、图像、语音和音乐标记，而不会发生冲突。
- 比较SEED-Tokenizer（图像）和speech - tokenizer residual-VQ（语音）在压缩和重建方面的权衡。
- 解释一下培养任何一代人的四阶段课程。
- 说出三种任意对任意的开放配方及其主要优缺点：MIO、AnyGPT、Unified-IO 2。

## 这个问题

统一的多模态模型很容易提出要求，但很难大规模构建。直到2024年，大多数“任意对任意”系统都是流水线化的：视觉模型→文本表示→语音模型→音频。每一跳都会丢失信息，增加延迟，并使训练复杂化。gpt - 40的演示视频显示了单模型替代方案的亚秒响应；开放系统落后了几个月。

工程方面的挑战：

- 每一种模态都必须存在标记器，必须对其进行无损压缩以进行重构，并以转换器可以使用的速率生成标记。
- 单个词汇表必须为文本（32k+）、图像（16k+）、语音（4k+）和音乐（8k+）分配空间。最少4万以上的参赛作品。
- 训练数据必须覆盖每一个输入输出对（文本→图像、图像→语音、语音→图像等），否则模型必须组合。
- 推断必须以足够快的速度流输出令牌，以满足会话延迟（<500ms的时间到第一个音频字节）。

## 这个概念

### 四种模式的四种标记器

MIO的标记器堆栈：

- 文本：标准BPE，词汇量~32000。
- 图像：SEED-Tokenizer(2023) -量化VAE与离散码本，4096个条目，每个图像32x32个标记。
- 语音：语音标记器残差- vq(2023) -编码16kHz波形到8个分层码本；第一层是粗鄙的内容，后一层增加韵律和说话人的身份。
- 音乐：类似残差- vq （Meta的MusicGen / Encodec家族），4-8个码本。

每种模态都会产生整数标记。令牌在共享词汇表中获得不相交的ID范围：

```
text:   0..31999
image:  32000..36095  (4096 image tokens)
speech: 36096..40191  (4096 speech base tokens, plus residual layers)
music:  40192..48383  (8192 music tokens)
sep:    48384..48390  (<image>, <speech>, <music>, </...>, etc.)
```

总共：~48k词汇量。输入嵌入和输出投影张成了它的全部。

### 流媒体解码

语音生成使用残差vq。变压器预测基本（第0层）语音令牌；一个并行解码的残差量化器预测后续的层。每个层0令牌大约是16kHz的50ms音频。

流模式：

1. 用户对着麦克风说话；实时音频标记器每50毫秒发出语音标记。
2. MIO在令牌到达时消耗它们（提示预填充+增量向前）。
3. 生成时输出令牌流；并行语音解码器将它们转换为音频样本，延迟约50-150ms。
4. 到第一个音频字节的时间：在MIO纸张中~300-500ms，接近gpt - 40的~250ms。

Mini-Omni (arXiv:2408.16725), GLM-4-Voice （arXiv:2412.02612）和Moshi （arXiv:2410.00037）是互补的流媒体语音- llm设计。Moshi在单个GPU上实现了160ms的往返。

### 四级课程

MIO的培训课程：

1. 第一阶段-对准。大型语态对语料库：文本-图像、文本-语音、文本-音乐。每一对都使用自己的标记词汇段。训练共享词汇。
2. 第二阶段-交错。多模态交错文档（带有图像+视频的博客，带有文本的播客等）。训练跨模态上下文。
3. 第三阶段：语言增强。额外的音频数据，以提高语音质量，而不会失去文本功能。
4. 第4阶段- SFT。跨模式的指令调整：VQA、字幕、叙述、语音对语音对话。

错过一个阶段会降低特定的能力：跳过阶段2，模型就会失去跨模态上下文；跳过第三阶段，语言能力就很差。

### Chain-of-visual-thought

MIO引入了视觉思维链：模型发出中间图像标记作为推理步骤。对于“猫在爬树吗？”模型：

1. 发射
2. 发出分析草图的文本。
3. 发出最终答案。

渲染的中间图像用作刮擦板。基准测试提高了空间推理任务。这个想法反映了文本推理的思维链。

### 任何对任何的竞争者

- AnyGPT (arXiv:2402.12226): 4种模式（文本，图像，语音，音乐），类似设计。
- 统一io 2 (arXiv:2312.17172)：增加视觉动作输出，深度，法线。更多的任务多样性，更小的规模。
- NExT-GPT (arXiv:2309.05519): LLM +模式特定扩散解码器。不是单一模式的方法。
- CoDi (arXiv:2305.11846)：可组合扩散；任意对任意通过共享潜势。

MIO是最接近纯令牌的任意对任意。AnyGPT是它的概念祖先。

### 延迟的预算

对于会话产品，每个组件的延迟都很重要：

- 麦克风到音频令牌：~50ms。
- 预填充（音频标记+历史记录）：在8B型号上约100毫秒。
- 第一个输出令牌：~50ms。
- 并行残差- vq +语音解码器：~100-150ms。

到第一个音频字节的总时间：最少~300ms。gpt - 40声称~250ms。Moshi声称160ms。MIO/AnyGPT在每个公共基准测试中都在400-600ms范围内。

### 为什么任何人对任何人都很难

即使在2026年，开放任意对任意模型也会在两个轴上跟踪封闭模型：

- 语音质量。残差vq标记器是有损的；与elevenlabs课堂上的声音相比，会话式语音听起来像机器人。
- 交叉模式推理。要求模型“歌唱你所看到的”仍然比纯视觉任务更容易失败。

这些都是有待研究的问题。Qwen3-Omni（第12.20课）是2025年最先进的开放尝试。

## 练习

1. 您的产品接受语音输入并返回语音输出。端到端延迟预算目标是什么？列出花费时间的组件。

2. 语音标记器残差- vq使用8个码本。提出为什么需要对剩余电平进行并行解码（而不是顺序解码），以及它带来的延迟节省。

3. 你的词汇量有32k文本+ 4k图像+ 4k语音。添加8k音乐和~10个分隔符。隐藏点4096的嵌入矩阵参数代价是多少？

4. 视觉思维链会发出一个中间图像。什么样的问题是有益的？哪些人会受到额外代币的伤害？

5. Read Moshi （arXiv:2410.00037）。描述一下它的“内心独白”技巧，并与MIO的视觉思维链进行比较。

## 关键术语

| Term | What people say | What it actually means |
|------|-----------------|------------------------|
| Any-to-any | "Multimodal in/out" | A single model that accepts and emits text, image, speech, and music in any direction |
| Residual-VQ | "Speech tokenizer stack" | Multi-codebook tokenization where each layer adds information; base layer is content, later layers are prosody |
| SEED-Tokenizer | "Image codes" | Discrete image tokenizer with 4096-entry codebook used by MIO |
| Chain-of-visual-thought | "Visual scratchpad" | The model generates an intermediate image as a reasoning step before its final answer |
| Time-to-first-audio-byte | "TTFAB" | Latency from user voice to first audio output; <500ms for conversational feel |
| Four-stage curriculum | "Training recipe" | Alignment -> interleaved -> speech-enhanced -> SFT, in that order |
