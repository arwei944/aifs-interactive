# 自我完善和批评：迭代输出改进

> Self-Refine （Madaan et al., 2023）使用一个LLM在一个循环中扮演三个角色——生成、反馈、改进。平均增益：7个任务+20绝对增益。批评家（Gou et al., 2023）通过外部工具路由验证来强化反馈步骤。到2026年，这种模式将作为“评估器-优化器”（Anthropic）或护栏循环（OpenAI Agents SDK）出现在每个框架中。

## 这个问题

agent给出了一个几乎正确的答案。也许一行代码有语法错误。也许摘要太长了。也许一个计划漏掉了一个边缘情况。您想要的是：代理对自己的输出进行批评，然后修复它。

Self-Refine显示，这种方法只需要一个模型，没有训练数据，也没有强化学习。但这里有一个问题：法学硕士不擅长对确凿事实进行自我验证。CRITIC通过外部工具（搜索、代码解释器、计算器、测试运行器）命名修复路径验证步骤。

这两篇论文一起定义了2026年迭代改进的默认值：生成、验证（在可能的情况下从外部进行）、细化、在验证者通过时停止。

## 这个概念

### 自我完善（Madaan et al., NeurIPS 2023）

一个法学硕士，三个角色：

```
generate(task)            -> output_0
feedback(task, output_0)  -> critique_0
refine(task, output_0, critique_0, history) -> output_1
feedback(task, output_1)  -> critique_1
refine(task, output_1, critique_1, history) -> output_2
...
stop when feedback says "no issues" or budget exhausted.
```

关键细节：本文对此进行了分析：下降历史和质量急剧下降。

标题：包括GPT-4在内的7项任务（数学、代码、首字母缩略词、对话）平均提高20分。没有培训，没有外部工具，单一模型。

### 批评家（Gou et al., arXiv:2305.11738, v4 Feb 2024）

Self-Refine的弱点：反馈步骤本身就是一个LLM评分。对于事实主张来说，这是不可靠的（幻觉在产生它的模型看来往往令人信服）。评论家代替

- 搜索事实主张的搜索引擎。
- 用于代码正确性的代码解释器。
- 用于算术的计算器。
- 特定于域的验证器（单元测试、类型检查器、检查器）。

验证者产生基于工具结果的结构化批评。精炼者然后在这个批判上附加条件。

标题：批评家在事实任务上胜过自我完善，因为批评是有根据的。对于没有外部验证的任务（创意写作、格式），CRITIC会简化为自我完善。

### 停止条件

两种常见的形状：

1. * *校验通过。**外部测试返回成功。可用时首选（单元测试、类型检查器、护栏断言）。
2. **没有反馈。**模型显示“输出正常”。便宜但不可靠；与最大迭代上限配对。

2026 default：合并。“如果验证器通过或模型显示良好且迭代>= 2或迭代>= max_iterations则停止。”

### 评估-优化器（Anthropic, 2024）

Anthropic在2024年12月的帖子中将其命名为五种工作流模式之一。两个角色:

- 评估者：对输出进行评分并提出批评。
- 优化器：修改给定评论的输出。

循环直到求值器通过。这是Anthropic框架下的自我完善/批判。关键的工程细节Anthropic补充说：评估器和优化器提示应该有本质上的不同，这样模型就不只是橡皮图章。

### OpenAI Agents SDK输出护栏

OpenAI Agents SDK将这种模式作为“输出护栏”发布。护栏是在代理的最终输出上运行的验证器。如果护栏绊倒（升起）护栏可以调用工具（critical风格），也可以是纯函数（self - refine风格）。

### 2026年的陷阱

- * *橡皮图章循环。**同样的模型使用同样的提示风格进行生成和评论，结果都是“对我来说很好”。使用结构不同的提示，或者使用更小的廉价模型进行批评。
- * * Over-refinement。**每个细化通过增加延迟和令牌。预算1-3通过；之后，升级到人工审核。
- **批评琐碎的任务。**如果没有外部验证者，则CRITIC退化为Self-Refine；不要为存根验证器支付延迟。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Self-Refine | "LLM that fixes itself" | Generate -> feedback -> refine loop in one model, with history |
| CRITIC | "Tool-grounded verification" | Replace feedback with an external verifier (search, code, calc, tests) |
| Evaluator-Optimizer | "Anthropic workflow pattern" | Two roles — evaluator scores, optimizer revises — looped to convergence |
| Output guardrail | "Post-hoc check" | OpenAI Agents SDK validator that runs after an agent produces output |
| Verify step | "Critique phase" | The load-bearing decision: grounded or self-rated |
| Refine history | "What the model already tried" | Prior outputs + critiques prepended to refine prompt; drop and quality collapses |
| Rubber-stamp loop | "Self-agreement failure" | Same-prompt critique returns "looks good"; fix with structurally different prompts |
| Stop condition | "Convergence test" | Verifier passes OR no feedback AND iteration cap; never single-condition |
