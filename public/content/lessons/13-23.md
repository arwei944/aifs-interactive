# 顶点-建立一个完整的工具生态系统

> 第13阶段教授每一件作品。这个顶点将它们连接到一个生产型系统中：一个带有工具+资源+提示+任务+ UI的MCP服务器、边缘的OAuth 2.1、RBAC网关、多服务器客户端、A2A子代理调用、OTel跟踪到收集器、CI中的工具中毒检测和代理。md +技能。md包。到最后，您可以为每个架构选择辩护。

**Type:** Build
**Languages:** Python (stdlib, end-to-end ecosystem harness)
**Prerequisites:** Phase 13 · 01 through 21
**Time:** ~120 minutes

## 学习目标

- 组成一个MCP服务器，公开工具、资源、提示和任务
- 在服务器前面设置一个OAuth 2.1网关，该网关强制使用RBAC和固定散列。
- 编写一个多服务器客户端，端到端跟踪OTel GenAI属性。
- 将部分工作委托给A2A附属代理；验证保留不透明度。
- 用AGENTS打包整个堆栈。md +技能。这样其他特工就可以操控它了。

## 这个问题

出货“研究和报告”系统：

- 用户问：“总结一下2026年被引用最多的三篇关于代理协议的arXiv论文。”
- 系统：通过MCP搜索arXiv；通过A2A将论文总结委托给专业作家代理；总体结果;将交互式报告呈现为MCP Apps记录每一步到OTel。

第13阶段的所有原语都出现了。这不是2026年由Anthropic （Claude Research产品），OpenAI（带有Apps SDK的GPTs）和第三方提供的玩具生产研究助理系统。

## 这个概念

### 体系结构

```
[user] -> [client] -> [gateway (OAuth 2.1 + RBAC)] -> [research MCP server]
                                                      |
                                                      +- MCP tool: arxiv_search (pure)
                                                      +- MCP resource: notes://recent
                                                      +- MCP prompt: /research_topic
                                                      +- MCP task: generate_report (long)
                                                      +- MCP Apps UI: ui://report/current
                                                      +- A2A call: writer-agent (tasks/send)
                                                      |
                                                      +- OTel GenAI spans
```

### 跟踪层次结构

```
agent.invoke_agent
 ├── llm.chat (kick off)
 ├── mcp.call -> tools/call arxiv_search
 ├── mcp.call -> resources/read notes://recent
 ├── mcp.call -> prompts/get research_topic
 ├── a2a.tasks/send -> writer-agent
 │    └── task transitions (opaque internals)
 ├── mcp.call -> tools/call generate_report (task-augmented)
 │    └── tasks/status polling
 │    └── tasks/result (completed, returns ui:// resource)
 └── llm.chat (final synthesis)
```

一个跟踪id。每个人都有权利

### 安全状况

- OAuth 2.1 + PKCE，带资源指示器，将受众锁定到网关。
- 网关持有上游凭据；用户永远不会看到它们。
- RBAC：`bob` has `research:read`, cannot call `generate_report`.
- 固定描述清单：删除了任何工具哈希值更改的服务器。
- 审计二准则：没有工具将不可信的输入、敏感数据和相应的操作结合在一起。

### 呈现

决赛客户端的主机（Claude Desktop等）在沙盒iframe中呈现交互式仪表板。仪表板包含一个已排序的论文列表、引用计数和一个调用按钮

## 使用它

Z0都是标准库，都在进程中，所以你可以端到端读取它。它运行研究-报告场景的完整流程：与网关握手、模拟OAuth 2.1、合并工具/列表、generate_report作为任务、A2A调用writer、ui://返回资源、发出OTel跨度。

看点：

- 每跳一个跟踪id。
- 网关策略阻止第二个用户写入。
- 任务生命周期从工作→完成并返回文本和ui://内容。
- A2A调用的内部状态对协调器是不透明的。
- 代理。md和SKILL。Md是另一个代理复制工作流所需的唯一文件。
