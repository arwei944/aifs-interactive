# 任何分辨率的愿景：Patch-n'-Pack和NaFlex

> 真实的图像不是224x224的正方形。收据是9:16，图表是16:9，医疗扫描可能是4096x4096，手机截图是9:19.5。2024年之前的VLM答案——将所有东西调整为固定的正方形——抛弃了OCR、文档理解和高分辨率场景解析工作所需的信号。NaViT （b谷歌，2023）显示，您可以将可变分辨率的贴片打包到具有块对角屏蔽的单个Transformer批次中。Qwen2-VL的M-RoPE（2024）完全放弃了绝对位置表。LLaVA-NeXT的AnyRes将高分辨率图像平铺到基础+子图像中。SigLIP 2的NaFlex变体（2025）现在是开放vlm的默认编码器，需要单个检查点来服务每个宽高比。本课从头到尾地实现patch-n' pack。

**Type:** Build
**Languages:** Python (stdlib, patch packer + block-diagonal mask)
**Prerequisites:** Phase 12 · 01 (ViT patches), Phase 12 · 05 (LLaVA)
**Time:** ~120 minutes

## 学习目标

- 将一批可变分辨率图像中的补丁打包到一个序列中，并构建块对角线注意力掩码。
- 对于给定的任务，可以选择AnyRes平铺（LLaVA-NeXT）、NaFlex （SigLIP 2）和M-RoPE （Qwen2-VL）。
- 无需调整大小即可计算OCR，图表和摄影的令牌预算。
- 列出三种square-resize的失效模式：文本被压扁、内容被裁剪、填充上的符号被浪费。

## 这个问题

Transformer需要一个顺序。批处理是相同长度的序列的堆栈。如果您的图像是224x224的，则每次获得196个补丁令牌，不需要填充，工作完成。在224上训练，在224上推断，再也不考虑决议。

世界不会合作。文档是纵向的（8.5x11英寸，2:3左右）。图表截图是横向的（16:9）。收据又高又薄（1:3）。2048 × 2048或更大的医疗成像船。移动设备屏幕截图为1170x2532（0.46:1）。

2024年前的三种选择以及每种选择失败的原因：

1. 将大小调整为固定的正方形（224x224或336x336）。压扁会扭曲文字和人脸。降级会破坏图表标签和OCR内容。直到LLaVA-1.5的标准做法。
2. 裁剪为固定长宽比。你扔掉了大部分图像，而选择裁剪位置本身就是一个视觉问题。
3. 垫到最长的一边。修复了失真，但浪费了50%以上的令牌在肖像图像的填充上。所有这些代币的二次注意力成本。

2024-2025年的答案是：让Transformer以图像的原生分辨率吃掉补丁，并找出如何在不浪费计算的情况下将异构批次打包成一个序列。

## 这个概念

### NaViT和补丁包

NaViT （Dehghani et al., 2023）是一篇证明这种方法大规模有效的论文。这个想法是机械的：

1. 对于批处理中的每个图像，以选定的补丁大小（例如14）计算其原生补丁网格。
2. 将每个图像的patch平铺成自己的可变长度序列。
3. 将所有图像的补丁连接到批处理的一个长序列中。
4. 建立一个对角块的注意力蒙版，这样图像a的补丁只会出现在图像a内。
5. 携带每个补丁的位置信息（2D RoPE或分数位置嵌入）。

336x336（576个令牌）、224x224（256个令牌）和448x336（768个令牌）的三个图像的批处理成为一个具有1600x1600块对角掩码的1600个令牌序列。没有填充。没有浪费的计算。Transformer处理任意宽高比。

NaViT还在训练过程中引入了分数补丁掉落——在批次中随机掉落50%的补丁——这既规范了训练，又加快了训练速度。SigLIP 2继承了这一点。

### AnyRes (LLaVA-NeXT)

LLaVA-NeXT的AnyRes是一个务实的选择。给定高分辨率图像和固定编码器（CLIP或SigLIP为336），平铺图像：

1. 从预def 的集合中选择一个网格布局- (1x1), (1x2), (2x1), (1x3), (3x1), （2x2）等-最适合图像的宽高比。
2. 将整个图像平铺到网格中；每个贴图变成336x336的裁剪。
3. 还要生成一个缩略图：将整个图像的大小调整为336x336，作为全局上下文标记。
4. 通过冻结的336编码器编码每个贴图。连接平铺标记+缩略图标记。

对于2x2网格加上缩略图的672x672图像：4 * 576 + 576 = 2880个视觉标记。昂贵但有效——LLM既关注当地细节，又关注全球背景。

当您的编码器被冻结并且只支持一种分辨率时，AnyRes是选择的路线。对于大型图像，它会增加令牌计数（4x4网格上的1344x1344图像是9216 + 576≈9800个令牌，这填充了大部分8k LLM上下文）。

### M-RoPE (Qwen2-VL)

Qwen2-VL介绍了多模态旋转位置嵌入。与NaViT的分数位置或AnyRes的平铺和缩略图不同，每个补丁都带有3D位置（时间、高度、宽度）。查询/键旋转处理任意的H、W和时间长度。

M-RoPE提供无需再培训的本机动态分辨率。在推理时，你输入任何HxW图像，补丁嵌入器产生H/14 xW /14个标记，每个标记获得其（t=0, r=row, c=col）位置，RoPE以正确的频率旋转注意力，完成。Qwen2.5-VL和Qwen3-VL延续了这一功能。InternVL3的V2PE是相同的思想，每个模态都有不同的编码。

与AnyRes不同，M-RoPE在原生分辨率下是O（H x W / P^2）个令牌——没有乘法贴图开销。与NaViT不同的是，它仍然需要每次转发一个图像。跨分辨率的批处理仍然需要最上面的patch-n' pack。

### NaFlex （SigLIP 2）。

NaFlex是SigLIP 2检查点的原生伸缩模式。单个模型在推理时提供多个序列长度（256、729、1024个令牌）。在内部，它在训练期间使用navit风格的patch-n' pack和每个patch的绝对分数位置。卖点：一个检查点，根据任务的推断选择你的令牌预算。

对于语义任务（分类、检索），256个标记。对于OCR或图表理解，1024个令牌。没有再培训。

### 包装口罩

块对角掩码是大多数实现失败的地方。对于长度的打包序列你可以从一个累积长度列表中构建它：

```
offsets = [0, n_0, n_0+n_1, ..., N_total]
M[i, j] = 1 iff there exists b where offsets[b] <= i < offsets[b+1] and offsets[b] <= j < offsets[b+1]
```

### 令牌的预算

根据任务选择策略：

- OCR / documents: 1024-4096个令牌。SigLIP 2 NaFlex在1024，或AnyRes 3x3 +缩略图。
- 图表和UI: 729-1024令牌，原生384-448。Qwen2.5-VL动态分辨率与最大像素上限。
- 自然照片：256-576代币就可以了。下游LLM看得够多了。在内容密度高的地方购买代币。
- 视频：空间池化后每帧64-128个令牌，2-8 FPS。第12.17课涵盖了这个。

2026生产规则：选择每个任务的最大像素上限，以本地长宽比编码，直到该上限，打包批，并跳过填充。Qwen2.5-VL曝光

## 关键术语

| Term | What people say | What it actually means |
|------|-----------------|------------------------|
| Patch-n'-pack | "NaViT-style packing" | Concatenate variable-length patch sequences from different images into one batch dimension |
| Block-diagonal mask | "Packing mask" | Attention mask that confines each image's patches to attend only to themselves, not neighbors in the pack |
| AnyRes | "LLaVA-NeXT tiling" | Split a high-res image into a grid of fixed-size tiles plus a global thumbnail; encode every tile with a fixed encoder |
| NaFlex | "SigLIP 2 native-flex" | Single SigLIP 2 checkpoint that serves 256/729/1024-token budgets at inference without retraining |
| M-RoPE | "Multimodal RoPE" | 3D rotary position encoding (time, row, column) that handles arbitrary H, W, T without position tables |
| cu_seqlens | "FlashAttention packing" | Cumulative-length tensor the FlashAttention varlen path uses instead of a dense block-diagonal mask |
| min_pixels / max_pixels | "Resolution bounds" | Qwen2.5-VL per-request knobs capping token count on very small or very large inputs |
| Visual token budget | "How many tokens per image" | Rough count of patch tokens emitted per image; sets the LLM's prompt budget and attention cost |
