# 顶点11 - LLM可观察性和评估仪表板

> Langfuse是开放式的。alize Phoenix发布了2026 GenAI semconv映射。Helicone和Braintrust在每用户成本归属上都翻了一番。tracelloop的OpenLLMetry成为事实上的SDK工具。生产形式是ClickHouse用于跟踪，Postgres用于元数据，Next.js用于UI，以及一小群eval作业（DeepEval， RAGAS, LLM-judge）运行采样跟踪。从至少四个SDK家族中构建一个自托管的摄取，并在五分钟内演示捕获注入的回归。

**Type:** Capstone
**Languages:** TypeScript (UI), Python / TypeScript (ingest + evals), SQL (ClickHouse)
**Prerequisites:** Phase 11 (LLM engineering), Phase 13 (tools), Phase 17 (infrastructure), Phase 18 (safety)
**运行阶段：** P11·P13·P17·P18
**Time:** 25 hours

## 问题

2026年运行生产流量的每个AI团队都会在模型旁边保留一个可观察平面。成本归因。幻觉检测。漂移监测。越狱的信号。SLO仪表板。PII泄漏警报。开源参考——Langfuse、Phoenix、OpenLLMetry——将OpenTelemetry GenAI语义约定融合为摄取模式。现在，您可以使用一个SDK和船舶兼容跨度来测量OpenAI， Anthropic，谷歌，LangChain， LlamaIndex和vLLM。

您将构建一个自托管的仪表板，它从至少四个SDK系列中摄取，在采样的跟踪上运行一小组eval作业，检测漂移和警报。测量条：给定一个故意注入的回归（一个开始产生PII的提示），仪表板捕获它并在五分钟内发出警报。

## 概念

摄取是OTLP HTTP。SDK生成GenAI-semconv跨度：在ClickHouse中进行柱状分析；元数据（用户、会话、应用程序）落在Postgres中。

eval作为批处理作业在采样轨迹上运行。DeepEval对忠诚度、毒性和答案相关性进行评分。当跟踪携带检索上下文时，RAGAS对检索指标进行评分。自def llm法官运行特定于领域的检查（PII泄漏、非策略响应）。Eval运行回写到与链接到父跟踪的Eval跨度相同的ClickHouse。

漂移检测观察嵌入空间随时间的分布（提示嵌入的PSI或KL散度）以及评价得分趋势。警报提供给Prometheus Alertmanager，然后是Slack / PagerDuty。UI是Next.js 15 with Recharts。

## 堆栈

- 摄取：OpenTelemetry sdk + GenAI语义约定；OTLP HTTP传输
- 收集器：OpenTelemetry收集器与尾部采样处理器（用于成本控制）
- 存储：ClickHouse用于存储跨度，Postgres用于存储元数据，S3用于存储原始事件存档
- 评估：DeepEval， RAGAS 0.2， alize Phoenix评估器包，自def LLM法官
- 漂移：每周汇总提示嵌入（句子Transformer）的PSI / KL
- 警报：Prometheus Alertmanager -> Slack / PagerDuty
- 15应用路由器+ Recharts +服务器动作
- 支持的sdk有：OpenAI、Anthropic、谷歌GenAI、LangChain、LlamaIndex、vLLM

## 构建它

1. **收集器配置。** OpenTelemetry收集器与OTLP HTTP接收器，尾部采样器保持100%的错误跟踪和10%的成功，并导出到ClickHouse和S3。

2. ** ClickHouse模式。**表通过user_id和app_id添加二级索引。

3. **SDK覆盖测试。**使用OpenLLMetry自动仪器的每个SDK （OpenAI, Anthropic，谷歌，LangChain, LlamaIndex, vLLM）编写一个小型客户端应用程序。在ClickHouse中验证每个生成的典型GenAI跨度。

4. ** Eval工作。**一个预定的作业读取最后15分钟的采样痕迹，并运行DeepEval的可靠性、毒性和答案相关性。输出是链接到父跟踪的eval跨度。

5. **自def LLM-judge。** PII泄漏判断：给出响应，调用守卫LLM来评分PII泄漏的可能性。得分高的响应会出现在分类队列中。

6. **漂移检测。**每周作业计算本周汇总的提示嵌入和过去4周基线之间的PSI。如果PSI超过阈值，则发出警报。

7. **仪表板。** Next.js 15与页面：概述（跨度/秒，成本/用户，p95延迟），跟踪（搜索+瀑布），评估（忠诚度趋势，毒性），漂移（PSI随着时间的推移），警报。

8. **提醒链。**普罗米修斯出口商读取eval得分总和和延迟百分位数；Alertmanager向Slack发送警告，向PagerDuty发送严重违规。

9. **回归探针。**注入一个bug：被评估的聊天机器人在1%的时间内开始泄漏假ssn。衡量MTTR：从bug部署到Slack警报。

## 练习

1. 为Haystack框架添加自def 工具。验证规范跨越土地ClickHouse与忠实

2. 在相同的轨迹上将DeepEval替换为Phoenix评估器。测量两个eval引擎之间的分数漂移。

3. 锐化漂移检测器：计算每个app-id的PSI，而不是全局。显示每个应用的漂移轨迹。

4. 添加一个“用户影响”页面：每个用户的成本和每个用户的故障率。

5. 建立一个尾抽样策略，保留100%毒性>.5的痕迹，加上剩余10%的分层样本。引入了测量抽样偏差。

## 关键术语

| Term | What people say | What it actually means |
|------|-----------------|------------------------|
| GenAI semconv | "OTel LLM attributes" | 2025 OpenTelemetry spec for LLM span attributes (system, model, tokens) |
| Tail sampling | "Post-trace sample" | Collector decides to keep or drop a trace after it completes (can peek errors) |
| PSI | "Population stability index" | Drift metric comparing two distributions; > 0.2 typically signals meaningful drift |
| LLM-judge | "Eval as model" | An LLM scoring another LLM's output on a rubric (faithfulness, toxicity, PII) |
| Tail-sampling policy | "Keep-rule" | Rule that decides which traces to persist vs drop; errored + sample-rate |
| Eval span | "Linked eval trace" | Child span carrying an eval score linked to the original LLM call span |
| Cost per user | "Unit economics" | Dollar cost attributed to a user_id over a window; key product metric |
