# MARL - MADDPG, QMIX, MAPPO

> 多智能体协调的强化学习遗产，它在2026年仍然为LLM-agent系统提供信息。**MADDPG** (Lowe et al., NeurIPS 2017, arXiv:1706.02275)引入了中心化训练，去中心化执行（CTDE）：每个评论家在训练过程中看到所有智能体的状态和行为；在测试时，只有本地参与者运行。适用于合作、竞争和混合环境。**QMIX** (Rashid et al., ICML 2018, arXiv:1803.11485)是具有单调混合网络的值分解；每个agent的Q组合成关节Q**MAPPO** (Yu et al., NeurIPS 2022, arXiv:2103.01955)是具有集中值函数的PPO；在粒子世界、SMAC、谷歌Research Football、Hanabi上“惊人的有效”，只需最少的调整。这些支持必须分散行动的代理团队的培训政策。MAPPO是默认的2026年协作- marl基线。这节课从一个小的网格世界玩具开始，在接触llm代理训练之前，将这三个想法放在肌肉记忆中。

## 问题

LLM-agent系统越来越多地训练代理间协调的策略：何时推迟，何时采取行动，呼叫哪个对等。告诉你如何训练这种策略的文献是多智能体强化学习（MARL），它早于LLM浪潮，并且有一小部分占主导地位的算法。

阅读没有模式词汇的MARL论文是痛苦的。集中式培训与分散执行（CTDE）、价值分解和集中式批评不是流行语——它们是针对特定问题的具体答案：

- 从每个智能体的角度来看，独立RL（每个智能体单独学习）是非平稳的。坏的。
- 集中式RL（一个代理控制所有代理）不能扩展并且违反执行约束。
- CTDE两者兼得：培训时使用全球信息，部署时使用本地政策。

## 概念

### 论文使用的三种环境

- **粒子世界（多代理粒子环境）。**带有合作/竞争任务的简单2D物理。MADDPG的原始测试平台。
- **星际争霸多代理挑战（SMAC）**合作性微观管理，局部观察。QMIX试验台。离散的动作，连续的状态。
- **谷歌研究足球，哈尔滨，MPE。** MAPPO基线。

不同的环境有不同的行动/观察类型。算法会做出相应的选择。

### MADDPG (2017) - CTDE模式

每个代理每个代理人也有一个评论家演员根据评论家的评价根据政策梯度进行更新。

```
actor update:    grad_theta_i J = E[grad_theta mu_i(o_i) * grad_a_i Q_i(x, a_1..n) at a_i=mu_i(o_i)]
critic update:   TD on Q_i(x, a_1..n) given next-state joint estimate
```

为什么CTDE：在培训的时候，我们知道每个人的行为；我们用它来减少每个评论家的差异。在部署时，每个代理只能看到

失败模式：批评家与N个agent一起成长（输入包括所有动作）。在没有近似值的情况下不能扩展超过~10个代理。

### QMIX(2018) -价值分解

合作。全局奖励是每个智能体q值的单调函数的和：

```
Q_tot(tau, a) = f(Q_1(tau_1, a_1), ..., Q_n(tau_n, a_n)),   df/dQ_i >= 0
```

单调性保证这正是你所需要的去中心化执行属性。在训练时，产生一个混合网络

为什么QMIX在SMAC上获胜：《星际争霸》的协作微管理具有同质代理、局部任务、全局奖励——非常适合价值分解。

失效模式：单调性约束是限制性的；有些任务的奖励结构不是单调可分解的（一个代理为团队牺牲）。扩展（QTRAN， QPLEX）放宽了这一点。

### MAPPO（2022）——被忽视的违约

多代理PPO：具有集中价值功能的PPO。每个代理都有自己的策略；所有代理都共享（或每个代理都有）查看完整状态的值函数。Yu et al. 2022在五个基准上对MAPPO与MADDPG、QMIX及其扩展进行了基准测试，发现：

- MAPPO在粒子世界、SMAC、b谷歌Research Football、Hanabi、MPE上匹配或击败了非策略的MARL方法。
- 需要最小的超参数调优。
- 稳定的培训;可跨种子繁殖。

在本文之前，社区低估了政策上的MARL。2026年，MAPPO将成为合作MARL的默认基线；任何新方法都必须打败它。

### 为什么llm代理工程师应该关心这个问题

三种直接用途：

1. * *路由器培训。**一个元代理选择哪个子代理处理一个任务。这是一个有N个分散子代理和一个集中路由器的MARL问题。现在适合。
2. * *角色出现。**在生成智能体模拟中，随着时间的推移，训练智能体采用互补角色是一个伪装的MARL问题。qmix风格的价值分解通过构造强制互补。
3. **使用多代理工具。**当代理共享工具并竞争预算时，通过CTDE培训他们产生可部署的尊重资源约束的本地策略。

实际警告：在2026年，大多数生产llm代理系统会提示它们的政策，而不是训练它们。当你有(a)大量的交互数据，(b)明确的奖励信号，(c)愿意投资于培训基础设施时，MARL就会出现。

### CTDE作为超越RL的设计模式

即使没有经过培训，CTDE也是一个有用的架构模式：

- 在*设计*期间，假设整个团队可见。
- 在*运行时*，强制分散执行：每个代理只看到

该模式迫使您保持每个代理的显式状态，并预先考虑部分可观察性。许多生产多代理系统在任何地方都默默地假定共享状态——CTDE规则阻止了这种情况。

### 非平稳性问题

当多个代理同时学习时，每个代理的环境（包括其他代理的策略）是非平稳的。经典的单智能体RL证明被打破了。本课中的MARL算法都解决了这个问题：

- 全局评论家看到所有的动作，所以它的价值估计是固定的。
- QMIX：值分解将学习移动到一个定义了最优性的联合q空间。
- MAPPO：中心化的价值函数抑制了他人政策变化带来的差异。

在LLM-agent系统中，非平稳性表现为“我的代理上个月工作了，现在上游的其他代理发生了变化，我的代理行为不正常。”用CTDE训练MARL是原则性的解决方案；即时级别的修复更快，但持久性较差。

### 这节课没有涵盖的内容

训练实际的网络是第09阶段的主题。本课构建脚本策略版本，演示CTDE、值分解和集中式值模式，而不需要梯度更新。目标是在获得完整的MARL库（PyMARL、MARLlib、RLlib多代理）之前内化模式。

## 船这

生产中的MARL很少见。当你使用它时：

- **从MAPPO开始。** 2022年的文件将此作为基准；首先复制它可以节省数周的时间来寻找更新奇的方法。
- **记录每个代理的观察和行动流。**调试没有每个代理跟踪的MARL是没有希望的。
- **将培训代码与执行代码分开。** CTDE是一门学科；让执行的路径真的只有看到
- **奖励塑形警告。** MARL对奖励设计非常敏感。在塑造过程中有一个协调缺陷，代理们学会利用它。进行对抗性测试。
- **对于LLM代理**，首先考虑提示级策略。只有在交互数据+奖励信号+基础设施都具备的情况下，才进行MARL训练。

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| MARL | "Multi-Agent RL" | Reinforcement learning for multi-agent systems. |
| CTDE | "Centralized Training, Decentralized Execution" | Train with global info; deploy with local policies. |
| MADDPG | "Multi-Agent DDPG" | CTDE with per-agent critic seeing all observations + actions. |
| QMIX | "Value decomposition" | Monotonic mixing of per-agent Qs. Cooperative. |
| MAPPO | "Multi-Agent PPO" | PPO with centralized value function. 2026 default baseline. |
| Value decomposition | "Sum of individual Qs" | Joint Q represented as a monotone function of per-agent Qs. |
| Non-stationarity | "Moving targets" | Each agent's env changes as others learn. The core MARL problem. |
| On-policy / off-policy | "Learn from current / replay" | PPO is on-policy (MAPPO); DDPG and Q-learning are off-policy. |
| SMAC | "StarCraft Multi-Agent Challenge" | Cooperative micromanagement benchmark; QMIX's homegrown ground. |
