# MARL - MADDPG, QMIX, MAPPO

## "Problem"

LLM-agent systems are increasingly training strategies for coordination among agents: when to delay, when to take action, and which peer to call. The literature that tells you how to train this strategy is multi-agent reinforcement Learning (MARL), which preceded the LLM wave and has a small number of dominant algorithms.

Reading MARL papers without pattern vocabulary is painful. Centralized training and decentralized execution (CTDE), value decomposition, and centralized criticism are not buzzwords - they are concrete answers to specific problems:

- From the perspective of each agent, independent RL (each agent learning independently) is non-stationary. Bad.
- Centralized RL (where one agent controls all agents) cannot be scaled and violates execution constraints.
- CTDE has both: it uses global information during training and local policies during deployment.

## Concept

### The three environments used in the thesis

- Particle world (multi-agent particle environment). Simple 2D physics with cooperative/competitive tasks. The original test platform of MADDPG.
- ** StarCraft Multi-Agent Challenge (SMAC) ** Cooperative Micromanagement, partial observation. QMIX test bench. Discrete actions, continuous states.
- Google Research Football, Harbin, MPE. MAPPO baseline.

Different environments have different types of actions/observations. The algorithm will make corresponding choices.

### MADDPG (2017) - CTDE Mode

Each agent also has a critic actor who updates based on the critics' evaluations in accordance with the policy gradient.

```
actor update:    grad_theta_i J = E[grad_theta mu_i(o_i) * grad_a_i Q_i(x, a_1..n) at a_i=mu_i(o_i)]
critic update:   TD on Q_i(x, a_1..n) given next-state joint estimate
```

Why CTDE: During training, we know everyone's behavior; We use it to reduce the differences among each critic. During deployment, each agent can only see

Failure mode: The critic grows with N agents (the input includes all actions). In the absence of approximations, it cannot be expanded to more than ~10 agents.

### QMIX(2018) - Value Decomposition

Cooperation. The global reward is the sum of the monotonic functions of the q values of each agent:

```
Q_tot(tau, a) = f(Q_1(tau_1, a_1), ..., Q_n(tau_n, a_n)),   df/dQ_i >= 0
```

Monotonicity ensures that this is precisely the decentralized execution attribute you need. During training, a hybrid network is generated

Why QMIX wins on SMAC: StarCraft's collaborative micromanagement features homogeneous agents, local tasks, and global rewards - making it highly suitable for value decomposition.

Failure mode: The monotonicity constraint is restrictive; The reward structure of some tasks is not monotonically decomposable (an agent sacrifices for the team). Extensions (QTRAN, QPLEX) relax this point.

### MAPPO (2022) - Overlooked Default

Multi-agent PPO: A PPO with concentrated value functions. Each agent has its own strategy; All agents share (or each agent has) a value function for viewing the complete state. Yu et al. 2022 benchmarked MAPPO with MADDPG, QMIX and its extensions on five benchmarks and found that:

- MAPPO matches or beats non-strategic MARL methods on Particle World, SMAC, b Google Research Football, Hanabi, MPE.
- Minimum hyperparameter tuning is required.
- Stable training; It can reproduce across seeds.

Before this article, the community underestimated MARL in terms of policy. In 2026, MAPPO will become the default baseline for cooperative MARL. Any new method must defeat it.

### Why should llm proxy engineers care about this issue

Three direct uses:

1. Router training. A meta-agent selects which sub-agent to handle a task. This is a MARL problem with N decentralized sub-agents and a centralized router. It's suitable now.
2. The character appears. In the simulation of generating agents, training agents to adopt complementary roles over time is a mask-like MARL problem. The value decomposition in the qmix style is achieved by constructing forced complementarity.
3. Use multi-agent tools. When agents share tools and compete for budgets, CTDE trains them to generate deployable local policies that respect resource constraints.

Actual warning: In 2026, most production llm agent systems will prompt their policies rather than train them. MARL emerges when you have (a) a large amount of interaction data, (b) clear reward signals, and (c) a willingness to invest in training infrastructure.

### CTDE, as a design pattern that surpasses RL

Even without training, CTDE is a useful architectural pattern:

- During the * design * period, assume that the entire team is visible.
- At runtime, enforce decentralized execution: each agent only sees

This mode forces you to maintain the explicit state of each agent and anticipate partial observability in advance. Many production multi-agent systems silently assume a shared state anywhere - CTDE rules prevent this.

### Non-stationarity problems

When multiple agents learn simultaneously, the environment of each agent (including the strategies of other agents) is non-stationary. The classic single-agent RL proof has been broken. All the MARL algorithms in this lesson have solved this problem:

- The global critic sees all the actions, so its value estimate is fixed.
- QMIX: Value decomposition moves learning to a joint q space that defines optimality.
- MAPPO: The centralized value function suppresses the differences brought about by changes in others' policies.

In an LLM-agent system, non-stationarity is manifested as "My agent started working last month. Now, other agents upstream have changed, and my agent's behavior is abnormal." Training MARL with CTDE is a fundamental solution. Immediate level repairs are faster but less persistent.

## This ship

MARL is rarely seen in production. When you use it:

- Start with MAPPO. The 2022 documents will take this as the benchmark. First, copying it can save several weeks of time to find more novel methods.
- Record the observation and action flow of each agent. Debugging a MARL without tracking each agent is hopeless.
- Separate the training code from the execution code. CTDE is a discipline. Let the execution path truly only be visible
- Reward shaping warnings. MARL is highly sensitive to reward design. There was a coordination defect in the shaping process, and the agents learned to take advantage of it. Conduct adversarial tests.
- For LLM proxies, consider the prompt level strategy first. MARL training should only be conducted when interaction data, reward signals and infrastructure are all in place.

## Key terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| MARL | "Multi-Agent RL" | Reinforcement learning for multi-agent systems. |
| CTDE | "Centralized Training, Decentralized Execution" | Train with global info; deploy with local policies. |
| MADDPG | "Multi-Agent DDPG" | CTDE with per-agent critic seeing all observations + actions. |
| QMIX | "Value decomposition" | Monotonic mixing of per-agent Qs. Cooperative. |
| MAPPO | "Multi-Agent PPO" | PPO with centralized value function. 2026 default baseline. |
| Value decomposition | "Sum of individual Qs" | Joint Q represented as a monotone function of per-agent Qs. |
| Non-stationarity | "Moving targets" | Each agent's env changes as others learn. The core MARL problem. |
| On-policy / off-policy | "Learn from current / replay" | PPO is on-policy (MAPPO); DDPG and Q-learning are off-policy. |
| SMAC | "StarCraft Multi-Agent Challenge" | Cooperative micromanagement benchmark; QMIX's homegrown ground. |
