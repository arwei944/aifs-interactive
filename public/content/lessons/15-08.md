# 有限自我完善设计

> 研究集中在四个基本要素上，以确定自我完善的循环。必须在每次编辑期间保持的形式不变量。无法修改的对齐锚。多目标约束，其中每个维度（安全性，公平性，健壮性）都必须保持，而不仅仅是性能。回归检测，当历史指标显示功能损失时暂停循环。它们都不是安全性的证明——信息论结果（Kolmogorov复杂度，Lob定理）限制了任何系统对其后继者的证明。这些缓解措施增加了无声失败的成本。

**Type:** Learn
**Languages:** Python (stdlib, bounded-loop with invariant check)
**Prerequisites:** Phase 15 · 07 (RSI), Phase 15 · 04 (DGM)
**Time:** ~60 minutes

## 这个问题

第7课的比赛模拟器显示，小的速度差异会形成大的差距。第4课的DGM案例研究表明，循环可以主动地与自己的评估者博弈。这两个结果都指向了同样的工程问题：你可以在一个自我完善的循环中施加什么约束，这样约束就不会被循环本身悄悄地削弱？

ICLR 2026 RSI研讨会总结（openreview.net/pdf?id=OsPQ6zTQXV）确定了四个这样的原语。Anthropic的RSP v3.0（第19课）和DeepMind的FSF v3（第20课）都在能力阈值中引用了它们。Meta hyperagent工作和社区框架（如SAHOO（2026年3月））在生产中实现了子集。

诚实的框架：这些都是缓解措施。信息论的结果限制了任何系统对其后继系统所能证明的东西，目前没有任何设计能正式地解决这个问题。有界循环比无界循环更安全，但从绝对意义上来说并不安全。

## 这个概念

### 原语1：形式不变量

不变量是在每次自我修改之前和之后都必须保持的属性。例子:

- 输出分布取决于一个固定的构造头（第17课）。
- 没有工具调用发送到未经授权的端点。
- 内存写入通过一个有日志记录的、有签名的路径。
- 评估器的模块散列与批准的版本匹配。

不变量由循环不能编辑的外部代码检查。如果提议的修改违反了不变量，它将被拒绝。这捕获了dgm风格的求值器篡改模式（第4课）。

难点在于选择既安全又可在合理时间内计算的不变量。过度指定会阻碍进展；不明确指定会让循环忽略重要的属性。

### 原语2：对齐锚

对齐锚是循环核心目标的不可变表示，固定在循环的编辑界面之外。例子:

- 在每次调用时从只读位置加载的宪法文本（第17课）。
- 具有独立访问控制的单独存储库中的求值器。
- 由人工签名并在每个周期重新验证的工具许可清单。

锚的作用是防止客观漂移。循环可以改进它追求目标的方式，但不能修改目标是什么。

微妙的失败模式：循环无法编辑的锚仍然可以被循环重新解释，因为它在读取锚的方式上发生了漂移。宪法人工智能（第17课）明确以理性为基础来处理新情况；推理层是解释漂移的所在。锚是必要的，但不是充分的。

### 基本要素3：多目标约束

优化单个标量分数的循环会找到捷径。必须同时满足多个硬约束的循环可用的捷径较少。典型的轴:

- 性能（任务级基准）
- 安全性（红队评估，已知不良的拒绝率）
- 公平性（敏感子组上的差异影响界限）
- 鲁棒性（OOD测试集，对抗性输入处理）

只有当每个约束都成立时，才接受修改。第13课的成本管理与财政限制叠加在一起。第18课的羊驼守卫插进去作为安全轴。

### 原语4：回归检测

每个周期的得分与历史分布进行比较。超出配置容差的下降将暂停循环。这捕获了无声的能力损失，否则将被吸收到运行平均值中，因为循环“改进了”它。

一个实际的实现：存储最后N个周期的每个任务的分数。每个新周期计算每个任务的增量。如果任何增量低于阈值，则拒绝循环并由人工检查。

### 信息理论限制

Kolmogorov复杂度和Lob定理设定了系统可以证明自身的上界。Schmidhuber的正式哥德尔机（第4课）的目标是这样的最高界；没有人完成非平凡证明。Lob的结果表明：如果一个系统可证明地相信“如果我证明我应该做X，我就会做X”，那么它将在没有证明它应该做X的情况下做X，这是一个众所周知的自我参照失败。

这对我们的原语意味着：它们不能解决安全问题。它们让无声的失败变得更加昂贵。一个恶意或漂移的循环会悄悄地绕过丢失的检查，现在必须主动破坏一个明确的检查，这是一个更可检测的签名。

### 一个工作示例

假设一个代理提议进行编辑。门控堆栈：

1. 不变检查：模块哈希，工具权限清单，宪法头。
2. 锚点检查：目标语句匹配已批准的版本（字节或语义）。
3. 多目标评价：性能、安全性、公平性、稳健性轴。
4. 回归检测：轴滴不超过公差。

四架飞机都必须通过才能着陆。任何单个故障都会暂停循环。

## 练习

1. 运行确认在不让黑客获胜的情况下，循环仍然在主要指标上有所改善。

2. 禁用回归检测。构造一个输入，当它导致无声的能力损失被接受时。

3. 禁用多目标约束。显示环路在性能轴上收敛，而安全轴下降。

4. 为编码代理设计一个对齐锚。什么文本，存储在哪里，如何检查？

5. 阅读ICLR 2026 RSI研讨会总结。从四个原语中选择一个，并提出对当前技术状态的具体改进。

## 关键术语

| Term | What people say | What it actually means |
|---|---|---|
| Invariant | "Always-true property" | A property checked by external code before and after every edit |
| Alignment anchor | "Pinned objective" | Immutable core-goal representation outside the loop's edit surface |
| Multi-objective constraint | "All axes must hold" | Performance, safety, fairness, robustness — all required |
| Regression detection | "Pause on drop" | Pause the loop when historical metric deltas suggest capability loss |
| Kolmogorov bound | "Information-theoretic limit" | Limits what a system can prove about its own successor |
| Lob's theorem | "Self-reference trap" | System can act on "I should" without proving it should |
| Gate stack | "Layered check" | Multiple primitives combined; any failure rejects the edit |
| Bounded improvement | "Mitigation, not proof" | Raises silent-failure cost; does not close the safety problem |
